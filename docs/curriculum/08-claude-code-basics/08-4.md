# 8-4. 플랜 모드와 권한 모드: 먼저 계획 보고 승인하기, 위험한 명령 다루기

| 과정 | 8. Claude Code 기초 |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 8-3 |
| 경험치 | 60 |

## 이 단원을 마치면

- 권한 모드 6가지(Manual/`default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`)가 각각 **무엇을 묻지 않고 하는지** 표로 말할 수 있다.
- `Shift+Tab`으로 모드를 바꾸고, `/plan`이나 `--permission-mode plan`으로 **계획부터** 받을 수 있다.
- 계획을 읽고 "승인 / 고쳐서 다시 / 거부"를 판단하고, `Ctrl+G`로 계획을 직접 편집할 수 있다.
- 위험한 명령(삭제, 강제 푸시, 비밀 노출)을 어느 모드에서도 막는 방법(권한 규칙, 훅 예고)을 안다.

## 왜 배우나 (나에게 어떤 쓸모)

6-3에서 "계획 먼저, 한 단계씩"을 배웠다. Claude Code는 그걸 **모드**로 만들어 뒀다. 플랜 모드에서는 Claude가 파일을 고칠 수 없고 계획만 낸다. 그리고 권한 모드는 "얼마나 믿고 맡길까"의 다이얼이다. 초보일수록 다이얼을 보수적으로 두고, 익숙해지면 푼다. 반대로 하면(처음부터 다 맡기면) 무엇이 어떻게 바뀌었는지 모른 채 앱이 망가진다. 매매로 치면 **손절 기준과 주문 한도**를 미리 정하는 것과 같다.

## 핵심 개념

(공식 permission-modes·best practices 문서, 확인일 2026-10-23. 버전에 따라 기본 모드가 다르니 문서 확인.)

### 1. 권한 모드 표

| 모드 | 묻지 않고 하는 것 | 맞는 때 |
|---|---|---|
| Manual (`default`) | 읽기만 | 모든 행동을 내가 검토, 민감한 작업 |
| `acceptEdits` | 읽기 + 파일 편집 + 흔한 파일 명령(mkdir, touch, mv, cp, sed — **rm·rmdir 도** 작업 폴더 안이면 묻지 않음. 폴더 밖·보호 경로·중요 경로 삭제는 묻는다) | 내가 보고 있는 코드를 반복 수정할 때 |
| `plan` | 읽기(+ auto 모드가 가능하면 분류기가 승인한 명령) | 바꾸기 전에 탐색·계획 |
| `auto` | 전부, 단 **분류기(두 번째 모델)** 가 위험한 것만 막음 | 긴 작업, 프롬프트 피로 줄이기 |
| `dontAsk` | 미리 허용한 도구만. 물어야 할 건 **거부** | CI·무인 실행 |
| `bypassPermissions` | 전부, 검사 없음 | **격리된 컨테이너/VM에서만** |

공식 문서: v2.1.283 이후 터미널·VS Code 대화형 세션의 기본 시작 모드는 `auto`다(그 전 버전은 Pro/Max/Team만). `Shift+Tab`을 누르면 `auto → default → acceptEdits → plan → auto` 순으로 돈다. `bypassPermissions`와 `dontAsk`는 순환에 없고 플래그로만 켠다.

**비유**: Manual은 결재 도장을 매번 받는 신입, acceptEdits는 문서 수정은 알아서 하되 외부 발송은 묻는 대리, auto는 감사팀(분류기)이 뒤에서 보는 팀장, bypass는 아무도 안 보는 상태(사고 나면 끝).

### 2. 초보자의 다이얼 설정

- **공부할 때(지금)**: `default`(Manual) 또는 `acceptEdits`. 변경마다 diff를 읽는 것이 공부다(8-2).
- **익숙한 반복 작업**: `auto`. 분류기가 "범위 밖 행동, 모르는 인프라, 외부 내용에 휘둘린 행동"을 막아 준다(공식 설명). 끝나고 `/diff`로 전체 확인.
- **절대 쓰지 않음**: `bypassPermissions`. 이 저장소 CLAUDE.md의 "강제 푸시·이력 삭제 금지"와 같은 선상이다.

시작 모드 지정: `claude --permission-mode plan` 처럼 플래그, 또는 `.claude/settings.json`의 `permissions.defaultMode`. 이 저장소에서 공부하는 동안은 `plan`을 기본으로 두는 것도 좋다(공식 문서 "Set plan mode as the default").

### 3. 플랜 모드: 계획 → 승인 → 실행

**들어가기**: `Shift+Tab`으로 `plan mode on`이 보일 때까지, 또는 요청 앞에 `/plan`을 붙이기(`/plan 자산관리부에 연금 추가`), 또는 `claude --permission-mode plan`.

**안에서**: Claude는 파일을 읽고 질문하고 계획을 쓰지만 **고치지 못한다.** 공식 best practices의 4단계:
1. 탐색: "assets.js와 ROOMS를 읽고 자산관리부 구조를 파악해."
2. 계획: "연금 종류를 추가하려면 어떤 파일이 바뀌어야 해? 계획을 만들어."
3. 구현: 계획을 승인하면 모드가 바뀌고 구현 시작.
4. 커밋.

**승인 화면의 선택지**(공식): "Yes, and use auto mode"(승인 후 auto로), "Yes, manually approve edits"(승인 후 편집마다 확인), "No, keep planning"(계속 계획). `Ctrl+G`를 누르면 계획이 편집기로 열려 **직접 고친 뒤** 진행할 수 있다.

**언제 쓰나**: 공식 문서 기준 — 접근이 불확실할 때, 여러 파일이 바뀔 때, 낯선 코드일 때. "diff를 한 문장으로 설명할 수 있으면 계획은 생략."

### 4. 위험한 명령은 모드와 별개로 막는다

모드는 "얼마나 묻나"다. "절대 하면 안 되는 것"은 따로 막는다.
- **권한 규칙** (`/permissions`): 도구별 허용/질문/거부 규칙. 예: `git push --force`는 거부, `npm run lint`는 허용. 공식 문서 "allow, ask, deny rules".
- **샌드박스** (`/sandbox`): 지원 플랫폼에서 파일·네트워크 접근을 OS 수준으로 제한.
- **훅**(9-3): 특정 폴더 쓰기 금지 같은 **결정적** 차단. CLAUDE.md의 "금지"는 지시일 뿐이라 훅이 필요한 경우가 있다(8-3).

위험 목록(이 프로젝트 기준): `rm -rf`, `git push --force`, `git reset --hard`, `.env` 읽기·출력, `localStorage` 전체 삭제 코드, 결제·주문 API 호출(4-3). 이 중 몇 개는 따라하기에서 거부 규칙으로 만든다.

### 5. "묻는 화면"을 읽는 법

Manual/acceptEdits에서 뜨는 승인 화면에는 **도구 이름**(Bash, Edit 등)과 **내용**(실행할 명령 전문, 바꿀 파일과 diff)이 있다. 읽을 것: 명령이 내 폴더 밖을 건드리나, 네트워크로 뭘 보내나, 삭제가 있나. 모르겠으면 **No**를 누르고 "이 명령이 뭘 하는지 설명해 줘"라고 묻는다. No는 실패가 아니라 질문이다.

## 따라하기

### 1. 모드 순환 보기 (15분)

세션에서 `Shift+Tab`을 눌러 입력창 아래 상태 표시줄의 모드 이름(`⏸ manual mode on`, `⏵⏵ accept edits on`, `⏸ plan mode on`, `⏵⏵ auto mode on`)이 바뀌는 걸 본다. 현재 모드는 이 상태 표시줄로 확인한다(`/status` 화면은 버전·모델·계정·연결을 보여 준다).

### 2. 플랜 모드로 기능 하나 (60분)

`/plan 재무부 이번 달 카드에 전월 대비 지출 증감률을 추가하고 싶어. 어떤 파일을 어떻게 고칠지 계획만.`
- 계획을 읽는다: 파일 목록, 순서, 검증 방법이 있나?
- 마음에 안 드는 항목을 "No, keep planning"으로 돌려보내 고치게 한다(예: "검증 단계를 Playwright로 바꿔").
- `Ctrl+G`로 계획을 열어 한 줄을 직접 고쳐 본다.
- "Yes, manually approve edits"로 승인 → 편집마다 diff를 읽고 승인.
- 브라우저 확인 → 커밋.

### 3. 거부 연습 (20분)

Manual 모드에서 "docs 폴더를 전부 지우고 다시 만들어 줘" 같은 요청을 한 뒤, 승인 화면에서 **No**를 누르고 "지우지 말고 이름만 바꾸는 방법은?"으로 바꾼다. No가 대화의 일부라는 걸 느낀다.

### 4. 거부 규칙 만들기 (30분)

`/permissions`에서 `git push --force`와 `rm -rf`를 **deny**로 등록한다. 등록 후 Claude에게 "강제 푸시해 줘"라고 시켜 거부되는지 확인한다(실제로 푸시되면 안 되므로 반드시 규칙을 먼저).

### 5. auto 모드 체험 (30분)

익숙한 작은 작업("docs/history.md에 오늘 한 일 한 줄 추가")을 `auto`에서 시켜 본다. 묻지 않고 끝나는지, 끝난 뒤 `/diff`로 변경이 보이는지 확인. 이 크기의 작업에만 auto를 쓴다는 감각을 잡는다.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 처음부터 auto/bypass | 뭐가 바뀌었는지 모름 | 공부 중엔 Manual/acceptEdits |
| 플랜 없이 큰 변경 | 엉뚱한 방향, 재작업 | 여러 파일·불확실하면 `/plan` |
| 계획을 안 읽고 승인 | 계획의 오해가 코드로 | 파일 목록·검증 방법 확인, Ctrl+G 편집 |
| 승인 화면을 반사적으로 Yes | 위험 명령 통과 | 도구·명령 전문 읽기, 모르면 No |
| 금지를 CLAUDE.md에만 | 가끔 어김 | `/permissions` deny, 훅 |
| 작은 수정에도 플랜 | 느림 | "한 문장으로 설명되면 생략" |

## 확인 퀴즈

**1. `acceptEdits`와 `auto`의 차이는?**

<details><summary>정답과 해설</summary>
acceptEdits는 파일 편집과 흔한 파일 명령(작업 폴더 안의 mkdir·mv·cp·rm 등)만 묻지 않고, 그 외(네트워크, 다른 명령)는 묻는다. auto는 전부 하되 분류기 모델이 위험한 것만 막는다.
</details>

**2. 플랜 모드에서 Claude가 못 하는 것은?**

<details><summary>정답과 해설</summary>
파일 편집. 읽기·질문·계획만 한다. 승인하면 모드가 바뀌어 편집이 시작된다.
</details>

**3. 계획이 80% 마음에 든다. 가장 빠른 처리는?**

<details><summary>정답과 해설</summary>
`Ctrl+G`로 계획을 편집기에서 직접 고친 뒤 승인. 또는 "No, keep planning"으로 고칠 점을 말한다.
</details>

**4. "절대 강제 푸시 금지"를 확실히 하려면 어디에 적나?**

<details><summary>정답과 해설</summary>
`/permissions`의 deny 규칙(또는 훅). CLAUDE.md의 문장은 지시라서 강제가 아니다.
</details>

**5. `bypassPermissions`를 써도 되는 유일한 상황은?**

<details><summary>정답과 해설</summary>
공식 문서 기준 격리된 컨테이너·VM 안. 내 컴퓨터·내 저장소에서는 쓰지 않는다.
</details>
