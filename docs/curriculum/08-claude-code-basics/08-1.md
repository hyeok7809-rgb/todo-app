# 8-1. Claude Code란: CLI/데스크톱/웹/IDE 확장, 세션과 컨텍스트, 요금(구독 vs API)

| 과정 | 8. Claude Code 기초 |
|---|---|
| 예상 시간 | 2시간 |
| 선수 단원 | 7-3 |
| 경험치 | 40 |

## 이 단원을 마치면

- Claude Code가 채팅과 어떻게 다른지(읽기·고치기·실행하기를 **스스로** 반복하는 에이전트)를 "맥락 수집 → 행동 → 검증" 순환으로 설명할 수 있다.
- 터미널 CLI, VS Code 확장, 데스크톱 앱, 웹(claude.ai/code), 모바일이 **같은 엔진**이며, 각각 언제 쓰면 좋은지 고를 수 있다.
- 세션(session)이 무엇이고, 세션이 컨텍스트(6-1)와 어떤 관계인지 안다.
- 구독과 API 중 어느 지갑으로 Claude Code가 돌아가는지 확인하고, 실수로 API 과금이 되지 않게 할 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

이 저장소 전체가 Claude Code로 만들어졌다. 0-4에서 설치하고 첫 대화를 했지만, "무엇이 가능하고 무엇을 조심해야 하는지"의 지도가 없으면 매번 더듬게 된다. 8과정은 그 지도다. 이 단원은 큰 그림(어디서, 어떻게 돌아가고, 돈은 어디서 나가나)을 잡고, 다음 단원들에서 하나씩 손에 익힌다.

## 핵심 개념

(Claude Code 공식 문서 overview·quickstart, 확인일 2026-10-21 기준. 기능은 빠르게 바뀌니 '더 보기'로 재확인.)

### 1. 채팅이 아니라 에이전트

**한 줄 정의**: 공식 문서의 표현대로 Claude Code는 "코드베이스를 읽고, 파일을 고치고, 명령을 실행하고, 개발 도구와 연동하는 에이전트형 코딩 도구"다.

**비유**: 채팅 AI가 전화 상담원이라면, Claude Code는 내 사무실에 출근해 서류함(폴더)을 직접 열어 보고, 수정하고, 테스트까지 돌려 보는 직원이다(0-4의 비유 그대로). 단, 직원은 **권한 모드**(8-4)에 따라 중요한 일 전에 나에게 묻는다.

**실제 예시** — 한 번의 요청에 일어나는 일:
```
나: "재무부에 카테고리 기능 추가해 줘"
Claude Code: app.js, index.html 읽기 → 수정안 작성 → 파일 고치기 → (내가 시키면) 브라우저로 확인 → 결과 보고
```
이 "읽기(맥락 수집) → 고치기(행동) → 확인(검증)"이 반복되는 것이 공식 문서가 말하는 작업 순환이다.

**왜 중요한가**: 채팅에서는 내가 복사·붙여넣기·실행을 다 했다. 여기서는 Claude가 한다. 그래서 **무엇을 허용할지**(8-4)와 **결과를 어떻게 검증할지**(8-6)가 핵심 기술이 된다.

### 2. 같은 엔진, 여러 입구

| 입구 | 특징 | 나에게 맞는 때 |
|---|---|---|
| 터미널 CLI (`claude`) | 가장 기본. 모든 기능 | 이 커리큘럼의 기본. 0-2 터미널을 배운 이유 |
| VS Code 확장 | 편집기 안에서 diff(변경 비교)를 눈으로 | 코드 변경을 읽으며 배울 때 |
| 데스크톱 앱 | 여러 세션 나란히, 예약 작업, 클라우드 세션 시작 | 세션 여러 개 관리 |
| 웹 (claude.ai/code) | 설치 없이 브라우저에서, 긴 작업 맡기고 나중에 확인 | 이 저장소가 처음 만들어진 곳 |
| 모바일 앱 | 웹 세션을 폰에서 | 밖에서 진행 확인 |

공식 문서: "각 입구는 같은 Claude Code 엔진에 연결되므로 저장소의 CLAUDE.md, 설정, MCP 서버가 모든 입구에서 동작한다." 즉 **설정은 저장소에 두면** 어디서 열어도 같다(8-3).

한 번 시작한 작업을 옮길 수도 있다: 웹에서 시작한 세션을 터미널로 가져오기(`claude --teleport`, 구독 필요), 터미널 세션을 데스크톱으로(`/desktop`), 폰에서 이어 가기(Remote Control). 지금은 "그런 게 있다" 정도만.

### 3. 세션과 컨텍스트

**한 줄 정의**: 세션은 한 번의 대화 묶음이다. 세션의 대화 전체(내 말, Claude의 답, 읽은 파일, 명령 결과)가 **컨텍스트 윈도우**(6-1)에 들어간다.

- `claude`로 시작하면 새 세션. `claude -c`는 이 폴더의 최근 세션 이어 가기, `claude -r`(또는 `/resume`)은 목록에서 고르기(공식 quickstart).
- 세션이 길어지면 앞부분이 요약된다(자동 compact). 작업이 바뀌면 `/clear`로 비운다(8-5).
- 세션은 폴더(프로젝트)에 묶인다. 이 저장소 폴더에서 `claude`를 치면 이 저장소의 CLAUDE.md를 읽는다.

**왜 중요한가**: "아까 말했는데 왜 잊었지"의 답이 여기 있다. 세션 = 책상. 비우고 다시 시작하는 게 더 잘 되는 경우가 많다(공식 best practices: "같은 문제로 두 번 넘게 고쳐 주었다면 /clear 하고 더 좋은 첫 요청으로").

### 4. 돈은 어디서 나가나

| 로그인 방식 | 지갑 | 확인 |
|---|---|---|
| claude.ai 구독(Pro/Max) 로그인 | 구독 한도(5시간·주간) | `/usage`에 플랜 사용량 막대 |
| Claude Console(API) 로그인 또는 `ANTHROPIC_API_KEY` 설정 | 토큰 종량 과금 | `/usage`의 Session 블록 달러 표시 |

공식 문서: "`ANTHROPIC_API_KEY` 환경변수가 설정돼 있고 사용에 동의하면 로그인 절차를 건너뛴다" — 즉 **API 키가 환경변수에 있으면 그 키로 과금**된다. 10과정에서 키를 만들면 Claude Code를 쓰는 터미널에서는 그 변수를 두지 않는다(4-2의 `.env`에만, 그것도 프로젝트 폴더의 파이썬 스크립트용으로).

공식 비용 문서의 참고 수치: 기업 평균 "개발자 1인당 활성일 기준 약 13달러, 월 150~250달러". 구독이면 이 비용이 한도 안에 포함된다. 구독 한도를 넘으면 `/usage-credits`로 추가 사용 크레딧을 켤 수 있다(지출 상한 설정 가능).

**왜 중요한가**: 6-4에서 정한 "사람 작업은 구독, 자동화는 API" 원칙을 Claude Code에서 지키는 방법이 **환경변수 관리**다.

### 5. Claude Code에서 쓸 수 있는 것들 (8·9과정 예고)

- **CLAUDE.md**(8-3): 매 세션 읽는 프로젝트 규칙. 이 저장소에 이미 있다.
- **권한 모드·플랜 모드**(8-4): 묻고 할지, 계획부터 할지.
- **슬래시 명령**(8-5): `/clear`, `/compact`, `/usage`, `/model`…
- **스킬**(9-2), **훅**(9-3), **서브에이전트**(9-1), **MCP**(9-4), **예약 작업**(9-5).

## 따라하기

### 1. 지금 내 입구 확인 (15분)

터미널에서 `claude --version`. 세션 안에서 `/status`로 버전·모델·계정·연결을 본다. 로그인 방식이 구독인지 확인(0-4). `/usage`로 플랜 사용량 막대를 본다.

### 2. 순환을 눈으로 보기 (30분)

이 저장소에서 `claude`를 열고:
> "routine.js의 routineStreak() 함수가 어떻게 동작하는지 설명해 줘. 파일을 읽어서."

Claude가 파일을 **읽는 단계**(맥락 수집)와 **답하는 단계**가 나뉘는 걸 본다. 이어서:
> "연속 달성일 계산이 맞는지 확인하는 작은 테스트 방법을 제안해 줘. 아직 고치지 마."

검증 단계를 설계하게 했다. 고치지 말라고 한 건 8-4(플랜 모드)의 예고다.

### 3. 세션 이어 가기 (20분)

`/exit`로 나갔다가 `claude -c`로 돌아온다. 아까 대화가 이어지는지 확인. `/rename streak-study`로 이름을 붙이고 나갔다가 `claude -r`로 목록에서 골라 본다.

### 4. 다른 입구 하나 (30분)

VS Code 확장 또는 데스크톱 앱을 설치해 **같은 저장소**를 열고, "README를 읽고 이 프로젝트를 3줄로 요약해"를 시켜 본다. 터미널과 같은 CLAUDE.md를 읽는지(요약에 "학습용"이라는 말이 들어가는지) 확인.

### 5. 지갑 점검 (15분)

터미널에서 `echo $ANTHROPIC_API_KEY`(Mac) 또는 `$env:ANTHROPIC_API_KEY`(PowerShell). **비어 있어야** 구독으로 돈다. 비어 있지 않다면 어디서 설정됐는지(쉘 설정 파일) 찾아 지운다. 10과정 전까지는 비어 있는 게 정상이다.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 채팅처럼 코드 복사해 넣음 | 비효율 | 파일을 읽게 한다("app.js 읽고…") |
| 한 세션에 온갖 작업 | 앞 규칙 망각, 품질 저하 | 작업마다 `/clear` |
| API 키가 환경변수에 | 구독 두고 과금 | 변수 제거, `.env`에만 |
| 어느 입구를 써야 할지 혼란 | 매번 새로 설정 | 설정은 저장소(CLAUDE.md)에, 입구는 상황대로 |
| 세션 이름 없이 나감 | 나중에 못 찾음 | `/rename` 후 `/resume` |

## 확인 퀴즈

**1. "맥락 수집 → 행동 → 검증" 순환에서, 바이브 코딩 초보가 가장 신경 써야 할 단계는?**

<details><summary>정답과 해설</summary>
검증. Claude가 고친 결과를 어떻게 확인할지(브라우저, 테스트, 스크린샷)를 내가 요청에 넣어야 한다(8-6). 행동은 Claude가 하지만 "됐다"의 기준은 내가 준다.
</details>

**2. 웹에서 만든 설정이 터미널에서도 적용되게 하려면 어디에 두나?**

<details><summary>정답과 해설</summary>
저장소 안(CLAUDE.md, .claude/ 설정). 모든 입구가 같은 엔진이라 저장소의 설정을 공유한다.
</details>

**3. `claude -c`와 `claude -r`의 차이는?**

<details><summary>정답과 해설</summary>
`-c`는 현재 폴더의 가장 최근 대화를 바로 잇고, `-r`은 이전 대화 목록에서 골라 잇는다.
</details>

**4. 구독으로 쓰는데 `/usage`에 달러 금액이 보인다. 무엇을 의심하나?**

<details><summary>정답과 해설</summary>
`ANTHROPIC_API_KEY` 환경변수로 API 과금 중일 가능성. (구독자에게도 Session 블록의 달러 추정치는 보이지만 "청구와 무관"하다고 문서가 설명한다. 플랜 사용량 막대가 보이면 구독이다.) 환경변수를 확인한다.
</details>

**5. 긴 작업을 맡기고 외출하려 한다. 어느 입구가 맞나?**

<details><summary>정답과 해설</summary>
웹(claude.ai/code) 또는 데스크톱의 클라우드 세션. 공식 문서가 "긴 작업을 시작해 두고 나중에 확인"하는 용도로 소개한다. 폰 앱으로 진행을 볼 수 있다.
</details>

## 숙제

1. **입구 결정** — 내 하루에 맞는 입구 조합을 정하라(예: 공부는 VS Code 확장, 긴 작업은 웹). `docs/model-policy.md`(6-4)에 추가.
2. **순환 관찰 3회** — 사흘 동안 작은 요청 하나씩 하고, 각 요청에서 Claude가 "읽은 파일 / 한 행동 / 검증한 방법"을 표로 적어라.
3. **8-2 예습** — 이 저장소에서 "하고 싶은 작은 변경" 하나를 정해 두라(예: 재무부 잔액 카드 문구 바꾸기). 다음 단원에서 처음부터 끝까지 혼자 한다.
