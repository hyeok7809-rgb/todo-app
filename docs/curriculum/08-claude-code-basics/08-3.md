# 8-3. CLAUDE.md와 메모리: 프로젝트 규칙 적어두기, 기억시키기

| 과정 | 8. Claude Code 기초 |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 8-2 |
| 경험치 | 60 |

## 이 단원을 마치면

- Claude Code의 두 기억 장치, **CLAUDE.md(내가 쓰는 규칙)** 와 **자동 메모리(Claude가 쓰는 메모)** 의 차이를 표로 말할 수 있다.
- CLAUDE.md를 둘 수 있는 세 위치(사용자·프로젝트·로컬)와 각각 누구에게 적용되는지 안다.
- `/init`으로 초안을 만들고, 공식 문서의 "넣을 것/뺄 것" 기준으로 다듬을 수 있다.
- 규칙이 무시될 때 원인(너무 긴 파일, 모호한 문장)을 찾아 고칠 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

6-1에서 "규칙은 파일에 적어야 안 잊는다"고 했고, 이 저장소의 `CLAUDE.md`가 바로 그 파일이다. 지금은 Claude가 써 준 것을 쓰고 있지만, 앞으로 규칙을 **내가** 고쳐 가야 한다. "주석을 한국어로", "빌드 도구 금지", "부서마다 파일 하나" 같은 규칙 덕분에 어느 세션에서 열어도 같은 방식으로 일한다. 이 단원은 그 파일을 내 것으로 만드는 시간이다.

## 핵심 개념

(공식 memory·best practices 문서, 확인일 2026-10-23.)

### 1. 두 가지 기억

| | CLAUDE.md | 자동 메모리(auto memory) |
|---|---|---|
| 누가 쓰나 | 나 | Claude |
| 내용 | 지시와 규칙 | 작업하며 배운 것·내 선호 |
| 범위 | 프로젝트·사용자·조직 | 저장소별 |
| 읽히는 때 | 매 세션 | 매 세션(처음 200줄 또는 25KB) |

공식 문서: 둘 다 "컨텍스트"이지 강제가 아니다. **반드시 막아야 하는 행동은 훅(9-3)으로** 한다. 지시는 구체적이고 짧을수록 잘 지켜진다.

### 2. CLAUDE.md를 두는 세 곳

| 종류 | 위치 | 적용 | 예 |
|---|---|---|---|
| 사용자 | `~/.claude/CLAUDE.md` | 내 모든 프로젝트 | "답은 한국어로, 결론부터" |
| 프로젝트 | `./CLAUDE.md` 또는 `./.claude/CLAUDE.md` | 그 저장소에서 일하는 모두 | 이 저장소의 파일 |
| 로컬 | `./CLAUDE.local.md` | 나만, 이 프로젝트에서 | 내 테스트 데이터 경로. `.gitignore`에 추가 |

현재 폴더와 그 **위** 폴더들의 CLAUDE.md가 시작할 때 전부 읽히고, 하위 폴더의 것은 그 폴더 파일을 건드릴 때 읽힌다. 여러 파일은 덮어쓰기가 아니라 **이어 붙여** 들어간다. 저장소에 `AGENTS.md`(다른 코딩 도구용 규칙 파일)만 있으면 그것을 대신 읽는다.

**비유**: 사용자 파일은 "내 일하는 방식", 프로젝트 파일은 "이 회사의 사규", 로컬 파일은 "내 책상 메모". 사규는 커밋해서 공유하고, 책상 메모는 공유하지 않는다.

### 3. `/init`과 다듬기

`/init`을 치면 Claude가 저장소를 분석해 빌드 명령·테스트 방법·관례를 담은 CLAUDE.md 초안을 만든다(이미 있으면 보강). 초안은 출발점일 뿐이다. 공식 best practices의 기준:

| ✅ 넣는다 | ❌ 뺀다 |
|---|---|
| Claude가 추측 못 하는 명령(실행·검증 방법) | 코드를 읽으면 알 수 있는 것 |
| 기본값과 **다른** 코드 스타일 | 언어의 표준 관례 |
| 저장소 예절(브랜치 이름, 커밋 규칙) | 자주 바뀌는 정보 |
| 이 프로젝트만의 설계 결정 | 긴 설명·튜토리얼 |
| 환경의 특이점(필요한 환경변수) | 파일 하나하나의 설명 |
| 직관적이지 않은 함정 | "깨끗한 코드를 써라" 같은 당연한 말 |

문서의 한 줄 기준: **"이 줄을 지우면 Claude가 실수하는가? 아니면 지워라."** 길면 중요한 규칙이 묻힌다. 200줄 아래를 권한다. 꼭 지켜야 할 한 줄에만 "IMPORTANT"를 붙인다(여러 줄에 붙이면 효과 없음). `/doctor`가 코드에서 알 수 있는 내용을 지우자고 제안해 준다(`/doctor prompt-audit`는 옛 모델용 지시·없는 파일 참조 같은 낡은 내용도 찾아 준다). `/context`로 파일이 읽혔는지 확인할 수 있다.

### 4. 다른 파일 가져오기와 규칙 폴더

- `@docs/ROADMAP.md`처럼 `@경로`를 적으면 그 파일이 시작할 때 함께 읽힌다(공식 "imports"). 긴 내용은 본문에 복사하지 말고 가져온다.
- `.claude/rules/*.md`에 주제별 규칙 파일을 둘 수 있다. 파일별로 "어떤 경로에만 적용"을 지정할 수도 있다(`paths`). 우리 저장소는 작아서 CLAUDE.md 하나면 충분하지만, 커지면 "부서별 규칙"으로 나눌 수 있다.

### 5. 자동 메모리

Claude가 작업하며 "이 사용자는 X를 선호한다", "이 프로젝트의 테스트는 Y로 돈다" 같은 것을 **스스로** 적는다. 저장 위치는 `~/.claude/projects/<프로젝트>/memory/`이고, `MEMORY.md` 색인 + 주제별 파일 구조다. `/memory`로 켜고 끄고 내용을 본다. 기본으로 켜져 있다(로컬 세션). 끄려면 `/memory`의 토글 또는 환경변수 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`.

**왜 중요한가**: 내가 매번 교정하던 것이 메모리에 쌓이면 교정이 줄어든다. 반대로 **틀린 학습**이 쌓일 수도 있으니 가끔 `/memory`로 내용을 읽고 지운다(7-1의 claude.ai 메모리 점검과 같은 습관).

### 6. 규칙이 안 지켜질 때

공식 문서의 진단:
- 계속 어기면 → 파일이 너무 길어 규칙이 묻혔다. 자른다.
- CLAUDE.md에 답이 있는데 물어보면 → 문장이 모호하다. 구체적으로.
- 한 규칙만 자꾸 빠지면 → 그 줄에만 "IMPORTANT".
- 그래도 안 되면 → 그건 지시로 될 일이 아니다. 훅(9-3)으로 강제.

CLAUDE.md는 코드처럼 다룬다: 문제가 생기면 고치고, 정기적으로 줄이고, 고친 뒤 행동이 바뀌는지 관찰하고, git에 커밋한다.

## 따라하기

### 1. 지금 파일 읽기 (20분)

이 저장소의 `CLAUDE.md`를 처음부터 끝까지 읽는다. 각 줄에 "이걸 지우면 Claude가 실수할까?"를 묻고, 지워도 될 줄에 표시한다. 8-2 숙제 3에서 찾은 "매번 말하게 되는 규칙"을 어디에 넣을지 정한다.

### 2. `/context`와 `/doctor` (20분)

세션에서 `/context`로 CLAUDE.md가 읽혔는지, 얼마나 차지하는지 본다. `/doctor`를 실행해 제안을 읽는다. 받아들일 것만 반영.

### 3. 규칙 한 줄 추가와 검증 (40분)

예: "커밋 메시지 첫 줄은 '단계: 무엇'". 추가하고 **새 세션**(`/clear`)에서 커밋을 시켜 규칙대로 나오는지 확인. 안 되면 문장을 고친다. 이 "고치고 → 새 세션에서 관찰" 루프가 CLAUDE.md 관리의 전부다.

### 4. 사용자 파일 만들기 (30분)

`~/.claude/CLAUDE.md`를 만들어 모든 프로젝트에 적용할 내 규칙 3줄을 적는다(한국어 답, 결론부터, 용어 풀어쓰기). 다른 폴더에서 `claude`를 열어 적용되는지 확인.

### 5. 자동 메모리 보기 (20분)

`/memory`로 자동 메모리 목록을 연다. 이 저장소에서 쌓인 메모가 있는지, 틀린 것이 있는지 본다. 없으면 일부러 교정("앞으로 함수 이름은 동사로 시작") 두어 번 한 뒤 다시 본다.

### 6. 커밋 (10분)

고친 `CLAUDE.md`를 커밋한다. `CLAUDE.local.md`를 만들었다면 `.gitignore`에 추가했는지 확인.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 전부 적음 | 규칙이 무시됨 | 200줄 아래로, "지우면 실수하나" 기준 |
| 당연한 말 | 토큰 낭비 | 코드로 알 수 있는 건 삭제 |
| 모호한 문장 | 물어보거나 엉뚱하게 | 구체적·측정 가능하게 |
| 강제가 필요한 걸 지시로 | 가끔 어김 | 훅(9-3) |
| 로컬 파일을 커밋 | 개인 경로 공유 | `.gitignore` |
| 자동 메모리 방치 | 틀린 학습 반복 | `/memory` 정기 점검 |

## 확인 퀴즈

**1. CLAUDE.md와 자동 메모리의 차이 두 가지.**

쓰는 주체(나 vs Claude)와 내용(규칙 vs 배운 것·선호). 둘 다 매 세션 읽히지만 강제는 아니다.
</details>

**2. "이 규칙은 나만, 이 프로젝트에서만" 적용하고 싶다. 어디에?**

<details><summary>정답과 해설</summary>
`./CLAUDE.local.md`. 그리고 `.gitignore`에 추가해 커밋되지 않게 한다.
</details>

**3. 규칙을 적었는데 Claude가 자꾸 어긴다. 첫 번째로 의심할 것은?**

<details><summary>정답과 해설</summary>
파일이 너무 길어 규칙이 묻힌 것. 자르고, 그래도 안 되면 그 줄에만 IMPORTANT, 그래도 안 되면 훅으로 강제.
</details>

**4. "이 줄을 지우면 Claude가 실수하는가?"라는 기준으로 다음 중 지울 줄은? (a) "검증은 index.html 열어 확인" (b) "깨끗한 코드를 써라" (c) "toISOString 금지"**

<details><summary>정답과 해설</summary>
(b). 당연한 말이라 효과가 없다. (a)는 Claude가 추측 못 하는 검증 방법, (c)는 이 프로젝트만의 함정이라 남긴다.
</details>

**5. 긴 참고 문서를 CLAUDE.md에 넣고 싶다. 통째로 복사하지 않는 방법은?**

<details><summary>정답과 해설</summary>
`@경로` import로 가져온다. 또는 항상 필요한 게 아니면 스킬(9-2)로 빼서 필요할 때만 읽히게 한다.
</details>
