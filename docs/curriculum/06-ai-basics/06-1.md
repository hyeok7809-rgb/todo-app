|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 5-3 |

## 이 단원을 마치면

- 대규모 언어 모델(LLM, Large Language Model)이 "다음에 올 토큰을 예측하는 기계"라는 것을 비유 없이도 설명할 수 있다.
- 토큰(token)이 무엇이고, 왜 요금·속도·길이 제한이 전부 토큰 단위인지 안다.
- 컨텍스트 윈도우(context window)가 "한 번에 볼 수 있는 책상 크기"라는 것과, 긴 대화에서 앞부분을 잊는 이유를 설명할 수 있다.
- 지식 컷오프(knowledge cutoff)가 무엇이고, "모델이 모르는 것"을 검색·문서로 채우는 방법을 안다.

## 왜 배우나 (나에게 어떤 쓸모)

지금까지 Claude Code를 쓰면서 "왜 이걸 모르지?", "왜 아까 말한 걸 잊었지?", "왜 이 정도에 돈이 이만큼 나가지?"를 한 번쯤 겪었을 것이다(5-3 숙제 3). 그 답이 전부 이 단원에 있다. 토큰을 알면 비용을 줄일 수 있고, 컨텍스트를 알면 요청을 쪼갤 줄 알게 되고, 컷오프를 알면 "검색해서 확인해"라고 말할 타이밍을 안다. 10과정에서 API로 직접 호출할 때는 이 개념이 그대로 **요금 명세서**가 된다.

## 핵심 개념

### 1. LLM은 "다음 토큰 예측기"다

**한 줄 정의**: LLM은 엄청난 양의 글을 읽고 "이 다음에 어떤 글자 조각이 올 확률이 높은가"를 배운 모델이다. 답변은 그 예측을 **한 토큰씩 이어 붙인** 결과다.

**비유**: 휴대폰 자판의 다음 단어 추천을 수십억 배 키운 것. 다만 바로 앞 단어만 보는 게 아니라 **지금까지의 대화 전체**(컨텍스트)를 보고 추천한다. 그래서 문맥에 맞는 긴 글이 나온다.

**실제 예시**: "오늘 코스피는" 다음에 올 토큰으로 "상승", "하락", "보합" 중 무엇이 올지 모델은 확률로 안다. 하지만 **오늘 실제로 어땠는지는 모른다.** 그럴듯한 쪽을 고를 뿐이다. 이것이 6-2 환각의 뿌리다.

**왜 중요한가**: "이해하고 답한다"가 아니라 "그럴듯한 다음을 예측한다"로 보면, 잘하는 일(글쓰기, 코드 패턴, 요약, 번역)과 못하는 일(최신 사실, 정확한 계산, 자기 확신의 근거)이 구분된다. 계산은 도구(코드 실행)에, 사실은 검색·문서에 맡기고, 모델에게는 **언어 작업**을 시킨다.

### 2. 토큰: 글자도 단어도 아닌 조각

**한 줄 정의**: 토큰은 모델이 글을 자르는 단위. 영어는 대략 단어 하나 또는 그 일부, 한글은 한 글자가 한두 토큰이 되기도 한다.

**실제 예시** (공식 모델 문서, 확인일 2026-10-21): 현재 Claude 모델의 컨텍스트 100만 토큰은 "대략 영어 55만 5천 단어 또는 유니코드 250만 글자"라고 적혀 있다. 즉 영어 1토큰 ≈ 0.55단어, 글자로는 ≈ 2.5자. **한글은 영어보다 토큰을 더 먹는다**(같은 뜻을 적어도 토큰 수가 많다). 그래서 한국어로 긴 대화를 하면 비용과 길이 제한이 더 빨리 찬다.

| 글 | 대략의 토큰 (감 잡기용) |
|---|---|
| "안녕하세요" | 3~6 |
| 이 단원 전체(약 1만 자) | 6,000~9,000 |
| `app.js` 전체(600줄) | 8,000~12,000 |
| 커리큘럼 66단원 전체 | 50만 이상 |

**왜 중요한가**: API 요금은 **입력 토큰 + 출력 토큰**으로 계산된다. Claude Code가 파일을 읽으면 그 파일이 입력 토큰이 되고, 답변이 출력 토큰이다. 긴 파일을 통째로 읽히는 요청, 같은 질문을 반복하는 대화는 그대로 돈이다.

### 3. 컨텍스트 윈도우: 한 번에 볼 수 있는 양

**한 줄 정의**: 모델이 한 번의 요청에서 볼 수 있는 토큰의 최대치. 대화 전체(내 말 + 모델 답 + 읽은 파일 + 시스템 지시)가 여기 들어가야 한다.

**비유**: 책상 크기. 책상에 올려 둔 서류만 볼 수 있다. 서류가 넘치면 **오래된 것부터 치워야** 한다. 모델에게 "기억"은 없다. 매 요청마다 책상 위에 있는 것을 처음부터 다시 읽는다.

**실제 예시**: 현재 Claude 모델들의 컨텍스트 윈도우는 100만 토큰, 한 번의 최대 출력은 12만 8천 토큰(공식 모델 표, 확인일 2026-10-21). 크지만 무한은 아니다. Claude Code에서 긴 세션을 하면 "컨텍스트가 요약됐다"는 안내가 뜨는데, 책상이 차서 앞부분을 요약본으로 바꿔 치운 것이다. 그래서 **세션 초반에 말한 세부 규칙을 나중에 잊은 것처럼** 보인다. 잊지 않게 하려면 규칙을 `CLAUDE.md` 같은 **파일**에 적어 매번 읽게 한다(8-3).

**왜 중요한가**: (1) 긴 작업은 세션을 나누거나 `/clear`로 책상을 비운다(8-5). (2) "아까 말했잖아"보다 "파일에 적어 두기"가 통한다. (3) 큰 파일을 통째로 넣기보다 필요한 부분만.

### 4. 학습 데이터와 지식 컷오프

**한 줄 정의**: 모델은 어느 시점까지의 글로 학습됐다. 그 시점(컷오프) 이후의 일은 **모른다.** 검색이나 내가 준 문서로만 알 수 있다.

**실제 예시** (공식 모델 표, 확인일 2026-10-21): 현재 Claude 모델들의 "신뢰할 수 있는 지식 컷오프"는 2026년 6월이다. 즉 2026년 10월의 뉴스, 최근 바뀐 라이브러리 버전, 이번 달 증권사 API 변경은 모델이 모른다. 이 커리큘럼이 "공식 문서를 열어 확인하라"고 반복하는 이유다.

**왜 중요한가**: "최신 ○○ 알려 줘"에 모델이 자신 있게 답하면 컷오프 이전 정보일 가능성이 크다. **날짜가 중요한 질문에는 검색 도구를 켜거나 문서를 붙여 준다.** Claude Code는 파일을 직접 읽고 웹을 가져올 수 있어 컷오프의 한계를 메운다.

### 5. 생각하기(thinking)와 노력(effort)

현재 Claude 모델은 답하기 전에 "생각"하는 토큰을 쓸 수 있고(adaptive thinking), API에는 `effort` 같은 설정이 있다(공식 모델 표, 확인일 2026-10-21). 어려운 문제는 더 생각하게 하면 정확해지지만 토큰(돈, 시간)이 더 든다. 쉬운 분류·요약에는 낮게, 설계·디버깅에는 높게. 10과정에서 직접 조절한다.

### 6. 모델은 하나가 아니다

같은 회사 안에서도 크기·속도·가격이 다른 모델이 여럿이다(6-4에서 비교). "AI가 틀렸다"가 아니라 "이 작업에 이 모델이 맞았나"를 먼저 묻는다.

## 따라하기

### 1. 토큰 감 잡기 (30분)

claude.ai(또는 Claude Code)에 이렇게 물어 본다.
> "다음 문장을 토큰으로 어떻게 나눌 것 같은지 추정해서 보여 줘: '오늘 삼성전자 매매 복기: 손절 기준을 지켰다.' 그리고 같은 뜻의 영어 문장도 비교해 줘."

모델의 추정은 근사치지만, 한글이 토큰을 더 먹는다는 감이 온다. 10과정에서 API의 토큰 카운트 기능으로 정확히 센다.

### 2. 컨텍스트가 차는 것 보기 (30분)

Claude Code에서 `/context`(또는 세션 안의 사용량 표시, 0-4)로 지금 컨텍스트가 얼마나 찼는지 본다. `app.js`를 읽게 한 뒤 다시 본다. 늘어난 양이 그 파일의 토큰이다. `/clear`로 비우면 어떻게 되는지도 본다. (명령 이름은 8-5와 공식 문서에서 다시 확인.)

### 3. 컷오프 실험 (30분)

claude.ai에 **검색 없이** "2026년 10월 셋째 주 코스피 종가"를 물어 본다. 모른다고 하거나 추정한다고 말하면 정상. 자신 있게 숫자를 말하면 그게 **환각**이다(6-2). 같은 질문을 검색을 켜고 다시 해 본다.

### 4. 책상 비우기 실험 (40분)

Claude Code에서 세션 맨 앞에 "앞으로 모든 답은 세 줄 이내로"라고 말한 뒤, 긴 작업(파일 여러 개 읽기·수정)을 시키고 20~30번 대화를 이어 간다. 어느 순간 답이 길어지면 앞의 규칙이 책상에서 밀린 것이다. 같은 규칙을 `CLAUDE.md`에 적고 새 세션에서 다시 해 본다. 차이를 메모.

### 5. 비용 추정 (30분)

6-4의 가격표를 미리 본다. Fable 5.1은 입력 100만 토큰당 10달러, 출력 100만 토큰당 50달러(공식 가격표, 확인일 2026-10-21). "app.js(1만 토큰)를 읽고 300줄(약 5천 토큰) 수정안을 받는 요청"의 비용을 계산해 보라. 답: 0.01×10 + 0.005×50 = 0.35달러. 구독으로 쓰면 이 비용이 한도에 포함되고, API로 쓰면 그대로 청구된다.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| "기억해 줘"라고만 말함 | 다음 세션에 잊음 | 파일(CLAUDE.md, 메모리 기능)에 적는다 |
| 파일 전체를 매번 붙여 넣음 | 비용 급증, 컨텍스트 소진 | 필요한 부분만, 또는 Claude Code가 직접 읽게 |
| 최신 정보를 모델에게 물음 | 컷오프 이전 답 또는 환각 | 검색·공식 문서를 붙이고 날짜를 명시 |
| 계산을 모델에게 맡김 | 틀린 숫자 | 코드로 계산시키거나 계산기·엑셀 |
| 긴 세션을 끝없이 이어감 | 품질 저하, 앞부분 망각 | 작업 단위로 `/clear`, 세션 분리 |

## 확인 퀴즈

**1. LLM이 "다음 토큰 예측기"라는 말이 환각(6-2)과 어떻게 연결되나?**

<details><summary>정답과 해설</summary>
모델은 사실 여부가 아니라 "그럴듯함"으로 다음 토큰을 고른다. 모르는 사실도 그럴듯하게 이어 붙일 수 있어서 자신 있는 거짓이 나온다.
</details>

**2. 같은 내용을 한국어와 영어로 쓰면 토큰 수가 어떻게 다르고, 비용에 어떤 영향이 있나?**

<details><summary>정답과 해설</summary>
한국어가 토큰을 더 쓴다. 입력·출력 모두 토큰 단위로 과금되므로 같은 작업도 한국어가 조금 더 비싸고 컨텍스트도 빨리 찬다. 코드 주석은 한국어로 쓰되, 긴 자료는 요약해서 넣는 식으로 조절한다.
</details>

**3. "세션 초반 규칙을 나중에 잊은 것 같다"의 원인과 해결은?**

<details><summary>정답과 해설</summary>
컨텍스트 윈도우가 차서 앞부분이 요약·제거됐기 때문. 규칙은 CLAUDE.md 같은 파일에 적어 매 요청에 읽히게 하고, 긴 작업은 세션을 나눈다.
</details>

**4. 지식 컷오프가 2026년 6월인 모델에게 2026년 10월의 라이브러리 변경을 묻는 올바른 방법은?**

<details><summary>정답과 해설</summary>
검색 도구를 켜거나 공식 문서(URL·본문)를 붙여 주고 "이 문서 기준으로" 답하게 한다. 모델 혼자의 답은 컷오프 이전일 수 있다고 전제한다.
</details>

**5. 입력 1만 토큰, 출력 2천 토큰 요청을 Fable 5.1(입력 $10/M, 출력 $50/M)로 100번 하면 비용은?**

<details><summary>정답과 해설</summary>
1회 = 0.01×10 + 0.002×50 = 0.10 + 0.10 = 0.20달러. 100회 = 20달러. 입력 캐싱(10-5)으로 반복 입력 비용을 크게 줄일 수 있다.
</details>
