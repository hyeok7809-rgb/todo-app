# 6-4. 모델 비교와 선택: Claude 계열(Fable/Opus/Sonnet/Haiku), GPT, Gemini — 언제 무엇을 쓰나, 비용 구조

|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 6-3 |
| 경험치 | 60 |

## 이 단원을 마치면

- 현재 Claude 모델 4종의 역할 차이(속도·가격·용도)를 표로 말할 수 있고, 작업마다 어떤 모델을 고를지 기준을 가진다.
- 구독(claude.ai Pro/Max)과 API 종량제가 **다른 지갑**이라는 것, 각각 언제 유리한지 설명할 수 있다.
- 프롬프트 캐싱·배치 같은 **할인 구조**가 있다는 것을 알고 10과정에서 쓸 준비를 한다.
- ChatGPT·Gemini를 "경쟁 제품"이 아니라 **검증용 두 번째 의견**과 각자의 강점으로 쓰는 법을 안다.

## 왜 배우나 (나에게 어떤 쓸모)

모델 이름이 자꾸 바뀌고 종류가 많아 보이지만, 고르는 기준은 세 가지뿐이다: **얼마나 어려운 일인가, 얼마나 많이 부를 것인가, 얼마나 빨라야 하는가.** 11과정에서 AI 직원을 여럿 둘 때 "전부 최고 모델"로 하면 비용이 터지고, "전부 싼 모델"로 하면 품질이 무너진다. 부서마다 다른 모델을 배치하는 감각을 여기서 만든다. 그리고 지금 가진 세 구독(클로드, ChatGPT, Gemini)을 **역할 분담**시키면 돈이 덜 든다.

## 핵심 개념

### 1. Claude 현재 라인업 (공식 모델 표, 확인일 2026-10-21)

| 모델 | API ID | 공식 설명 | 속도 | 가격(100만 토큰, 입력/출력) |
|---|---|---|---|---|
| Claude Fable 5.1 | `claude-fable-5-1` | 까다로운 추론, 긴 호흡의 에이전트 작업 | 느림 | $10 / $50 |
| Claude Opus 5.5 | `claude-opus-5-5` | 오래 도는 에이전트 코딩·지식 작업. **대부분의 작업은 여기서 시작** | 보통 | $4 / $20 |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | 속도와 지능의 균형 | 빠름 | $2 / $10 |
| Claude Haiku 5.5 | `claude-haiku-5-5` | 분류·추출·라우팅 같은 대량·저지연 작업 | 가장 빠름 | $0.10 / $0.50 부터 |

공통: 텍스트·이미지 입력, 도구 사용, 컨텍스트 100만 토큰, 최대 출력 12만 8천 토큰, 지식 컷오프 2026년 6월. 문서는 "확실하지 않으면 Opus 5.5로 시작하고, 더 어려운 추론·장기 작업에 Fable 5.1"을 권한다. (이름 옆 숫자는 세대다. 새 세대가 나오면 표를 다시 확인.)

**비유**: 회사 직원. Fable은 어려운 설계를 맡는 수석, Opus는 실무 리더, Sonnet은 빠른 실무자, Haiku는 단순 반복을 대량으로 처리하는 인턴. 인턴에게 설계를 시키거나 수석에게 복사를 시키면 둘 다 낭비다.

### 2. 작업별 선택 기준

| 작업 | 추천 | 이유 |
|---|---|---|
| 새 기능 설계, 어려운 버그, 긴 자동 작업 | Opus 5.5 (막히면 Fable 5.1) | 추론 품질 |
| 일상 코딩, 문서 작성, 요약 | Sonnet 5.5 | 충분히 똑똑하고 빠르고 싸다 |
| 매일 수백 건 분류·추출(뉴스 태깅, 메시지 분류) | Haiku 5.5 | 단가 1/40~1/100 |
| 11과정 AI 직원 | 팀장 = Opus, 팀원 = Sonnet/Haiku | 역할별 배치 |

**왜 중요한가**: 가격 차이가 **최대 100배**다. 같은 일을 Haiku로 할 수 있는데 Fable로 하면 100배를 내는 것이다. 먼저 싼 모델로 시도하고, 품질이 부족할 때만 올린다.

### 3. 두 개의 지갑: 구독 vs API

| | 구독 (claude.ai Pro/Max) | API (platform.claude.com) |
|---|---|---|
| 지불 | 월정액 | 쓴 토큰만큼 |
| 한도 | 5시간 세션·주간 한도(0-4) | 월 사용 상한을 내가 설정 |
| 쓰는 곳 | claude.ai 채팅, Claude Code(터미널·데스크톱·웹) | 내 코드(10과정), 11과정 AI 직원 |
| 유리할 때 | 사람이 직접 대화·코딩할 때 | 프로그램이 자동으로 부를 때 |

**주의**: Claude Code에서 `ANTHROPIC_API_KEY` 환경변수가 설정돼 있으면 구독 대신 API 과금이 된다(0-4). 사람이 쓰는 건 구독, 자동화는 API. 지갑을 섞지 않는다.

클라우드 세션 크레딧처럼 **별도 크레딧**이 있는 경우도 있다. 이 커리큘럼을 만든 세션이 그랬다. 만료일이 있으니 그 전에 쓴다.

### 4. 할인 구조 (공식 가격표, 확인일 2026-10-21)

- **프롬프트 캐싱**: 같은 긴 입력(시스템 지시, 문서, 코드)을 반복해서 보내면, 캐시된 부분은 **기본 입력가의 10%**(Fable 5.1은 2.5%, Opus/Sonnet 5.5는 5%)만 낸다. 캐시에 쓰는 비용은 조금 더 비싸다(5분 캐시 $12.50/M 등). 매일 같은 `CLAUDE.md`·문서를 넣는 AI 직원에게 결정적이다.
- **배치 API**: 급하지 않은 요청을 모아 보내면 **50% 할인**. 밤새 돌리는 뉴스 요약, 월말 리포트에 맞다.
- 수치는 바뀐다. 10-5에서 실제로 쓸 때 가격표를 다시 본다.

### 5. ChatGPT와 Gemini: 역할 분담

세 서비스 모두 비슷한 일을 할 수 있지만, 여기서는 **클로드를 주력**으로 두고 나머지를 이렇게 쓴다.

- **두 번째 의견(6-2)**: 같은 질문을 던져 답이 갈리면 검증 신호.
- **각자의 강점**: 서비스마다 검색·이미지·문서·연동 기능이 다르고 자주 바뀐다. 공식 페이지(아래 더 보기)에서 현재 기능을 확인하고, "클로드로 안 되는 것"이 있을 때만 쓴다.
- **학습용 설명**: 같은 개념을 세 서비스에 각각 설명시켜 **가장 이해되는 설명**을 고르는 것도 좋은 공부법이다.

구체적 모델 이름·요금은 이 글에 적지 않는다. 확인일 기준으로도 바뀌기 쉽고, 각 서비스 공식 페이지가 정답이다. **여기서 배울 것은 "비교하는 기준"이지 "순위"가 아니다.**

### 6. 선택을 코드로 고정하지 않는다

10과정에서 모델 ID를 코드에 적게 된다. 그때 `MODEL = os.environ.get("CLAUDE_MODEL", "claude-sonnet-5-5")` 처럼 **환경변수로 빼 두면** 모델이 바뀌어도 코드를 안 고친다(4-2의 원칙 그대로).

## 따라하기

### 1. 모델 메뉴 확인 (20분)

claude.ai에서 모델 선택 메뉴를 열어 지금 고를 수 있는 모델을 적는다(6-3 숙제 3). 공식 모델 표와 비교해 이름이 같은지 본다. 다르면 표가 오래된 것이니 **공식 페이지가 기준**.

### 2. 같은 일, 다른 모델 (40분)

같은 요청(6-3의 매매 복기 코치 템플릿)을 Sonnet과 Opus(가능하면 Haiku도)에 각각 보낸다. 품질 차이가 느껴지는지, 속도는 어떤지 메모. **대부분의 일상 요청은 차이가 작다**는 걸 확인하는 게 목적이다.

### 3. 비용 시뮬레이션 (40분)

11과정의 AI 직원을 상상한다: 매일 (a) 뉴스 50건 분류 (b) 보유 종목 요약 1건 (c) 주간 리포트 1건. 각각 입력·출력 토큰을 어림하고(6-1 표), 모델을 배치해 월 비용을 계산한다. 전부 Fable로 했을 때와 역할별 배치(Haiku/Sonnet/Opus)를 비교. 캐싱을 적용하면 얼마나 줄지도 계산.

### 4. 두 번째 의견 실험 (30분)

6-2에서 모은 "틀린 답" 하나를 ChatGPT와 Gemini에게도 물어 본다. 셋이 갈리는지, 같이 틀리는지 기록. 그 결과를 `docs/hallucination-log.md`(6-2 숙제)에 추가.

### 5. 내 모델 정책 (20분)

`docs/model-policy.md`에 "어떤 일에 어떤 모델/서비스"를 표로 적는다. 11과정에서 AI 직원 설정의 기본값이 된다.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 항상 최상위 모델 | 비용·속도 낭비 | 싼 모델부터, 부족할 때 올리기 |
| 항상 최하위 모델 | 설계·디버깅 품질 저하 | 작업 난이도로 구분 |
| API 키를 Claude Code에 설정 | 구독 대신 과금 | 사람 작업은 구독, 자동화만 API |
| 모델 ID를 코드에 박음 | 모델 변경 때마다 수정 | 환경변수 |
| 서비스 비교 글을 맹신 | 오래된 정보 | 공식 페이지, 확인일 |
| 캐싱 없이 긴 지시 반복 | 입력 비용 폭증 | 10-5 프롬프트 캐싱 |

## 확인 퀴즈

**1. 하루 1,000건의 짧은 메시지를 "매매/잡담/긴급"으로 분류하는 봇. 어떤 모델이 맞고 왜?**

<details><summary>정답과 해설</summary>
Haiku 5.5. 공식 설명대로 분류·라우팅 같은 대량·저지연 작업용이고 단가가 가장 낮다. 품질이 부족하면 Sonnet으로 올린다.
</details>

**2. 구독 한도가 다 찼는데 급히 코딩해야 한다. API 키를 Claude Code에 넣으면 되나? 주의점은?**

<details><summary>정답과 해설</summary>
동작은 하지만 그 순간부터 종량 과금이 된다(0-4). 쓰고 나면 환경변수를 반드시 지우고, API 콘솔에서 월 상한을 설정해 둔다.
</details>

**3. 프롬프트 캐싱이 11과정 AI 직원에게 특히 유리한 이유는?**

<details><summary>정답과 해설</summary>
AI 직원은 매번 같은 긴 지시서·문서를 입력으로 받는다. 캐시된 입력은 기본가의 10%(모델에 따라 2.5~5%)만 내므로 반복 비용이 크게 준다.
</details>

**4. 두 모델이 다른 답을 했을 때 할 일은?**

<details><summary>정답과 해설</summary>
둘 중 하나 이상이 틀렸다는 신호. 실행·공식 출처로 확인한다(6-2). 셋 다 같아도 맞다는 보장은 아니다.
</details>

**5. 모델 ID를 코드에 직접 적지 말라는 이유와 방법.**

<details><summary>정답과 해설</summary>
모델은 세대가 바뀌고 은퇴한다(공식 표에 은퇴 예정일이 있다). 환경변수·설정 파일에 두면 코드 수정 없이 바꿀 수 있다.
</details>
