## 이 단원을 마치면

- API 키(API key)가 "비밀번호와 같은 급"인 이유와, 어떤 종류의 값들이 비밀인지 목록으로 말할 수 있다.
- 비밀값을 코드에 적지 않고 **환경변수(environment variable)** 와 **`.env` 파일**로 넘기는 방법을 Windows와 Mac에서 각각 할 수 있다.
- `.gitignore`가 무엇이고, 왜 `.env`를 꼭 거기에 넣어야 하는지 설명하고 직접 설정할 수 있다.
- 키가 새어 나갔을 때 5분 안에 해야 할 일(폐기 → 재발급 → 이력 정리)을 순서대로 할 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

다음 단원(4-3)에서 증권사 API 키를 발급받는다. 그 키는 **내 계좌로 주문을 넣을 수 있는 열쇠**다. 클로드 API 키(10과정)는 **내 카드로 요금이 나가는 열쇠**다. 이 두 열쇠를 코드에 그대로 적고 GitHub에 올리는 사고가 초보자에게 가장 흔하고 가장 비싸다. 공개 저장소에 올라간 키는 몇 분 안에 자동 수집기(봇)가 긁어 간다. 이 단원은 "키를 어디에 두고, 어떻게 넘기고, 새면 어떻게 하나"를 몸에 익히는 시간이다. 한 번 익히면 모든 언어, 모든 서비스에 똑같이 적용된다.

## 핵심 개념

### 1. 비밀값이란 무엇인가

**한 줄 정의**: 알면 내 돈·내 계정·내 데이터를 남이 쓸 수 있게 되는 모든 문자열.

**비유**: 집 열쇠, 카드 뒷면 CVC 번호, 공인인증서 비밀번호. "그냥 숫자·글자 몇 줄"이지만 그 자체가 권한이다.

**실제 예시** — 이 과정에서 만나게 될 비밀값:

| 종류 | 어디서 나오나 | 새면 생기는 일 |
|---|---|---|
| API 키 / 앱키·앱시크릿 | 증권사, 공공데이터포털, 클로드 콘솔 | 남이 내 이름으로 호출·주문·과금 |
| 접근 토큰(access token) | 키로 로그인하면 받는 임시 열쇠 | 유효기간 동안 같은 권한 |
| 계좌번호 + 비밀번호 | 증권사 | 설명 불필요 |
| 텔레그램 봇 토큰 | BotFather (4-4) | 남이 내 봇으로 메시지 발송 |
| 데이터베이스 비밀번호, SSH 키 | 서버 (11과정) | 서버 통째로 |

**왜 중요한가**: "이건 비밀인가?"를 매번 고민하지 말고, **"서비스가 발급해 준 긴 무작위 문자열은 전부 비밀"** 로 일괄 처리하면 실수가 없다.

### 2. 코드와 비밀을 분리한다: 환경변수

**한 줄 정의**: 환경변수는 운영체제가 프로그램에 넘겨 주는 "이름=값" 메모다. 프로그램은 코드 안에 값을 적는 대신 **이름으로 물어본다**.

**비유**: 금고 비밀번호를 서류(코드)에 적어 두면 서류를 복사하는 사람마다 비밀번호를 갖게 된다. 대신 서류에는 "비밀번호는 경리에게 물어볼 것"이라고만 적고, 경리(운영체제)가 그때그때 알려 준다. 서류는 마음껏 공유해도 된다.

**실제 예시** (0-2에서 본 PATH도 환경변수였다):

```python
# 나쁜 예: 코드에 비밀이 박혀 있다. 이 파일을 공유하는 순간 끝.
APP_KEY = "PSxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"

# 좋은 예: 이름으로 물어본다. 파일을 공유해도 값은 안 넘어간다.
import os
APP_KEY = os.environ["KIS_APP_KEY"]   # 없으면 KeyError가 나서 "설정 안 했네"를 바로 안다
```

환경변수를 넣는 방법 (한 번 열린 터미널 창에서만 유효):

| OS | 명령 |
|---|---|
| Mac / Linux | `export KIS_APP_KEY="값"` |
| Windows PowerShell | `$env:KIS_APP_KEY = "값"` |
| Windows CMD | `set KIS_APP_KEY=값` |

확인: `python -c "import os; print(os.environ.get('KIS_APP_KEY'))"`.

**왜 중요한가**: 코드와 비밀이 분리되면 (1) GitHub에 올려도 안전하고 (2) 같은 코드를 모의투자 키/실전 키로 바꿔 돌릴 때 코드를 안 고친다.

### 3. 매번 치기 귀찮다: `.env` 파일

**한 줄 정의**: `.env`는 "이름=값" 줄을 모아 둔 텍스트 파일이고, `python-dotenv` 패키지가 이걸 읽어 환경변수처럼 넣어 준다.

**실제 예시**:

```
# .env  (프로젝트 폴더 맨 위에 둔다. 따옴표 없이, 공백 없이)
KIS_APP_KEY=PSxxxxxxxx
KIS_APP_SECRET=yyyyyyyy
KIS_ACCOUNT=12345678-01
KIS_MODE=paper
```

```python
# settings.py
from dotenv import load_dotenv   # pip install python-dotenv
import os

load_dotenv()                     # 같은 폴더(또는 상위)의 .env 를 읽어 os.environ 에 넣는다
APP_KEY = os.environ["KIS_APP_KEY"]
APP_SECRET = os.environ["KIS_APP_SECRET"]
MODE = os.environ.get("KIS_MODE", "paper")   # 없으면 기본값 "paper"(모의)
```

파일 이름이 점(`.`)으로 시작하면 탐색기·Finder에서 **숨김 파일**로 취급된다. VS Code에서는 보인다. Windows 탐색기에서 `.env`로 저장하면 `.env.txt`가 되기 쉬우니 VS Code에서 "새 파일"로 만들어라.

**왜 중요한가**: 터미널을 열 때마다 `export`를 치지 않아도 되고, 어떤 비밀이 필요한지가 한 파일에 정리된다. 대신 **이 파일 하나가 금고**가 됐으니 다음 개념이 필요하다.

### 4. 금고를 저장소에 안 올리는 장치: `.gitignore`

**한 줄 정의**: `.gitignore`는 "이 파일/폴더는 Git이 못 본 척해라"라는 목록이다. 여기 적힌 파일은 `git add .`를 해도 올라가지 않는다.

**실제 예시** — 이 저장소에 이미 `.gitignore`가 있다. 거기에 추가할 것:

```
# 비밀
.env
.env.*
*.pem
kis_devlp.yaml

# 파이썬 찌꺼기
__pycache__/
.venv/

# 운영체제
.DS_Store
Thumbs.db
```

확인 방법: `git status`를 쳤을 때 `.env`가 **목록에 안 나오면** 성공. 나오면 아직 무시가 안 된 것이다.

중요한 함정: **이미 한 번 커밋된 파일은 `.gitignore`에 적어도 계속 추적된다.** 그때는 `git rm --cached .env` 로 "추적만 해제"(파일은 남김)한 뒤 커밋한다. 그리고 그 키는 이미 이력에 남았으니 **재발급**해야 한다(6절).

**왜 중요한가**: `.env`를 만들었는데 `.gitignore`에 안 넣는 것이 초보자 사고의 90%다. `.env`를 만드는 순간 `.gitignore`에 넣는 것을 **한 동작**으로 묶어라.

### 5. 동료에게 알려 주는 방법: `.env.example`

비밀값 없이 **이름만** 적은 견본 파일을 올린다. 다른 컴퓨터에서(또는 미래의 내가) 복사해 쓰라고.

```
# .env.example  (이건 올려도 된다. 값이 없으니까)
KIS_APP_KEY=
KIS_APP_SECRET=
KIS_ACCOUNT=
KIS_MODE=paper
```

Claude Code에게 "이 프로젝트 설정해 줘"라고 하면 이 파일을 보고 무엇이 필요한지 안다. **Claude Code에게도 실제 키를 채팅에 붙여 넣지 마라.** "`.env`에 KIS_APP_KEY가 있다"고만 말하면 된다. 이 세션의 기록은 저장되고 공유될 수 있다.

### 6. 새어 나갔을 때: 폐기가 먼저, 원인 분석은 나중

**순서** (5분 안에):
1. **폐기(revoke)**: 발급받은 사이트에서 그 키를 삭제·만료시킨다. 증권사는 앱키 재발급 메뉴, 클로드 콘솔은 API Keys에서 삭제.
2. **재발급**: 새 키를 받아 `.env`만 고친다. 코드는 안 건드린다(이래서 분리한 것이다).
3. **이력 정리**: GitHub에 올라갔다면, 파일을 지워도 **커밋 이력에 남는다.** 이력을 지우는 도구(`git filter-repo` 등)가 있지만 초보자에게는 어렵고, 어차피 이미 긁혔다고 가정해야 한다. 그래서 1번이 먼저다.
4. **알림 설정**: GitHub는 공개 저장소에서 키 모양을 감지하면 이메일을 보낸다(Secret scanning). 그 메일을 받았다면 이미 늦었을 수 있으니 즉시 1번.

**왜 중요한가**: 사고가 났을 때 "어떻게 새었지?"를 먼저 찾는 사람은 그 사이에 돈을 잃는다. 폐기가 항상 먼저다.

### 7. 그 밖의 습관

- **최소 권한**: 조회만 할 거면 조회 권한 키만. 증권사 API는 모의투자 키로 시작한다(4-3).
- **키를 화면에 찍지 않는다**: `print(APP_KEY)` 금지. 디버깅할 때는 `print(APP_KEY[:4] + "...")` 처럼 앞 4글자만.
- **로그 파일에도 안 남긴다**: `requests`가 헤더를 로그에 찍게 하지 않는다.
- **스크린샷 주의**: 터미널 캡처를 올릴 때 `.env` 내용이나 헤더가 찍혀 있지 않은지 본다.
- **공용 컴퓨터·클라우드 세션**: 거기 `.env`를 두지 않는다. 쓰고 나서 지운다.

## 따라하기

### 1. `.env`와 `.gitignore` 만들기 (20분)

1. 이 저장소 폴더에서 VS Code로 `.env` 새 파일을 만들고 아래를 적는다(가짜 값).
   ```
   TEST_SECRET=hello-1234
   ```
2. `.gitignore`를 열어 맨 아래에 `.env`를 한 줄 추가하고 저장한다.
3. 터미널에서 `git status`. `.env`가 **안 보이면** 성공. 보이면 `.gitignore`의 철자와 저장 여부를 확인.
4. `.env.example`을 만들어 `TEST_SECRET=` 한 줄을 적고, 이건 `git status`에 **보이는지** 확인(올려도 되는 파일이니까).

### 2. 파이썬으로 읽어 보기 (20분)

```bash
# 가상환경이 켜진 상태에서 (3-1)
pip install python-dotenv
```

```python
# secret_check.py
from dotenv import load_dotenv
import os

load_dotenv()
secret = os.environ.get("TEST_SECRET")

if secret is None:
    print("TEST_SECRET 이 없습니다. .env 를 확인하세요.")
else:
    print("읽음:", secret[:3] + "...")   # 앞 3글자만. 전체를 찍는 습관을 처음부터 안 들인다
```

`python secret_check.py` → `읽음: hel...`. 이제 `.env`를 잠시 다른 이름으로 바꾸고 다시 실행 → 안내 문구가 나오는지 확인. 되돌려 놓는다.

### 3. 환경변수로 직접 넘겨 보기 (15분)

`.env`를 쓰지 않고 터미널에서 직접:

| OS | 명령 |
|---|---|
| Mac | `export TEST_SECRET="from-shell"` 그리고 `python secret_check.py` |
| PowerShell | `$env:TEST_SECRET = "from-shell"` 그리고 `python secret_check.py` |

`load_dotenv()`는 **이미 있는 환경변수를 덮어쓰지 않는다**(기본값). 그래서 `from...`이 찍힌다. 서버에 올릴 때는 `.env` 대신 이 방식(호스팅 서비스의 환경변수 설정 화면)을 쓴다(12-3).

### 4. 실수 재현과 복구 (30분)

일부러 사고를 내 보자. **가짜 값으로만** 한다.
1. `.gitignore`에서 `.env` 줄을 잠시 지우고 `git add .env` → `git status`에 올라간 걸 확인. (커밋은 하지 말 것.)
2. `git rm --cached .env` 로 추적 해제 → 파일은 그대로 있는데 `git status`에서 빠진 걸 확인.
3. `.gitignore`에 `.env`를 다시 넣는다.
4. 만약 커밋까지 했다면? `git log -p -- .env` 로 이력에 값이 남는 걸 눈으로 본다(이 실습에선 생략 가능). 그래서 **재발급**이 답이다.

### 5. Claude Code에게 비밀 다루기 시키기 (20분)

Claude Code에서 이렇게 요청해 본다:
> "이 프로젝트에 python-dotenv를 쓰는 settings.py를 만들어 줘. 필요한 키는 KIS_APP_KEY, KIS_APP_SECRET, KIS_ACCOUNT이고, .env.example도 만들어 줘. 실제 값은 내가 .env에 직접 넣을 거야."

결과를 읽고 확인할 것: (1) 코드에 진짜 값이 없는가 (2) `.gitignore`에 `.env`가 있는가 (3) `.env.example`에 값이 비어 있는가. **AI가 만든 코드도 이 세 가지를 내가 검사한다.**

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| `.env.txt`로 저장됨 | `load_dotenv()`가 못 읽음, 값이 None | VS Code에서 파일 이름을 `.env`로 바꾼다. Windows 탐색기 "알려진 확장명 숨기기" 때문 |
| `.env`에 따옴표·공백 | 값에 따옴표가 포함되거나 안 읽힘 | `KEY=값` 형태로, `=` 양옆 공백 없이 |
| `.gitignore`에 넣었는데 `git status`에 보임 | 이미 추적 중 | `git rm --cached .env` 후 커밋, 키 재발급 |
| 키를 채팅/이슈/캡처에 붙여 넣음 | 수집 봇에 노출 | 즉시 폐기·재발급. "지우면 되겠지"는 안 통한다 |
| `print(APP_KEY)`로 디버깅 | 터미널 기록·로그에 남음 | 앞 몇 글자만 찍거나 길이만 찍는다 |
| 실전 키로 테스트 | 실수 한 번이 실제 주문 | 모의투자 키로 먼저. `KIS_MODE=paper` 기본값 |
| `os.environ["X"]`에서 KeyError | 환경변수 미설정 | 오히려 좋은 신호. `.env`를 채우거나 `.get("X", 기본값)` 사용 |

**3. 키가 GitHub 공개 저장소에 올라간 것을 발견했다. 할 일을 순서대로 말하라.**

<details><summary>정답과 해설</summary>
(1) 발급처에서 키 폐기 (2) 새 키 발급해 `.env`만 교체 (3) 저장소에서 파일 삭제 + `.gitignore` 반영 (4) 필요하면 이력 정리. 핵심은 원인 분석보다 폐기가 먼저라는 점. 지워도 이력과 이미 긁어 간 사본은 남는다고 가정한다.
</details>

**4. `os.environ["KIS_APP_KEY"]`와 `os.environ.get("KIS_APP_KEY")`의 차이는? 어느 쪽이 "설정을 깜빡한" 실수를 더 빨리 알려 주나?**

<details><summary>정답과 해설</summary>
대괄호 방식은 값이 없으면 즉시 `KeyError`로 멈춘다. `.get()`은 없으면 `None`을 돌려주고 계속 진행하다가 나중에 엉뚱한 곳에서 터진다. 필수 비밀값은 대괄호(또는 `.get()` 후 `None` 검사)로 **일찍 실패**하게 두는 편이 낫다. 선택값(모드 등)은 `.get("X", 기본값)`.
</details>

**5. Claude Code에게 증권사 API 코드를 짜 달라고 할 때 키를 어떻게 전달해야 하나?**

<details><summary>정답과 해설</summary>
전달하지 않는다. "키는 `.env`의 `KIS_APP_KEY`에 있다"고 **이름만** 알려 주고, 코드가 `os.environ`으로 읽게 한다. 채팅 기록은 저장·공유될 수 있어 키를 붙여 넣는 것은 공개와 같다. 결과 코드에 값이 하드코딩되지 않았는지 내가 확인한다.
</details>
