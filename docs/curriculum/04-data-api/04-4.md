# 4-4. 스케줄링과 알림: cron/작업 스케줄러로 스크립트 자동 실행, 텔레그램 봇으로 알림 받기

| 과정 | 4. 데이터와 API, 자동화 |
|---|---|
| 예상 시간 | 4시간 |
| 선수 단원 | 4-3 |
| 경험치 | 80 |

## 이 단원을 마치면

- "자동화"가 실제로는 **(1) 스크립트 (2) 시간표 (3) 알림** 세 조각의 조합이라는 걸 설명할 수 있다.
- Mac/Linux의 `cron`과 Windows의 **작업 스케줄러**에 파이썬 스크립트를 등록해 매일 정해진 시각에 돌릴 수 있다.
- 텔레그램 봇을 만들어(BotFather) 파이썬에서 내 휴대폰으로 메시지를 보낼 수 있다.
- 자동 실행 스크립트가 **조용히 실패**하지 않도록 로그 파일과 실패 알림을 붙일 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

"매매 끝나고 10시 이후엔 할 게 없다"는 말을 뒤집으면, 10시 이후에 **나 대신 돌아가는 것**이 있어야 한다는 뜻이다. 장 마감 후 보유 종목 요약, 아침 8시 휴장 여부 확인, 밤 11시 "오늘 가계부 기록 안 함" 알림. 전부 이 단원의 세 조각으로 만든다. 11과정의 "24시간 돌아가는 AI 회사"도 결국 스케줄러가 AI 직원을 깨우는 구조다. 이 단원이 그 뼈대다.

## 핵심 개념

### 1. 자동화의 세 조각

**한 줄 정의**: 자동화 = 할 일(스크립트) + 언제(스케줄러) + 결과를 나에게(알림).

**비유**: 자동 커피머신. 원두와 물(스크립트), 타이머(스케줄러), 다 되면 울리는 소리(알림). 소리가 없으면 커피가 식는다. 알림이 없는 자동화는 **고장 나도 모른다.**

**왜 중요한가**: 초보자는 스크립트에만 공을 들이고 알림을 빼먹는다. 그러면 어느 날 조용히 멈춰 있고, 2주 뒤에 "어, 요즘 알림 안 오네"로 알게 된다.

### 2. 스크립트를 "자동 실행용"으로 다듬기

터미널에서 손으로 돌릴 때와 자동으로 돌 때의 차이:

| 손으로 | 자동으로 |
|---|---|
| 내가 그 폴더에 있다 | **어느 폴더에서 실행될지 모른다** → 절대경로 사용 |
| 가상환경을 켰다 | 안 켜져 있다 → 가상환경 안의 파이썬을 **직접** 지정 |
| 화면에 print가 보인다 | 아무도 안 본다 → **파일에 로그** |
| 에러가 나면 내가 본다 | 아무도 모른다 → **실패 알림** |

```python
# daily_report.py - 자동 실행용 뼈대
from pathlib import Path
from datetime import datetime
import logging, sys
from notify import notify   # 5절에서 만드는 notify.py (같은 폴더). 이 줄이 없으면 notify()에서 NameError

BASE = Path(__file__).resolve().parent          # 이 파일이 있는 폴더 (어디서 실행하든 같다)
LOG = BASE / "logs" / "daily_report.log"
LOG.parent.mkdir(exist_ok=True)

logging.basicConfig(filename=LOG, level=logging.INFO,
                    format="%(asctime)s %(levelname)s %(message)s")   # 언제, 어떤 수준, 무슨 일

def main():
    logging.info("시작")
    # ... 여기서 4-3의 API 호출, 3-3의 파일 처리 ...
    logging.info("끝")

if __name__ == "__main__":        # 다른 파일에서 import 될 때는 안 돌게
    try:
        main()
    except Exception as error:    # 무슨 에러든 잡아서
        logging.exception("실패") # 로그에 전체 내용을 남기고
        notify("daily_report 실패: " + str(error))   # 나에게 알리고 (아래 5절)
        sys.exit(1)               # 0이 아닌 값 = 실패했다고 운영체제에 알린다
```

### 3. Mac/Linux: cron

**한 줄 정의**: `crontab`이라는 시간표 파일에 "언제 무엇을" 한 줄씩 적으면, cron이 그 시각에 실행한다.

**형식**: `분 시 일 월 요일 명령`. `*`는 "매번".

```
# crontab -e 로 열어서 추가. 평일(1-5) 15:40 에 리포트, 매일 23:00 에 루틴 알림
40 15 * * 1-5 /Users/me/todo-app/.venv/bin/python /Users/me/todo-app/daily_report.py >> /Users/me/todo-app/logs/cron.log 2>&1
0  23 * * *   /Users/me/todo-app/.venv/bin/python /Users/me/todo-app/remind_routine.py >> /Users/me/todo-app/logs/cron.log 2>&1
```

- 파이썬 경로가 `.venv/bin/python`인 이유: 가상환경이 안 켜진 상태에서 돌기 때문(2절).
- `>> 파일 2>&1`: 화면 출력(표준 출력과 에러)을 파일에 **덧붙인다**. 안 하면 출력이 사라진다.
- 시간은 **컴퓨터의 시간대**다. 컴퓨터가 꺼져 있으면 안 돈다(노트북 덮개를 덮으면 잠든다). 24시간 돌리려면 11-3의 서버가 필요하다.
- Mac은 처음 실행 시 "터미널에 폴더 접근 권한" 팝업이 뜰 수 있다. 시스템 설정 → 개인정보 보호에서 허용.

확인: `crontab -l`로 목록, `grep CRON /var/log/syslog`(Linux) 또는 로그 파일로 실행 여부.

### 4. Windows: 작업 스케줄러 (Task Scheduler)

**한 줄 정의**: GUI로 "트리거(언제)"와 "동작(무엇을)"을 등록하는 윈도우 내장 도구.

**등록 순서**:
1. 시작 메뉴 → "작업 스케줄러" → 오른쪽 "기본 작업 만들기".
2. 이름: `daily_report`. 트리거: 매일, 15:40. (평일만은 "작업 만들기"(고급)에서 요일 지정.)
3. 동작: 프로그램 시작.
   - 프로그램/스크립트: `C:\Users\me\todo-app\.venv\Scripts\python.exe`
   - 인수 추가: `daily_report.py`
   - **시작 위치**: `C:\Users\me\todo-app` ← 이걸 비우면 "파일 없음"으로 실패한다
4. 만들고 나서 작업을 오른쪽 클릭 → **실행**으로 즉시 테스트. "마지막 실행 결과"가 `0x0`이면 성공.
5. 속성 → 조건에서 "AC 전원일 때만"을 끄면 노트북 배터리에서도 돈다. 설정에서 "예약된 시작을 놓친 경우 가능한 빨리 실행"을 켜면 꺼져 있던 시간의 작업을 켜지자마자 돌린다.

PowerShell로 같은 일을 할 수도 있다(`Register-ScheduledTask`). GUI로 한 번 해 보고 나서 Claude Code에게 "이 작업을 PowerShell 명령으로 만들어 줘"라고 하면 된다.

### 5. 알림: 텔레그램 봇

**한 줄 정의**: 텔레그램에서 BotFather에게 봇을 만들면 **봇 토큰**을 준다. 그 토큰으로 `sendMessage` API를 부르면 내 채팅방에 메시지가 온다.

**왜 텔레그램인가**: 무료, 한국에서 흔히 쓰고, HTTP 한 번으로 보낼 수 있다(4-1 그대로). 카카오톡은 개인 봇이 어렵다.

**실제 예시**:
1. 텔레그램에서 `@BotFather` 검색 → `/newbot` → 이름과 사용자명(끝이 `bot`) 입력 → **토큰** 받음(`123456789:AAH...` 모양). `.env`에 `TELEGRAM_BOT_TOKEN=`으로 저장. **비밀이다**(4-2).
2. 내 봇을 찾아 "시작"을 누르고 아무 메시지나 보낸다(봇이 나에게 먼저 말을 걸 수 없어서, 내가 먼저 말을 걸어야 한다).
3. 브라우저에서 `https://api.telegram.org/bot<토큰>/getUpdates` 열기 → JSON에서 `"chat":{"id": 숫자...}`의 숫자가 **내 chat_id**. `.env`에 `TELEGRAM_CHAT_ID=`.
4. 파이썬:

```python
# notify.py
import os, requests
from dotenv import load_dotenv
load_dotenv()

TOKEN = os.environ["TELEGRAM_BOT_TOKEN"]
CHAT_ID = os.environ["TELEGRAM_CHAT_ID"]

def notify(text):
    url = f"https://api.telegram.org/bot{TOKEN}/sendMessage"
    response = requests.post(url, data={"chat_id": CHAT_ID, "text": text}, timeout=10)
    response.raise_for_status()   # 200이 아니면 예외 (3-5)

if __name__ == "__main__":
    notify("테스트: notify.py 에서 보냄")
```

`python notify.py` → 휴대폰에 메시지가 오면 성공. 이제 어떤 스크립트든 `from notify import notify` 한 줄로 알림을 붙일 수 있다.

**왜 중요한가**: 알림 함수가 하나 있으면 (1) 성공 요약 (2) 실패 내용 (3) "오늘 루틴 안 했음" 같은 **나를 관리하는 메시지**까지 전부 같은 통로로 온다.

### 6. 실패를 설계한다

- **종료 코드**: 실패 시 `sys.exit(1)`. 스케줄러가 "실패"로 기록한다.
- **로그는 날짜별로 커진다**: 한 달에 한 번 `logs/` 정리 또는 `logging.handlers.RotatingFileHandler`(검색해 보기).
- **중복 실행 방지**: 전 작업이 아직 돌고 있는데 다음이 시작되면 꼬인다. 간단한 방법은 시작할 때 `running.lock` 파일을 만들고 끝날 때 지우는 것. 파일이 이미 있으면 그냥 종료.
- **멱등성(idempotent, 여러 번 돌아도 결과 같음)**: 같은 날 두 번 돌아도 리포트가 두 번 저장되지 않게, 저장 전에 "오늘 것 이미 있나" 확인.
- **시간대와 휴장일**: 4-3 숙제의 `is_market_holiday()`를 스크립트 맨 앞에서 불러 휴장이면 "휴장" 알림만 보내고 종료.

## 따라하기

### 1. 알림부터 (40분)

핵심 개념 5절대로 봇을 만들고 `notify.py`가 휴대폰에 메시지를 보내게 한다. 토큰과 chat_id는 `.env`에만.

### 2. 자동 실행용 스크립트 (50분)

`daily_report.py`를 2절 뼈대로 만든다. `main()` 안에는 일단 간단한 일만: 4-3의 공휴일 JSON을 읽어 "내일 휴장 여부"를 `notify()`로 보낸다. 손으로 `python daily_report.py` 실행 → 메시지와 `logs/daily_report.log`를 확인.

### 3. 스케줄러 등록 (50분)

- Mac: `crontab -e`에 **2분 뒤** 시각으로 한 줄 등록 → 2분 기다려 메시지가 오는지 확인 → 원하는 시각(예: 평일 15:40)으로 수정.
- Windows: 작업 스케줄러에 등록 → 오른쪽 클릭 "실행"으로 즉시 테스트 → "마지막 실행 결과 0x0" 확인.
- 로그 파일에 "시작/끝"이 찍혔는지 본다.

### 4. 일부러 실패시키기 (30분)

`main()` 안에 `raise ValueError("테스트 실패")`를 넣고 스케줄러로 돌려 본다. 휴대폰에 "daily_report 실패: 테스트 실패"가 오고, 로그에 전체 오류(traceback)가 남고, 스케줄러가 실패(종료 코드 1)로 기록하면 성공. 되돌려 놓는다.

### 5. 루틴 알림 (40분)

`remind_routine.py`: 매일 23:00에 "오늘 루틴 체크했어?"를 보낸다. 지금 앱의 루틴 기록은 브라우저 안에만 있어서 파이썬이 읽을 수 없다. 그래서 일단은 무조건 보내는 알림으로 만들고, **"어떻게 하면 파이썬이 내 루틴 기록을 읽을 수 있을까?"** 를 메모해 둔다. (답은 "저장소를 브라우저 밖(파일·서버)으로 옮긴다"이며 11-4에서 다룬다.)

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| cron에 `python`만 적음 | 손으로는 되는데 자동은 실패 | 가상환경의 파이썬 절대경로 |
| 상대경로(`data/x.json`) | 자동 실행 시 파일 없음 | `Path(__file__).parent` 기준 절대경로 |
| 작업 스케줄러 "시작 위치" 비움 | `0x1`, 파일 없음 | 시작 위치에 프로젝트 폴더 |
| 출력 리다이렉트 없음 | 에러가 어디에도 안 남음 | `>> 로그 2>&1` 또는 logging |
| 봇이 메시지를 못 보냄 | 400 chat not found | 내가 봇에게 먼저 말을 걸고 `getUpdates`로 chat_id 재확인 |
| 노트북이 잠들어 실행 안 됨 | 그 시각에 아무 일도 없음 | 전원 설정 변경, 또는 11-3 서버 |
| 토큰을 코드에 적음 | 유출 | `.env` + `.gitignore`(4-2) |

## 확인 퀴즈

**1. cron 한 줄 `30 8 * * 1-5 ...`는 언제 실행되나? 토요일에도 도나?**

<details><summary>정답과 해설</summary>
월~금(1-5) 매일 08:30. 요일 필드가 1-5이므로 토(6)·일(0)에는 안 돈다. 컴퓨터가 그 시각에 켜져 있어야 한다.
</details>

**2. 손으로 돌리면 되는데 스케줄러로 돌리면 "모듈을 찾을 수 없음"이 난다. 원인과 해결은?**

<details><summary>정답과 해설</summary>
자동 실행 시 가상환경이 켜져 있지 않아 시스템 파이썬이 쓰인다. 명령에 가상환경 안의 파이썬 절대경로(`.venv/bin/python` 또는 `.venv\Scripts\python.exe`)를 적는다.
</details>

**3. 알림 없는 자동화의 가장 큰 위험은?**

<details><summary>정답과 해설</summary>
조용히 멈춘 것을 모른다는 것. 실패 알림(예외를 잡아 `notify`)과 성공 요약 알림을 둘 다 붙여야 "안 오는 것"도 신호가 된다.
</details>

**4. 텔레그램 봇이 처음에 나에게 메시지를 못 보내는 이유와 해결은?**

<details><summary>정답과 해설</summary>
봇은 먼저 말을 걸 수 없다. 내가 봇과의 채팅을 시작(메시지 전송)해야 하고, 그 뒤 `getUpdates`로 chat_id를 얻어 `sendMessage`에 쓴다.
</details>

**5. 같은 스크립트가 하루에 두 번 돌아도 문제가 없게 만드는 두 가지 장치는?**

<details><summary>정답과 해설</summary>
(1) 중복 실행 방지(lock 파일) (2) 멱등성: 저장·발송 전에 "오늘 것이 이미 있나"를 확인해 건너뛴다.
</details>
