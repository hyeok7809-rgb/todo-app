## 이 단원을 마치면

- 공공데이터포털에서 API 하나를 신청해 키를 받고, 파이썬으로 호출해 JSON을 받아 올 수 있다.
- 한국투자증권 Open API(KIS Developers)의 구조(앱키·앱시크릿 → 접근토큰 → 시세·주문 API)를 그림으로 그릴 수 있고, **모의투자(vps)** 환경에서 현재가를 조회할 수 있다.
- 증권사 공식 샘플 저장소(`koreainvestment/open-trading-api`)의 폴더 구조를 알고, 필요한 예제를 찾아 읽을 수 있다.
- 자동매매를 시작하기 전에 알아야 할 법적·운영상 주의(책임, 호출 제한, 실전 전환 위험)를 목록으로 말할 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

지금은 매매 프로그램을 따로 쓰고 있다. 그 프로그램이 하는 일(시세 받기, 주문 넣기)을 **코드로 직접 할 수 있게 되면** 두 가지가 열린다. (1) 내 복기·자산 앱에 실제 잔고와 체결 내역을 자동으로 넣기 (2) 11과정에서 AI 직원에게 "장 마감 후 보유 종목 요약"을 시키기. 이 단원은 주문까지 가지 않는다. **인증하고 시세를 읽는 것**까지만 확실히 한다. 주문은 모의투자에서, 충분히 검증된 뒤, 본인이 책임질 수 있을 때 한다.

## 핵심 개념

### 1. 공공데이터포털: 가장 쉬운 "진짜 API" 연습장

**한 줄 정의**: 정부·공공기관이 제공하는 데이터 API 모음(data.go.kr). 회원가입 후 "활용신청"을 하면 서비스별 인증키를 준다.

**비유**: 도서관 회원증. 한 번 만들면 여러 열람실(API)에 신청서 한 장씩 내고 들어간다.

**실제 예시** — 흐름:
1. data.go.kr 회원가입 → 원하는 API 검색(예: "금융위원회 주식시세정보", "한국천문연구원 특일 정보") → 활용신청 → 마이페이지에서 **일반 인증키(Encoding/Decoding)** 확인.
2. 신청 직후에는 키가 반영되기까지 시간이 걸릴 수 있다(보통 한두 시간). 그 전에는 인증 오류가 난다.
3. 호출은 4-1에서 배운 GET + 쿼리 파라미터다. `serviceKey` 파라미터에 키를 넣는다.

```python
# public_api.py  (키는 .env 의 DATA_GO_KR_KEY 에)
import os, requests
from dotenv import load_dotenv

load_dotenv()
KEY = os.environ["DATA_GO_KR_KEY"]

# 예: 한국천문연구원 특일 정보 - 공휴일 조회 (실제 URL·파라미터는 포털의 "상세설명" 탭에서 확인)
url = "http://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/getRestDeInfo"
params = {"serviceKey": KEY, "solYear": 2026, "solMonth": "12", "_type": "json"}

response = requests.get(url, params=params, timeout=10)
print(response.status_code)
data = response.json()
items = data["response"]["body"]["items"]["item"]   # 포털 응답은 보통 이렇게 깊다
for item in items:
    print(item["locdate"], item["dateName"])          # 20261225 기독탄신일
```

**왜 중요한가**: 돈이 걸리지 않은 API로 "키 발급 → 호출 → JSON 파싱 → 에러 처리" 전체 흐름을 먼저 익힌다. 공휴일 API는 나중에 "장 휴장일" 판단에 그대로 쓴다.

### 2. KIS Developers: 구조 한눈에

**한 줄 정의**: 한국투자증권이 제공하는 REST/웹소켓 API. 계좌가 있어야 하고, 앱키·앱시크릿으로 **접근토큰**을 받은 뒤 그 토큰으로 시세·잔고·주문 API를 부른다.

**비유**: 앱키·앱시크릿 = 신분증과 비밀번호. 접근토큰 = 창구에서 받은 **당일 출입증**. 출입증을 목에 걸고(헤더에 넣고) 각 창구(API)에 간다.

**실제 예시** — 공식 샘플 저장소 README(확인일 2026-10-21)가 안내하는 절차:
1. 한국투자증권 **계좌 개설** 및 ID 연결
2. 홈페이지 또는 앱에서 **Open API 서비스 신청**
3. **앱키(App Key)·앱시크릿(App Secret)** 발급
4. **모의투자용과 실전투자용 앱키를 각각** 준비

샘플 코드는 이 키들을 `kis_devlp.yaml`이라는 설정 파일(기본 경로 `~/KIS/config/kis_devlp.yaml`)에서 읽는다. 인증은 `ka.auth(svr="vps")`(모의) 또는 `ka.auth(svr="prod")`(실전)로 하며, 접근토큰은 **1분당 1회** 발급 제한이 있다고 README에 적혀 있다. 즉 호출할 때마다 토큰을 새로 받으면 안 되고, **받은 토큰을 저장해 두고 재사용**해야 한다.

호출 한 건의 모양은 4-1 퀴즈 1에서 이미 봤다:

```
GET /uapi/domestic-stock/v1/quotations/inquire-price?FID_COND_MRKT_DIV_CODE=J&FID_INPUT_ISCD=005930
authorization: Bearer <접근토큰>
appkey: <앱키>
appsecret: <앱시크릿>
tr_id: FHKST01010100        ← "거래 ID". 어떤 API인지 식별. 모의/실전에 따라 다른 경우가 있다
custtype: P                 ← 개인
```

**왜 중요한가**: 증권사 API가 어렵게 느껴지는 이유는 헤더가 많아서일 뿐, 구조는 4-1의 HTTP 그대로다. "토큰 받기 → 헤더에 싣기 → tr_id로 어떤 기능인지 말하기" 세 가지만 기억하면 된다.

### 3. 모의투자(vps)부터

**한 줄 정의**: 실제 돈 없이 같은 API로 연습하는 환경. 앱키가 따로 있고, 인증 시 `svr="vps"`.

**왜 먼저인가**: 실수 한 번이 실제 주문이 되는 실전과 달리, 모의투자는 코드가 틀려도 손해가 없다. README는 모의투자 계좌가 **REST 호출 제한이 더 낮아** 연속 호출이 많은 작업에는 실전 계좌를 권한다고 적고 있다. 즉 모의투자에서 "느리게, 적게" 호출하는 습관을 들이면 실전에서도 안전하다.

**실전 전환은 설정 한 줄**(`svr="prod"`, 상품코드 `product="01"`)이라서 **오히려 위험하다.** README도 "실제 거래가 체결될 수 있으니 주의"라고 경고한다. 전환은 `.env`의 `KIS_MODE`로 관리하고, 기본값을 항상 `paper`(모의)로 둔다(4-2).

Claude Code 활용법: 이 저장소를 내 컴퓨터에 받아 두고(5-3) "`examples_llm/domestic_stock/inquire_price` 를 읽고, 내 `.env` 키로 삼성전자 현재가를 찍는 스크립트를 만들어 줘"라고 하면 된다. **키는 말하지 않는다.**

주의: 샘플은 **예고 없이 바뀔 수 있고**, 샘플로 만든 프로그램의 손해는 회사가 책임지지 않는다고 README에 명시돼 있다. 즉 최종 책임은 나다.

### 5. 호출 제한과 에러

- 초당 거래건수를 넘기면 `EGW00201` 오류가 난다(README). 반복문 안에서 API를 부를 때는 `time.sleep()`으로 간격을 둔다.
- 토큰 발급은 1분 1회. 토큰을 파일에 저장하고 만료 전까지 재사용한다(샘플 코드가 이미 그렇게 한다).
- 4-1에서 배운 대로 **상태 코드와 응답 본문의 `rt_cd`/`msg1`** 을 같이 본다. HTTP 200이어도 본문에 오류 코드가 있을 수 있다.
- 장 시간 외에는 시세가 멈추거나 빈 값이 온다. "에러"가 아니라 "장이 닫힘"일 수 있다.

### 6. 법적·운영상 주의 (반드시 읽기)

이 부분은 **전문가 확인이 필요한 영역**이다. 아래는 공부 시작 전 알아야 할 최소한이며, 실제 자동매매를 운영하기 전에 증권사 약관과 관련 법령을 직접 확인하거나 전문가에게 물어라.

1. **약관**: Open API 이용약관에 동의하고 쓰는 것이다. 금지 행위(과도한 호출, 타인 제공 등)가 적혀 있다.
2. **시세 재배포 금지**: 받아 온 시세를 남에게 제공·판매하는 것은 별도 계약이 필요한 영역이다. 13과정에서 "앱 판매"를 생각할 때 **시세 데이터는 상품에 넣지 않는다**가 안전하다.
3. **주문 책임**: 코드 버그로 잘못 나간 주문도 내 주문이다. 모의투자 → 소액 실전 → 확대 순서, 그리고 **하루 최대 주문 금액·횟수 상한을 코드에 박아 둔다**(안전장치).
4. **불공정거래**: 자동매매 자체는 합법이지만, 시세 조종·통정매매 같은 행위는 자동이든 수동이든 불법이다.
5. **세금·신고**: 매매 수익의 세금은 자동매매와 무관하게 동일하다. 13-2에서 다룬다.
6. **운영**: 인터넷 끊김, 토큰 만료, 장 휴장일, 증권사 점검 시간을 코드가 처리해야 한다. 4-4의 알림과 11-3의 모니터링이 그 답이다.

## 따라하기

### 1. 공공데이터포털 키 받아 호출하기 (60분)

1. data.go.kr 가입 → "특일 정보" 또는 관심 있는 금융 API 검색 → 활용신청(자동 승인인 것 고르기).
2. 마이페이지에서 인증키 확인 → `.env`에 `DATA_GO_KR_KEY=` 로 저장(4-2).
3. 포털의 "상세설명" 탭에서 요청 URL과 파라미터 표를 읽고 위 `public_api.py`를 **그 API에 맞게** 고친다.
4. 실행. 인증 오류가 나면 (a) 키 반영 대기 (b) Encoding/Decoding 키 혼동 (c) `_type=json` 누락 중 하나다.
5. 결과를 `holidays_2026.json`으로 저장해 두자(3-3의 파일 쓰기). 나중에 "장 휴장일" 판단에 쓴다.

### 2. KIS 서비스 신청과 키 보관 (30분, 계좌가 있는 경우)

1. apiportal.koreainvestment.com → "서비스 신청" 안내에 따라 **모의투자** 앱키부터 발급.
2. `.env`에 `KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_ACCOUNT`, `KIS_MODE=paper` 저장. 화면 캡처 금지, 채팅에 붙여 넣기 금지.
3. 계좌가 없으면 이 실습은 건너뛰고 3번(샘플 읽기)만 한다.

### 3. 공식 샘플 저장소 받아서 읽기 (40분)

```bash
# 작업 폴더로 이동한 뒤 (5-3에서 git clone 을 배우지만, 미리 써 본다)
git clone https://github.com/koreainvestment/open-trading-api.git
cd open-trading-api
```

- `README.md`를 끝까지 읽는다(한국어).
- `examples_llm/domestic_stock/` 안에서 `inquire_price` 폴더를 찾아 파일을 연다. 함수가 받는 인자, 헤더 이름, `tr_id`가 보일 것이다.
- `kis_devlp.yaml` 견본을 찾아 어떤 항목이 필요한지 적어 둔다. **이 파일은 `.gitignore`에 넣는다**(4-2 숙제에 이미 넣었을 것이다).

### 4. 모의투자 현재가 조회 (60분, 키가 있는 경우)

샘플 저장소의 인증 모듈(`kis_auth.py`)과 `inquire_price` 예제를 **그대로** 써서 삼성전자(005930) 현재가를 찍는다. 저장소 README의 설치 방법(uv 또는 pip)을 따른다. 직접 손으로 헤더를 조립하지 말고, 공식 샘플이 하는 방식을 먼저 따라 한다. 성공하면:

- `ka.auth(svr="vps")`가 어디서 토큰을 저장하는지 찾아본다(파일로 캐시한다).
- 같은 스크립트를 **두 번 연속** 실행했을 때 토큰을 다시 발급하는지 확인한다(1분 1회 제한을 떠올리자).

### 5. 안전장치 설계하기 (30분)

아직 주문 코드는 짜지 않는다. 대신 종이에 적는다.
- 모드가 `prod`일 때 반드시 사람이 확인하는 단계를 넣는 방법(예: 실행 시 "REAL" 이라고 타이핑해야 진행).
- 하루 주문 금액·횟수 상한값을 어디에 둘지(`.env`? 코드 상수?).
- 토큰 만료, 호출 제한 오류(`EGW00201`), 장 휴장일 각각에 대한 대응.

이 목록은 11-3(24시간 운영)에서 코드가 된다.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 공공데이터 키 신청 직후 호출 | 인증 오류 | 반영까지 기다린다. Encoding/Decoding 키 혼동도 확인 |
| 호출마다 토큰 재발급 | 1분 1회 제한에 걸림 | 토큰을 파일에 저장해 재사용(샘플이 이미 함) |
| 반복문에서 쉬지 않고 호출 | `EGW00201` | `time.sleep()`으로 간격, 필요한 것만 호출 |
| HTTP 200인데 데이터가 이상 | 본문의 `rt_cd`가 오류 | 상태 코드와 본문 코드 둘 다 검사 |
| 모의/실전 tr_id 혼동 | 권한·형식 오류 | 문서에서 모의투자용 tr_id가 따로 있는지 확인 |
| `svr="prod"`로 테스트 | 실제 주문 | 기본값 `paper`, 실전은 명시적 확인 단계 |
| 키를 `kis_devlp.yaml`에 넣고 커밋 | 키 유출 | `.gitignore`에 추가, 이미 올렸으면 재발급 |

**2. 접근토큰을 호출할 때마다 새로 받으면 안 되는 이유 두 가지.**

<details><summary>정답과 해설</summary>
(1) README에 발급이 1분당 1회로 제한돼 있어 연속 호출이 실패한다. (2) 불필요한 요청이라 호출 제한(초당 건수)에도 불리하다. 토큰을 파일에 저장해 만료 전까지 재사용한다.
</details>

**3. "모의투자에서 잘 되니 실전으로 바꾸자"고 할 때 코드에서 바꾸는 것은 한 줄뿐이다. 그래서 더 위험한 이유와 대책은?**

<details><summary>정답과 해설</summary>
실수로(또는 설정 파일 복사 실수로) `prod`가 되면 바로 실제 주문이 나간다. 대책: 기본값을 `paper`로 두고, `prod`일 때는 실행 시 명시적 확인 단계를 넣고, 하루 주문 금액·횟수 상한을 코드에 둔다.
</details>

**4. 공공데이터포털 API 응답에서 원하는 목록이 `data["response"]["body"]["items"]["item"]`처럼 깊은 이유와, 중간에 키가 없을 때 안전하게 꺼내는 방법은?**

<details><summary>정답과 해설</summary>
포털 표준 응답 형식이 header/body로 감싸고 items 안에 item 배열을 두기 때문. 결과가 0건이면 `items`가 빈 문자열이거나 `item`이 없을 수 있다. `.get()`을 단계별로 쓰거나 `try/except KeyError`로 감싸고, 0건일 때의 처리를 따로 둔다(3-5 예외 처리).
</details>

**5. 받아 온 시세를 내가 만든 앱에 넣어 남에게 유료로 제공해도 되나?**

<details><summary>정답과 해설</summary>
기본적으로 안 된다고 가정한다. 시세 재배포는 별도 계약·허가 영역이며 약관 위반이 될 수 있다. 13과정에서 상품을 설계할 때 시세 데이터는 제외하고, 확실하지 않으면 증권사와 전문가에게 확인한다.
</details>
