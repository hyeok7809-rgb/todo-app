# 9-3. 훅: 도구 실행 전후 자동 규칙(테스트, 포맷, 알림)

| 과정 | 9. Claude Code 심화 |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 9-2 |
| 경험치 | 60 |

## 이 단원을 마치면

- 훅(hook)이 "Claude가 특정 순간에 **반드시** 실행하는 내 셸 명령"이라는 것과, CLAUDE.md(지시)와의 결정적 차이(**결정적 vs 권고**)를 설명할 수 있다.
- `settings.json`의 `hooks` 블록을 읽고 쓸 수 있고, 대표 이벤트(PreToolUse, PostToolUse, Stop, Notification 등)가 언제 발생하는지 안다.
- 훅 스크립트의 입력(stdin JSON)과 결과(종료 코드 0/2, JSON 출력)의 뜻을 알고, "특정 파일 수정 차단"과 "편집 후 문법 검사" 훅을 만들 수 있다.
- 훅이 **내 컴퓨터에서 실제로 명령을 실행**한다는 보안 함의를 알고, 남의 훅을 검토 없이 쓰지 않는다.

## 왜 배우나 (나에게 어떤 쓸모)

8-3과 8-4에서 "지시로 안 되는 건 훅으로"라고 미뤄 뒀다. `.env`를 절대 읽지 못하게, 커밋 전에 반드시 문법 검사를, 작업이 끝나면 휴대폰으로 알림을. 이런 "예외 없이 매번"은 LLM의 판단에 맡기면 안 된다. 공식 문서의 표현: "훅은 결정적 제어를 준다. 어떤 행동이 **항상** 일어나게 하고, LLM이 그것을 선택하길 기대하지 않는다." 4-4의 텔레그램 알림 함수가 여기서 Claude Code에 연결된다.

## 핵심 개념

(공식 hooks-guide·hooks 문서, 확인일 2026-10-21.)

### 1. 훅이란

**한 줄 정의**: 사용자가 정의한 셸 명령. Claude Code가 생애주기의 특정 지점에서 실행한다.

**비유**: 공장의 안전장치. 작업자(Claude)에게 "뜨거운 곳 만지지 마"라고 말하는 게 CLAUDE.md라면, 손이 들어가면 기계가 **멈추는** 센서가 훅이다. 말은 어길 수 있지만 센서는 어길 수 없다.

| | CLAUDE.md / 스킬 | 훅 |
|---|---|---|
| 성격 | 권고(컨텍스트) | **결정적**(항상 실행) |
| 누가 판단 | LLM | 내 스크립트 |
| 용도 | 방식·스타일·절차 | 차단·검사·알림·포맷 |

### 2. 이벤트

공식 가이드가 예시로 다루는 순간들:
- **Notification**: Claude가 내 입력을 기다릴 때 → 데스크톱 알림
- **PostToolUse**(편집 후): 파일 편집 뒤 → 포맷터·문법 검사 실행
- **PreToolUse**(도구 실행 전): 특정 파일 쓰기 → **차단**
- **Stop**: Claude가 턴을 끝내려 할 때 → 검사가 통과할 때까지 끝내지 못하게(8-6)
- **SessionStart**, 압축 후 컨텍스트 재주입, 설정 변경 감사, 권한 자동 승인 등

이벤트마다 **matcher**로 어떤 도구(Bash, Edit, Write 등)에만 걸지 좁힐 수 있다. 전체 이벤트 목록과 입력 형식은 훅 레퍼런스에.

### 3. 설정 모양

`settings.json`(8-3·9-6: 사용자 `~/.claude/settings.json`, 프로젝트 `.claude/settings.json`, 로컬 `.claude/settings.local.json`)에 `hooks` 블록. 공식 첫 예시(Mac 알림):

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude Code needs your attention\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}
```

구조: 이벤트 이름 → [ { matcher, hooks: [ { type: "command", command: "..." } ] } ]. `/hooks`로 설정된 훅을 본다. Claude에게 "파일 편집 후 eslint 돌리는 훅 써 줘"라고 시켜도 된다(공식 best practices) — 단 결과를 내가 읽는다.

### 4. 입력과 결과

훅은 **stdin으로 JSON**을 받는다(공식: 모든 이벤트에 `session_id`, `cwd`가 있고 이벤트마다 추가 데이터, 예: PreToolUse에는 `tool_name`, `tool_input`). 결과는 종료 코드로:

| 종료 코드 | 뜻 |
|---|---|
| 0 | 결정 없음(정상 권한 흐름대로). JSON을 stdout에 찍으면 그 JSON이 결정 |
| 2 | **차단**. stderr에 이유를 쓰면 Claude에게 피드백으로 전달(이벤트에 따라) |
| 그 외 | 대부분 진행(이벤트별 예외 있음) |

더 세밀한 제어(승인, 입력 수정 등)는 종료 0 + JSON 출력. 8-5 비용 문서의 "테스트 출력 걸러내기" 훅이 그 예(PreToolUse에서 명령을 바꿔치기).

### 5. 우리 프로젝트의 훅 세 개

1. **`.env` 보호** (PreToolUse, matcher Read/Bash): 입력 JSON에 `.env`가 들어 있으면 `exit 2` + "비밀 파일은 읽지 않는다".
2. **편집 후 문법 검사** (PostToolUse, matcher Edit|Write): 편집된 파일이 `.js`면 `node -e "new Function(...)"`로 검사, 실패하면 stderr로 에러를 돌려줘 Claude가 고치게.
3. **끝나면 알림** (Stop 또는 Notification): 4-4의 `notify.py`로 텔레그램 "작업 끝났어" (토큰은 `.env`에, 훅 스크립트가 `load_dotenv`).

### 6. 보안

훅은 **내 권한으로 내 컴퓨터에서** 명령을 실행한다. 공식 가이드의 주의: 설정 파일(특히 저장소에 커밋된 `.claude/settings.json`)의 훅은 폴더를 신뢰해야 동작하고, 남이 커밋한 훅을 그대로 믿지 않는다. 6-2의 "남의 스킬 읽고 켜기"와 같은 원칙. 훅 스크립트에 비밀을 하드코딩하지 않는다(4-2).

## 따라하기

### 1. 알림 훅 (20분)

공식 예시(Mac은 `osascript`, Windows는 PowerShell 토스트나 간단히 `msg`/소리)를 `~/.claude/settings.json`에 넣는다. Claude가 질문을 던질 때 알림이 오는지 확인. `/hooks`에 보이는지.

### 2. `.env` 차단 훅 (40분)

`.claude/hooks/protect-env.sh`(Mac/Linux) 또는 `.ps1`(Windows):
```bash
#!/bin/bash
input=$(cat)
if echo "$input" | grep -q '\.env'; then
  echo "비밀 파일(.env)은 읽거나 실행에 포함할 수 없습니다" >&2
  exit 2
fi
exit 0
```
`.claude/settings.json`의 `PreToolUse`에 matcher `Read|Bash`로 등록. "`.env` 내용 보여 줘"라고 시켜 **차단되는지** 확인. 이 훅 파일은 커밋한다(프로젝트 규칙).

### 3. 편집 후 문법 검사 훅 (40분)

PostToolUse(matcher `Edit|Write`)에서 stdin JSON의 파일 경로가 `.js`면 `node -e`로 검사. 실패 시 에러를 stderr로 출력하고 `exit 2`. Claude에게 일부러 문법이 깨진 수정을 시켜(예: 괄호 하나 빼기) 훅이 잡고 Claude가 고치는지 본다. (JSON 파싱은 `jq`가 있으면 `jq -r .tool_input.file_path`, 없으면 Claude에게 파이썬으로 써 달라고.)

### 4. 텔레그램 알림 훅 (30분)

Stop 이벤트에 `python scripts/notify.py "Claude Code 작업 끝"`(4-4의 스크립트). 가상환경 파이썬 절대경로 사용(4-4의 교훈). 긴 작업을 시키고 휴대폰 알림을 받는다.

### 5. 검토 습관 (10분)

`/hooks`로 전체 목록을 보고, 각 훅이 "무엇을 실행하는지" 한 줄씩 `docs/hooks.md`에 적는다. 앞으로 훅을 추가할 때마다 갱신.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 훅이 안 돎 | 아무 일 없음 | `/hooks` 확인, 스크립트 실행 권한(`chmod +x`), 폴더 신뢰 |
| JSON 문법 오류 | Settings Error | 쉼표·주석 제거, `/status` |
| 차단 이유 없음 | Claude가 왜 막혔는지 모름 | stderr에 이유 + exit 2 |
| 훅이 너무 느림 | 매 편집마다 대기 | 가벼운 검사만, 무거운 건 Stop에 |
| 비밀이 훅 명령에 | 설정 파일에 노출 | `.env` + 스크립트 |
| 남의 훅 그대로 커밋 | 알 수 없는 명령 실행 | 읽고 이해한 것만 |

## 확인 퀴즈

**1. "커밋 전 문법 검사"를 CLAUDE.md가 아니라 훅으로 하는 이유.**

<details><summary>정답과 해설</summary>
CLAUDE.md는 권고라 LLM이 건너뛸 수 있다. 훅은 이벤트마다 결정적으로 실행돼 예외가 없다.
</details>

**2. PreToolUse 훅에서 종료 코드 2와 0의 차이.**

<details><summary>정답과 해설</summary>
2는 그 도구 호출을 차단하고 stderr의 이유가 Claude에게 전달된다. 0은 결정 없음으로 정상 권한 흐름대로 진행(JSON을 출력하면 그 JSON이 결정).
</details>

**3. 훅 스크립트가 "어떤 파일을 편집하려는지" 아는 방법.**

<details><summary>정답과 해설</summary>
stdin으로 받는 JSON의 `tool_input`(예: 파일 경로)을 읽는다. 이벤트마다 필드가 다르니 레퍼런스에서 확인.
</details>

**4. 저장소에 커밋된 훅이 바로 실행되지 않을 수 있는 이유.**

<details><summary>정답과 해설</summary>
폴더 신뢰(workspace trust) 전에는 프로젝트 설정의 일부가 적용되지 않는다. 남이 커밋한 명령이 내 컴퓨터에서 돌지 않게 하는 보호장치.
</details>

**5. 무거운 검사(전체 Playwright)를 어느 이벤트에 두는 게 맞나?**

<details><summary>정답과 해설</summary>
Stop(턴이 끝날 때) 또는 커밋 전 스킬. 매 편집(PostToolUse)에 두면 작업이 느려진다.
</details>

## 숙제

1. **거부 규칙 → 훅** — 8-4 숙제 2의 "절대 금지 명령 5개" 중 `git push --force`와 `rm -rf`를 PreToolUse 훅으로도 막아라. `/permissions` deny와 둘 다 있는 상태에서 각각 어떻게 막히는지 비교.
2. **루틴 알림 통합** — 4-4의 `remind_routine.py`를 Stop 훅과 연결해 "Claude Code 작업을 끝낸 날은 코딩 공부 루틴을 체크하라"는 알림이 오게 하라.
3. **9-4 예습** — "채팅에 복사해 붙이는 외부 데이터"가 무엇인지 적어 두라(공시, 매매 기록, 캘린더…). MCP가 그걸 없앤다.
