# 9-5. 웹/원격 세션과 스케줄 작업, GitHub 연동 자동화

| 과정 | 9. Claude Code 심화 |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 9-4 |
| 경험치 | 60 |

## 이 단원을 마치면

- 클라우드 세션(claude.ai/code)이 어떻게 내 저장소를 받아 브랜치를 만들고 PR까지 가는지, 로컬과 무엇이 같고 다른지 말할 수 있다.
- 터미널에서 `claude --cloud "작업"`으로 작업을 보내고, `claude --teleport`로 가져올 수 있다.
- **클라우드 예약 작업**(scheduled tasks, 구 routines)을 `/schedule`로 만들어, 컴퓨터가 꺼져 있어도 매일 돌게 할 수 있다. 4-4의 cron과 무엇이 다른지 안다.
- PR 자동 수정(auto-fix)과 GitHub 이벤트 트리거가 무엇인지 알고, 안전하게 켜는 조건을 안다.

## 왜 배우나 (나에게 어떤 쓸모)

4-4에서 "노트북이 잠들면 cron이 안 돈다"고 했다. 이 단원의 클라우드 예약 작업이 그 문제를 Claude Code 쪽에서 푼다. 11과정 "24시간 돌아가는 회사"의 가장 쉬운 첫 버전은 서버를 사는 게 아니라 **예약 작업 몇 개**다. 이 저장소가 처음 만들어진 곳이 바로 클라우드 세션이고, 그 세션이 `claude/…` 브랜치를 만들어 push했다. 그 구조를 이제 내가 다룬다.

## 핵심 개념

(공식 claude-code-on-the-web·routines 문서, 확인일 2026-10-23. 예약 작업은 "research preview"라 바뀔 수 있다.)

### 1. 클라우드 세션

**한 줄 정의**: 내 컴퓨터가 아니라 클라우드 인프라에서 도는 Claude Code 세션. 노트북을 닫아도 계속 돌고, 어느 기기에서든 확인·조종한다.

- 플랜: Pro, Max, Team(Enterprise는 일부 좌석). 사용량은 다른 Claude 사용과 **같은 한도**에서 빠지고 VM 요금은 따로 없다.
- 시작: 브라우저 claude.ai/code, 모바일 앱 Code 탭, 데스크톱에서 Cloud 선택, 터미널 `claude --cloud`, 예약 작업.
- GitHub 연결: Claude GitHub App 설치(웹 온보딩) 또는 터미널에서 `/web-setup`(내 `gh` 토큰 전송). 자격 증명은 Anthropic 서버에 암호화돼 있고 VM 안으로 들어가지 않는다.
- **환경(environment)**: 네트워크 접근 수준(Trusted 기본: 패키지 저장소 등 허용 목록만), 환경변수, 설정 스크립트. 비밀은 환경변수보다 "network secrets"로.
- 세션은 `claude/` 접두 브랜치를 만들어 작업하고, diff 보기·인라인 코멘트·PR 생성이 웹에서 된다.
- 명령 차이: `/compact`, `/context`, `/clear`(같은 클라우드 세션 안에서 빈 대화로 시작)는 되고, 터미널 전용 화면을 여는 `/resume`·`/plugin`은 안 된다. `/model`·`/effort`·`/rename`은 `/model sonnet`처럼 인자로 준다.
- 공유: Pro/Max는 Private/Public. 공개 전에 비밀·사설 코드가 세션에 없는지 확인.

### 2. 터미널 ↔ 클라우드

```bash
claude --cloud "docs/specs/report-room.md 의 1단계를 구현해"   # 현재 저장소의 GitHub 원격·현재 브랜치를 클론해 새 클라우드 세션
claude -p "테스트도 추가해" --cloud <session-id>              # 진행 중인 세션에 메시지 보내기
claude --teleport                                            # 클라우드 세션을 터미널로 가져오기(브랜치 fetch + 대화 로드)
```

공식 팁: **로컬에서 플랜 모드로 계획 → 커밋·push → `--cloud`로 자동 실행**. `--cloud`는 로컬 체크아웃이 아니라 GitHub의 브랜치를 클론하니 **먼저 push**. 원격이 없으면 로컬 저장소를 번들로 올리되, Mac/Linux/WSL 에서는 `.env` 같은 비밀 파일의 미커밋 변경을 빼고 올린다. **Windows 에서는 미커밋 변경이 이름과 상관없이 그대로 올라가니**(공식 문서) 올리기 전에 `.env` 수정분을 되돌리거나 stash 한다. 테레포트 조건: 깨끗한 작업 트리, 같은 저장소, 브랜치가 push됨, 같은 계정.

### 3. 클라우드 예약 작업

**한 줄 정의**: 프롬프트 + 저장소 + 커넥터를 한 번 저장해 두고, **트리거**가 오면 클라우드 세션으로 자동 실행하는 것.

트리거 세 종류: **스케줄**(시간별·매일·매주·1회), **API**(엔드포인트에 POST + 토큰), **GitHub 이벤트**(PR 열림·릴리스 등). 한 작업에 여러 트리거를 붙일 수 있다.

만들기: 웹 claude.ai/code/routines → New task, 또는 터미널 `/schedule daily PR review at 9am`, `/schedule tomorrow at 9am, …`(1회). 관리: `/schedule list`, `/schedule update`, `/schedule run`, 그리고 "`/schedule 왜 오늘 아침 리뷰가 아무것도 안 했어?`"처럼 실행 로그를 물을 수 있다.

**중요한 성질**(공식):
- 권한 모드를 고르지 않는다. 실행은 **auto 모드**(분류기 모델이 위험한 것만 막음 · 8-4)로 시작해 셸·스킬·커넥터를 승인 없이 쓰고, ask 규칙에 걸리거나 분류기가 거듭 막으면 그 실행 세션 안에 승인 질문이 떠서 내가 열어 답할 때까지 기다린다. 그래서 저장소·환경·커넥터를 **필요한 만큼만** 준다.
- 내 계정 소속. 커밋·PR·Slack 메시지가 **내 이름**으로 나간다.
- 프롬프트가 전부다. "자급자족적이고 무엇이 성공인지 명시"해야 한다(8-6의 여섯 칸).
- 정각 실행은 몇 분 늦을 수 있으니 9:07처럼. 최소 간격 1시간.
- 실행마다 새 세션이 생기고, 녹색 상태는 "인프라 오류 없이 끝남"이지 **작업 성공이 아니다**. 열어서 읽는다(4-4의 "알림 없는 자동화" 교훈).
- 한도: 예약 실행 시간당 100회(계정) · Run now·API 호출은 작업마다 시간당 30회 등. 구독 사용량에서 차감(한도에 닿으면 사용량 크레딧을 켠 경우에만 계속). API 로 보낸 `text`는 "믿을 수 없는 자료" 꼴로 감싸여 들어오므로 프롬프트가 그 내용을 쓰라고 명시해야 한다.

### 4. cron(4-4) vs 예약 작업

| | cron / 작업 스케줄러 | 클라우드 예약 작업 |
|---|---|---|
| 어디서 | 내 컴퓨터(켜져 있어야) | 클라우드(항상) |
| 무엇을 | 파이썬 스크립트 | Claude Code 세션(판단·코드 수정 가능) |
| 비용 | 전기 | 구독 사용량 |
| 데이터 접근 | 내 파일 전부 | 저장소 + 커넥터만 |
| 맞는 일 | 단순 반복(시세 수집, 알림) | 판단이 필요한 반복(리뷰, 요약, 정리) |

둘을 섞는다: 시세 수집은 cron, "오늘 수집한 데이터를 읽고 요약해 커밋"은 예약 작업.

### 5. GitHub 연동

- **Auto-fix PR**: PR의 CI 실패·리뷰 코멘트에 Claude가 반응해 수정을 push. 클라우드 세션의 CI 상태 바에서 토글, 또는 터미널 `/autofix-pr`. Claude GitHub App 설치 필요. 댓글이 **내 계정**으로 달리고 "Claude Code 작성"으로 표시된다. 댓글로 배포가 트리거되는 저장소에서는 끈다(공식 경고).
- **GitHub 트리거**: `pull_request.opened` 같은 이벤트에 예약 작업 실행. 필터(작성자, 라벨, 브랜치)로 좁힌다.
- **GitHub Actions**: CI 파이프라인에서 Claude를 돌리는 별도 방법(문서 참고).

## 따라하기

### 1. 클라우드 세션 하나 (40분)

claude.ai/code에서 이 저장소를 열고(GitHub 연결), "docs/history.md에 오늘 날짜로 '클라우드 세션 테스트' 한 줄 추가"를 시킨다. 브랜치 이름, diff 보기, PR 만들기 버튼을 확인(PR은 만들지 않아도 된다). 세션 목록에서 공유 설정이 Private인지 확인.

### 2. `--cloud`와 `--teleport` (40분)

로컬에서 플랜 모드로 작은 계획을 세워 `docs/specs/cloud-test.md`에 저장·커밋·push → `claude --cloud "docs/specs/cloud-test.md 실행"` → 폰 앱으로 진행 확인 → 끝나면 `claude --teleport`로 가져와 `git log`에 클라우드 커밋이 보이는지.

### 3. 첫 예약 작업: 주간 학습 리포트 (50분)

`/schedule 매주 일요일 20:07, docs/study-notes/ 와 docs/review/ 를 읽고 이번 주 학습·복기 요약을 docs/weekly/YYYY-MM-DD.md 로 커밋해. 성공 기준: 파일이 생기고 각 섹션에 최소 3줄.` 생성 후 **Run now**로 즉시 실행해 세션을 열어 읽는다. 녹색이어도 내용이 맞는지 확인. 커넥터 탭에서 불필요한 커넥터를 뺀다.

### 4. 1회 예약 (15분)

`/schedule in 3 days, ROADMAP.md 의 다음 미완 단계를 요약해 알려 줘` 같은 1회 작업을 만들고 완료 후 자동으로 꺼지는지 확인.

### 5. Auto-fix 조건 점검 (20분)

이 저장소에 CI가 없으니 지금은 켜지 않는다. 대신 "켜도 되는 조건" 체크리스트를 `docs/github-automation.md`에 적는다: GitHub App 설치, 댓글 트리거 자동화 없음, 브랜치 보호 규칙, 내 이름으로 댓글이 달린다는 인지.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| push 안 하고 `--cloud` | 옛 커밋에서 시작 | 먼저 push, "Branch is not on GitHub" 메시지 확인 |
| 예약 작업 프롬프트가 모호 | 아무것도 안 하거나 엉뚱 | 여섯 칸, 성공 기준 명시 |
| 녹색 = 성공이라 믿음 | 실패를 몇 주 모름 | 세션 열어 읽기, 알림 연결 |
| 커넥터 전부 포함 | 과도한 권한 | 필요한 것만 |
| 정각 스케줄 | 몇 분 지연 | 9:07처럼 |
| Auto-fix를 배포 트리거 저장소에 | 의도치 않은 배포 | 끄거나 자동화 점검 |

## 확인 퀴즈

**1. 클라우드 세션의 요금은 어디서 나가나?**

<details><summary>정답과 해설</summary>
구독 사용량 한도에서(다른 Claude 사용과 공유). VM 자체 요금은 없다. 병렬로 여러 세션을 돌리면 그만큼 더 빠진다.
</details>

**2. `claude --cloud`가 클론하는 것은 로컬 폴더인가, GitHub 브랜치인가?**

<details><summary>정답과 해설</summary>
GitHub 원격의 현재 브랜치. 로컬 커밋이 있으면 먼저 push. 원격이 없으면 로컬을 번들로 올린다.
</details>

**3. 예약 작업이 승인 없이 전부 실행하므로 안전을 어디서 확보하나?**

<details><summary>정답과 해설</summary>
범위 제한: 선택한 저장소, 환경의 네트워크·변수, 포함한 커넥터만 쓸 수 있다. 필요한 것만 준다. 브랜치 보호 규칙으로 push 범위도 제한.
</details>

**4. cron과 예약 작업을 어떻게 나눠 쓰나?**

<details><summary>정답과 해설</summary>
단순 반복(수집·알림)은 cron, 판단이 필요한 반복(요약·리뷰·정리)은 예약 작업. 둘을 이어 쓴다.
</details>

**5. 예약 작업 실행 목록의 녹색 표시는 무엇을 뜻하나?**

<details><summary>정답과 해설</summary>
인프라 오류 없이 세션이 시작·종료됐다는 것뿐. 작업이 성공했는지는 세션을 열어 확인한다.
</details>
