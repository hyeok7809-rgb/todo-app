# 9-1. 서브에이전트: 병렬 작업과 역할 분담, 언제 쓰고 언제 안 쓰나

| 과정 | 9. Claude Code 심화 |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 8-6 |
| 경험치 | 60 |

## 이 단원을 마치면

- 서브에이전트(subagent)가 "자기 책상(컨텍스트)을 따로 가진 보조 Claude"라는 것과, 왜 쓰는지 다섯 가지 이유(공식 문서)를 말할 수 있다.
- 내장 서브에이전트(Explore, Plan, general-purpose)를 요청으로 부를 수 있고, `.claude/agents/`에 **커스텀 서브에이전트**를 하나 만들 수 있다.
- 서브에이전트에 더 싼 모델(haiku/sonnet)을 지정해 비용을 줄일 수 있다.
- "병렬로 돌리면 빠르다"는 말의 **비용 측면**(토큰은 더 든다)을 알고, 이 커리큘럼이 그랬듯 필요할 때만 쓴다.

## 왜 배우나 (나에게 어떤 쓸모)

8-5에서 "긴 출력은 서브에이전트로 걸러 요약만 받아라"고 했다. 이 단원이 그 방법이다. 그리고 11과정의 "AI 직원"은 개념적으로 서브에이전트의 확장이다: 역할별 지시서, 제한된 도구, 각자의 컨텍스트, 팀장이 결과를 모음. 이 커리큘럼과 픽셀 오피스 자체가 서브에이전트 여러 개를 병렬로 돌려 만들어졌고(그래서 비용이 컸다), 그 경험이 "언제 쓰고 언제 안 쓰나"의 교훈이다.

## 핵심 개념

(공식 sub-agents 문서, 확인일 2026-10-23.)

### 1. 서브에이전트란

**한 줄 정의**: 특정 유형의 작업을 맡는 전문 보조 AI. **자기 컨텍스트 윈도우**, 자기 시스템 프롬프트, 자기 도구 권한을 가진다.

**비유**: 팀장(메인 세션)이 "이 서류함 뒤져서 관련 문서 목록만 가져와"라고 신입(서브에이전트)에게 시킨다. 신입은 서류 수백 장을 읽지만 팀장 책상에는 **요약 한 장**만 올라온다. 팀장 책상이 깨끗하다.

**공식 문서의 다섯 이유**:
1. **컨텍스트 보존**: 탐색·구현을 메인 밖에서 하고 요약만 반환
2. **제약 강제**: 도구를 제한(읽기 전용 등)
3. **설정 재사용**: 사용자 레벨 에이전트를 여러 프로젝트에서
4. **행동 특화**: 역할별 시스템 프롬프트
5. **비용 통제**: Haiku 같은 저비용 모델로 라우팅

### 2. 내장 서브에이전트

| 이름 | 역할 |
|---|---|
| Explore | 빠른 **읽기 전용** 코드 탐색·분석 |
| Plan | 플랜 모드에서 계획 전 리서치(읽기 전용) |
| general-purpose | 탐색과 수정이 모두 필요한 복합 작업 |
| (그 밖) | `claude`(범용 기본), `claude-code-guide`(Claude Code 사용법 질문, haiku), `statusline-setup` 같은 도우미도 내장 |

호출: 요청에 "서브에이전트로 ~을 조사해"라고 쓰거나(공식 best practices: `Use subagents to investigate X`), Claude가 description을 보고 알아서 위임한다. 8-6의 "무한 탐색" 처방이 바로 Explore다.

### 3. 커스텀 서브에이전트 만들기

`.claude/agents/이름.md`(프로젝트) 또는 `~/.claude/agents/`(모든 프로젝트)에 마크다운 파일 하나. 공식 예:

```markdown
---
name: code-reviewer
description: Reviews code for quality and best practices
tools: Read, Glob, Grep
model: sonnet
---
You are a senior code reviewer. ...
```

- 필수: `name`, `description`(Claude가 언제 위임할지 판단하는 기준. 7-2의 스킬 description과 같은 역할)
- 자주 쓰는 선택: `tools`(허용 도구), `model`(sonnet/opus/haiku/fable/inherit), `permissionMode`, `maxTurns`, `background`
- 호출: 이름을 언급, `@"code-reviewer (agent)"`로 멘션, 또는 `claude --agent code-reviewer`로 세션 전체를 그 에이전트로.

**우리 프로젝트에 맞는 에이전트**: `lesson-checker`(읽기 전용, haiku) — "lesson 문서가 CLAUDE.md의 학습용 규칙(비유·숙제 3개)을 지키는지 검사"; `beginner-reviewer`(sonnet) — "고급 문법 사용, 한국어 주석 누락을 찾아 보고".

### 4. 포그라운드 vs 백그라운드

- **포그라운드**: 메인 대화가 기다린다. 권한 질문이 그대로 나에게 온다.
- **백그라운드**: 동시에 돈다. 권한 요청은 메인 세션에 표시되고 `Esc`로 그 호출만 거부할 수 있다. 메인 대화에서 Claude가 만든 서브에이전트는 설정이 없으면 백그라운드로 시작한다. `/tasks`로 상태를 본다.

### 5. 모델 지정과 비용

우선순위(공식): 호출 시 `model` 파라미터 > frontmatter `model` > `CLAUDE_CODE_SUBAGENT_MODEL` 환경변수 > 메인 모델. 비용 문서 권고: "단순 서브에이전트 작업에는 `model: haiku`".

**비용 주의(공식)**: 서브에이전트 요청도 **같은 사용량 한도**에 포함된다. 각자 토큰을 쓴다. 상세 결과를 돌려주는 서브에이전트를 여럿 돌리면 메인 컨텍스트도 많이 찬다. 즉 병렬은 **시간을 사고 토큰을 낸다.** 이 커리큘럼 제작에서 세 후보를 병렬로 만든 것이 그 사례다(품질은 올랐지만 크레딧이 크게 줄었다).

### 6. 언제 쓰고 언제 안 쓰나

| 쓴다 | 안 쓴다 |
|---|---|
| 파일을 많이 읽어야 하는 조사 | 파일 한두 개 고치는 작은 변경 |
| 테스트·로그처럼 출력이 긴 작업 | 결과를 내가 직접 읽어야 하는 작업 |
| 서로 독립적인 작업 여러 개 | 순서대로 해야 하는 작업 |
| "다른 눈"이 필요한 리뷰(8-6 리뷰 세션 대신) | 비용이 민감할 때 |
| 읽기 전용으로 제한하고 싶을 때 | — |

공식 best practices의 "적대적 리뷰": 끝났다고 치기 전에 서브에이전트에게 **새 컨텍스트에서** diff를 보고 빠진 것을 보고하게 한다. 단 "정확성·요구사항에 영향 있는 것만" 보고하게 해 과잉 설계를 막는다. 번들 스킬 `/code-review`가 이것을 해 준다.

## 따라하기

### 1. Explore 써 보기 (20분)

"서브에이전트를 써서, 이 저장소에서 `todayString()`을 쓰는 모든 곳을 찾아 파일·함수 이름만 목록으로 가져와." 끝난 뒤 `/context`로 메인 컨텍스트가 거의 안 늘었는지 확인. 같은 요청을 서브에이전트 없이 해서 비교.

### 2. 커스텀 에이전트 만들기 (40분)

`.claude/agents/beginner-reviewer.md`:
```markdown
---
name: beginner-reviewer
description: 학습용 코드 규칙 검사. 고급 문법(class, import/export, 화살표 함수 남용, async), 한국어 주석 누락, 번호 구역 구조 위반을 찾아 보고한다. 코드 변경 후 리뷰에 사용.
tools: Read, Grep, Glob
model: sonnet
---
너는 비전공 초보자용 교육 프로젝트의 리뷰어다. CLAUDE.md의 "학습용 코드" 규칙 기준으로
지정된 파일을 검사하고, 위반을 파일:줄 번호와 함께 보고한다. 스타일 취향은 보고하지 않는다.
고치지 말고 보고만 한다.
```
커밋한 뒤 "beginner-reviewer로 assets.js를 검사해"라고 시킨다. 보고가 오면 타당한 것만 고친다.

### 3. 적대적 리뷰 (30분)

작은 변경 하나를 만든 뒤 "서브에이전트로 이 diff를 리뷰해. 정확성·요구사항 문제만, 스타일 제외." 또는 `/code-review`. 지적이 과한지, 맞는지 판단한다.

### 4. 모델 바꿔 비교 (20분)

`beginner-reviewer`의 `model`을 `haiku`로 바꿔 같은 검사를 돌린다. 품질 차이와 `/usage`의 토큰 차이를 적는다.

### 5. 비용 복기 (20분)

`/usage`의 사용량 분석에서 서브에이전트 비중을 본다. 이번 단원에서 쓴 토큰을 어림하고, "이 중 서브에이전트 없이도 됐을 작업"을 하나 꼽는다.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 모든 작업을 서브에이전트로 | 토큰 급증 | 조사·긴 출력·독립 작업에만 |
| description이 모호 | 위임이 안 되거나 엉뚱하게 | "무엇을 + 언제"를 구체적으로 |
| 도구 제한 없음 | 리뷰어가 파일을 고쳐 버림 | `tools: Read, Grep, Glob` |
| 상세 결과를 그대로 반환 | 메인 컨텍스트 소모 | "요약만 보고" 지시 |
| 메인 모델 그대로 상속 | 불필요한 비용 | 단순 작업은 `model: haiku` |
| 리뷰 지적 전부 반영 | 과잉 설계 | 정확성·요구사항만 |

## 확인 퀴즈

**1. 서브에이전트가 메인 컨텍스트를 아끼는 원리는?**

<details><summary>정답과 해설</summary>
자기 컨텍스트 윈도우에서 파일을 읽고 작업한 뒤 요약만 메인으로 돌려주기 때문. 읽은 파일 전문은 메인에 남지 않는다.
</details>

**2. 리뷰용 서브에이전트에 `tools: Read, Grep, Glob`만 주는 이유.**

<details><summary>정답과 해설</summary>
제약 강제. 리뷰어가 파일을 수정하지 못하게 해 "보고만" 하도록 보장한다.
</details>

**3. 병렬 서브에이전트가 "공짜 속도"가 아닌 이유.**

<details><summary>정답과 해설</summary>
각 서브에이전트가 자기 토큰을 쓰고 같은 사용량 한도에 포함된다. 시간을 사고 토큰(돈·한도)을 낸다.
</details>

**4. 서브에이전트 모델 결정의 우선순위.**

<details><summary>정답과 해설</summary>
호출 시 model 파라미터 > frontmatter model > CLAUDE_CODE_SUBAGENT_MODEL > 메인 모델. 단순 작업은 haiku.
</details>

**5. 11과정 AI 직원과 서브에이전트의 관계는?**

<details><summary>정답과 해설</summary>
AI 직원은 역할별 지시서·제한된 도구·자기 컨텍스트·결과 취합이라는 서브에이전트의 구조를 스케줄러(4-4)와 API(10과정)로 확장한 것이다.
</details>
