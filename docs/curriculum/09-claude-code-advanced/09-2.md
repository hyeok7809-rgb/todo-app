# 9-2. 스킬 만들기: 반복 작업을 /명령으로, SKILL.md 구조

| 과정 | 9. Claude Code 심화 |
|---|---|
| 예상 시간 | 4시간 |
| 선수 단원 | 9-1 |
| 경험치 | 80 |

## 이 단원을 마치면

- 7-2에서 만든 `SKILL.md`를 `.claude/skills/`에 넣어 `/trade-review`처럼 **명령으로** 부를 수 있다.
- `$ARGUMENTS`로 인자를 받는 스킬("`/fix-issue 12`")을 만들 수 있다.
- `disable-model-invocation`, `user-invocable` 같은 frontmatter로 "내가 부를 때만 / Claude가 알아서"를 조절할 수 있다.
- "CLAUDE.md의 어느 부분을 스킬로 옮길지"를 공식 기준("사실이 아니라 절차가 됐으면")으로 판단한다.

## 왜 배우나 (나에게 어떤 쓸모)

8-3에서 CLAUDE.md는 짧아야 한다고 했고, 8-5에서 "가끔 필요한 절차는 스킬로"라고 했다. 이 단원이 그 이사(移徙)다. 그리고 스킬은 claude.ai(7-2)와 **같은 파일 형식**이라 한 번 쓰면 양쪽에서 쓴다. 매일 하는 복기, 단원 끝낼 때의 체크, 커밋 전 검증 같은 절차를 `/명령` 하나로 줄이면 공부 시간이 코딩이 아니라 **배우는 데** 쓰인다.

## 핵심 개념

(공식 skills 문서, 확인일 2026-10-21.)

### 1. 위치

| 범위 | 경로 | 적용 |
|---|---|---|
| 개인 | `~/.claude/skills/<이름>/SKILL.md` | 이 컴퓨터의 모든 프로젝트 |
| 프로젝트 | `.claude/skills/<이름>/SKILL.md` | 이 저장소. **커밋하면** 어디서 열어도 같이 온다 |
| 플러그인 | `<plugin>/skills/<이름>/SKILL.md` | 설치한 플러그인 |

7-2에서 `skills/`에 둔 파일을 `.claude/skills/`로 옮기면(또는 복사) 바로 `/trade-review`가 된다. claude.ai 계정 스킬도 동기화 설정에 따라 보일 수 있다.

### 2. frontmatter 필드

```markdown
---
name: trade-review               # 명령 이름. 없으면 폴더 이름
description: 매매 기록을 받아 150자 복기. "복기"라고 하면 사용.   # 자동 호출 판단 기준
argument-hint: [기록 파일 경로]    # / 메뉴 자동완성에 보이는 힌트
disable-model-invocation: true    # Claude가 알아서 부르지 못하게 (내가 /로만)
---
```

- `description`과 `when_to_use`를 합쳐 1,536자에서 잘린다. 7-2처럼 "무엇 + 언제".
- `disable-model-invocation: true`: **부작용 있는 작업**(커밋, 푸시, 파일 대량 수정)은 내가 부를 때만. 공식 best practices 예시 `fix-issue`가 그렇다.
- `user-invocable: false`: `/` 메뉴에서 숨기고 Claude만 쓰게(지식성 스킬).
- 그 외 `allowed-tools`, `context: fork`(서브에이전트처럼 분리 실행), `paths`(특정 경로에서만) 등은 필요해질 때 문서에서.

### 3. 인자: `$ARGUMENTS`

```markdown
---
name: fix-issue
description: GitHub 이슈 번호를 받아 고친다
disable-model-invocation: true
---
Analyze and fix the GitHub issue: $ARGUMENTS.
1. gh issue view 로 내용을 읽는다
2. 관련 파일을 찾는다
3. 고치고 검증한다
4. 커밋 메시지를 쓴다
```

`/fix-issue 123` → `$ARGUMENTS`가 `123`. 위치별 `$0`, `$1`(또는 `$ARGUMENTS[0]`)도 된다. 본문에 자리가 없으면 끝에 `ARGUMENTS: 값`이 덧붙는다.

### 4. 호출 두 가지

- **직접**: `/trade-review docs/review/today.md`. `/`를 치면 목록·자동완성.
- **자동**: 요청이 description과 맞으면 Claude가 로드. `disable-model-invocation`이면 안 됨.

번들 스킬(공식): `/code-review`, `/doctor`, `/batch`, `/debug`, `/loop`, `/claude-api` 등은 Claude가 상황에 따라 자동으로도 부른다. `/verify`는 직접 부를 때만. `disableBundledSkills`로 끌 수 있다.

### 5. 스킬 vs CLAUDE.md vs 서브에이전트

| | CLAUDE.md | 스킬 | 서브에이전트 |
|---|---|---|---|
| 로드 | 항상 | 쓸 때만 | 위임할 때만, **다른 컨텍스트** |
| 내용 | 사실·규칙 | **절차** | 역할 + 도구 제한 |
| 전환 기준(공식) | — | "CLAUDE.md의 한 절이 사실이 아니라 **절차**가 됐으면 스킬로" | 조사·긴 출력·제약 필요 |

### 6. 좋은 스킬의 모양

- 하나의 절차. 번호 단계. 각 단계의 **검증**(8-6).
- 입력과 출력 형식 명시(6-3).
- 부작용 있는 단계(커밋·푸시)는 마지막에, 그리고 `disable-model-invocation: true`.
- 긴 참고 자료는 같은 폴더의 다른 파일로 두고 본문에서 "필요하면 REFERENCE.md를 읽어라"(7-2).
- 스크립트를 넣을 수 있지만, 이 과정에서는 마크다운 지침만으로 시작한다.

## 따라하기

### 1. 복기 스킬 이사 (20분)

`skills/trade-review/` → `.claude/skills/trade-review/`로 복사. `claude` 재시작 → `/`를 쳐서 목록에 보이는지 → `/trade-review` + 기록 붙여넣기. 7-2의 claude.ai와 같은 결과가 나오는지 비교. 커밋.

### 2. 단원 완료 스킬 (50분)

`.claude/skills/finish-unit/SKILL.md`:
```markdown
---
name: finish-unit
description: 커리큘럼 단원 하나를 끝낼 때 복습 퀴즈·요약·다음 단원 안내를 한다. 단원 id(예: 3-2)를 인자로.
argument-hint: [단원 id]
disable-model-invocation: true
---
단원 $ARGUMENTS 를 마무리한다.
1. docs/curriculum/ 에서 해당 단원 파일을 찾아 "확인 퀴즈"를 읽는다.
2. 사용자에게 퀴즈 5문항을 하나씩 내고 답을 받아 채점·해설한다.
3. 틀린 문항의 개념을 다른 비유로 1분 분량 재설명한다.
4. 단원 핵심을 3줄로 요약하고 docs/study-notes/<id>.md 에 저장한다.
5. 다음 단원 제목과 예상 시간을 알려 준다. 교육부에서 체크하라고 안내한다.
```
`/finish-unit 1-2`로 실제로 돌려 본다.

### 3. 커밋 전 검증 스킬 (40분)

`.claude/skills/precommit/SKILL.md`: 1) `node -e`로 모든 .js 문법 검사 2) Playwright 검증(CLAUDE.md의 방법) 3) `git diff --stat` 요약 4) 한국어 커밋 메시지 제안(커밋은 하지 않음). `disable-model-invocation: true`. 돌려 보고 결과를 읽는다.

### 4. CLAUDE.md 이사 (30분)

CLAUDE.md에서 "절차"에 해당하는 줄(예: 새 부서 여는 순서)을 찾아 `new-room` 스킬로 옮기고 CLAUDE.md에는 "새 부서는 /new-room 참고" 한 줄만 남긴다. `/context`로 줄어든 양 확인. 커밋.

### 5. 자동 호출 시험 (20분)

`description`만 있고 `disable-model-invocation`이 없는 지식성 스킬 하나(예: `pixel-style`: "픽셀 UI 규칙: 테두리 3~4px 검정, 상태 색은 data-status") 를 만들고 "사장실에 버튼 하나 추가"를 요청해 스킬이 자동으로 로드되는지 본다(`/context`나 응답의 언급으로).

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 스킬이 목록에 없음 | `/`에 안 보임 | 경로·파일명(SKILL.md)·frontmatter 확인, 재시작 |
| 커밋하는 스킬이 자동 호출 | 의도치 않은 커밋 | `disable-model-invocation: true` |
| 절차가 길어 본문 비대 | 토큰 낭비 | 참고 파일 분리 |
| 인자 없이 호출 | `$ARGUMENTS` 빈값 | `argument-hint`, 본문에 "인자가 없으면 물어라" |
| CLAUDE.md에 절차 방치 | 매 세션 로드 | 스킬로 이사 |
| 검증 없는 단계 | 실패해도 진행 | 단계마다 확인 |

## 확인 퀴즈

**1. `.claude/skills/`에 두고 커밋하면 생기는 이점.**

<details><summary>정답과 해설</summary>
저장소를 여는 모든 입구(터미널·웹·데스크톱)와 모든 컴퓨터에서 같은 스킬을 쓴다(8-1 "설정은 저장소에"). 버전 관리도 된다.
</details>

**2. 커밋·푸시를 하는 스킬에 꼭 넣을 frontmatter와 이유.**

<details><summary>정답과 해설</summary>
`disable-model-invocation: true`. 부작용이 있는 작업은 Claude가 알아서 부르지 못하게 하고 내가 `/`로만 부른다.
</details>

**3. "CLAUDE.md의 한 절을 스킬로 옮길 때"의 공식 기준.**

<details><summary>정답과 해설</summary>
그 절이 사실(규칙)이 아니라 절차(순서)가 됐을 때. 절차는 쓸 때만 로드되는 스킬이 맞다.
</details>

**4. `/fix-issue 123`에서 `123`은 본문의 어디로 들어가나?**

<details><summary>정답과 해설</summary>
`$ARGUMENTS`(또는 `$0`) 자리. 자리가 없으면 본문 끝에 `ARGUMENTS: 123`으로 덧붙는다.
</details>

**5. 스킬과 서브에이전트의 결정적 차이.**

<details><summary>정답과 해설</summary>
스킬은 현재 대화에 절차를 로드하고, 서브에이전트는 다른 컨텍스트에서 역할·도구 제한을 갖고 일한 뒤 요약을 돌려준다. (`context: fork`로 스킬을 분리 실행할 수도 있다.)
</details>
