## 이 단원을 마치면

- 리스트(list)와 딕셔너리(dict)가 JavaScript의 배열·객체에 대응한다는 것을 알고, 넣기·빼기·찾기·정렬을 할 수 있다.
- 리스트 컴프리헨션 한 줄로 `filter`와 `map`을 대신하고, 문자열을 `split`·`strip`·`replace`·`join`·`in`으로 다룰 수 있다.
- 텍스트·CSV·JSON 파일을 `with open()`으로 안전하게 읽고 쓸 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

자동화의 재료는 거의 전부 **파일**로 온다. 증권사 HTS에서 내려받는 체결 내역은 CSV(엑셀이 여는 쉼표 구분 표), 웹 API가 주는 시세는 JSON, 매매 일지는 txt. 파일을 열면 손에 쥐어지는 것이 **리스트**(줄들의 목록)와 **딕셔너리**(한 줄의 이름:값 묶음)다. 1-6에서 배열·객체·JSON을 배웠으니 이 단원은 그 파이썬판이다.

이 저장소와의 연결도 직접적이다. app.js의 `save()`는 `entries` 배열을 `JSON.stringify`로 문자열로 바꿔 localStorage에 넣는다. 그 문자열을 파일로 저장하면 파이썬의 `json.load()`가 **같은 모양의 리스트와 딕셔너리**로 읽는다. 브라우저 앱과 파이썬 자동화를 잇는 다리가 JSON이고, 로드맵 6단계 "백업(내보내기/가져오기)"의 원리가 바로 이것이다.

## 핵심 개념

### 1. 리스트(list): 순서 있는 목록

**한 줄 정의**: 대괄호로 감싼, 순서가 있고 바꿀 수 있는 값의 목록. JavaScript 배열에 해당.

**비유**: 체결 내역서의 줄들. 순서가 있고, 끝에 추가되고, 중간 것을 뺄 수 있다.

**실제 예시** (튜토리얼 "자료 구조"의 메서드):

```python
fruits = ["orange", "apple", "pear", "banana", "kiwi", "apple", "banana"]
fruits.append("grape")      # 끝에 넣기 (JS: push)      fruits.pop()은 끝에서 빼기
fruits.insert(0, "melon")   # 위치에 넣기               fruits.remove("apple")은 값으로 제거
fruits.count("banana")      # 2                         fruits.index("pear")는 위치 찾기
fruits.sort()               # 제자리 정렬 (reverse=True로 내림차순), fruits.reverse()는 뒤집기
copy = fruits.copy()        # 복사본 (JS: slice())      del fruits[0]은 위치로 삭제
"kiwi" in fruits            # 포함 여부 → True / False
len(fruits), fruits[0], fruits[-1], fruits[1:3]   # 길이, 첫, 끝, 슬라이스
```

**컴프리헨션(comprehension)**: 1-6의 `filter`와 `map`을 한 줄로. 튜토리얼 예제 `squares = [x**2 for x in range(10)]`.

```python
amounts = [e["amount"] for e in entries]                        # map
expenses = [e for e in entries if e["type"] == "expense"]       # filter
big = [e["title"] for e in entries if e["amount"] >= 50000]     # 둘 다
```

읽는 법: "`for` 뒤의 각 요소에 대해, `if`를 통과하면, 맨 앞의 식을 모아 새 리스트로". `deleteEntry`의 `entries.filter(e => e.id !== id)`가 `[e for e in entries if e["id"] != id]`다.

**튜플(tuple)과 세트(set)**: 튜플은 **바꿀 수 없는** 목록(`t = 12345, 54321, 'hello!'`)으로, 3-2의 `return level, xp_in_level`이 돌려준 것이다. 세트는 중괄호로 묶은 **중복 없는** 모음이라 튜토리얼 예제 `basket = {'apple', 'orange', 'apple', ...}`에서 중복이 사라진다. "오늘 거래한 종목 종류"처럼 중복 제거에 쓴다.

**왜 중요한가**: 파일에서 읽은 줄, API가 준 항목, 종목 목록이 전부 리스트로 온다.

### 2. 딕셔너리(dict): 이름표 붙은 묶음

**한 줄 정의**: `{키: 값}` 쌍의 모음. 튜토리얼 표현으로 "연관 기억(associative memories)"이며 "키는 어떤 불변 타입도 된다"(보통 문자열). JavaScript 객체에 해당.

**비유**: 1-6의 "내역 한 건 = 제목·금액·날짜 묶음". 종목코드 → 종목명 대응표도 딕셔너리다.

**실제 예시** (표준 자료형 문서의 `d[key]`, `get`, `items`):

```python
entry = {"type": "expense", "title": "점심", "amount": 9000}
entry["amount"]              # 9000      JS: entry.amount (파이썬은 대괄호+따옴표)
entry["date"] = "2026-10-21" # 키 추가.  del entry["date"]로 삭제
entry.get("memo", "")        # 키가 없으면 기본값 (없는 키를 [ ]로 꺼내면 KeyError)
"title" in entry             # True
list(entry)                  # 키 목록 ['type', 'title', 'amount']

prices = {"005930": 72000, "035720": 41000}
for code, price in prices.items():        # (키, 값) 쌍으로 순회
    print(code, price)
```

**집계 패턴**(가장 많이 쓴다): "종목별 합계"는 빈 딕셔너리에 키가 없으면 0부터 더한다. `get(key, default)`는 문서대로 "키가 있으면 값을, 없으면 default를 돌려준다."

```python
by_title = {}
for e in entries:
    by_title[e["title"]] = by_title.get(e["title"], 0) + e["amount"]
```

**왜 중요한가**: JSON의 `{ }`가 그대로 딕셔너리로 들어온다. API 응답(3-5)도, 가계부 백업도, 설정 파일도 전부 딕셔너리다.

### 3. 문자열 처리

**한 줄 정의**: 문자열 메서드는 원본을 바꾸지 않고 **새 문자열(또는 리스트)을 돌려준다**.

**실제 예시** (표준 자료형 문서 "문자열 메서드"):

| 메서드 | 하는 일 | 예 |
|---|---|---|
| `split(sep)` | 구분자로 잘라 리스트 | `'1,2,3'.split(',')` → `['1', '2', '3']` |
| `strip()` | 양끝 공백 제거 | `'   spacious   '.strip()` → `'spacious'` |
| `replace(old, new)` | 바꾸기 | `"1,500,000".replace(",", "")` → `"1500000"` |
| `sep.join(목록)` | 리스트를 구분자로 잇기 | `",".join(["a", "b"])` → `"a,b"` |
| `startswith`/`endswith` | 접두·접미 확인 | `name.endswith(".csv")` |
| `find(sub)` | 위치(없으면 -1) | `"Python".find("th")` → `2` |
| `zfill(width)` | 왼쪽 0 채우기 | `"42".zfill(5)` → `'00042'` (종목코드 6자리!) |
| `in` | 포함 여부 | `'Py' in 'Python'` → `True` |

**왜 중요한가**: HTS에서 복사한 "1,500,000"은 숫자가 아니라 문자열이다. `replace(",", "")` 후 `int()`. 종목코드 "5930"은 `zfill(6)`으로 "005930". 자동화의 절반은 이런 "지저분한 문자열 정리"다.

### 4. 텍스트 파일: `open()`과 `with`

**한 줄 정의**: `open(파일, 모드, encoding=...)`이 파일 객체를 돌려주고, `with` 블록이 끝나면 자동으로 닫는다.

**비유**: 장부를 꺼내(open) 쓰고 반드시 금고에 다시 넣는다(close). `with`는 "나갈 때 자동으로 잠기는 금고".

**실제 예시** (튜토리얼 "파일 읽고 쓰기"):

```python
with open("journal.txt", "a", encoding="utf-8") as f:   # 'a' = 끝에 덧붙이기
    f.write("2026-10-21 삼성전자 +2.1% 추세 추종 성공\n")   # 쓴 글자 수를 돌려준다

with open("journal.txt", encoding="utf-8") as f:        # 모드 생략 = 'r' 읽기
    for line in f:                                       # 한 줄씩
        if "삼성전자" in line:
            print(line.strip())                          # 끝의 줄바꿈 제거
```

모드: `'r'` 읽기(기본), `'w'` 쓰기(**같은 이름의 기존 파일은 지워진다**), `'a'` 덧붙이기, `'b'`를 붙이면 바이너리. `with`의 장점은 튜토리얼 그대로 "블록이 끝나면, 도중에 예외가 나더라도 파일이 제대로 닫힌다." 전체를 한 번에 읽으려면 `f.read()`, 한 줄은 `f.readline()`.

`encoding="utf-8"`을 항상 적는 이유: 내장 함수 문서가 "텍스트 모드에서 encoding을 지정하지 않으면 플랫폼에 따라 다르다(`locale.getencoding()`)"고 한다. Windows에서 한글이 깨지는 원인 1순위다.

**왜 중요한가**: 로그(3-5), 매매 일지, 설정 파일이 전부 텍스트 파일이다.

### 5. CSV: 엑셀과 주고받는 표

**한 줄 정의**: CSV(Comma Separated Values)는 "스프레드시트와 데이터베이스에서 가장 흔한 가져오기/내보내기 형식"(csv 모듈 문서)이며, 파이썬 `csv` 모듈이 읽고 쓴다.

**실제 예시** (csv 모듈 문서의 DictWriter/DictReader):

```python
import csv

with open("trades.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["date", "name", "buy", "sell", "qty"])
    writer.writeheader()
    writer.writerow({"date": "2026-10-21", "name": "삼성전자", "buy": 72000, "sell": 73500, "qty": 10})

with open("trades.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):          # 각 줄이 딕셔너리 {'date': ..., 'name': ...}
        print(row["name"], int(row["sell"]) - int(row["buy"]))
```

문서의 주의: 파일을 열 때 **`newline=''`를 지정**해야 한다. 안 하면 "따옴표 안의 줄바꿈이 올바르게 해석되지 않는다"(Windows에서는 빈 줄이 끼는 증상으로 자주 나타난다). CSV에서 읽은 값은 **전부 문자열**이라 `int()`/`float()`가 필요하다. 딕셔너리 대신 리스트로 받으려면 `csv.reader(f)`, 쓰려면 `csv.writer(f).writerow([...])`.

**왜 중요한가**: 3-6의 pandas가 CSV를 훨씬 편하게 읽지만, 원리를 알아야 pandas가 이상하게 읽을 때 원인을 잡는다.

### 6. JSON: 앱과 파이썬의 공용어

**한 줄 정의**: `json.dumps`/`json.loads`는 문자열과 파이썬 객체를 오가고, `json.dump`/`json.load`는 파일과 오간다. JS의 `JSON.stringify`/`JSON.parse`에 해당.

**실제 예시** (json 모듈 문서):

```python
import json
json.dumps([1, "simple", "list"])          # '[1, "simple", "list"]'
json.loads('["foo", {"bar": null}]')       # ['foo', {'bar': None}]

with open("ledger.json", "w", encoding="utf-8") as f:
    json.dump(entries, f, ensure_ascii=False, indent=2)
with open("ledger.json", encoding="utf-8") as f:
    entries = json.load(f)
```

변환표(문서): object→`dict`, array→`list`, string→`str`, number→`int`/`float`, true/false→`True`/`False`, null→`None`. `indent=2`는 보기 좋게 들여쓰기, `ensure_ascii=False`는 한글을 `\uXXXX`로 바꾸지 않고 그대로 쓴다(기본값 `True`면 ASCII가 아닌 글자를 전부 이스케이프). 튜토리얼: "JSON 파일은 UTF-8로 인코딩해야 한다."

**왜 중요한가**: app.js가 localStorage에 넣는 문자열이 정확히 JSON이고, 3-5의 API 응답도 JSON이다. 이 한 모듈로 브라우저 앱·웹 API·파이썬이 연결된다.

### 실습 2. 가계부 저장/불러오기를 파이썬으로 (30분)

app.js의 `save()`/`load()`를 파일 기반으로 옮긴다. `ledger_io.py`:

```python
import json

FILE = "ledger.json"

def load():
    try:
        with open(FILE, encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:          # 파일이 아직 없으면 빈 목록 (예외 처리는 3-5)
        return []

def save(entries):
    with open(FILE, "w", encoding="utf-8") as f:
        json.dump(entries, f, ensure_ascii=False, indent=2)

def add_entry(entries, type_, title, amount):
    entries.append({"id": len(entries) + 1, "type": type_, "title": title, "amount": amount})

entries = load()
add_entry(entries, "expense", "점심", 9000)
add_entry(entries, "income", "배당", 32000)
save(entries)
print(f"{len(entries)}건 저장. 파일을 열어 보세요.")
```

두 번 실행하면 4건이 된다(불러와서 덧붙이니까). VS Code로 `ledger.json`을 열어 한글이 그대로 보이면 `ensure_ascii=False`가 작동한 것이다. `type_`에 밑줄이 붙은 이유: `type`은 내장 함수 이름이라 가리지 않으려는 관례다.

### 실습 3. 체결 내역 CSV 만들고 종목별 집계 (40분)

`trades_csv.py`. 먼저 CSV를 만들고, 다시 읽어 종목별 손익을 딕셔너리로 모은다.

```python
import csv

rows = [
    {"date": "2026-10-20", "name": "삼성전자", "buy": 72000, "sell": 73500, "qty": 10},
    {"date": "2026-10-20", "name": "카카오", "buy": 41000, "sell": 39500, "qty": 20},
    {"date": "2026-10-21", "name": "삼성전자", "buy": 73000, "sell": 72100, "qty": 5},
]
with open("trades.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=list(rows[0]))   # 첫 행의 키가 열 이름
    writer.writeheader()
    for row in rows:
        writer.writerow(row)

by_name = {}
with open("trades.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        profit = (int(row["sell"]) - int(row["buy"])) * int(row["qty"])
        by_name[row["name"]] = by_name.get(row["name"], 0) + profit

for name, profit in sorted(by_name.items(), key=lambda kv: kv[1], reverse=True):
    print(f"{name:<6} {profit:>+10,}원")
```

`sorted(..., key=lambda kv: kv[1], reverse=True)`는 "값(kv[1]) 기준 내림차순". 삼성전자 +10,500원, 카카오 -30,000원이 나온다. 엑셀로 `trades.csv`를 열어 같은 표가 보이는지 확인한다. 한글이 깨지면 엑셀 쪽 인코딩 설정 문제이니 VS Code로 열어 내용 자체는 정상인지 먼저 본다.

### 실습 4. 브라우저 가계부 → 파이썬 집계 (35분)

1. `index.html`을 브라우저로 열고 내역을 몇 건 넣는다.
2. F12 → Application(크롬) → Local Storage → `ledger-entries` 값을 더블클릭해 전부 복사한다(lesson-01의 확인 방법).
3. `automation` 폴더에 `ledger-entries.json`을 만들어 붙여 넣고 저장한다.
4. `summary.py`:

```python
import json
with open("ledger-entries.json", encoding="utf-8") as f:
    entries = json.load(f)

income = sum(e["amount"] for e in entries if e["type"] == "income")
expense = sum(e["amount"] for e in entries if e["type"] == "expense")
by_date = {}
for e in entries:
    signed = e["amount"] if e["type"] == "income" else -e["amount"]
    by_date[e["date"]] = by_date.get(e["date"], 0) + signed

print(f"수입 {income:,}원 / 지출 {expense:,}원 / 잔액 {income - expense:,}원")
for date in sorted(by_date):
    print(date, f"{by_date[date]:+,}원")
```

app.js가 만든 `{id, type, title, amount, date}` 객체가 그대로 딕셔너리로 들어온다. 잔액이 브라우저 화면과 같으면 성공. 이게 6단계 "백업/가져오기"의 절반이다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `KeyError: 'memo'` | 없는 키를 `[ ]`로 꺼냄 | `d.get("memo", 기본값)` 또는 `if "memo" in d` |
| `IndexError: list index out of range` | 길이 밖의 위치 | `len()` 확인, 마지막은 `[-1]` |
| 파일이 통째로 사라짐 | `'w'` 모드는 기존 내용을 지운다 | 덧붙이기는 `'a'`, 읽기는 `'r'` |
| Windows에서 한글 깨짐 | 기본 인코딩이 플랫폼마다 다름 | `open(..., encoding="utf-8")` 항상 |
| CSV에 빈 줄이 하나씩 낌 | `newline=''` 누락 | csv 문서대로 `open(..., newline="")` |
| `json.dump` 결과가 `점심` | `ensure_ascii` 기본값 `True` | `ensure_ascii=False` |
| CSV 숫자 계산이 이상함(`"10" + "5"`) | CSV 값은 전부 문자열 | `int()`/`float()` 변환 |
| 복사했는데 원본도 바뀜 | `b = a`는 같은 리스트를 가리킴 | `b = a.copy()` |

## 확인 퀴즈

**1. `[e["amount"] for e in entries if e["type"] == "expense"]`를 JavaScript의 filter/map으로 쓰면?**

<details><summary>정답과 해설</summary>

`entries.filter(e => e.type === "expense").map(e => e.amount)`. 컴프리헨션의 `if`가 filter, 맨 앞의 식이 map이다.
</details>

**2. `open("journal.txt", "w")`로 열어 한 줄 쓰면 기존 일지는 어떻게 되나?**

<details><summary>정답과 해설</summary>

지워진다. 튜토리얼: `'w'`는 "쓰기 전용이며 같은 이름의 기존 파일은 지워진다." 덧붙이려면 `'a'`, 그리고 `encoding="utf-8"`도 같이.
</details>

**3. CSV 파일을 열 때 `newline=''`를 적는 이유는?**

<details><summary>정답과 해설</summary>

csv 모듈 문서: 지정하지 않으면 "따옴표 안의 줄바꿈이 올바르게 해석되지 않는다." 실무에서는 Windows에서 빈 줄이 끼는 증상으로 나타난다.
</details>

**4. `json.dump(entries, f)`로 저장했더니 한글이 `점심`로 보인다. 깨진 건가?**

<details><summary>정답과 해설</summary>

깨진 게 아니라 이스케이프된 것이다. `ensure_ascii` 기본값이 `True`라 ASCII가 아닌 글자를 `\uXXXX`로 쓴다. `json.load`로 읽으면 다시 한글이 된다. 사람이 읽기 좋게 하려면 `ensure_ascii=False`.
</details>

**5. `by_name[row["name"]] = by_name.get(row["name"], 0) + profit`에서 `.get(..., 0)`이 없으면?**

<details><summary>정답과 해설</summary>

처음 보는 종목에서 `by_name[row["name"]]`을 읽는 순간 `KeyError`. `get`은 키가 없을 때 기본값 0을 돌려주므로 "0부터 더하기"가 된다.
</details>
