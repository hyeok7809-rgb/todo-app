# 3-5. requests로 API 호출, 예외 처리(try/except), 로그 남기기

| 과정 | 3. Python 기초: 자동화의 언어 |
|---|---|
| 예상 시간 | 4시간 |
| 선수 단원 | 3-4 |

## 이 단원을 마치면

- `requests.get()`으로 웹 API를 호출하고 상태 코드·헤더·JSON 본문을 꺼낼 수 있다.
- `timeout`, `raise_for_status()`로 "조용히 실패하는" 호출을 막을 수 있다.
- `try`/`except`/`else`/`finally`의 흐름을 설명하고, 구체적인 예외 이름으로 잡을 수 있다.
- `logging`으로 레벨별 메시지를 파일에 남기고, 새벽에 혼자 돌던 스크립트가 왜 멈췄는지 추적할 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

2-6에서 브라우저의 `fetch`로 공개 API를 불러 봤다. 파이썬에서는 `requests`가 그 역할이고, 4-3의 한국투자증권 Open API, 4-4의 텔레그램 봇, 10단원의 Claude API까지 전부 "URL로 요청 보내고 JSON 받기"의 반복이다.

그런데 네트워크는 **실패가 기본값**이다. 증권사 서버가 느리고, 와이파이가 끊기고, API가 점검 중이다. 사람이 보고 있을 때는 다시 누르면 되지만, 새벽 3시에 혼자 도는 스크립트는 그러지 못한다. 그래서 세 가지가 묶여 한 단원이다. **호출하고(requests), 실패를 처리하고(try/except), 무슨 일이 있었는지 남긴다(logging).** 매매로 치면 "주문 넣고, 거부되면 규칙대로 대응하고, 매매 일지를 쓴다"다.

## 핵심 개념

### 1. `requests`: HTTP 요청 한 줄

**한 줄 정의**: `requests.get(url)`이 서버에 요청을 보내고 응답(Response) 객체를 돌려준다. 설치는 `python -m pip install requests`(3-1에서 했다).

**비유**: 증권사 콜센터에 전화해 "삼성전자 현재가요"라고 묻는 것. URL이 전화번호, params가 질문 내용, 응답이 상담원의 대답이다. HTTP 자체(메서드, 상태 코드, 헤더)는 4-1에서 자세히 본다.

**실제 예시** (requests 공식 Quickstart):

```python
import requests

r = requests.get("https://api.github.com/events")        # Quickstart 첫 예제
r.status_code                  # 200 이면 성공
r.headers["content-type"]      # 응답 헤더 (대소문자 구분 없는 딕셔너리)
r.text                         # 본문 문자열
r.json()                       # 본문을 JSON으로 해석 → 리스트/딕셔너리

payload = {"key1": "value1", "key2": "value2"}
r = requests.get("https://httpbin.org/get", params=payload)   # ?key1=value1&key2=value2 를 붙여 준다
r.url
headers = {"user-agent": "my-app/0.0.1"}
r = requests.get("https://httpbin.org/get", headers=headers)  # 헤더 지정 (API 키도 보통 여기)
r = requests.post("https://httpbin.org/post", json=payload)   # 보낼 때는 post + json=
```

**왜 중요한가**: 시세·환율·뉴스·알림 전송이 전부 이 호출의 변형이다. `params`와 `headers`를 알면 어떤 API 문서든 읽힌다.

### 2. 응답 확인: 상태 코드와 `raise_for_status()`

**한 줄 정의**: 응답이 왔다고 성공이 아니다. `r.status_code`를 보거나 `r.raise_for_status()`로 실패 응답(4xx, 5xx)을 예외로 바꾼다.

**실제 예시** (Quickstart):

```python
r.status_code == requests.codes.ok        # True면 200
bad_r = requests.get("https://httpbin.org/status/404")
bad_r.raise_for_status()                  # requests.exceptions.HTTPError: 404 Client Error
```

Quickstart의 경고 두 가지. `r.json()`이 실패하면 `requests.exceptions.JSONDecodeError`가 나고, 반대로 **"`r.json()`이 성공했다고 요청이 성공한 것은 아니다**(서버가 에러 내용을 JSON으로 줄 수 있다). `r.raise_for_status()`를 쓰거나 `r.status_code`가 기대한 값인지 확인하라."

**왜 중요한가**: 증권사 API는 토큰이 만료되면 JSON으로 "에러 코드"를 돌려준다. 상태 코드와 본문을 둘 다 봐야 "시세가 0원"이라는 엉터리 데이터를 걸러낸다.

### 3. `timeout`: 기다리는 시간의 상한

**한 줄 정의**: `timeout=초`를 주면 그 시간 안에 응답이 없을 때 `requests.exceptions.Timeout` 예외가 난다.

**실제 예시** (Quickstart): `requests.get("https://github.com/", timeout=0.001)`은 거의 바로 Timeout이 난다. 문서의 강조: **"거의 모든 운영 코드는 거의 모든 요청에 이 매개변수를 써야 한다."** 안 쓰면 서버가 응답을 안 줄 때 스크립트가 영원히 멈춘다.

**왜 중요한가**: 4-4에서 스케줄러로 돌리는 스크립트가 멈춰 있으면 다음 실행까지 막힌다. 시세 조회에는 5초, 파일 다운로드에는 30초처럼 **항상** 넣는다.

### 4. 예외(exception)와 `try`/`except`

**한 줄 정의**: 예외는 실행 중 발생한 오류 신호이고, `try` 블록에서 난 예외를 `except`가 받아 처리하면 프로그램이 죽지 않는다.

**비유**: 주문이 거부되는 상황. "잔고 부족", "호가 범위 초과"처럼 **이유별로** 대응이 다르다. 전부 뭉뚱그려 "에러"로 받으면 뭘 고쳐야 할지 모른다.

**실제 예시** (튜토리얼 "오류와 예외"):

```python
while True:
    try:
        x = int(input("숫자를 넣으세요: "))
        break
    except ValueError:
        print("숫자가 아닙니다. 다시.")

def divide(x, y):
    try:
        result = x / y
    except ZeroDivisionError:
        print("division by zero!")
    else:                                  # 예외가 없었을 때만
        print("result is", result)
    finally:                               # 예외 여부와 상관없이 항상
        print("executing finally clause")
```

튜토리얼이 설명하는 `try`의 동작: 예외가 없으면 `except`를 건너뛰고 끝난다. 예외가 나고 `except`의 종류와 맞으면 그 블록을 실행한 뒤 `try/except` 다음으로 이어간다. **맞지 않으면 바깥 `try`로 넘어가고, 끝까지 아무도 안 받으면 프로그램이 멈춘다.** 여러 종류를 한 번에 받으려면 `except (RuntimeError, TypeError, NameError):`, 예외 객체를 쓰려면 `except OSError as err:` 뒤에 `print("OS error:", err)`. 직접 일으킬 때는 `raise ValueError("수량은 1 이상")`.

튜토리얼의 원칙: "처리하려는 예외의 종류를 **가능한 한 구체적으로** 적는 것이 좋은 습관이다." `except Exception:`으로 전부 삼키면 오타(NameError)까지 숨어 버린다.

**왜 중요한가**: 1-7에서 "에러 메시지를 읽는 법"을 배웠다. 이제는 어떤 에러가 날지 **미리 예상해 대응을 적는** 단계다. 예상한 실패(네트워크, 잘못된 입력, 없는 파일)는 받아 처리하고, 예상 못 한 실패는 그대로 터뜨려 로그에 남긴다.

### 5. requests의 예외 가족

**한 줄 정의**: Quickstart에 따르면 requests가 일으키는 모든 예외는 `requests.exceptions.RequestException`을 상속하며, 네트워크 문제는 `ConnectionError`, 실패 상태 코드는 `HTTPError`(`raise_for_status` 시), 시간 초과는 `Timeout`, 리다이렉트 초과는 `TooManyRedirects`다.

**실제 예시** (재시도 패턴, `time.sleep(seconds)`는 "주어진 초만큼 실행을 멈춘다"):

```python
import time
import requests

def fetch_json(url, params=None, retries=3, timeout=5):
    for attempt in range(1, retries + 1):
        try:
            r = requests.get(url, params=params, timeout=timeout)
            r.raise_for_status()
            return r.json()
        except requests.exceptions.Timeout:
            print(f"{attempt}번째 시도 시간 초과")
        except requests.exceptions.ConnectionError as err:
            print(f"{attempt}번째 시도 연결 실패: {err}")
        except requests.exceptions.HTTPError as err:
            print(f"서버가 거부: {err}")
            return None                    # 404 같은 건 다시 해도 같으니 바로 포기
        time.sleep(2)
    return None
```

**왜 중요한가**: "3번 재시도 후 포기, 단 4xx는 즉시 포기"가 자동화 스크립트의 표준 골격이다. 이 함수 하나를 4단원 내내 재사용한다.

### 6. `logging`: 혼자 도는 스크립트의 증인

**한 줄 정의**: `logging`은 메시지에 **레벨**과 **시각**을 붙여 콘솔이나 파일에 남기는 표준 모듈이다. `print`는 "사용자에게 보여 줄 출력", `logging`은 "나중에 무슨 일이 있었는지 추적할 기록"(logging HOWTO의 용도 표).

**실제 예시** (logging HOWTO):

```python
import logging

logging.basicConfig(
    filename="trading.log", encoding="utf-8", level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s", datefmt="%Y-%m-%d %H:%M:%S",
)
logging.info("시세 조회 시작")
logging.warning("%s 응답 지연 %d초", "삼성전자", 3)     # 변수는 %s, %d 자리에 넣는다
logging.error("토큰 만료")
```

레벨(HOWTO 표): `DEBUG` "문제 진단용 상세 정보", `INFO` "예상대로 동작한다는 확인", `WARNING` "예상 밖의 일이 있었거나 곧 문제가 생길 조짐"(기본 레벨), `ERROR` "더 심각한 문제로 어떤 기능을 수행하지 못함", `CRITICAL` "프로그램이 계속 돌 수 없을 수 있는 심각한 오류". `level=logging.INFO`로 설정하면 INFO 이상만 기록되고 DEBUG는 버려진다. HOWTO의 기본 예제에서 `logging.warning('Watch out!')`은 출력되지만 `logging.info('I told you so')`는 출력되지 않는 이유가 이것이다.

**왜 중요한가**: 4-4에서 스케줄러가 새벽에 스크립트를 돌린다. 아침에 "왜 알림이 안 왔지?"의 답은 `trading.log`에만 있다.

## 따라하기

`automation` 폴더, 가상환경 켠 상태에서. 아래 주소는 requests 공식 문서가 예제로 쓰는 공개 주소다. 하나가 응답하지 않으면 다른 것으로 바꿔 본다. 한국투자증권·공공데이터 같은 **키가 필요한 API는 4-3**에서 다룬다.

### 실습 1. 첫 호출과 응답 뜯어보기 (20분)

```python
# first_call.py
import requests

r = requests.get("https://api.github.com/events", timeout=5)
print("상태:", r.status_code, "/ 타입:", r.headers["content-type"])
events = r.json()
print("항목 수:", len(events), "/ 첫 항목의 키:", list(events[0]))
print("첫 항목 type:", events[0]["type"])
```

응답은 리스트이고 각 항목이 딕셔너리다(3-3). `r.json()` 결과를 `json.dump(..., indent=2)`로 파일에 저장해 VS Code로 열어 구조를 눈으로 본다.

### 실습 2. params, 404, timeout 체험 (20분)

```python
# probe.py
import requests

r = requests.get("https://httpbin.org/get", params={"code": "005930", "n": 5}, timeout=5)
print(r.url)                     # 쿼리가 붙은 최종 URL
print(r.json()["args"])          # 서버가 받은 매개변수를 되돌려 준다

bad = requests.get("https://httpbin.org/status/404", timeout=5)
print("상태:", bad.status_code)
bad.raise_for_status()           # 여기서 HTTPError로 멈춘다
```

마지막 줄의 에러 메시지를 읽는다(1-7의 습관). 그다음 `timeout=5`를 `timeout=0.001`로 바꿔 실행해 `Timeout` 계열 예외도 본다.

### 실습 3. 안전한 호출 함수 (40분)

핵심 개념 5의 `fetch_json`을 `net.py`에 저장하고(모듈, 3-4), `__main__` 가드에서 세 경우를 시험한다.

```python
if __name__ == "__main__":
    print(fetch_json("https://httpbin.org/get", params={"q": "test"}))   # 정상 → 딕셔너리
    print(fetch_json("https://httpbin.org/status/404"))                   # 서버 거부 → None
    print(fetch_json("https://httpbin.org/get", timeout=0.001))           # 3회 시간 초과 → None
```

세 번째가 "1번째 시도 시간 초과 … 3번째 …" 뒤 `None`을 찍으면 재시도 골격이 완성된 것이다. 프로그램이 **죽지 않고** `None`을 돌려줬다는 점이 핵심이다.

### 실습 4. 로그 붙이기 (40분)

`net.py`의 `print`를 전부 `logging`으로 바꾸고, 호출하는 쪽에서 `basicConfig`를 한 번만 설정한다.

```python
# net.py 안: print(...) → logging.warning(...) / logging.error(...)
# 성공 시 logging.info("%s 응답 %d바이트", url, len(r.text))

# run.py
import logging
from net import fetch_json

logging.basicConfig(filename="trading.log", encoding="utf-8", level=logging.INFO,
                    format="%(asctime)s %(levelname)s %(message)s", datefmt="%Y-%m-%d %H:%M:%S")
logging.info("=== 실행 시작 ===")
data = fetch_json("https://httpbin.org/get", params={"code": "005930"})
if data is None:
    logging.error("시세를 못 가져와 종료")
else:
    logging.info("성공: %s", data["args"])
```

실행 후 `trading.log`를 연다. 시각·레벨·메시지가 한 줄씩 쌓인다. `level`을 `logging.WARNING`으로 바꾸면 INFO 줄이 사라지는 것, `timeout=0.001`로 바꾸면 WARNING 3줄과 ERROR 1줄이 남는 것을 확인한다.

### 실습 5. 3-3의 저장 코드에 예외 처리 (20분)

3-3 실습 2의 `load()`는 `FileNotFoundError`만 잡았다. 파일 내용이 깨졌을 때(`json.JSONDecodeError`)도 빈 목록 대신 **경고 로그를 남기고 멈추도록** 고친다. `ledger.json`에 글자 하나를 지워 깨뜨린 뒤 실행해, 로그에 ERROR가 남고 원본을 덮어쓰지 않는지 확인한다. 깨진 파일을 `[]`로 덮어쓰면 백업 없는 데이터가 날아간다. **"모르는 상태면 아무것도 쓰지 않는다"** 가 저장 코드의 원칙이다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 스크립트가 멈춘 채 아무 출력 없음 | `timeout` 미지정 | 모든 요청에 `timeout=` |
| `r.json()`은 되는데 값이 이상함 | 서버가 에러를 JSON으로 줌 | `raise_for_status()` 또는 `status_code` 확인 |
| `except:`로 다 잡았더니 오타도 안 보임 | 너무 넓은 예외 | 구체적 예외 이름으로, 예상 못 한 건 터지게 둔다 |
| `logging.info`가 파일에 안 남음 | 기본 레벨 WARNING | `basicConfig(level=logging.INFO)` |
| 로그 파일에 한글이 깨짐 | 인코딩 미지정 | `basicConfig(..., encoding="utf-8")` |
| `basicConfig`를 여러 모듈에서 호출 | 설정은 한 번만 적용됨 | 실행 파일(run.py)에서 한 번, 모듈에서는 `logging.xxx()`만 |
| 404인데 3번 재시도 | 4xx는 다시 해도 같다 | `HTTPError`는 즉시 `return None` |

## 확인 퀴즈

**1. `r = requests.get(url)` 뒤에 `r.json()`이 정상 동작했다. 요청이 성공했다고 볼 수 있나?**

<details><summary>정답과 해설</summary>

아니다. Quickstart: "json() 디코딩 성공이 응답의 성공을 뜻하지 않는다. 서버가 실패 내용을 JSON으로 줄 수 있다." `r.raise_for_status()`나 `r.status_code` 확인이 필요하다.
</details>

**2. `try` 블록에서 `ValueError`가 났는데 `except ZeroDivisionError:`만 있다. 어떻게 되나?**

<details><summary>정답과 해설</summary>

종류가 맞지 않으므로 바깥 `try`로 넘어가고, 끝까지 받는 곳이 없으면 프로그램이 에러 메시지와 함께 멈춘다. 예상한 예외만 정확히 적는 이유다.
</details>

**3. `else`와 `finally`는 각각 언제 실행되나?**

<details><summary>정답과 해설</summary>

`else`는 `try`에서 예외가 **없었을 때만**, `finally`는 예외 여부와 **상관없이 항상**(정리 작업용). 튜토리얼 `divide()` 예제에서 `divide(2, 1)`은 "result is 2.0" 뒤에 "executing finally clause"를 찍는다.
</details>

**4. 재시도 함수에서 `HTTPError`만 즉시 `return None`하는 이유는?**

<details><summary>정답과 해설</summary>

404·401 같은 상태 코드는 다시 보내도 결과가 같다(주소나 인증 문제). 시간 초과·연결 실패는 일시적일 수 있어 재시도 가치가 있다.
</details>

**5. `logging.basicConfig(level=logging.WARNING)` 상태에서 `logging.info("시작")`은 기록되나?**

<details><summary>정답과 해설</summary>

안 된다. 설정 레벨 이상만 기록된다. HOWTO의 기본 예제에서 `warning('Watch out!')`은 나오고 `info('I told you so')`는 안 나오는 것과 같다.
</details>
