# 7-2. 스킬과 맞춤 지침: 반복 작업을 템플릿으로, 내 말투·형식 고정하기

| 과정 | 7. 클로드 제대로 쓰기 (claude.ai) |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 7-1 |
| 경험치 | 60 |

## 이 단원을 마치면

- 스킬(skill)이 "필요할 때만 켜지는 작업 설명서"라는 것과, 계정 지침·프로젝트 지침과의 차이를 표로 말할 수 있다.
- `SKILL.md` 한 장으로 스킬을 만들어 claude.ai에 올리고, 켜고, 잘 켜지는지 시험할 수 있다.
- `description`(설명) 한 줄이 "언제 이 스킬을 쓸지"를 정한다는 것을 알고, 잘 안 켜질 때 고칠 줄 안다.
- 6-3에서 만든 템플릿(매매 복기 코치, 에러 해결)을 스킬로 옮긴다. 9-2에서 같은 파일이 Claude Code 스킬이 된다.

## 왜 배우나 (나에게 어떤 쓸모)

6-3에서 템플릿을 `docs/prompts.md`에 모았다. 하지만 매번 복사해 붙이는 건 결국 안 하게 된다. 스킬은 그 템플릿을 Claude 안에 넣어 두고 **"복기해 줘"라고만 하면 알아서 꺼내 쓰게** 하는 장치다. 더 중요한 건 스킬이 **공개 표준**(지원 문서: Agent Skills, agentskills.io)이라 claude.ai에서 만든 `SKILL.md`를 Claude Code에서도 그대로 쓴다는 점이다. 한 번 잘 만든 "내 작업 설명서"가 채팅·코딩·나중의 AI 직원(11과정)까지 따라간다.

## 핵심 개념

(지원 센터 "What are skills?", "How to create custom skills" 문서, 확인일 2026-10-21 기준.)

### 1. 스킬이란

**한 줄 정의**: 지침·스크립트·참고 자료를 담은 **폴더**. Claude가 작업에 맞을 때 동적으로 불러와서 그 방식대로 일한다.

**비유**: 신입 직원용 업무 매뉴얼 한 권. 평소엔 서랍에 있다가 "복기 보고서 작성" 업무가 떨어지면 꺼내 읽고 그대로 한다. 매뉴얼이 없으면 매번 선배(나)가 처음부터 설명해야 한다.

**실제 예시**: 폴더 구조 (문서 예시 기준)

```
trade-review/            ← 폴더 이름 = 스킬 이름
├── SKILL.md             ← 필수. 맨 위에 name/description, 아래에 지침
├── REFERENCE.md         ← 선택. 긴 참고 자료는 따로 떼고 SKILL.md에서 언급
└── scripts/             ← 선택. 실행 가능한 코드(파이썬 등)
```

(문서는 파일명을 소문자 `skill.md`로 적기도 한다. Claude Code 문서는 `SKILL.md`. 둘 다 통하지만 이 커리큘럼은 `SKILL.md`로 통일한다.)

### 2. 세 가지 지침의 차이

| | 계정 지침(Instructions for Claude) | 프로젝트 지침 | 스킬 |
|---|---|---|---|
| 적용 범위 | 모든 대화 | 그 프로젝트의 대화 | **작업이 맞을 때만** |
| 켜지는 방식 | 항상 | 프로젝트 안에서 항상 | Claude가 description을 보고 판단, 또는 내가 호출 |
| 컨텍스트 비용 | 매번 | 매번 | 쓸 때만(6-1의 책상을 아낀다) |
| 담을 것 | 내 소개, 말투 | 주제별 역할·규칙 | **절차**(1단계, 2단계…), 형식, 스크립트 |

**왜 중요한가**: 프로젝트 지침에 복기·에러해결·요약 절차를 전부 넣으면 길어져서 매번 책상을 차지하고, 서로 섞인다. 절차는 스킬로 빼고 지침은 짧게.

### 3. SKILL.md 구조

```markdown
---
name: trade-review
description: 국내주식 단타 매매 기록을 받아 잘한 점·고칠 점·내일 규칙으로 150자 복기를 쓴다. "복기", "매매 정리"라고 하면 사용.
---

# 매매 복기 코치

## 역할
10년 차 단타 트레이더의 코치. 냉정하되 비난하지 않는다.

## 절차
1. 기록에서 손절 기준 위반, 추격 매수, 물타기를 찾는다.
2. 잘한 점 2개, 고칠 점 2개를 "~했을 때 ~했다 → ~해야 했다" 꼴로 쓴다.
3. 내일 지킬 규칙 1줄.

## 형식
총 150자 이내. 번호 목록. 숫자는 그대로 인용.

## 하지 말 것
종목 추천, 시장 전망.
```

문서가 정한 것: `name`은 최대 64자, `description`은 **최대 200자**이고 "이 스킬이 무엇을 하고 언제 쓰는지"를 담는다. Claude는 **description만 보고** 스킬을 쓸지 정하고, 본문은 쓰기로 한 뒤에 읽는다. 그래서 description에 "언제"를 꼭 적는다("복기라고 하면"). `dependencies`(필요 패키지)는 선택.

### 4. 올리고 켜기

1. 폴더 이름을 스킬 이름과 맞추고, **폴더째** ZIP으로 압축한다(ZIP을 열었을 때 바로 파일이 아니라 폴더가 보여야 한다).
2. claude.ai → Customize → Skills → Add → ZIP 업로드.
3. 같은 화면에서 스킬을 **활성화**한다.
4. 조건: 설정 → Capabilities에서 code execution(코드 실행)이 켜져 있어야 한다. Free~Enterprise 모든 플랜.
5. 시험: 스킬이 켜질 만한 말("오늘 복기해 줘")을 여러 번 바꿔 보내고, Claude의 생각(thinking)에 스킬을 읽었다는 표시가 있는지 본다. 안 켜지면 description을 고친다.

### 5. 다른 방법들

- **대화로 편집**: 스킬 파일이 대화 옆에 열리면 바꿀 부분을 드래그해 "Edit with Claude"로 고친다(문서).
- **화면 녹화로 만들기**: Mac 앱의 Cowork에서, Pro/Max/Team 플랜. 내가 하는 작업을 최대 약 10분 녹화하면 Claude가 스킬 초안을 만든다. 녹화 중 비밀번호·민감 정보가 화면에 나오지 않게 한다(6-2). 영상·음성은 보관되지 않는다.
- **Claude에게 설명해서 만들기**: "이런 절차로 복기하고 싶은데 SKILL.md로 만들어 줘"라고 하면 형식을 맞춰 준다. 내용은 내가 검토한다.

### 6. 안전 습관 (문서의 모범 사례)

- 스크립트를 넣을 때 API 키·비밀번호를 하드코딩하지 않는다(4-2).
- 남이 만든 스킬은 켜기 전에 내용을 읽는다.
- 스킬 하나 = 작업 하나. 처음엔 마크다운 지침만으로 시작하고 필요할 때 늘린다.
- 외부 서비스 연동은 스킬 안에서 직접 하지 말고 MCP·커넥터로(7-1, 9-4).

## 따라하기

### 1. 첫 스킬: 매매 복기 코치 (40분)

핵심 개념 3절의 `SKILL.md`를 내 습관에 맞게 고쳐 `skills/trade-review/SKILL.md`로 **이 저장소에** 저장한다(9-2에서 Claude Code가 그대로 쓴다). ZIP으로 묶어 claude.ai에 올리고 켠다. "오늘 복기: [기록]"을 보내 150자 형식으로 오는지 확인.

### 2. 켜지지 않을 때 고치기 (20분)

일부러 description을 "매매 코치"처럼 짧게 바꿔 올려 본다. "복기해 줘"에 안 켜지면 description에 **언제**("복기, 매매 정리라고 하면")를 다시 넣고 재업로드. 차이를 메모.

### 3. 두 번째 스킬: 에러 해결 (40분)

6-3의 에러 해결 템플릿을 `skills/fix-error/SKILL.md`로. 절차: (1) 에러 메시지에서 종류·위치 찾기 (2) 원인 후보 3개 (3) 가장 쉬운 확인 방법 (4) 수정안은 diff로. description에 "에러 메시지를 붙이면 사용". 올리고, 실제 에러(1-7에서 모았던 것)로 시험.

### 4. 지침 다이어트 (20분)

7-1에서 만든 프로젝트 지침 중 **절차**에 해당하는 부분을 스킬로 옮기고, 지침은 역할·말투·제약만 남긴다. 지침이 절반 이하로 줄면 성공.

### 5. 스킬 폴더 커밋 (15분)

`skills/` 폴더를 저장소에 커밋한다. 이 폴더가 9-2에서 `.claude/skills/`로 옮겨져 `/trade-review`가 된다.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| description이 "무엇"만 | 스킬이 안 켜짐 | "언제"를 넣는다. 200자 안에서 구체적으로 |
| ZIP 루트가 파일 | 업로드 실패 | 폴더째 압축 |
| code execution 꺼짐 | 스킬 메뉴 없음 | 설정 → Capabilities |
| 스킬 하나에 작업 여러 개 | 엉뚱한 절차 실행 | 작업마다 스킬 분리 |
| 스크립트에 키 하드코딩 | 유출 | 환경변수·MCP |
| 남의 스킬 그냥 켬 | 의도치 않은 동작 | 읽고 나서 켠다 |

## 확인 퀴즈

**1. 프로젝트 지침에 두면 안 되고 스킬로 빼야 하는 내용은?**

<details><summary>정답과 해설</summary>
특정 작업의 절차(복기 1→2→3단계, 에러 해결 순서 등). 지침은 항상 로드돼 컨텍스트를 차지하고 섞이지만, 스킬은 작업이 맞을 때만 로드된다.
</details>

**2. Claude가 스킬을 쓸지 말지 판단할 때 읽는 것은?**

<details><summary>정답과 해설</summary>
frontmatter의 description(최대 200자). 본문은 쓰기로 한 뒤에 읽는다. 그래서 description에 "무엇을 + 언제"를 적는다.
</details>

**3. 스킬 폴더를 이 저장소에도 저장하는 이유는?**

<details><summary>정답과 해설</summary>
스킬은 공개 표준이라 같은 SKILL.md를 Claude Code(9-2)와 나중의 AI 직원(11과정)에서도 쓴다. 저장소에 두면 버전 관리(5과정)도 된다.
</details>

**4. 화면 녹화로 스킬을 만들 때 주의할 점은?**

<details><summary>정답과 해설</summary>
녹화 중 비밀번호·계좌 등 민감 정보가 화면·음성에 나오지 않게 한다. Mac 앱 Cowork, Pro/Max/Team에서만 가능하고 영상은 보관되지 않는다.
</details>

**5. 남이 공유한 스킬을 받았다. 켜기 전에 할 일은?**

<details><summary>정답과 해설</summary>
SKILL.md와 스크립트를 읽어 무엇을 하는지, 외부로 데이터를 보내는지 확인한다(6-2의 검증 습관). 스크립트가 있으면 특히.
</details>
