# 7-3. 실전 활용: 매매 복기 분석 템플릿, 문서 요약, 데이터 분석, 공부 도우미로 쓰기

| 과정 | 7. 클로드 제대로 쓰기 (claude.ai) |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 7-2 |
| 경험치 | 60 |

## 이 단원을 마치면

- 내 하루에서 Claude가 맡을 반복 작업 4가지(복기, 요약, 데이터 분석, 공부)를 각각 **프로젝트 + 스킬 + 입력 형식**의 조합으로 설계할 수 있다.
- CSV·표 데이터를 붙여 "분석"을 시킬 때 무엇을 요구하고 무엇을 믿지 말아야 하는지(계산은 코드로) 안다.
- 커리큘럼 공부에 Claude를 "답을 주는 사람"이 아니라 **"설명·퀴즈·피드백 담당"** 으로 쓰는 루틴을 만든다.
- 일주일치 사용 기록을 보고 어떤 작업이 가장 효과 있었는지 평가할 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

기능(7-1)과 스킬(7-2)을 알아도 **내 하루에 끼워 넣지 않으면** 그냥 지식이다. 이 단원은 "10시 매매 종료 → 복기 → 공부 → 저녁 정리"라는 실제 하루에 Claude를 어디에 놓을지 정하는 시간이다. 그리고 이 네 가지 작업이 11과정에서 **AI 직원의 업무**가 된다. 지금은 내가 채팅에서 손으로 시키지만, 그때는 스케줄러(4-4)가 자동으로 시킨다. 설계는 지금 해 두는 것이 싸다.

## 핵심 개념

### 1. 작업 설계 틀: 입력 → 스킬 → 출력 → 어디에 저장

| 작업 | 입력(내가 주는 것) | 스킬/프로젝트 | 출력 형식 | 저장 |
|---|---|---|---|---|
| 매매 복기 | 오늘 기록(식별 정보 제거) | trade-review | 150자 3항목 | 복기 노트(파일) |
| 문서 요약 | PDF·기사·공시 | summarize | 결론 3줄 + 근거 + 내 질문 | 프로젝트 지식 |
| 데이터 분석 | CSV(가계부 백업·매매 기록) | analyze-table | 표 + 한 줄 해석 + 계산 코드 | 저장소 docs |
| 공부 도우미 | 단원 문서, 내 답 | study-coach | 설명·퀴즈·채점 | 교육부 체크 |

**왜 중요한가**: 출력을 **어디에 저장할지** 정하지 않으면 채팅 속에 흩어진다. 복기 노트는 파일로, 요약은 프로젝트 지식으로, 분석은 저장소로. 저장처가 정해지면 11과정에서 AI 직원이 같은 곳에 쓰게 하면 된다.

### 2. 매매 복기: 감정이 아니라 규칙 위반을 세게

복기의 목적은 "오늘 잘했나"가 아니라 **"내 규칙을 어겼나"** 다. 그래서 스킬(7-2)이 손절·추격·물타기를 먼저 찾는다. 입력에는 종목·진입·청산·손익·한 줄 메모만. 계좌·이름은 뺀다(6-2). 일주일에 한 번은 7일치 복기를 붙여 "반복되는 위반 패턴 1개"를 뽑게 한다. 이것이 인사부 루틴 "주식 매매 복기"의 실제 내용이다.

### 3. 문서 요약: 결론·근거·내 질문

긴 글(공시, 기사, 커리큘럼 단원)을 붙이고 "요약해"만 하면 밋밋한 요약이 온다. 형식을 정한다(6-3):
- 결론 3줄
- 근거가 되는 **원문 인용** 2개(환각 방지: 인용이 실제로 있는지 내가 확인)
- 이 글이 **내 결정**(매매, 공부, 돈)에 미치는 영향 1줄
- 내가 더 물어봐야 할 질문 2개

### 4. 데이터 분석: 계산은 코드가, 해석은 모델이

CSV를 붙이고 "분석해"라고 하면 모델이 **암산**으로 합계를 낼 수 있다. 틀린다(6-1). 반드시 "**코드로 계산하고 코드와 결과를 같이 보여 줘**"라고 한다. claude.ai는 코드 실행 기능(설정 → Capabilities)이 켜져 있으면 파이썬으로 계산한다. 그러면 (1) 숫자가 맞고 (2) 그 코드가 3-6(pandas)의 교재가 된다.

좋은 입력: 사장실 백업 JSON(2.5단계)이나 가계부 내보내기. "이번 달 카테고리별 지출 비율, 지난달 대비 증감, 가장 큰 항목 3개. 표로. 계산 코드 포함."

### 5. 공부 도우미: 답 대신 질문을 시킨다

커리큘럼을 읽고 Claude에게 "이 단원 설명해 줘"라고 하면 **내가 읽은 것을 다시 읽어 주는** 셈이다. 대신:
- "이 단원의 핵심 개념 3절을 **다른 비유**로 설명해 줘" (이해 확인)
- "퀴즈 5문항을 내고, 내 답을 받아 채점·해설해 줘" (7-2 숙제 1 스킬)
- "내가 쓴 이 코드에서 단원에서 배운 개념이 어디에 쓰였는지 짚어 줘" (적용 확인)
- "틀린 문제의 개념을 1분 분량으로 다시 설명하고, 비슷한 문제 하나 더" (보강)

**왜 중요한가**: "AI가 대신 해 주는 공부"는 남지 않는다. AI가 **채점·질문·피드백**을 맡고 생각은 내가 하면 남는다.

### 6. 일주일 평가

주말(일요일 회고, SCHEDULE.md)에 네 작업 각각에 대해 "쓴 횟수, 도움 정도(1~5), 고칠 점"을 적는다. 도움이 2 이하인 작업은 템플릿·스킬을 고치거나 버린다. 쌓인 평가가 11과정에서 "어떤 AI 직원을 먼저 둘지"의 근거가 된다.

## 따라하기

### 1. 복기 루틴 실제 가동 (30분)

오늘(또는 최근) 매매 기록으로 trade-review 스킬을 돌린다. 결과를 `docs/review/2026-12-01.md` 같은 파일로 저장한다. 인사부 "주식 매매 복기" 루틴을 체크한다. **이 흐름이 매일 반복된다.**

### 2. 요약 템플릿 만들기 (30분)

`skills/summarize/SKILL.md`를 3절 형식으로 만든다. 최근 읽은 공시나 기사 하나로 시험하고, 원문 인용 2개가 **실제로 원문에 있는지** 찾아본다(6-2).

### 3. 가계부 분석 (40분)

사장실에서 백업을 내려받아 `ledger-entries` 부분만 CSV나 표로 만들어(또는 JSON 그대로) 붙이고, 4절의 요청을 보낸다. 계산 코드가 포함됐는지, 합계가 앱의 "이번 달" 카드와 같은지 비교. 다르면 어느 쪽이 틀렸는지 찾는다(둘 다 내가 만든 것이다).

### 4. 공부 도우미 루틴 (40분)

커리큘럼 단원 하나(이미 끝낸 것)를 붙이고 5절의 네 가지 요청을 차례로 한다. 가장 효과 있었던 것을 `docs/prompts.md`에 "공부 루틴"으로 적는다.

### 5. 하루 시간표에 넣기 (20분)

"10:00 매매 종료 → 10:30 복기(1번) → 11:00~16:00 커리큘럼 + 공부 도우미(4번) → 저녁 가계부 기록 → 22:00 인사부 체크" 처럼 **Claude를 쓰는 시각**을 일정표에 적는다. SCHEDULE.md 맨 위에 추가해 커밋.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 복기에 계좌·이름 포함 | 식별 정보 노출 | 종목·가격·손익·메모만 |
| 요약만 시키고 확인 안 함 | 없는 내용이 섞임 | 원문 인용 요구 + 대조 |
| 합계를 모델에게 맡김 | 틀린 숫자 | 코드 계산 + 결과 비교 |
| "설명해 줘"만 반복 | 공부가 남지 않음 | 퀴즈·채점·적용 확인 |
| 결과를 채팅에 방치 | 다음 주에 못 찾음 | 저장처 정하기(파일·지식·저장소) |
| 평가 없이 계속 사용 | 효과 없는 작업에 시간 낭비 | 주간 평가 1~5점 |

## 확인 퀴즈

**1. 네 작업의 출력을 각각 어디에 저장하기로 했고, 왜 저장처가 중요한가?**

<details><summary>정답과 해설</summary>
복기→파일, 요약→프로젝트 지식, 분석→저장소 docs, 공부→교육부 체크(+prompts.md). 저장처가 정해져야 흩어지지 않고, 11과정에서 AI 직원이 같은 곳에 쓰게 할 수 있다.
</details>

**2. CSV 분석을 시킬 때 반드시 덧붙일 한마디와 이유.**

<details><summary>정답과 해설</summary>
"코드로 계산하고 코드와 결과를 같이 보여 줘". 모델의 암산은 틀릴 수 있고, 코드는 검증 가능하며 교재가 된다.
</details>

**3. 요약 형식에 "원문 인용 2개"를 넣는 이유는?**

<details><summary>정답과 해설</summary>
환각 방지. 인용이 원문에 실제로 있는지 내가 대조할 수 있어서 요약의 신뢰도를 확인하는 장치가 된다.
</details>

**4. 공부 도우미로 쓸 때 피해야 할 요청과 대신 할 요청.**

<details><summary>정답과 해설</summary>
피할 것: "이 단원 설명해 줘"(이미 읽은 것 반복). 대신: 다른 비유로 설명, 퀴즈·채점, 내 코드에서 개념 찾기, 틀린 개념 보강.
</details>

**5. 주간 평가에서 점수가 낮은 작업을 어떻게 하나?**

<details><summary>정답과 해설</summary>
템플릿·스킬을 고쳐 다시 시도하거나 버린다. 효과 없는 작업을 습관으로 남기지 않는다. 평가는 11과정 AI 직원 우선순위의 근거.
</details>
