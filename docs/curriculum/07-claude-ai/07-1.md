# 7-1. claude.ai 기능 지도: 프로젝트, 아티팩트, 파일 업로드, 커넥터, 메모리, 모델 선택

| 과정 | 7. 클로드 제대로 쓰기 (claude.ai) |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 6-4 |
| 경험치 | 60 |

## 이 단원을 마치면

- claude.ai의 주요 기능 6가지(프로젝트, 아티팩트, 파일 업로드, 커넥터, 메모리, 모델 선택)가 각각 **어떤 문제를 푸는지** 한 줄로 말할 수 있다.
- "같은 맥락을 매번 다시 설명하는" 문제를 프로젝트 지침·지식·메모리 중 무엇으로 풀지 고를 수 있다.
- 메모리가 무엇을 기억하고 무엇을 기억하지 않는지, 끄거나 초기화할 때 무슨 일이 생기는지 안다.
- 내 작업(매매 복기, 코딩 공부, 가계부)을 위한 프로젝트 3개를 실제로 만든다.

## 왜 배우나 (나에게 어떤 쓸모)

지금까지는 Claude Code(코딩 도구)를 주로 썼다. 하지만 하루의 대부분, 특히 매매 복기와 공부 질문은 **claude.ai 채팅**에서 한다. 채팅을 "그때그때 질문하는 창"으로만 쓰면 매번 내 상황을 다시 설명하게 되고(6-1의 컨텍스트 문제), 좋은 답을 받아도 흩어진다. 프로젝트·메모리·아티팩트를 쓰면 채팅이 **쌓이는 작업 공간**이 된다. 유료 구독을 이미 하고 있으니 기능을 다 쓰는 게 남는 장사다.

## 핵심 개념

(아래 기능 설명은 Claude 지원 센터 문서, 확인일 2026-10-21 기준이다. 화면 메뉴는 바뀔 수 있으니 '더 보기'의 문서로 재확인한다.)

### 1. 프로젝트(Projects): 주제별 작업 공간

**한 줄 정의**: 관련 대화들을 한 폴더에 모으고, 그 폴더 전체에 적용되는 **지침**과 **지식(파일)** 을 붙여 둘 수 있는 공간.

**비유**: 매매 복기용 바인더. 표지 안쪽에 "복기 규칙"(지침)을 붙이고, 뒤에는 참고 자료(지식)를 끼워 둔다. 바인더를 열면 매번 규칙을 다시 말할 필요가 없다.

**실제 예시** (지원 문서):
- 만들기: 왼쪽 메뉴의 Projects(또는 claude.ai/projects) → "+ New Project" → 이름·설명. 설명은 Claude에게 보이지 않는다.
- 지식 추가: 프로젝트 페이지 오른쪽 지식 영역의 "+"로 문서·텍스트·코드 업로드. 프로젝트 안 **모든** 채팅의 컨텍스트가 된다. 유료 플랜은 지식이 많아지면 RAG 모드(필요한 부분만 꺼내 읽는 방식)가 자동으로 켜진다.
- 지침: "Set project instructions"에 Claude의 역할·말투·형식을 적는다. 프로젝트 안 모든 채팅에 적용된다. **6-3의 템플릿을 여기에 넣는다.**
- 주의: 채팅끼리는 맥락을 공유하지 않는다. 여러 채팅에서 써야 할 정보는 지식에 넣는다.
- 무료 계정은 프로젝트 5개까지. 공유는 Team/Enterprise 플랜만.

**왜 중요한가**: 6-3의 네 요소 중 **역할·맥락·형식**을 프로젝트에 한 번 적어 두면, 채팅에서는 "오늘 기록"만 붙이면 된다.

### 2. 아티팩트(Artifacts): 대화 옆에 열리는 결과물

**한 줄 정의**: Claude가 만든 문서·슬라이드·디자인·작은 웹 앱 같은 결과물이 대화 옆 창에 열리고, 사이드바의 Artifacts 탭에 저장되는 기능.

**실제 예시** (지원 문서): Docs(문서), Slides(발표), Design(시안·랜딩 페이지)은 모든 플랜에서 기본으로 켜져 있고, Dashboards(베타)는 Pro 이상. 코드 조각, 단일 페이지 웹사이트, 다이어그램도 만든다. 설정 → Capabilities의 "Cloud code execution and file creation"이 켜져 있어야 한다. 문서는 Word/PDF/Markdown/Google Docs로 내보낼 수 있다.

**이 프로젝트와의 관계**: 우리 앱(`index.html`)이 바로 "단일 페이지 웹 앱"이다. 아티팩트로 작은 도구를 빨리 시험해 보고, 마음에 들면 Claude Code로 저장소에 옮기는 흐름이 가능하다. 단, 아티팩트는 Claude 서비스 안에 있고 우리 앱은 내 저장소에 있다는 점이 다르다.

### 3. 파일 업로드: 한 번 보여 주기 vs 계속 보여 주기

채팅에 파일을 붙이면 **그 채팅에서만** 읽는다. 매번 필요한 파일은 프로젝트 지식에 넣는다. 올리기 전에 6-2의 데이터 정책(식별 정보 제거)을 적용한다.

### 4. 커넥터(Connectors): 외부 도구 연결

**한 줄 정의**: Claude를 내가 이미 쓰는 도구와 데이터 소스(문서 저장소, 캘린더, 메신저 등)에 연결하는 기능. 지원 센터에는 General / Pre-Built Connectors / Custom Connectors 세 묶음의 문서가 있다.

**왜 중요한가**: 9-4에서 배우는 MCP와 같은 개념이다. 채팅에서 "내 드라이브의 복기 시트 읽어서 요약해"가 가능해진다. 연결 가능한 서비스 목록은 바뀌니 설정 화면과 문서에서 확인한다. 연결은 곧 **데이터 접근 권한**이므로 필요한 것만 연결한다(6-2).

### 5. 메모리(Memory): 대화를 넘어 기억

**한 줄 정의**: Claude가 대화 중에 알게 된 내 역할·프로젝트·선호·코딩 스타일 같은 것을 주제별로 저장해 두고, 다음 대화에서 참고하는 기능.

**실제 예시** (지원 문서):
- 기억하는 것: 역할·프로젝트·업무 맥락, 사람과 장소, 소통 방식 선호, 기술·코딩 스타일, 진행 중인 작업.
- 기본으로 저장하지 않는 것: 건강·종교·정치 같은 민감 주제(설정에서 켤 수 있음). 정부 ID 번호, 금융 계좌번호 등은 저장하지 않는다.
- 설정: Settings → Memory. "Generate memory from chats"를 끄면 **일시정지**(기존 유지) 또는 **초기화**(전부 삭제, 되돌릴 수 없음, 프로젝트 메모리 포함)를 고른다.
- 채팅 하나만 메모리 없이: 새 채팅에서 첫 메시지 전에 "+" → Memory 끄기. 시크릿 채팅은 검색 대상에서도 빠진다.
- 프로젝트마다 메모리가 따로 있고, 프로젝트 안에서는 그 프로젝트 메모리 + 계정 메모리를 함께 쓴다. 완전히 분리하려면 프로젝트의 "Use account memory"를 끈다.
- 대화 검색(Search past chats)은 Pro 이상. 설정 → Memory에서 끌 수 있다.
- 레거시 방식(Settings → Capabilities에 Memory가 보이는 경우)은 동작이 다르다. 내 화면이 어느 쪽인지 확인.

**왜 중요한가**: 6-1에서 "모델은 기억이 없다"고 했다. 메모리는 그 빈틈을 **서비스 쪽에서** 메우는 장치다. 대신 무엇이 저장되는지 내가 알고 관리해야 한다. 분기마다 Settings → Memory의 Topics를 한 번 훑어보자.

### 6. 모델 선택

대화창의 모델 메뉴에서 고른다(6-4). 일상 질문은 Sonnet, 어려운 설계·분석은 Opus. 한도(5시간 세션·주간)는 모델과 무관하게 공유된다(0-4).

### 7. 계정 전체 지침(Instructions for Claude)

왼쪽 아래 이니셜 → Settings → "Instructions for Claude"에 **모든 대화**에 적용되는 일반 지침을 적는다(지원 문서). 예: "나는 비전공 초보다. 용어는 처음 나올 때 풀어 써라. 답은 결론부터." 프로젝트 지침은 그 프로젝트에만, 이것은 전체에.

| 같은 맥락을 반복하기 싫을 때 | 쓰는 것 |
|---|---|
| 모든 대화에 | Instructions for Claude |
| 특정 주제의 대화들에 | 프로젝트 지침 |
| 참고 자료를 늘 읽히고 싶을 때 | 프로젝트 지식 |
| 내가 말하지 않아도 알아서 기억 | 메모리 (단, 내용 확인) |
| 특정 작업 방식(복기 형식 등) | 스킬 (7-2) |

## 따라하기

### 1. 계정 지침 적기 (15분)

Settings → Instructions for Claude에 내 상황(비전공 초보, 트레이더, 목표, 선호 답변 형식)을 5줄로 적는다. 6-3 네 요소 중 "맥락"이다.

### 2. 프로젝트 3개 만들기 (40분)

- **매매 복기**: 지침에 6-3의 복기 코치 템플릿. 지식에 `docs/ai-data-policy.md`(6-2)와 내 매매 규칙 문서.
- **코딩 공부**: 지침 "이 저장소(나의 1인 회사)를 만들며 배우는 중. 설명은 비유 먼저, 코드는 function/for/if만". 지식에 `docs/ROADMAP.md`, `CLAUDE.md`.
- **생활·자산**: 지침 "혼자 사는 1인 가구의 가계·자산 상담. 결론부터, 숫자는 표로".
각 프로젝트에서 채팅 하나씩 해 보고, 지침이 먹히는지 확인.

### 3. 메모리 점검 (20분)

Settings → Memory → Topics를 읽는다. 틀린 것, 오래된 것, 저장되면 안 되는 것이 있으면 지운다. 어떤 방식(새 Memory / 레거시 Capabilities)인지 메모.

### 4. 아티팩트 한 개 (30분)

"코딩 공부" 프로젝트에서 "루틴 연속 달성일을 계산하는 작은 웹 도구를 아티팩트로 만들어 줘. 날짜 목록을 넣으면 streak를 보여 주면 돼"라고 해 본다. 결과를 Artifacts 탭에서 다시 열어 보고, 우리 `routine.js`의 `routineStreak()`와 로직을 비교한다.

### 5. 커넥터 둘러보기 (20분)

설정에서 커넥터 목록을 보고, **지금 당장 필요한 것만** 연결한다(없으면 연결하지 않는다). 연결한 것은 어떤 데이터에 접근하는지 적어 둔다.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 채팅마다 상황 재설명 | 시간 낭비, 답 품질 들쭉 | 프로젝트 지침 + 계정 지침 |
| 지식에 아무거나 다 넣음 | 엉뚱한 자료 참조 | 프로젝트당 꼭 필요한 파일만 |
| 메모리 내용을 모름 | 옛 정보로 답함 | 분기마다 Topics 점검 |
| 초기화를 가볍게 누름 | 전부 삭제, 복구 불가 | 일시정지 먼저 |
| 민감 정보를 지식에 업로드 | 식별 정보 노출 | 6-2 데이터 정책 |
| 커넥터 무분별 연결 | 불필요한 데이터 접근 | 필요한 것만, 목록 기록 |

## 확인 퀴즈

**1. "매번 내 매매 규칙을 다시 설명한다"를 해결하는 기능은? 두 가지 이상.**

<details><summary>정답과 해설</summary>
프로젝트 지침(그 프로젝트의 모든 채팅에 적용)과 프로젝트 지식(규칙 문서 업로드). 계정 지침은 모든 대화에 적용되므로 복기 규칙처럼 주제 한정 내용에는 프로젝트가 맞다.
</details>

**2. 프로젝트 안의 채팅 A에서 말한 내용을 채팅 B가 아는가?**

<details><summary>정답과 해설</summary>
모른다. 채팅끼리 맥락을 공유하지 않는다(지원 문서). 공유하려면 지식에 넣거나, 메모리가 그 내용을 저장했을 때만 참고된다.
</details>

**3. 메모리 "일시정지"와 "초기화"의 차이는?**

<details><summary>정답과 해설</summary>
일시정지는 기존 메모리를 유지하되 사용·저장을 멈춘다. 초기화는 프로젝트 메모리까지 전부 영구 삭제하고 되돌릴 수 없다.
</details>

**4. 메모리가 기본적으로 저장하지 않는 정보의 예는?**

<details><summary>정답과 해설</summary>
민감 주제(건강·종교·정치 등, 설정으로 켤 수 있음)와 정부 ID 번호·금융 계좌번호 등. 그래도 6-2의 원칙대로 비밀은 애초에 입력하지 않는다.
</details>

**5. 아티팩트와 우리 저장소 앱의 차이, 그리고 둘을 함께 쓰는 흐름은?**

<details><summary>정답과 해설</summary>
아티팩트는 Claude 서비스 안의 결과물, 우리 앱은 내 저장소의 파일. 아티팩트로 빠르게 시험 → 괜찮으면 Claude Code로 저장소에 옮겨 커밋하는 흐름.
</details>
