# 13-2. 앱/서비스 판매: 결제(토스페이먼츠/Stripe), 구독 모델, 사업자·세금 기초(개요, 전문가 확인 권고)

| 과정 | 13. 수익화 |
|---|---|
| 예상 시간 | 4시간 |
| 선수 단원 | 13-1 |
| 경험치 | 80 |

## 이 단원을 마치면

- "내가 쓰는 앱"을 "남이 돈 내고 쓰는 서비스"로 바꾸려면 무엇이 더 필요한지(계정·로그인, 데이터 분리, 결제, 약관, 지원) 목록으로 말할 수 있다.
- 결제 연동의 큰 그림(결제창 → 승인 → 내 서버 확인 → 권한 부여, 웹훅)과 국내(토스페이먼츠 등)·해외(Stripe 등) 선택 기준을 안다.
- 가격 모델(일회성, 구독, 사용량)과 **첫 가격**을 정하는 방법을 안다.
- 사업자 등록, 세금, 약관·개인정보 처리방침이 **전문가 확인이 필요한 영역**임을 알고, 무엇을 물어볼지 질문 목록을 만든다.

## 왜 배우나 (나에게 어떤 쓸모)

"앱을 만들어 판다"는 목표의 실제 작업은 **코딩이 아닌 것**이 절반이다. 로그인·결제·약관·세금. 이 단원은 그 절반의 지도다. 코딩 부분(로그인, 결제 연동)은 지금까지 배운 API(4-1)·보안(12-2)·배포(12-3)의 조합이고, 나머지는 **전문가에게 물어볼 질문**을 준비하는 것이다. 4-3·6-2에서 반복한 "전문가 확인"이 여기서 구체화된다.

## 핵심 개념

(결제사·플랫폼·세법은 자주 바뀌고 이 글 작성 환경에서 해당 사이트를 열 수 없었다. 아래는 **구조**를 설명하며, 절차·수수료·법령은 반드시 공식 페이지와 전문가에게 확인한다.)

### 1. 나 → 남: 추가로 필요한 것

| 지금(내 앱) | 서비스가 되려면 | 배운 곳 |
|---|---|---|
| localStorage, 내 브라우저 | **계정·로그인**, 사용자별 데이터 분리(서버 DB) | 12-3 길 C 확장 |
| 내 `.env`의 API 키 | 사용자별 사용량 측정·한도(내 API 비용이 곧 원가) | 10-5 |
| 내가 확인 | **결제** + 권한 부여(유료 기능 잠금 해제) | 이 단원 |
| 없음 | 약관·개인정보 처리방침·환불 규정 | 전문가 |
| 텔레그램 나에게 | 고객 지원 채널, 장애 공지 | 12-4 |
| 내 데이터 | 시세·증권 연동은 **빼거나** 별도 계약(4-3) | 4-3 |

**비유**: 집에서 먹는 요리와 식당 개업. 요리(앱)는 같아도 위생 허가(약관·법), 계산대(결제), 테이블 관리(계정)가 생긴다.

### 2. 결제의 큰 그림

```
① 사용자가 "구독" 클릭 → ② 결제사 결제창(카드 입력은 결제사 화면에서, 내 서버는 카드번호를 절대 보지 않음)
→ ③ 결제사가 결과를 내 서버에 알림(웹훅, 4-1의 POST) → ④ 내 서버가 결제사 API로 **재확인**(위조 방지)
→ ⑤ 사용자 계정에 "유료 ~까지" 표시 → ⑥ 앱이 그 표시를 보고 기능 해제
```
- 국내 카드·계좌이체·간편결제: 토스페이먼츠 같은 국내 PG(전자지급결제대행). 해외 고객·달러 결제: Stripe 류.
- 테스트 키/실결제 키가 따로 있다(4-3의 모의/실전과 같은 구조). **테스트로 끝까지** 해 본 뒤 실결제.
- 웹훅은 외부에서 오는 요청이므로 **서명 검증**(결제사가 제공) 없이는 믿지 않는다(12-2 "밖에서 온 값").
- 구독은 "정기 결제" 기능(빌링키)을 쓴다. 갱신 실패·해지·환불 처리를 코드에 넣어야 한다.
- Claude Code에게 "토스페이먼츠 공식 문서를 읽고 테스트 결제 흐름을 구현"을 시킬 수 있지만, ④의 재확인과 웹훅 서명 검증이 있는지 **내가 확인**한다.

### 3. 가격 모델

| 모델 | 맞는 경우 | 주의 |
|---|---|---|
| 일회성 | 도구 하나, 업데이트 적음 | 지속 수익 없음 |
| 구독(월/연) | 계속 쓰는 자기관리·리포트 | 매달 가치를 줘야 해지 안 함 |
| 사용량 | AI 호출이 원가(10-5) | 사용자가 비용 예측 어려움 → 상한 제공 |

첫 가격: (1) 내 원가(AI 비용 + 서버 + 결제 수수료) × 3 이상 (2) 비슷한 서비스 가격 조사 (3) **작게 시작**해서 10명에게 팔아 보고 조정. 무료 체험(14일)과 유료의 경계를 분명히.

### 4. 사업자·세금 (개요만, 전문가 확인)

일반적으로 **계속·반복적으로 판매하면 사업자 등록**이 필요하고, 온라인 판매는 통신판매업 신고가 따르는 경우가 많으며, 매출에 따라 부가가치세·소득세 신고 의무가 생긴다. 주식 매매 소득과는 **별개**다. 간이/일반, 업종, 신고 시기, 경비 처리는 상황마다 달라 **세무사·국세청 상담**이 정답이다. 이 커리큘럼은 "무엇을 물어볼지"까지만 책임진다.

**전문가에게 물어볼 질문 목록**:
1. 월 N만 원 수준의 온라인 구독 판매를 시작하려면 사업자 등록·통신판매업 신고가 필요한가? 시기는?
2. 간이과세와 일반과세 중 무엇이 맞나? 부가세 신고 주기는?
3. AI API 비용·서버 비용·도메인은 경비 처리되나? 증빙은 무엇을 모아야 하나?
4. 약관·개인정보 처리방침은 어떤 내용이 필수이고, 어디서 표준안을 얻나?
5. 환불 규정은 법적 최소 기준이 있나?
6. 주식 매매 소득과 사업 소득이 섞일 때 신고는?

### 5. 약관·개인정보

사용자의 가계부·루틴·복기 데이터는 **개인정보**다. 수집 항목, 목적, 보관 기간, 제3자 제공(AI API에 보내는 것 포함!), 파기 절차를 처리방침에 적어야 한다. 6-2에서 내 데이터를 AI에 어디까지 줄지 고민한 것을, 이제 **남의 데이터**에 대해 더 엄격하게 한다: 식별 정보 제거 후 전송, 최소 수집, 암호화 저장(호스팅의 DB 암호화), 삭제 요청 처리.

### 6. 작게 파는 순서

1. 13-1 포트폴리오로 관심 있는 사람 10명 찾기(커뮤니티, 지인).
2. **수동 운영**으로 시작: 결제는 계좌이체, 계정은 내가 만들어 줌, 지원은 톡. 코딩 없이 수요 확인.
3. 10명이 한 달 쓰고 5명이 재결제하면 자동화(로그인·결제 연동).
4. 그때 사업자·약관을 전문가와 정리.
순서를 바꾸면(결제 연동부터) 팔리지 않는 것을 완벽하게 만든다.

## 따라하기

### 1. 서비스화 목록 (30분)

1절 표를 내 앱 기준으로 채워 `docs/business/service-gap.md`에. 각 항목의 예상 작업 시간.

### 2. 결제 흐름 그리기 (40분)

2절 흐름을 내 앱 화면·서버 엔드포인트 이름으로 그린다(코드 없이). 웹훅 서명 검증과 재확인 단계가 있는지 표시.

### 3. 테스트 결제 (90분, 선택)

결제사 개발자 문서의 테스트 키로 "결제창 열기 → 승인 → 웹훅 받기"까지 로컬에서 해 본다. Claude Code에 공식 문서 URL을 주고 구현시키되 2절의 두 검증을 내가 확인. **실결제 키는 만들지 않는다.**

### 4. 가격 계산 (30분)

10-5 비용표 + 서버 + 결제 수수료(공식 페이지 확인)로 1인당 월 원가를 계산하고 가격 후보 3개를 적는다. 비슷한 서비스 3개의 가격도.

### 5. 전문가 질문지 (30분)

4절 질문 목록을 내 상황으로 고쳐 `docs/business/questions-for-expert.md`에. 세무사 상담·국세청 상담 예약을 실제로 잡는다(비용이 들면 그것도 원가).

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 결제 연동부터 | 안 팔리는 것을 완성 | 수동 10명 먼저 |
| 카드 정보를 내 서버에 | 법적·보안 위험 | 결제사 결제창만 |
| 웹훅을 그대로 믿음 | 위조 결제로 권한 해제 | 서명 검증 + 재확인 |
| 남의 데이터를 AI에 그대로 | 개인정보 위반 | 최소 수집, 식별 정보 제거, 처리방침 |
| 세금·등록을 미룸 | 가산세·과태료 | 전문가 상담 먼저 |
| 시세 데이터 포함 | 재배포 문제(4-3) | 제외 또는 계약 |

## 확인 퀴즈

**1. 내 앱이 서비스가 되려면 추가되는 것 다섯 가지.**

<details><summary>정답과 해설</summary>
계정·로그인과 사용자별 데이터 분리, 사용량 측정, 결제와 권한 부여, 약관·개인정보 처리방침·환불 규정, 고객 지원. 시세 연동은 제외·계약.
</details>

**2. 결제 흐름에서 내 서버가 절대 다루지 않는 것과 꼭 하는 것.**

<details><summary>정답과 해설</summary>
카드 번호는 결제사 화면에서만. 내 서버는 웹훅 서명 검증과 결제사 API 재확인을 꼭 한다.
</details>

**3. 첫 가격을 정하는 세 가지 기준.**

<details><summary>정답과 해설</summary>
원가의 3배 이상, 비슷한 서비스 조사, 작게 시작해 10명에게 팔고 조정.
</details>

**4. 사업자·세금에서 이 커리큘럼이 책임지는 범위.**

<details><summary>정답과 해설</summary>
구조 이해와 전문가에게 물어볼 질문 목록까지. 절차·세율·시기는 세무사·국세청 확인.
</details>

**5. 남의 데이터를 AI API에 보낼 때 달라지는 것.**

<details><summary>정답과 해설</summary>
개인정보 처리방침에 제3자 제공(AI API)을 명시하고, 식별 정보 제거·최소 수집·삭제 요청 처리를 해야 한다. 내 데이터보다 엄격하다.
</details>

## 숙제

1. **수동 판매 실험** — 포트폴리오를 보고 관심 있는 사람 3명에게 "한 달 무료로 써 보고 피드백"을 요청하라. 계정은 수동으로.
2. **원가표** — 사용자 10명·50명·200명일 때 월 원가(AI·서버·결제 수수료)를 표로 만들어 `docs/business/cost.md`에.
3. **13-3 예습** — "내가 남을 위해 해 줄 수 있는 자동화" 3가지를 적어 두라(예: 가계부 정리 스크립트, 매매 복기 봇 세팅).
