# 13-3. 외주·프리랜스: 플랫폼(크몽, 위시켓 등), 견적·계약, AI로 생산성 높이기

| 과정 | 13. 수익화 |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 13-2 |
| 경험치 | 60 |

## 이 단원을 마치면

- 외주의 흐름(의뢰 → 요구사항 정리 → 견적 → 계약 → 작업 → 검수 → 정산)을 알고, 각 단계에서 **초보 프리랜서가 당하는 함정**을 피할 수 있다.
- 8-6의 여섯 칸 요청문을 **의뢰인과의 요구사항 문서**로 바꿔 쓰고, "범위 밖"을 계약에 넣는다.
- 작업 시간을 기록해 **시급 기반 견적**을 낼 수 있고, AI(Claude Code)로 줄인 시간을 어떻게 가격에 반영할지 결정한다.
- 플랫폼 수수료·정산 구조와 세금(13-2)을 알고, 첫 소액 외주 1건을 실제로 받는 계획을 세운다.

## 왜 배우나 (나에게 어떤 쓸모)

앱 판매(13-2)는 수요가 생길 때까지 시간이 걸린다. 외주는 **당장 돈이 되는** 길이고, 남의 문제를 풀면서 실력과 포트폴리오(13-1)가 같이 는다. 그리고 AI 코딩을 아는 비전공자의 경쟁력은 "싸고 빠르게"가 아니라 **요구사항을 정확히 듣고(6-3·8-6) 검증까지 해 주는 것**(12-1)이다. 그게 이 커리큘럼 전체에서 연습한 일이다.

## 핵심 개념

(플랫폼 수수료·정책은 자주 바뀌고 이 글 작성 환경에서 해당 사이트를 열 수 없었다. 구조만 설명한다. 반드시 각 플랫폼 공식 안내를 확인.)

### 1. 외주의 흐름과 함정

| 단계 | 할 일 | 함정 | 대책 |
|---|---|---|---|
| 의뢰 | 플랫폼 공고 또는 지인 | "간단한 거예요"에 속음 | 요구사항 문서 전까지 견적 안 냄 |
| 요구사항 | 8-6 여섯 칸을 의뢰인용으로 | 말로만 합의 | 문서로, 의뢰인 서명/확인 |
| 견적 | 시간 × 시급 + 위험 가산 | 너무 싸게 | 기록된 시간 기준, 수정 횟수 명시 |
| 계약 | 범위·납기·검수 기준·수정 횟수·정산·저작권 | 계약 없이 시작 | 플랫폼 계약 또는 표준계약서 |
| 작업 | 브랜치·테스트·주간 보고 | 혼자 끌어안음 | 중간 보고, 데모 |
| 검수 | 검증 기준대로 시연 | "느낌이 아니다" | 계약의 검수 기준 |
| 정산 | 플랫폼 에스크로 또는 계약서대로 | 미수금 | 선금, 플랫폼 보호 |

**비유**: 매매 규칙. 진입(견적) 전에 손절(범위 밖)과 목표(검수 기준)를 정해 두면 감정으로 흔들리지 않는다.

### 2. 요구사항 문서 = 여섯 칸의 의뢰인 버전

| 칸 | 내용 |
|---|---|
| 목표 | 의뢰인이 얻는 결과 한 줄("매일 아침 네이버 카페 새 글을 텔레그램으로") |
| 입력·환경 | 어떤 데이터·계정·컴퓨터를 쓰나(비밀은 의뢰인이 직접 입력, 4-2) |
| 산출물 | 코드 + 설치 안내 + 실행 영상 |
| 검수 기준 | "평일 08:00에 메시지 1통, 3일 연속 확인" |
| 범위 밖 | "유료 API 비용, 디자인 변경, 다른 사이트 추가는 별도" |
| 일정·수정 | 납기, 수정 2회 포함, 이후 시간당 |

이 문서가 곧 계약의 핵심이고, Claude Code에 넘길 스펙(8-6 인터뷰 패턴)이 된다. 의뢰인과의 대화도 **Claude에게 인터뷰 질문을 뽑게** 하면 빠진 질문이 준다.

### 3. 견적

1. 비슷한 작업을 내 프로젝트에서 할 때 **실제 걸린 시간**(커밋 시각, 로그)을 근거로.
2. 시급 = (내가 원하는 월 수입 ÷ 월 작업 가능 시간) × 1.3(비작업 시간·세금 여유). 처음엔 시장가보다 조금 낮게, 사례 3개 생기면 올린다.
3. AI로 2배 빨라졌다고 가격을 절반으로 하지 않는다. 가치(의뢰인이 아낀 시간)로 매기고, 속도는 **마진**이다. 다만 "검증·문서·지원"에 시간을 더 쓴다 — 그게 차별점.
4. 위험 가산: 외부 API 의존(바뀔 수 있음, 4-3), 의뢰인 환경 불명, 촉박한 납기.
5. 수수료: 플랫폼은 보통 결제액의 일정 비율을 떼고, 세금 신고는 내 몫(13-2 전문가 질문 6). 견적에 포함.

### 4. 플랫폼 vs 직접

| | 플랫폼(크몽·위시켓 류) | 지인·커뮤니티 직접 |
|---|---|---|
| 장점 | 에스크로(정산 보호), 공고 많음, 평점이 포트폴리오 | 수수료 없음, 관계 |
| 단점 | 수수료, 가격 경쟁, 초기 평점 0 | 계약·정산 전부 내 책임 |
| 시작 | 소액 "세팅 대행"(봇·자동화 설치) 공고로 평점 쌓기 | 13-1 포트폴리오로 1건 |

첫 1~3건은 플랫폼의 **작은 작업**(텔레그램 봇 세팅, 엑셀 자동화, 복기 봇 설치)으로 평점과 후기를 만든다. 후기가 다음 의뢰를 부른다.

### 5. AI를 쓴다고 말해도 되나

의뢰인이 사는 건 **결과와 책임**이다. "AI 도구로 작업하되 설계·검증·지원은 제가 합니다"라고 밝히는 것이 신뢰에 유리하고, 계약서에 "제3자 도구 사용"을 명시하면 분쟁이 준다. 반대로 의뢰인 데이터를 AI에 넣을 때는 **허락**이 필요하다(13-2의 개인정보, 6-2). 계약서에 "의뢰인 데이터는 식별 정보 제거 후 AI 도구에 전달하거나 전달하지 않음"을 적는다.

### 6. 작업 방식 (이 커리큘럼의 종합)

브랜치(5-2) → 스펙(8-6) → 테스트(12-1) → Claude Code 구현(8·9) → 보안 리뷰(12-2) → 배포·설치 안내(12-3) → runbook 간단 버전(11-3·12-4)을 산출물에 포함. "코드만 던지는" 프리랜서와의 차이가 여기서 난다.

## 따라하기

### 1. 요구사항 문서 연습 (40분)

가상의 의뢰("매일 아침 특정 카페 새 글 텔레그램 알림")를 2절 표로 작성. Claude Code에 "의뢰인에게 물어볼 질문 10개"를 뽑게 해 문서를 보강.

### 2. 내 시급 (20분)

3절 공식으로 시급 계산. 커리큘럼 중 실제 작업 하나(예: 4-4 알림 봇)의 소요 시간을 커밋 시각으로 재어 견적 예시를 만든다.

### 3. 플랫폼 둘러보기 (40분)

플랫폼 2곳에 가입하고 "자동화/봇/파이썬" 공고 10개를 읽어 (a) 요구사항이 명확한가 (b) 예산 (c) 내가 할 수 있나를 표로. 공식 수수료·정산 안내 페이지를 읽는다.

### 4. 첫 상품 등록 (50분)

"텔레그램 알림 봇 세팅 대행" 같은 소액 상품을 13-1 포트폴리오 링크·사례와 함께 등록. 범위 밖과 수정 횟수를 상품 설명에 명시.

### 5. 계약서 초안 (30분)

표준계약서(플랫폼 제공 또는 공공 표준안)를 구해 2절 항목이 들어 있는지 확인. 빠진 항목은 특약으로. 전문가 질문지(13-2)에 "외주 계약서 검토" 추가.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 요구사항 없이 견적 | 끝없는 수정 | 문서 먼저, 수정 횟수 명시 |
| AI 속도로 가격 할인 | 저가 경쟁 | 가치 기준, 검증·지원으로 차별 |
| 계약 없이 시작 | 미수금 | 플랫폼 에스크로, 선금 |
| 의뢰인 데이터를 AI에 | 분쟁·위반 | 허락, 식별 정보 제거, 계약 명시 |
| 코드만 납품 | 유지보수 문의 폭주 | 설치 안내·runbook 포함, 유지보수는 별도 계약 |
| 큰 건부터 | 실패 시 타격 | 소액 3건으로 평점 |

## 숙제

1. **첫 소액 외주** — 한 달 안에 소액 1건(지인 포함)을 2절 문서·계약·검수 기준으로 끝내고 후기를 받아라. 금액보다 **절차를 지켰는지**가 목표.
2. **시간 기록** — 그 작업의 단계별 시간을 기록해 견적 정확도를 계산하라(예상 vs 실제).
3. **13-4 예습** — 12월 1일부터 지금까지의 커리큘럼 진도·막힌 곳·바꾼 것을 `docs/study-notes/`에서 훑어 한 페이지로 요약해 두라.
