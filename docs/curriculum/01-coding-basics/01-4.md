# 1-4. 반복문: for, while, for...of, 반복 안에서 누적하기(합계·개수)

| 과정 | 1. 코딩의 기본 개념 (JavaScript로) |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 1-3 |
| 경험치 | 60 |

## 이 단원을 마치면

- `for...of`로 배열의 요소를 하나씩 꺼내 처리하는 코드를 읽고 쓸 수 있다.
- "0에서 시작해서 하나씩 더한다"는 **누적 패턴**으로 합계, 개수, 최대값을 구할 수 있다.
- 고전 `for (초기; 조건; 증감)`과 `while`이 언제 필요한지 구별하고, 무한 루프를 피할 수 있다.
- `break`와 `continue`로 반복을 중간에 끊거나 건너뛸 수 있다.
- 가계부 앱에 "총 수입 / 총 지출" 요약을 반복문으로 직접 넣을 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

매매 복기의 본질은 반복이다. 체결 내역 100건을 **하나씩** 보며 "이건 익절, 이건 손절, 이건 수수료만 날림"을 센다. 한 달 지출 200건을 하나씩 보며 식비만 더한다. 사람은 10건만 넘어가도 실수하지만, 컴퓨터는 100만 건도 똑같은 정확도로 한다. 그 "하나씩 똑같이"가 반복문이다.

이미 봤다. `app.js`의 `calculateBalance()`는 `entries`를 **하나씩 꺼내서** 수입이면 더하고 지출이면 뺀다. `render()`는 **하나씩 꺼내서** 화면에 줄을 만든다. 2과정에서 만들 "이번 달 카테고리별 합계", 3과정에서 파이썬으로 할 "주가 CSV 한 줄씩 읽기", 4과정의 "종목 리스트를 돌며 시세 조회"가 전부 같은 모양이다. 이 단원에서 익히는 **누적 패턴** 하나가 그 전부의 뼈대다.

## 핵심 개념

### 1. 반복문(loop): 같은 일을 여러 번

**한 줄 정의.** 반복문(loop)은 코드 블록을 조건이 만족되는 동안, 또는 목록의 요소 수만큼 되풀이해서 실행한다. MDN: "반복문이 기본적으로 하는 일은 모두 같습니다. 반복문은 한 동작을 여러 번 반복합니다. (사실 0회 반복하는 것도 가능합니다.)"

**비유.** 체결 내역 출력물을 한 줄씩 손가락으로 짚으며 내려가는 것. 마지막 줄에서 손가락이 멈춘다. 내역이 0건이면 손가락은 한 번도 안 움직인다.

**자바스크립트의 반복문.** MDN 안내서는 `for`, `do...while`, `while`, `for...in`, `for...of`와 `break`, `continue`를 소개한다. 이 단원은 그중 실무에서 90%를 차지하는 `for...of`, 고전 `for`, `while`을 다룬다. (`for...in`은 객체의 키를 돌 때 쓰는데, 배열에는 쓰지 않는다. 1-6에서 `Object.keys`로 대신한다.)

### 2. `for...of`: 목록의 요소를 하나씩

**한 줄 정의.** `for (const 요소 of 배열) { ... }`는 배열의 첫 요소부터 마지막까지 하나씩 `요소`에 담아 블록을 실행한다. MDN: `for...of` 명령문은 "반복 가능한 객체(Array, Map, Set, String 등)에 대해서 반복"한다.

**비유.** "이 바구니(`entries`)에서 하나(`entry`)씩 꺼내서, 꺼낼 때마다 이걸 해라."

**실제 예시.** `app.js`에 세 번 나온다.

```js
// (1) 잔액 계산: 하나씩 꺼내 더하거나 뺀다
for (const entry of entries) {
  if (entry.type === "income") { balance = balance + entry.amount; }
  else { balance = balance - entry.amount; }
}

// (2) 화면 그리기: 하나씩 꺼내 <li>를 만든다
for (const entry of recentFirst) {
  const item = document.createElement("li");
  // ...
}

// (3) 지도의 방 버튼마다 클릭 이벤트를 붙인다 (querySelectorAll의 결과도 반복 가능)
for (const roomBtn of document.querySelectorAll(".room")) {
  roomBtn.addEventListener("click", function () { /* ... */ });
}
```

`const entry`를 쓸 수 있는 이유: 한 바퀴마다 **새로운** `entry` 상자가 만들어지고, 그 바퀴 안에서는 다른 값을 넣지 않기 때문이다(MDN: "블록 내부 변수를 수정하지 않는 경우 `let` 대신 `const`도 사용할 수 있습니다").

**왜 중요한가.** 인덱스(몇 번째인지)가 필요 없고 "전부 한 번씩"이면 무조건 `for...of`다. 가장 읽기 쉽고 실수가 적다.

### 3. 누적 패턴: 합계, 개수, 최대값

**한 줄 정의.** 반복 **바깥**에 누적 변수를 만들어 두고, 반복 **안**에서 조금씩 갱신한 뒤, 반복이 끝난 뒤 그 변수를 쓴다.

**비유.** 계산기의 `M+`. 영수증을 한 장씩 보며 금액을 `M+`로 누르고, 마지막에 `MR`로 합계를 본다. 시작할 때 메모리를 0으로 비워 두는 게 핵심이다.

**실제 예시.** 세 가지 변형이 전부다.

```js
// 합계: 0에서 시작, 더해 간다
let expenseTotal = 0;
for (const entry of entries) {
  if (entry.type === "expense") {
    expenseTotal = expenseTotal + entry.amount;   // expenseTotal += entry.amount 와 같다
  }
}

// 개수: 0에서 시작, 1씩 센다
let incomeCount = 0;
for (const entry of entries) {
  if (entry.type === "income") {
    incomeCount++;                                // incomeCount = incomeCount + 1
  }
}

// 최대값: 첫 비교에서 무조건 갱신되도록 아주 작은 값에서 시작
let biggest = 0;
for (const entry of entries) {
  if (entry.type === "expense" && entry.amount > biggest) {
    biggest = entry.amount;
  }
}
```

**세 가지 규칙.** (1) 누적 변수는 반복 **밖**에 `let`으로. 안에 두면 매 바퀴 0으로 초기화된다. (2) 시작값을 신중히: 합계·개수는 `0`, 최대값은 `0`이나 `-Infinity`, 최소값은 `Infinity`. (3) 반복이 끝난 **뒤에** 결과를 쓴다.

**왜 중요한가.** "통계"라고 부르는 거의 모든 것(합계, 평균, 승률, 최대 손실, 연속 달성일)이 이 패턴의 변형이다. 1-6의 `reduce`는 이 패턴을 한 줄로 줄인 것뿐이다.

### 4. 고전 `for`: 횟수와 인덱스가 필요할 때

**한 줄 정의.** `for (초기문; 조건문; 증감문) { ... }`는 초기문을 한 번 실행하고, 조건문이 참인 동안 블록과 증감문을 되풀이한다.

**실행 순서 (MDN 안내서).** (1) 초기문 실행 → (2) 조건 검사, 거짓이면 종료 → (3) 블록 실행 → (4) 증감문 실행 후 (2)로.

```js
for (let i = 0; i < entries.length; i++) {
  console.log(i + 1 + "번째:", entries[i].title);
}
```

`i`는 0부터 시작하고(배열 인덱스가 0부터라서), `i < length`이므로 마지막 인덱스 `length - 1`에서 멈춘다. `i++`는 `i = i + 1`. 여기서 `i`는 바퀴마다 값이 바뀌므로 `let`이어야 한다(`const i`는 `i++`에서 에러).

**언제 쓰나.** "1부터 10까지", "앞 요소와 뒤 요소 비교(`entries[i]`와 `entries[i + 1]`)", "거꾸로 돌기(`i--`)"처럼 **번호**가 필요할 때. 그 외에는 `for...of`.

### 5. `while`: 몇 번일지 모를 때

**한 줄 정의.** `while (조건) { ... }`는 조건이 참인 동안 블록을 반복한다. MDN: "`while` 문은 테스트 조건이 참으로 평가되는 동안, 지정된 문을 실행하는 반복을 생성합니다. 문이 실행되기 전에 조건이 평가됩니다."

**비유.** "잔고가 목표에 닿을 때까지 복리로 굴린다." 몇 달 걸릴지는 돌려 봐야 안다.

```js
let money = 1000000;
let months = 0;
while (money < 2000000) {
  money = money * 1.02;   // 월 2% 가정
  months++;
}
console.log(months, "개월");   // 36
```

**무한 루프 주의.** 블록 안에서 조건에 쓰인 변수를 바꾸지 않으면 영원히 돈다. MDN도 `while (true)`를 "피하세요"라고 적는다. 브라우저가 멈추면 탭을 닫아야 한다. `while`을 쓸 땐 "이 변수가 매 바퀴 조건을 향해 움직이나?"를 꼭 확인한다. 위 예에서 수익률을 `1.0`으로 바꾸면 `money`가 안 늘어서 무한 루프다.

**`do...while`.** 블록을 **먼저 한 번** 실행하고 조건을 본다(MDN: "조건문을 확인하기 전에 문장은 한번 실행됩니다"). 드물게 쓴다.

### 6. `break`와 `continue`

**한 줄 정의.** `break`는 반복을 즉시 끝내고 다음 문장으로 넘어가고(MDN: "현재 반복문… 을 종료하고, 그 다음 문으로 프로그램 제어를 넘깁니다"), `continue`는 이번 바퀴만 건너뛰고 다음 바퀴로 간다(MDN: "현재 반복에서 명령문의 실행을 종료하고 반복문의 처음으로 돌아가").

```js
// 처음 나오는 10만 원 이상 지출을 찾으면 더 볼 필요 없다
let firstBig;
for (const entry of entries) {
  if (entry.type === "expense" && entry.amount >= 100000) {
    firstBig = entry;
    break;
  }
}

// 수입은 건너뛰고 지출만 출력
for (const entry of entries) {
  if (entry.type === "income") {
    continue;
  }
  console.log(entry.title, entry.amount);
}
```

**왜 중요한가.** `break`는 "찾았으면 그만"으로 시간을 아끼고, `continue`는 깊은 중첩 대신 "해당 없음은 먼저 쳐내기"(1-3의 가드 절과 같은 발상)로 코드를 평평하게 만든다.

### 실습 3. 최대 지출과 평균 (15분)

콘솔에서 누적 패턴 두 가지를 직접 쳐 본다.

```js
let biggest = 0;

for (const e of entries) { if (e.type === "expense") { sum += e.amount; count++; } }
```

### 실습 4. 레벨표 출력 (`for`) 과 복리 계산 (`while`) (25분)

`study` 폴더에 `levels.js`.

```js
const XP_PER_LEVEL = 100;

// 1) 기록 0건~30건일 때 레벨표 (고전 for: 횟수가 정해져 있다)
for (let n = 0; n <= 30; n += 5) {
  const xp = n * 10;
  const level = Math.floor(xp / XP_PER_LEVEL) + 1;
  console.log(`${n}건 → ${xp} XP → Lv.${level}`);
}

// 2) 100만 원이 월 2%로 200만 원 되는 데 몇 달? (while: 횟수를 모른다)
let money = 1000000;
let months = 0;
while (money < 2000000) {
  money *= 1.02;
  months++;
}
console.log(`${months}개월 후 ${Math.round(money).toLocaleString("ko-KR")}원`);

// 3) 매달 손실 3%를 세 번 연속 보면 중단 (break)
let streak = 0;
const monthlyReturns = [0.02, -0.03, -0.03, 0.05, -0.03, -0.03, -0.03, 0.01];
for (let i = 0; i < monthlyReturns.length; i++) {
  streak = monthlyReturns[i] < 0 ? streak + 1 : 0;
  if (streak === 3) {
    console.log(`${i + 1}번째 달에 3연속 손실. 매매 중단`);
    break;
  }
}
```

`node levels.js`로 실행(Windows PowerShell, Mac 동일). 그다음 (2)의 `1.02`를 `1.0`으로 바꾸면 무한 루프가 된다. 실행 후 터미널이 멈추면 `Ctrl + C`로 끊는다(Mac도 `Ctrl + C`). 무한 루프를 **한 번은 직접 겪어 보는 것**이 목표다. 끝나면 `1.02`로 되돌린다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 마지막 요소가 `undefined` | `i <= entries.length` (하나 더 돎) | `i < entries.length`. 인덱스는 0부터 `length - 1` |
| 합계가 항상 마지막 금액 하나 | 누적 변수를 반복 **안**에서 선언 | `let total = 0;`을 반복 **밖**으로 |
| 브라우저/터미널이 멈춤 | 무한 루프. 조건 변수를 안 바꿈 | 블록 안에서 조건 변수가 움직이는지 확인. 터미널은 `Ctrl + C` |
| `TypeError: Assignment to constant variable.` in `for` | `for (const i = 0; ...; i++)` | 고전 `for`의 카운터는 `let` |
| `for...of`에서 `entry is not iterable` | 배열이 아닌 것(객체, `null`)을 돌림 | `console.log(typeof x, x)`로 확인. 객체는 `Object.keys` (1-6) |
| 반복 중에 배열에서 삭제했더니 건너뜀 | 돌고 있는 배열을 수정 | `filter`로 새 배열을 만든다 (1-6, `deleteEntry`가 그렇게 한다) |
| `for (...);` 뒤에 블록이 안 돎 | 괄호 뒤 세미콜론이 빈 문장을 만듦 | `)` 다음에 바로 `{` |
| 평균이 `NaN` | 0으로 나눔 | 개수 0일 때 분기 처리 |

## 확인 퀴즈

**1. `app.js`의 `calculateBalance()`에서 누적 변수는 무엇이고, 시작값은 왜 0인가?**

<details><summary>정답과 해설</summary>

`balance`. 반복 밖에서 `let balance = 0`으로 만들고, 반복 안에서 더하거나 뺀 뒤, 반복이 끝난 후 `return balance`한다. 합계는 "아무것도 안 더한 상태"가 0이므로 0에서 시작한다. 최대값이라면 시작값이 달라진다.
</details>

**2. `for (let i = 0; i < 5; i++)`는 몇 번 돌고 `i`는 어떤 값들을 가지는가?**

<details><summary>정답과 해설</summary>

5번. `i`는 0, 1, 2, 3, 4. `i`가 5가 되는 순간 `i < 5`가 거짓이라 멈춘다. MDN 예제 그대로 "step 0 through 4"다.
</details>

**3. 다음 코드의 문제는?**

```js
let n = 0;
while (n < 3) {
  console.log(n);
}
```

<details><summary>정답과 해설</summary>

무한 루프. 블록 안에서 `n`이 바뀌지 않으므로 `n < 3`이 영원히 참이다. `n++`를 블록 안에 넣어야 한다. `while`을 쓸 때는 조건에 쓰인 변수가 매 바퀴 조건을 향해 움직이는지 확인한다.
</details>

**4. `break`와 `continue`의 차이를 "지출만 출력하다가 10만 원 이상을 만나면 그만"이라는 요구로 설명하라.**

<details><summary>정답과 해설</summary>

수입을 만나면 `continue`(이번 것만 건너뛰고 계속), 10만 원 이상 지출을 만나면 출력 후 `break`(반복 자체를 끝냄). `continue`는 "다음!", `break`는 "끝!"이다.
</details>

**5. `for...of` 대신 고전 `for`를 써야 하는 경우를 하나 들어라.**

<details><summary>정답과 해설</summary>

앞뒤 요소를 비교할 때(`entries[i]`와 `entries[i - 1]`의 날짜 비교), 1부터 N까지 숫자 자체를 돌 때, 거꾸로 돌 때처럼 **인덱스나 횟수**가 필요한 경우. 단순히 "전부 한 번씩"이면 `for...of`가 낫다.
</details>
