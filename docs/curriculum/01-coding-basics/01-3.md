# 1-3. 조건문: if/else, 비교·논리 연산자, 참/거짓으로 취급되는 값

| 과정 | 1. 코딩의 기본 개념 (JavaScript로) |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 1-2 |
| 경험치 | 60 |

## 이 단원을 마치면

- `if / else if / else`로 "조건에 따라 다른 일을 하는" 코드를 읽고 쓸 수 있다.
- 비교 연산자(`===`, `!==`, `<`, `>`, `<=`, `>=`)와 논리 연산자(`&&`, `||`, `!`)를 조합해 매매 규칙 같은 조건을 표현할 수 있다.
- `==`와 `===`의 차이를 알고, 왜 항상 `===`를 쓰는지 설명할 수 있다.
- 참 같은 값(truthy)과 거짓 같은 값(falsy) 8가지를 외우고, `if (saved)` 같은 코드가 왜 동작하는지 안다.
- 가계부 앱에 "큰 지출 경고"와 "마이너스 잔액 빨간색" 기능을 조건문으로 직접 넣을 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

매매 규칙은 전부 조건문이다. "손절가에 닿으면 판다. 아니면 들고 간다." "거래량이 평균의 3배 이상**이고** 5일선 위**이면** 관심 종목에 넣는다." 당신은 이미 머릿속에서 수십 개의 `if`를 매일 돌리고 있다. 이 단원은 그걸 컴퓨터가 알아듣는 형태로 적는 법이다.

자동화의 핵심도 조건문이다. "잔액이 마이너스면 빨갛게", "10만 원 넘는 지출이면 한 번 더 묻기", "루틴을 7일 연속 달성하면 보상". 4과정에서 만들 알림 봇도 결국 "조건이 맞으면 텔레그램 보내기"다.

그리고 `==`와 `===`, 참 같은 값 같은 자바스크립트 특유의 함정은 클로드가 써 준 코드를 검토할 때 바로 눈에 띄어야 하는 부분이다. 이걸 모르면 "왜 `"0"`인데 참이지?" 같은 데서 몇 시간을 날린다.

## 핵심 개념

### 1. 조건문(if...else): 갈림길

**한 줄 정의.** `if` 문은 괄호 안의 조건이 참이면 중괄호 안의 코드를 실행하고, `else`가 있으면 거짓일 때 그쪽 코드를 실행한다. MDN: "`if` 문은 지정한 조건이 참인 경우 명령문을 실행합니다. 조건이 거짓인 경우 또 다른 명령문이 실행될 수 있습니다."

**비유.** 손절 규칙. "현재가가 손절가 이하**이면** 매도, **아니면** 보유."

**실제 예시.** `app.js`의 `calculateBalance()`.

```js
for (const entry of entries) {
  if (entry.type === "income") {
    balance = balance + entry.amount;   // 수입이면 더하고
  } else {
    balance = balance - entry.amount;   // 아니면(지출이면) 뺀다
  }
}
```

조건이 셋 이상이면 `else if`를 잇는다. MDN은 "JavaScript에서는 `elseif`(하나의 단어) 키워드가 존재하지 않는다"고 못 박는다. 띄어쓰기 필수다.

```js
function judge(buyPrice, currentPrice) {
  const rate = (currentPrice - buyPrice) / buyPrice * 100;
  if (rate <= -3) {
    return "손절";
  } else if (rate >= 5) {
    return "익절";
  } else {
    return "보유";
  }
}
```

위에서부터 검사해서 **처음으로 참이 되는 곳만** 실행하고 나머지는 건너뛴다(MDN: "처음으로 `true`로 평가되는 조건의 명령문들만 실행됩니다"). 그래서 조건의 **순서**가 결과를 바꾼다.

**중괄호는 항상.** 한 줄짜리 `if`는 중괄호를 생략할 수 있지만, MDN 안내서의 모범 사례는 "항상 블록문을 함께 사용하는 것"이다. 나중에 줄을 하나 추가했을 때 생기는 버그를 막는다. 우리 `app.js`도 전부 중괄호를 쓴다.

**왜 중요한가.** 프로그램의 "판단"은 전부 이 구조다. 복잡해 보이는 로직도 쪼개면 `if`의 중첩과 나열이다.

### 2. 비교 연산자: 조건을 만드는 재료

**한 줄 정의.** 비교 연산자(comparison operator)는 두 값을 비교해 불리언(`true`/`false`)을 돌려준다.

| 연산자 | 뜻 | 예 |
|---|---|---|
| `===` | 같다 (타입까지) | `entry.type === "income"` |
| `!==` | 다르다 | `entry.id !== id` (`deleteEntry`가 쓴다) |
| `<`, `>` | 작다, 크다 | `amount <= 0` |
| `<=`, `>=` | 이하, 이상 | `rate >= 5` |

**`==`와 `===`.** 자바스크립트에는 "같다"가 두 개다. MDN 일치 연산자 문서: "일치 연산자(`===`)는 두 피연산자의 타입이 다르면 동일하지 않다고 여깁니다." 반면 동등 연산자(`==`)는 "다른 타입의 피연산자들끼리의 비교를 시도"하며 비교 전에 타입을 바꾼다.

```js
"1" == 1;      // true   (문자열을 숫자로 바꿔서 비교)
"1" === 1;     // false  (타입이 다르니 끝)
0 == false;    // true
0 === false;   // false
null == undefined;   // true
null === undefined;  // false
```

**원칙: 항상 `===`와 `!==`를 쓴다.** `==`는 "알아서 바꿔 주는" 규칙이 복잡해서 예측이 어렵다. 1-2에서 배운 대로 경계에서 `Number()`로 타입을 맞춰 두면 `===`로 충분하다. 클로드가 `==`를 쓴 코드를 주면 `===`로 바꿔 달라고 하자.

**`NaN` 주의.** `NaN === NaN`은 `false`다(MDN: "피연산자 중 하나가 `NaN`라면 `false`를 반환합니다"). `Number.isNaN(x)`로 확인한다.

### 3. 논리 연산자: 조건 합치기

**한 줄 정의.** `&&`(그리고), `||`(또는), `!`(아니다)로 조건을 조합한다.

**비유.** 조건검색식의 "AND / OR / NOT".

**실제 예시.** `app.js` 7번 구역의 입력 검증.

```js
if (title === "" || amount <= 0) {
  return;   // 내용이 비었거나 금액이 이상하면 아무것도 안 한다
}
```

"제목이 비었다 **또는** 금액이 0 이하다 → 둘 중 하나라도 참이면 그만둔다."

```js
// 매수 조건: 거래량 3배 이상 그리고 5일선 위 그리고 이미 보유하지 않음
if (volumeRatio >= 3 && price > ma5 && !holding) {
  console.log("관심 종목 추가");
}
```

**단락 평가(short-circuit).** MDN 논리적 AND 문서: `&&`는 "왼쪽에서 오른쪽으로 평가할 때 처음으로 만나는 거짓 같은 피연산자의 값을 반환"하고, "모두 참 같은 값이라면 마지막 피연산자의 값을 반환"한다. 그리고 거짓을 만나면 "나머지 피연산자는 평가하지 않습니다". `||`는 반대로 처음 만나는 참 같은 값을 돌려준다. 이 성질 때문에 `&&`와 `||`의 결과가 꼭 `true`/`false`가 아닐 수 있다(`"" && "foo"`는 `""`). 지금은 "조건 안에서 쓰면 참/거짓처럼 동작한다"만 알면 된다.

**우선순위.** `!` > `&&` > `||`. 헷갈리면 괄호를 친다. `(a && b) || c`처럼 쓰면 읽는 사람도 편하다.

### 4. 참 같은 값(truthy)과 거짓 같은 값(falsy)

**한 줄 정의.** `if (값)`처럼 불리언이 필요한 자리에 불리언이 아닌 값을 넣으면, 자바스크립트가 그 값을 참 또는 거짓으로 **취급**한다. 거짓으로 취급되는 값이 거짓 같은 값(falsy), 나머지 전부가 참 같은 값(truthy)이다.

**거짓 같은 값 목록 (MDN 용어집).** `false`, `0`, `-0`, `0n`, `""`(빈 문자열), `null`, `undefined`, `NaN`. **이 여덟 개가 전부다.** 나머지는 모두 참이다.

**비유.** 호가창이 비어 있으면(`""`, `null`) "없음"으로, 뭐라도 적혀 있으면 "있음"으로 치는 것.

**실제 예시.** `app.js`의 `load()`.

```js
const saved = localStorage.getItem(STORAGE_KEY);   // 저장된 게 없으면 null
if (saved) {                                       // null → 거짓 → 건너뜀
  entries = JSON.parse(saved);
}
```

`saved === null`이라고 안 쓰고 `if (saved)`로 짧게 쓴 것이다. 빈 문자열이어도(저장은 됐는데 내용이 없는 이상한 경우) 건너뛰니 더 안전하기도 하다.

**함정 세 가지 (MDN 참 같은 값 문서의 예).** `"0"`은 참이다(비어 있지 않은 문자열). `"false"`도 참이다. `[]`(빈 배열)과 `{}`(빈 객체)도 참이다. "배열이 비었는지"는 `entries.length === 0`으로 확인해야 한다. `app.js`의 `render()`가 정확히 그렇게 쓴다.

**왜 중요한가.** `if (amount)`로 "금액이 입력됐나"를 검사하면 `0`도 걸러진다. 의도한 것인지 아닌지에 따라 버그가 된다. 명확히 하려면 `amount > 0`처럼 비교식을 쓴다.

### 5. 일찍 빠져나가기(early return)와 가드 절

**한 줄 정의.** 조건이 안 맞으면 함수 앞부분에서 `return`으로 바로 끝내는 패턴이다.

**실제 예시.** `app.js` 두 곳.

```js
// 폼 제출: 검증 실패면 바로 끝
if (title === "" || amount <= 0) {
  return;
}
addEntry(typeInput.value, title, amount);

// 지도의 방 버튼: 잠긴 방이면 알림만 띄우고 끝
if (roomBtn.classList.contains("locked")) {
  alert("아직 잠겨 있어요. 다음 단계에서 열립니다!");
  return;
}
```

`else`로 감싸는 대신 "안 되는 경우를 먼저 쳐내면" 아래 코드가 들여쓰기 없이 평평해져 읽기 쉽다. 클로드가 쓰는 코드에도 매우 자주 나온다.

### 6. 삼항 연산자(조건 ? 값1 : 값2)

**한 줄 정의.** 조건이 참이면 `값1`, 거짓이면 `값2`를 돌려주는 한 줄짜리 `if/else`다.

```js
const sign = entry.type === "income" ? "+" : "-";
const label = profit > 0 ? "익절" : "손절";
```

값 하나를 고를 때만 쓴다. 조건 안에서 여러 줄을 실행해야 하면 `if/else`가 낫다. 중첩 삼항은 읽기 어려우니 피한다.

재무부에서 (1) 내용을 비우고 추가, (2) 금액에 `0` 입력 후 추가, (3) 금액에 `-500` 입력 후 추가. 세 경우 모두 아무 일도 안 일어난다. `app.js`의 `if (title === "" || amount <= 0) return;`이 막은 것이다. (HTML의 `required`, `min="1"` 속성이 브라우저 차원에서 먼저 막을 수도 있다. 둘 다 있는 이유는 2과정에서 다룬다.)

```js
if (title === "" || amount <= 0) {

}
```

저장, 새로고침, 다시 시도. 알림이 뜨면 성공.

### 실습 3. 큰 지출 경고 (20분)

`app.js` 7번 구역, 검증 바로 아래에 추가한다.

```js
if (typeInput.value === "expense" && amount >= 100000) {
  const ok = confirm("10만 원 이상 지출입니다. 기록할까요?");
  if (!ok) {
    return;   // "취소"를 누르면 기록하지 않는다

```

지출 150000원을 넣어 보자. 확인 창이 뜨고, 취소하면 기록되지 않는다. 수입 150000원은 묻지 않는다(`&&`의 첫 조건이 거짓이라 뒤는 보지도 않는다). `confirm()`은 확인/취소 창을 띄우고 불리언을 돌려주는 브라우저 기능이다.

### 실습 4. 마이너스 잔액은 빨간색 (15분)

`render()` 안의 잔액 줄을 이렇게 바꾼다.

```js
const balance = calculateBalance();
balanceText.textContent = formatMoney(balance);
if (balance < 0) {
  balanceText.style.color = "#d63b3b";
} else {
  balanceText.style.color = "";      // 원래 색으로
}
```

지출을 잔액보다 많이 넣어 마이너스로 만들면 빨개진다. 수입을 넣어 플러스로 돌리면 원래 색으로 돌아온다. **데이터가 바뀔 때마다 `render()`가 다시 그리므로** 조건을 `render()` 안에 두면 항상 최신 상태가 반영된다. (`else` 쪽이 없으면 한 번 빨개진 뒤 안 돌아온다. 지워 보고 확인하자.)

### 실습 5. 매매 판단기 (25분)

`study` 폴더에 `judge.js`.

```js
const buyPrice = 52000;
const currentPrice = 50200;
const holdingDays = 4;

const rate = (currentPrice - buyPrice) / buyPrice * 100;
let action;

if (rate <= -3) {
  action = "손절";
} else if (rate >= 5) {
  action = "익절";
} else if (holdingDays >= 3 && rate < 1) {
  action = "시간 손절 (3일 넘게 안 움직임)";
} else {
  action = "보유";
}

console.log(`수익률 ${rate.toFixed(2)}% → ${action}`);
```

`node judge.js`로 실행(Windows PowerShell, Mac 동일). `currentPrice`와 `holdingDays`를 바꿔 가며 네 갈래가 전부 나오게 만들어 본다. 그다음 `else if` 두 개의 순서를 바꾸면 결과가 달라지는 경우를 찾아본다. 규칙의 **우선순위**가 코드의 **순서**라는 걸 체감하는 게 목표다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `if (type = "income")`이 항상 참 | `=`(할당)을 `==`/`===`(비교) 자리에 씀 | 비교는 `===`. MDN도 조건에서 할당은 지양하라고 적는다 |
| `"1" == 1`이 참이라 엉뚱한 분기로 감 | `==`의 자동 타입 변환 | 항상 `===`, 경계에서 `Number()` |
| `else if`를 `elseif`로 씀 | 그런 키워드 없음 | 띄어 쓴다 |
| `if (amount)`가 금액 0을 걸러 버림 | `0`은 거짓 같은 값 | 의도를 분명히: `amount > 0` 또는 `amount !== undefined` |
| `if (entries)`가 빈 배열도 참 | `[]`는 참 같은 값 | `entries.length === 0`으로 검사 |
| 한 줄 `if`에 줄을 추가했더니 항상 실행됨 | 중괄호 생략 | 항상 `{ }`를 쓴다 |
| `NaN`을 `=== NaN`으로 못 잡음 | `NaN`은 자신과 다름 | `Number.isNaN(값)` |
| 조건이 복잡해져 읽기 어려움 | `&&`, `||` 뒤섞임 | 괄호로 묶고, 조건에 이름을 붙인다: `const isBigExpense = ...` |

**2. `"0" == 0`, `"0" === 0`, `Boolean("0")`의 결과는?**

<details><summary>정답과 해설</summary>

`true`, `false`, `true`. `==`는 문자열을 숫자로 바꿔 비교하고, `===`는 타입이 다르면 바로 거짓이다. `"0"`은 비어 있지 않은 문자열이라 참 같은 값이다. 세 개가 서로 다른 질문이라는 걸 구별하는 게 핵심이다.
</details>

**3. 거짓 같은 값 여덟 개를 적어라.**

<details><summary>정답과 해설</summary>

`false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`. 이 외의 모든 값(`"0"`, `"false"`, `[]`, `{}` 포함)은 참 같은 값이다.
</details>

**4. 다음 코드에서 `rate`가 `-5`일 때 결과는? 두 조건의 순서를 바꾸면?**

```js
if (rate <= -3) { action = "손절"; }
else if (rate <= -1) { action = "경고"; }
```

<details><summary>정답과 해설</summary>

`"손절"`. 순서를 바꿔 `rate <= -1`을 먼저 검사하면 `-5`도 그 조건에 걸려 `"경고"`가 되고 손절 분기에는 영원히 도달하지 못한다. `else if`는 처음 참인 곳만 실행하므로 **좁은(강한) 조건을 먼저** 둔다.
</details>

**5. `if (typeInput.value === "expense" && amount >= 100000)`에서 수입 150000원을 넣으면 `amount >= 100000`은 평가되는가?**

<details><summary>정답과 해설</summary>

평가되지 않는다. `&&`는 첫 피연산자가 거짓이면 즉시 그 값을 돌려주고 나머지는 보지 않는다(단락 평가). 이 성질은 `obj && obj.name`처럼 "있을 때만 접근"하는 코드에도 쓰인다.
</details>

## 숙제

1. **카테고리 색.** `render()`에서 `entry.title`에 "커피"나 "배달"이 들어 있으면(`entry.title.includes("커피")`) 제목 옆에 "☕" 또는 "🛵"를 붙여 보자. `if / else if`로. 힌트: `title.textContent = "☕ " + entry.title;`

3. **매매 판단기 확장.** `judge.js`에 "장 마감 10분 전(`minutesToClose <= 10`)이고 수익 중(`rate > 0`)이면 익절"이라는 규칙을 추가한다. 기존 규칙과의 우선순위를 정해 `else if` 순서를 결정하고, 이유를 주석으로 적는다. 완성본을 클로드에게 보여주고 "조건의 순서에 논리적 구멍이 있는지 봐 줘"라고 요청한다.
4. **`==` 사냥.** 클로드에게 "자바스크립트 가계부 예제 코드 30줄 써 줘"라고 요청한 뒤, 받은 코드에서 `==`, `var`, 중괄호 없는 `if`를 찾아 `===`, `const/let`, 중괄호로 고쳐 본다. 못 찾았다면 그 자체로 통과.
