# 1-1. 프로그램이란: 입력→처리→출력, 코드가 위에서 아래로 실행되는 순서, 브라우저 콘솔 사용법

| 과정 | 1. 코딩의 기본 개념 (JavaScript로) |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 0-4 |
| 경험치 | 60 |

## 이 단원을 마치면

- "프로그램"이 무엇인지 **입력 → 처리 → 출력** 세 단어로 설명할 수 있다.
- 코드가 **위에서 아래로, 한 줄씩** 실행된다는 것을 알고, 순서를 바꾸면 왜 망가지는지 설명할 수 있다.
- 브라우저의 **콘솔(Console)** 을 열어서 계산을 해 보고, 우리 가계부 앱의 함수를 직접 불러 볼 수 있다.
- `console.log()`로 "지금 이 값이 뭔지" 찍어 보는 습관의 첫걸음을 뗀다.
- 터미널에서 `node`로 자바스크립트 파일 하나를 실행해 본다.

## 왜 배우나 (나에게 어떤 쓸모)

지금까지(0과정) 컴퓨터와 터미널, 도구 설치를 끝냈다. 이제부터는 "코드를 읽고 쓰는" 본격적인 단계다. 그런데 첫 단원에서 문법부터 외우는 건 비효율적이다. 먼저 **프로그램이 돌아가는 모양**을 몸으로 느끼는 게 먼저다.

트레이더인 당신은 이미 "프로그램적 사고"를 매일 하고 있다. HTS의 조건검색식을 떠올려 보자. "거래량이 전일 대비 300% 이상이고, 5일선 위에 있는 종목을 찾아라." 이건 **입력**(전 종목 시세) → **처리**(조건 비교) → **출력**(종목 리스트)이다. 매매 복기도 마찬가지다. 체결 내역(입력) → 손익 계산(처리) → 오늘의 성적표(출력). 코딩은 이 흐름을 컴퓨터가 알아듣는 말로 적는 일이다.

## 핵심 개념

### 1. 프로그램(program) = 입력 → 처리 → 출력

**한 줄 정의.** 프로그램(program)은 "어떤 입력(input)을 받아서, 정해진 규칙대로 처리(process)하고, 결과를 출력(output)하는 명령의 묶음"이다.

**비유.** 가계부 앱을 떠올리자. 당신이 "점심 / 9000원 / 지출"을 입력하고 추가 버튼을 누른다(입력). 앱은 내역을 목록에 넣고 잔액을 다시 계산한다(처리). 화면 위 카드에 바뀐 잔액이 뜬다(출력). 주식으로 치면, 입력은 호가창과 체결 데이터, 처리는 내 매매 규칙, 출력은 주문이다.

**실제 예시.** 우리 앱의 `app.js` 7번 구역이 정확히 이 모양이다.

```js
// 입력: 입력칸에서 값을 꺼낸다
const title = titleInput.value.trim();
const amount = Number(amountInput.value);

// 처리: 내역을 추가하고 저장한다 (addEntry 안에서 잔액도 다시 계산한다)
addEntry(typeInput.value, categoryInput.value, title, amount);

// 출력: render()가 화면을 다시 그린다 (addEntry 안에서 호출됨)
```

**왜 중요한가.** 앞으로 어떤 기능을 만들든 "입력이 뭐고, 처리가 뭐고, 출력이 뭐지?"라고 쪼개면 설계가 끝난다. 클로드에게 요청할 때도 이 세 가지를 적어 주면 결과가 훨씬 정확해진다. 예: "입력은 체결 내역 CSV, 처리는 종목별 손익 합계, 출력은 표."

### 2. 코드는 위에서 아래로, 한 줄씩 실행된다

**한 줄 정의.** 자바스크립트는 파일의 맨 위부터 아래로, 한 명령문(statement)씩 순서대로 실행한다.

**비유.** 라면 레시피를 생각하자. "물을 끓인다 → 면을 넣는다 → 스프를 넣는다." 순서를 바꿔서 면부터 넣고 물을 부으면 결과가 달라진다. 코드도 똑같다. 컴퓨터는 융통성이 없어서, 적힌 순서 그대로만 한다.

**실제 예시.** `app.js`의 맨 아래 8번 구역을 보자.

```js
// ---------- 8. 시작 ----------
// 페이지가 열리면 지도를 만들고, 저장된 내역을 불러와서 화면에 그린다. (지도 만들기와 다른 부서의 불러오기 줄은 생략했다. 실제 파일에는 load()와 render() 사이에 routineLoad() 등 네 줄이 더 있다)
load();
render();
```

`load()`가 먼저 실행되어 저장된 내역을 `entries`에 채우고, 그다음 `render()`가 그 내역으로 화면을 그린다. 이 두 줄의 순서를 바꾸면 어떻게 될까? `render()`가 먼저 실행되는 시점에는 `entries`가 아직 빈 배열이라 "아직 내역이 없어요"가 뜨고, 그다음 `load()`가 데이터를 채우지만 화면은 다시 그리지 않는다. 데이터는 있는데 화면은 비어 있는 상태가 된다. (따라하기에서 직접 해 본다.)

**예외가 하나 있다.** "함수(function)"는 정의해 두는 것과 실행하는 것이 다르다. `function render() { ... }`라고 적어 둔 부분은 정의일 뿐, 그 자리에서 실행되지 않는다. 누군가 `render()`라고 **불러야** 실행된다. 그래서 `app.js`에서 함수 정의들은 위에 모여 있고, 실제로 일을 시작시키는 `load(); render();`는 맨 아래에 있다. 함수는 1-5에서 자세히 다룬다. 지금은 "정의는 미리, 실행은 부를 때"만 기억하자.

**왜 중요한가.** 초보자가 겪는 에러의 상당수가 "순서" 문제다. 아직 만들어지지 않은 변수를 쓰거나, HTML 요소가 생기기 전에 자바스크립트가 그 요소를 찾는 경우다. 에러를 보면 먼저 "이 줄이 실행되는 시점에, 이게 존재하나?"를 묻자.

### 3. 프로그래밍 언어와 자바스크립트(JavaScript)

**한 줄 정의.** 프로그래밍 언어(programming language)는 사람이 쓰고 컴퓨터가 실행할 수 있게 약속된 글쓰기 규칙이고, 자바스크립트(JavaScript)는 그중 **웹 브라우저가 직접 이해하는 언어**다.

**비유.** 한국어, 영어처럼 언어마다 문법이 다르지만 "주어, 동사, 목적어"라는 뼈대는 비슷하다. 프로그래밍 언어도 수십 가지가 있지만, 변수·조건·반복·함수라는 뼈대는 거의 같다. 이 과정에서 자바스크립트로 배운 사고방식은 3과정의 파이썬(Python)에서 그대로 쓰인다.

**실제 예시.** MDN은 웹을 세 층짜리 케이크에 비유한다. HTML은 내용의 구조(제목, 입력칸, 버튼), CSS는 모양(색, 크기), 자바스크립트는 동작(버튼을 누르면 무슨 일이 일어나는지). 우리 앱의 `index.html`, `style.css`, `app.js`가 정확히 이 세 층이다(0-1과 이 저장소의 `docs/lesson-01.md`에서 본 "뼈대 / 인테리어 / 전기 배선" 비유와 같다).

**왜 자바스크립트부터인가.** 설치가 필요 없다. 브라우저만 있으면 지금 당장 실행된다. 결과가 화면에 바로 보인다. 그리고 당신이 만들 가계부·루틴·리포트 앱이 전부 브라우저에서 돌아간다. 자동화 스크립트는 나중에 파이썬으로 쓰겠지만, 처음 배우기엔 "즉시 눈에 보이는" 자바스크립트가 가장 덜 답답하다.

### 4. 명령문, 세미콜론, 주석, 대소문자

**한 줄 정의.** 명령문(statement)은 컴퓨터에게 내리는 한 개의 명령이고, 보통 한 줄에 하나씩 쓰며 끝에 세미콜론(`;`)을 붙인다.

**비유.** 명령문은 문장이고, 세미콜론은 마침표다. 한 줄에 한 문장만 쓰면 마침표를 생략해도 자바스크립트가 알아서 끊어 주지만(MDN 문법 문서의 "자동 세미콜론 삽입"), 버그 예방 차원에서 항상 붙이는 습관이 좋다고 MDN도 권한다. 우리 `app.js`도 전부 붙여 두었다.

**주석(comment)** 은 컴퓨터가 무시하는 메모다. `//` 뒤의 내용은 그 줄 끝까지 주석, `/* ... */` 사이는 여러 줄 주석이다. `app.js`에 한글로 적힌 설명이 전부 주석이다. 주석은 "미래의 나"와 "클로드"를 위한 것이다. 코드를 왜 이렇게 썼는지 적어 두면, 석 달 뒤에 고칠 때 시간이 반으로 준다.

```js
// 한 줄 주석: 기록 한 건 = 10 경험치
const XP_PER_ENTRY = 10;

/* 여러 줄 주석:
   100 경험치마다 레벨이 하나 오른다 */
const XP_PER_LEVEL = 100;
```

**대소문자.** 자바스크립트는 대소문자를 구별한다. `render`와 `Render`는 완전히 다른 이름이다. `console.log`를 `Console.log`로 치면 에러다. 이게 초보자 에러 1순위다.

**왜 중요한가.** 문법 오류는 가장 흔하고 가장 쉽게 고치는 에러다. "한 줄에 한 명령, 끝에 세미콜론, 대소문자 정확히"만 지켜도 절반은 피한다.

### 5. 브라우저 콘솔(Console): 자바스크립트와 대화하는 창

**한 줄 정의.** 콘솔(Console)은 브라우저 개발자 도구(Developer Tools) 안에 있는 창으로, 자바스크립트 한 줄을 입력하면 즉시 실행하고 결과를 보여주며, 페이지에서 난 에러도 여기에 표시된다.

**비유.** 계산기 겸 대화창이다. 계산기처럼 `1 + 1`을 치면 `2`가 나오고, 대화창처럼 "지금 잔액 얼마야?"라고 물으면(함수를 부르면) 답을 준다. HTS로 치면 "주문 창 옆에 붙어 있는 수식 테스트 창"이다.

**여는 법 (MDN 개발자 도구 문서 기준).**

| 방법 | Windows | Mac |
|---|---|---|
| 키보드 | `Ctrl` + `Shift` + `I` 또는 `F12` | `⌘` + `⌥(Option)` + `I` |
| 마우스 | 페이지에서 오른쪽 클릭 → **검사(Inspect)** | `Ctrl`+클릭 → **검사(Inspect)** |

개발자 도구가 열리면 위쪽 탭 중 **Console** 을 누른다. (크롬 기준. Safari는 기본으로 꺼져 있어서 설정에서 개발자 메뉴를 켜야 한다. 이 과정은 크롬을 기준으로 한다.)

**콘솔에서 할 수 있는 세 가지.**

1. **계산하기.** `1234 * 3` 처럼 치고 Enter.
2. **값 확인하기.** 페이지의 변수 이름을 치면 현재 값이 보인다. 우리 앱에서 `entries`를 치면 저장된 내역 배열이 펼쳐진다.
3. **함수 부르기.** `calculateBalance()`를 치면 잔액 숫자가 나온다. `addEntry("expense", "food", "콘솔 테스트", 1000)`을 치면 실제로 내역이 추가되고 화면이 바뀐다(두 번째 인수 `"food"`는 카테고리 값으로, `index.html`의 `#entry-category` 옵션 중 하나다).

**`console.log()`.** 코드 안에서 "이 값을 콘솔에 출력해라"라고 시키는 명령이다. MDN은 이렇게 정의한다. "`console.log()` 정적 메서드는 메시지를 콘솔에 출력합니다." 괄호 안에 여러 값을 쉼표로 나열하면 한 줄에 나란히 찍힌다.

```js
console.log("잔액:", calculateBalance());
console.log("내역 수:", entries.length);
```

이 한 줄이 앞으로 당신의 디버깅 도구 1호다. "이 시점에 이 변수에 뭐가 들어 있지?"가 궁금할 때마다 찍는다. (1-7에서 더 깊이 다룬다.)

**왜 중요한가.** 콘솔은 "안전한 실험실"이다. 파일을 고치지 않고도 함수를 불러 보고, 값을 확인하고, 에러를 읽을 수 있다. 그리고 클로드에게 질문할 때 콘솔의 빨간 에러 메시지를 그대로 복사해 주면, 답의 정확도가 급격히 올라간다.

### 실습 1. 콘솔 열고 계산기로 쓰기 (10분)

1. 탐색기(Windows) 또는 Finder(Mac)에서 `index.html`을 더블클릭해 크롬으로 연다.
2. `F12`(Windows) 또는 `⌘ + ⌥ + I`(Mac)를 누른다. 아래나 옆에 개발자 도구가 열린다.
3. 위쪽 탭에서 **Console** 을 누른다.
4. 다음을 한 줄씩 치고 Enter를 친다.

```js
1 + 1
3000 * 22
"안녕"
"점심" + " 9000원"
```

관찰: 숫자 계산은 숫자가, 따옴표로 감싼 글자(문자열)는 글자가 나온다. `"점심" + " 9000원"`처럼 문자열을 `+`로 이으면 붙어서 `"점심 9000원"`이 된다. (1-2에서 자세히.)

### 실습 2. 우리 앱의 속을 들여다보기 (15분)

콘솔은 지금 열려 있는 페이지의 자바스크립트에 접근할 수 있다. `app.js`가 만든 변수와 함수를 직접 불러 보자.

```js
entries
entries.length
calculateBalance()
formatMoney(1234567)
```

- `entries`: 저장된 내역 배열이 펼쳐진다. 아직 아무것도 안 넣었으면 `[]`(빈 배열)이다. 왼쪽 삼각형 ▶ 을 누르면 안을 펼쳐 볼 수 있다.
- `entries.length`: 내역 개수. 
- `calculateBalance()`: 잔액 숫자. 괄호 `()`가 "실행해라"는 뜻이다. 괄호 없이 `calculateBalance`만 치면 함수 자체(코드 본문)가 보인다. 이 차이를 꼭 한 번 눈으로 확인하자.
- `formatMoney(1234567)`: `"1,234,567원"`. 괄호 안 숫자가 **입력**, 돌아온 문자열이 **출력**이다.

### 실습 3. 콘솔에서 앱을 조작하기 (15분)

```js
addEntry("expense", "food", "콘솔에서 넣은 점심", 9000)
```

Enter를 치는 순간 화면의 목록에 내역이 추가되고, 잔액이 바뀌고, "+10 EXP" 팝업이 뜬다. 버튼을 누른 게 아니라 **함수를 직접 부른** 것이다. 버튼은 결국 이 함수를 대신 불러 주는 장치일 뿐이라는 걸 체감하자.

지우려면 `entries[entries.length - 1]`로 마지막 내역의 `id`를 확인한 뒤 `deleteEntry(그 id)`를 치면 된다. 버튼을 한 번도 안 누르고 가계부를 조작한 것이다.

### 실습 4. 실행 순서를 망가뜨려 보기 (20분)

이제 "위에서 아래로"를 눈으로 확인한다. 먼저 내역을 두세 건 넣어 둔다(화면에서 추가 버튼으로).

1. VS Code로 `app.js`를 연다.
2. 맨 아래 8번 구역에서 `render();` 줄을 잘라내어 `load();` 줄 바로 위에 붙인다(두 줄 사이에 `routineLoad();` 같은 다른 부서의 불러오기 줄이 있으니 `render();` 한 줄만 옮긴다).

```js
// 바꾸기 전
load();
render();

// 바꾼 후 (일부러 틀리게)
render();
load();
```

3. 저장(`Ctrl+S` / `⌘+S`)하고 브라우저를 새로고침(`F5` / `⌘+R`)한다. 재무부에 들어가 보자.
4. 관찰: 목록에 "아직 내역이 없어요"가 뜬다. 그런데 콘솔에서 `entries`를 치면 데이터가 들어 있다. 데이터는 불러왔지만(`load`), 그 **전에** 화면을 그려 버려서(`render`) 빈 화면이 남은 것이다.
5. 콘솔에서 `render()`를 직접 치면? 내역이 나타난다. 순서만 문제였다는 증거다.
6. 다시 원래 순서로 돌려놓고 저장, 새로고침. 정상으로 돌아온다.

### 실습 5. 터미널에서 자바스크립트 파일 실행하기 (20분)

브라우저 없이도 자바스크립트를 돌릴 수 있다. 0-3에서 설치한 Node.js가 그 역할을 한다. 공부용 폴더를 만들고, 파일 하나를 만들어 실행해 보자.

**Windows (PowerShell)**

```powershell
cd ~
mkdir study
cd study
code hello.js
```

**Mac (터미널)**

```bash
cd ~
mkdir study
cd study
code hello.js
```

(`code` 명령이 없다고 나오면 VS Code에서 직접 `study` 폴더를 열고 새 파일 `hello.js`를 만들면 된다.)

`hello.js`에 다음을 적고 저장한다.

```js
// 입력
const 매수가 = 52000;
const 매도가 = 53500;
const 수량 = 10;

// 처리
const 손익 = (매도가 - 매수가) * 수량;

// 출력
console.log("손익:", 손익, "원");
```

터미널에서 실행한다(Windows, Mac 동일).

```bash
node hello.js
```

`손익: 15000 원`이 출력되면 성공이다. Node.js 공식 문서의 `console.log()` 설명처럼, 터미널(표준 출력)에 줄바꿈과 함께 찍힌다. 브라우저 콘솔에서 본 것과 같은 `console.log`가 터미널에서도 똑같이 동작한다.

이제 세 줄의 순서를 바꿔 보자. `console.log` 줄을 맨 위로 올리고 다시 `node hello.js`를 치면 에러가 난다. 아직 만들어지지 않은 `손익`을 쓰려 했기 때문이다. 에러 문구를 읽어 보고(1-7에서 읽는 법을 배운다) 원래대로 돌려놓자.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 콘솔에 `Uncaught ReferenceError: Console is not defined` | 대소문자. `console`은 전부 소문자 | `console.log`로 고친다 |
| `Uncaught SyntaxError: Invalid or unexpected token` | 따옴표를 안 닫았거나 괄호 짝이 안 맞음 | 따옴표·괄호 짝을 센다. VS Code는 짝을 색으로 보여준다 |
| 콘솔에 `entries`를 쳤는데 `ReferenceError: entries is not defined` | `index.html`이 아니라 다른 탭(예: 구글)에서 콘솔을 열었다 | 우리 앱 탭에서 콘솔을 연다 |
| `app.js`를 고쳤는데 아무 변화가 없다 | 저장을 안 했거나 새로고침을 안 했다 | 저장(`Ctrl+S`) → 새로고침(`F5`). 그래도 안 되면 `Ctrl+Shift+R`(강력 새로고침) |
| `console.log("안녕")` 밑에 `undefined`가 뜬다 | 정상. `console.log`는 돌려주는 값이 없다 | 무시해도 된다 |

**습관 하나.** 뭔가 안 되면 콘솔부터 본다. 빨간 글씨가 있으면 첫 줄을 그대로 복사한다. 그 문구로 검색하거나 클로드에게 "이 에러가 떴어요: (붙여넣기). `app.js` 8번 구역을 고친 직후예요"라고 물으면 된다. **무엇을 고친 직후인지**를 같이 말하는 게 핵심이다.

## 확인 퀴즈

**1. 가계부 앱에서 "추가" 버튼을 눌렀을 때, 입력·처리·출력은 각각 무엇인가?**

<details><summary>정답과 해설</summary>

입력: 입력칸의 종류·내용·금액. 처리: `addEntry()`가 내역 객체를 만들어 `entries`에 넣고 `save()`로 저장하며 `calculateBalance()`로 잔액을 다시 계산하는 것. 출력: `render()`가 목록과 잔액을 화면에 다시 그리는 것. 어떤 기능이든 이 세 조각으로 쪼개서 설명할 수 있어야 한다.
</details>

**2. `app.js` 맨 아래의 `load(); render();`를 `render(); load();`로 바꾸면 어떤 일이 생기는가? 왜?**

<details><summary>정답과 해설</summary>

화면에 "아직 내역이 없어요"가 뜨지만 콘솔에서 `entries`를 보면 데이터는 있다. 코드는 위에서 아래로 실행되므로 `render()`가 먼저 빈 `entries`로 화면을 그리고, 그다음 `load()`가 데이터를 채우지만 화면을 다시 그리는 코드는 없기 때문이다.
</details>

**3. 콘솔에서 `calculateBalance`와 `calculateBalance()`의 차이는?**

<details><summary>정답과 해설</summary>

괄호 없이 치면 함수 자체(코드 본문)가 보이고, 괄호를 붙이면 함수를 **실행**해서 결과(잔액 숫자)가 나온다. 괄호가 "실행해라"는 신호다.
</details>

**4. 콘솔에 `console.log("안녕")`을 쳤더니 "안녕" 아래에 `undefined`가 떴다. 에러인가?**

<details><summary>정답과 해설</summary>

에러가 아니다. 콘솔은 입력한 명령의 결과값을 항상 표시하는데, `console.log`는 출력만 하고 돌려주는 값이 없어서(반환 값 `undefined`) 그렇게 보이는 것이다. `1 + 1`처럼 결과값이 있는 식은 그 값이 보인다.
</details>

**5. 다음 코드를 `node`로 실행하면 어떤 문제가 생기는가?**

```js
console.log("손익:", 손익);
const 손익 = 15000;
```

<details><summary>정답과 해설</summary>

에러가 난다. 1번째 줄이 실행되는 시점에 `손익`은 아직 만들어지지 않았기 때문이다(`const`로 선언한 변수는 선언 줄에 도달하기 전에는 쓸 수 없다. MDN은 이 구간을 "temporal dead zone"이라고 부른다). 선언을 위로 올리면 해결된다. "이 줄이 실행될 때 이게 존재하나?"를 묻는 습관이 순서 에러를 막는다.
</details>
