| 예상 시간 | 3시간 |

## 이 단원을 마치면

- 변수(variable)가 "이름 붙인 상자"라는 것을 알고, `const`와 `let`을 상황에 맞게 고를 수 있다.
- 기본 자료형(숫자, 문자열, 불리언, `undefined`, `null`)을 구별하고 `typeof`로 확인할 수 있다.
- `"9000"`(문자열)과 `9000`(숫자)이 다르다는 것을 알고, 입력칸에서 온 값을 `Number()`로 바꿔야 하는 이유를 설명할 수 있다.
- `app.js`에서 `const`와 `let`이 각각 어디에 쓰였는지 찾고 이유를 말할 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

매매 복기를 엑셀로 해 봤다면 "셀"을 안다. A1에 매수가, B1에 매도가를 넣고 C1에 `=B1-A1`을 쓴다. 변수는 그 셀에 **이름**을 붙인 것이다. `매수가`, `매도가`, `손익`. 이름이 있으니 코드가 읽히고, 값이 바뀌어도 수식은 그대로다.

자료형은 "셀에 든 게 숫자냐 글자냐"다. 엑셀에서 숫자가 글자로 인식되어 합계가 0이 나오는 황당한 경험, 한 번쯤 있을 것이다. 코딩에서는 이게 훨씬 자주, 더 조용히 터진다. 우리 가계부 앱의 `Number(amountInput.value)` 한 줄은 정확히 그 사고를 막는 장치다. 이 단원을 끝내면 그 한 줄이 왜 거기 있는지 알게 되고, 클로드가 써 준 코드의 `const`, `let`, 따옴표, `null`이 더는 눈에 걸리지 않는다.

## 핵심 개념

### 1. 변수(variable): 값에 붙인 이름표

**한 줄 정의.** 변수(variable)는 값을 담아 두고 이름으로 꺼내 쓰는 저장 공간이다.

**비유.** 증권 계좌에 "단타용", "장기용" 별칭을 붙이면 계좌번호를 외울 필요가 없다. `52000` 대신 `매수가`라고 부르면, 값이 바뀌어도 그 이름을 쓰는 코드는 안 고쳐도 된다.

**실제 예시.** `app.js` 맨 위.

```js
let entries = [];                      // 내역 전체를 담을 상자 (나중에 내용이 바뀐다)
const STORAGE_KEY = "ledger-entries";  // localStorage에 쓸 이름표 (절대 안 바뀐다)
```

변수를 만드는 것이 **선언(declaration)**, 값을 넣는 것이 **할당(assignment)** 이다. `=`는 "같다"가 아니라 "오른쪽 값을 왼쪽 이름에 넣어라"다. 그래서 `balance = balance + entry.amount`가 말이 된다. "지금 잔액에 금액을 더해서 다시 잔액에 넣어라."

**왜 중요한가.** 좋은 이름은 주석보다 낫다. `a`, `tmp` 대신 `buyPrice`, `profit`이라고 쓰면 석 달 뒤의 당신도, 클로드도 코드를 바로 이해한다.

### 2. `const`와 `let`: 안 바뀌는 상자, 바뀌는 상자

**한 줄 정의.** `const`는 한 번 넣으면 다른 값을 다시 넣을 수 없는 변수, `let`은 다시 넣을 수 있는 변수다.

**비유.** `const`는 계좌번호, `let`은 잔고.

**실제 예시.** `app.js`에서 찾아보자.

```js
// const: 설정값, 화면 요소, 한 번 만들고 안 바꾸는 것
const XP_PER_ENTRY = 10;
const form = document.getElementById("entry-form");

// let: 누적하거나 통째로 교체하는 것
let entries = [];     // deleteEntry에서 entries = entries.filter(...) 로 통째로 바뀐다
let balance = 0;      // calculateBalance 안에서 더하고 빼며 바뀐다
```

MDN `const` 문서: "`const` 선언은 블록 범위의 상수를 선언합니다. 상수의 값은 재할당할 수 없으며 다시 선언할 수도 없습니다." 선언할 때 반드시 값을 같이 넣어야 한다(`const FOO;`는 에러).

**중요한 함정.** `const`는 "상자를 다른 상자로 못 바꾼다"는 뜻이지 "상자 안 내용물을 못 건드린다"가 아니다. MDN 그대로: "오브젝트의 키는 보호되지 않습니다", "배열에 아이템을 삽입하는 건 가능합니다".

```js
const list = [];
list.push("점심");     // 괜찮다. 상자 안에 넣은 것
list = ["저녁"];        // TypeError. 상자 자체를 바꾸려 한 것
```

그래서 `entries = entries.filter(...)`처럼 배열을 **새것으로 교체**하는 `entries`는 `let`이어야 한다.

**고르는 기준.** 일단 전부 `const`로 쓰고, 다시 할당해야 해서 에러가 나면 그때 `let`으로 바꾼다. 바뀌면 안 되는 값이 실수로 바뀌는 사고를 자바스크립트가 대신 막아 준다. `let`과 `const`는 자신이 선언된 중괄호 `{ }` 안에서만 보인다(블록 범위). 1-5에서 자세히 본다.

### 3. 자료형(data type): 값의 종류

**한 줄 정의.** 자료형(data type)은 값이 어떤 종류인지(숫자, 글자, 참/거짓 등)를 말한다.

**비유.** 지갑 속 현금, 달러, 카드 포인트. 다 "돈"이지만 그냥 더할 수 없다. 자료형이 다르면 섞어 계산할 때 사고가 난다.

**실제 예시.** MDN "JavaScript의 타입과 자료구조"는 원시 자료형 7가지와 객체(Object)를 설명한다. 초보 단계에서 매일 쓰는 건 다섯 가지다.

| 자료형 | 예 | `typeof` 결과 | 우리 앱에서 |
|---|---|---|---|
| 숫자(Number) | `9000`, `3.14`, `-500` | `"number"` | `amount`, `balance` |
| 문자열(String) | `"점심"`, `'income'` | `"string"` | `title`, `type`, `date` |
| 불리언(Boolean) | `true`, `false` | `"boolean"` | `entry.type === "income"`의 결과 |
| undefined | 값을 안 넣은 변수 | `"undefined"` | `let x;` 직후의 `x` |
| null | 의도적으로 "없음" | `"object"` (역사적 오류) | `localStorage.getItem()`이 저장된 게 없을 때 |

**`typeof`.** 값의 자료형을 문자열로 알려 주는 연산자다. 콘솔에서 `typeof 9000`, `typeof "9000"`을 쳐 보면 `"number"`, `"string"`이 나온다. 

**왜 중요한가.** 자바스크립트는 **동적 타입** 언어다. MDN: "변수를 선언할 때 데이터 형을 지정할 필요가 없음을 의미합니다. 또한 데이터 형이 스크립트 실행 도중 필요에 의해 자동으로 변환됨을 뜻합니다." 편하지만 이 "자동 변환"이 조용한 버그의 주범이다.

### 4. 숫자(Number)

**한 줄 정의.** 숫자(Number)는 정수와 소수를 구분 없이 한 종류로 다루는 자료형이다.

**실제 예시.**

```js
const 손익 = (53500 - 52000) * 10;          // 15000
const 수익률 = (53500 - 52000) / 52000 * 100;  // 2.8846...
console.log(수익률.toFixed(2));              // "2.88" (소수 둘째 자리까지의 문자열)

const level = Math.floor(xp / XP_PER_LEVEL) + 1;  // app.js: 나눗셈 몫을 내림
const xpInLevel = xp % XP_PER_LEVEL;              // 나머지
```

MDN `Number` 문서의 사실 몇 가지.

- `37`과 `37.0`은 같은 숫자다. 정수형이 따로 없다.
- `Number("123")` → `123`. 바꿀 수 없으면 `Number("foo")` → `NaN`. `Number("")` → `0`.
- `NaN`("Not a Number")의 자료형은 숫자이고, **자기 자신과도 같지 않다**. `NaN`인지 확인할 때는 `Number.isNaN(값)`을 쓴다.
- 소수 계산은 근사값이다. MDN: "Number는 소수점 이하 17자리 정도만 유지하며 산술은 반올림의 대상이 됩니다." 콘솔에서 `0.1 + 0.2`를 쳐 보면 `0.30000000000000004`다. 돈은 **원 단위 정수**로 계산하고 표시할 때만 `toFixed`로 다듬는다.

### 5. 문자열(String)

**한 줄 정의.** 문자열(String)은 따옴표로 감싼 글자의 나열이다.

**실제 예시.** 큰따옴표 `"점심"`, 작은따옴표 `'점심'`은 같고, 백틱은 **템플릿 리터럴(template literal)** 로 `${ }` 안에 변수나 식을 끼울 수 있다(MDN: "내장된 표현식을 허용하는 문자열 리터럴").

```js
const title = "점심", amount = 9000;
console.log("내역: " + title + " " + amount + "원");   // + 로 잇기
console.log(`내역: ${title} ${amount}원`);               // 템플릿 리터럴 (읽기 쉽다)
console.log(title.length);                               // 2 (글자 수)
console.log("  점심  ".trim());                           // "점심" (양끝 공백 제거. app.js가 쓴다)
```

**가장 중요한 함정: 숫자와 문자열의 `+`.** MDN 문법 문서 그대로.

```js
"37" - 7;   // 30     (빼기는 숫자로 바꿔서 계산)
"37" + 7;   // "377"  (더하기는 문자열 이어 붙이기!)
```

`+`는 한쪽이라도 문자열이면 "이어 붙이기"다. `"9000" + 1000`은 `"90001000"`이다. 입력칸, `localStorage`, URL에서 오는 값은 **전부 문자열**이다. 그래서 **경계**(값이 외부에서 들어오는 지점)에서 `Number()`로 명시적으로 바꾼다. 우리 앱이 폼에서 값을 받자마자 `Number(amountInput.value)`를 하는 이유다. 그 뒤로는 모든 코드가 "amount는 숫자"라고 믿고 쓸 수 있다. 반대 방향은 `String(9000)` → `"9000"`.

### 6. 불리언(Boolean): 참과 거짓

**한 줄 정의.** 불리언(Boolean)은 `true` 또는 `false` 두 값만 가지는 자료형이다.

**비유.** 체크박스. "5일선 위에 있는가?"의 답.

**실제 예시.** 비교의 결과가 불리언이다. `9000 > 5000` → `true`. `entry.type === "income"` → `type`이 `"income"`이면 `true`. `app.js`의 `if (entry.type === "income")`가 이 값을 보고 갈림길을 고른다(1-3).

### 7. `undefined`와 `null`: 두 가지 "없음"

**한 줄 정의.** `undefined`는 "값이 아직 안 정해짐", `null`은 "일부러 비워 둠"이다.

**비유.** `undefined`는 지원서의 빈칸(아직 안 적음), `null`은 "해당 없음"이라고 직접 적은 칸.

**실제 예시.** MDN: "개념적으로, `undefined`는 값이 없음을 의미하고, `null`은 객체가 없음을 의미합니다." `undefined`가 나오는 때:

- 값 없이 선언한 변수 `let x;` → `undefined`
- 객체에 없는 속성 `entry.memo` → `undefined`
- 아무것도 돌려주지 않는 함수의 결과 `render()` → `undefined`
- `find()`로 못 찾았을 때 (1-6)

`null`은 "찾았는데 없다"를 알릴 때 브라우저나 라이브러리가 돌려준다. MDN `Storage.getItem()` 문서: 키가 없으면 `null`을 반환한다. 그래서 `app.js`의 `load()`는 이렇게 시작한다.

```js
const saved = localStorage.getItem(STORAGE_KEY);
if (!saved) return;          // null이면 거짓 → !로 뒤집어 참 → 함수를 바로 끝낸다
// (실제 코드는 이 뒤에 try/catch와 모양 검사가 더 있다. 1-7에서 본다)
```

**함정.** `typeof null`은 `"object"`다(MDN: "하위호환 유지를 위해"). `null` 확인은 `값 === null`로 한다. `null == undefined`는 `true`지만 `null === undefined`는 `false`다. 1-3에서 배우듯 **항상 `===`를 쓴다**.

### 실습 3. `Number()`를 빼면 앱이 어떻게 망가지는가 (20분)

1. `app.js` 7번 구역의 `const amount = Number(amountInput.value);`를 실험용으로 `const amount = amountInput.value;`로 바꾼다.
2. 저장, 새로고침. **수입** 10000원을 추가한다.
3. 관찰: 잔액이 `010000원`처럼 이상하다(쉼표도 안 붙는다. 문자열에는 숫자용 `toLocaleString` 서식이 적용되지 않기 때문이다). `calculateBalance`의 `balance + entry.amount`가 `0 + "10000"` = `"010000"`(문자열)이 됐기 때문이다. 콘솔에서 `typeof calculateBalance()`를 치면 `"string"`.
4. 지출 9000원을 추가하면? `"010000" - 9000`은 빼기라서 숫자 `1000`이 된다. 더하기와 빼기가 다르게 동작하는 걸 직접 본 것이다.
5. **반드시** `Number(...)`를 되돌리고 저장한다. 이상한 내역은 × 로 지운다.

### 실습 4. 매매 기록 변수 파일 (25분)

1-1의 `study` 폴더에 `trade.js`를 만든다(Windows PowerShell, Mac 모두 `cd ~/study` 후 `code trade.js`).

```js
const stock = "삼성전자";      // 문자열
const buyPrice = 71000;        // 숫자
const sellPrice = 72500;
const quantity = 30;
let memo;                      // 아직 값 없음 → undefined

const profit = (sellPrice - buyPrice) * quantity;
const rate = (sellPrice - buyPrice) / buyPrice * 100;
const isWin = profit > 0;      // 불리언

console.log(`${stock} ${quantity}주: 손익 ${profit.toLocaleString("ko-KR")}원, 수익률 ${rate.toFixed(2)}%`);
console.log("익절 여부:", isWin, "/ 메모:", memo, typeof memo);

memo = "장 초반 급등 추격. 다음엔 눌림 기다리기";
console.log("메모:", memo);
```

`node trade.js`로 실행한 뒤 세 가지 실험. (1) `buyPrice = 70000;`을 추가해 `const` 에러를 확인하고 지운다. (2) `const quantity = "30";`으로 바꿔 본다(곱하기는 숫자로 바꿔 그럴듯하게 나오지만 `+`가 섞이면 깨진다). (3) `let memo = null;`로 바꾸고 `typeof memo`를 본다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 합계가 `"900010000"`처럼 길다 | 문자열끼리 `+` | 경계에서 `Number()`. `typeof`로 확인 |
| `TypeError: Assignment to constant variable.` | `const`에 다시 할당 | 정말 바뀌어야 하면 `let`, 아니면 로직을 고친다 |
| `SyntaxError: Missing initializer in const declaration` | `const x;`처럼 값 없이 선언 | `const`는 선언과 동시에 값을 넣는다 |
| `ReferenceError: Cannot access 'x' before initialization` | 선언 줄보다 위에서 사용 | 선언을 위로 올린다 |
| `SyntaxError: Identifier 'x' has already been declared` | 콘솔에서 같은 이름을 두 번 선언 | 새로고침하거나 다른 이름 |
| 화면에 `NaN` | 숫자가 아닌 것을 계산 | 입력값 확인. `Number.isNaN()`으로 걸러 안내 |
| `0.1 + 0.2`가 `0.3`이 아니다 | 부동소수점 근사 | 돈은 원 단위 정수로. 표시만 `toFixed` |

## 확인 퀴즈

**1. `app.js`에서 `entries`는 `let`인데 `STORAGE_KEY`는 `const`다. 이유는?**

<details><summary>정답과 해설</summary>

`entries`는 `deleteEntry()`에서 `entries = entries.filter(...)`로 **새 배열을 다시 할당**하므로 `let`이어야 한다. `STORAGE_KEY`는 절대 바뀌지 않으므로 `const`가 맞고, 실수로 바뀌는 것을 자바스크립트가 막아 준다.
</details>

**2. `const list = []; list.push("점심");`은 에러인가?**

<details><summary>정답과 해설</summary>

아니다. `const`는 변수가 **다른 배열을 가리키는 것**만 막는다(MDN: "배열에 아이템을 삽입하는 건 가능합니다"). `list = ["저녁"]`처럼 통째로 바꾸는 것만 에러다.
</details>

**3. `"9000" + 1000`과 `"9000" - 1000`의 결과와 자료형은?**

<details><summary>정답과 해설</summary>

`"90001000"`(문자열)과 `8000`(숫자). `+`는 한쪽이 문자열이면 이어 붙이고, `-`는 숫자 연산만 있어서 문자열을 숫자로 바꿔 계산한다. 이 비대칭 때문에 입력값은 경계에서 `Number()`로 바꾼다.
</details>

**4. `let memo;` 직후 `typeof memo`는? `let memo = null;`이면?**

<details><summary>정답과 해설</summary>

`"undefined"`, 그리고 `"object"`(역사적 오류). 그래서 `null` 확인은 `memo === null`로 한다.
</details>

**5. 가계부 잔액이 `NaN원`으로 표시됐다. 가장 먼저 의심할 것은?**

<details><summary>정답과 해설</summary>

어떤 내역의 `amount`가 숫자가 아니라는 것(`undefined`이거나 `Number()`가 바꾸지 못한 문자열). `NaN`은 한 번 섞이면 그 뒤 모든 합계가 `NaN`이 된다. 콘솔에서 `entries`를 펼쳐 `amount`의 자료형을 확인하고, 입력 단계에서 `Number.isNaN()`으로 걸러 준다.
</details>
