# 1-5. 함수: 입력(매개변수)과 출력(return), 함수로 쪼개는 이유, 스코프

| 과정 | 1. 코딩의 기본 개념 (JavaScript로) |
|---|---|
| 예상 시간 | 4시간 |
| 선수 단원 | 1-4 |
| 경험치 | 80 |

## 이 단원을 마치면

- 함수를 **정의**하는 것과 **호출**하는 것의 차이를 알고, 매개변수(parameter)로 값을 넣고 `return`으로 결과를 받을 수 있다.
- "비슷한 코드 두 개"를 매개변수 하나짜리 함수 하나로 합칠 수 있다.
- 스코프(scope)를 이해해서 "함수 안 변수가 밖에서 안 보이는" 에러를 읽을 수 있다.
- 함수 표현식과 화살표 함수(`=>`)를 읽을 수 있고, 함수를 다른 함수에 값처럼 넘기는 콜백(callback)이 무엇인지 안다.
- `app.js`가 왜 여덟 개 구역과 서른 개 남짓한 함수로 나뉘어 있는지 설명할 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

지금까지의 코드는 "위에서 아래로 한 번" 흐르는 것이었다. 함수는 그 흐름에 **이름을 붙여 몇 번이고 다시 쓰는** 장치다. `formatMoney(1234567)`을 열 군데서 부르지만 "1,234,567원"으로 바꾸는 법은 한 곳에만 적혀 있다. 나중에 "₩1,234,567"로 바꾸고 싶으면 그 한 곳만 고친다.

클로드와 일할 때 함수는 **대화의 단위**다. "잔액 계산하는 함수 하나 만들어 줘", "이 함수가 음수를 받으면 어떻게 돼?", "`render`를 둘로 쪼개 줘". 함수 단위로 요청하고, 함수 단위로 검증하고, 함수 단위로 되돌린다. 1-4에서 만든 `totalIncome`과 `totalExpense`가 거의 똑같은 걸 봤다. 그 불편함을 해결하는 게 이 단원의 첫 실습이다.

그리고 스코프를 모르면 "분명히 만든 변수인데 `is not defined`"라는 에러 앞에서 멈춘다. 이 단원 뒤로는 그 에러가 30초짜리가 된다.

## 핵심 개념

### 1. 함수(function): 이름 붙인 작업 묶음

**한 줄 정의.** 함수(function)는 입력을 받아 정해진 작업을 하고 결과를 돌려주는 코드 묶음이며, 정의해 두고 이름으로 호출한다. MDN: "함수를 정의해도 함수가 실행되는 것은 아닙니다. 함수를 정의하는 것은 함수의 이름과 수행할 작업을 지정하는 것입니다."

**비유.** HTS의 "조건검색식 저장". 한 번 만들어 이름을 붙여 두면 매일 아침 이름만 눌러 돌린다. 만들 때(정의)는 아무 종목도 안 나온다. 누를 때(호출) 나온다.

**실제 예시.** `app.js`의 가장 작은 함수.

```js
// 정의: function 키워드, 이름, 괄호 안 매개변수, 중괄호 안 본문
function formatMoney(number) {
  return number.toLocaleString("ko-KR") + "원";
}

// 호출: 이름 + 괄호 + 인수
formatMoney(9000);            // "9,000원"
balanceText.textContent = formatMoney(calculateBalance());   // 결과를 바로 다른 곳에 쓴다
```

MDN 함수 선언 문서의 구문 그대로다: `function name([param[, param,[..., param]]]) { [statements] }`.

### 2. 매개변수(parameter)와 인수(argument): 입력

**한 줄 정의.** 매개변수(parameter)는 함수를 정의할 때 괄호 안에 적는 "입력 이름"이고, 인수(argument)는 호출할 때 실제로 넣는 값이다.

**비유.** 매개변수는 주문서의 빈칸("종목: ___, 수량: ___"), 인수는 거기에 적어 넣은 값("삼성전자, 10").

**실제 예시.**

```js
function addEntry(type, category, title, amount) {   // 매개변수 4개
  const entry = { id: Date.now(), type: type, category: category, title: title, amount: amount, date: ... };
  entries.push(entry);
  save();
  render();
  showXpPop();
}

addEntry("expense", "food", "점심", 9000);          // 인수 4개. 순서대로 들어간다
```

**순서가 전부다.** `addEntry(9000, "food", "점심", "expense")`라고 부르면 `type`에 `9000`이 들어간다. 에러는 안 나고 조용히 이상한 내역이 생긴다. 인수를 빠뜨리면 그 매개변수는 `undefined`가 된다(1-2). `formatMoney()`처럼 비워서 부르면 `undefined.toLocaleString`을 시도해 `TypeError`가 난다.

### 3. `return`: 출력

**한 줄 정의.** `return 값;`은 함수 실행을 그 자리에서 끝내고 값을 호출한 곳에 돌려준다. MDN: "`return` 명령문은 함수 실행을 종료하고, 주어진 값을 함수 호출 지점으로 반환합니다." 값을 안 적거나 `return`이 아예 없으면 `undefined`를 돌려준다.

**실제 예시.** `app.js`의 함수는 두 종류로 나뉜다.

| 종류 | 예 | `return` | 하는 일 |
|---|---|---|---|
| 계산하는 함수 | `calculateBalance`, `formatMoney`, `totalXp` | 있다 | 입력 → 결과. 화면·저장소를 건드리지 않는다 |
| 일을 하는 함수 | `render`, `save`, `load`, `showXpPop` | 없다 | 화면을 그리거나 저장한다 (부수효과) |

계산하는 함수는 콘솔에서 `calculateBalance()`처럼 불러 결과를 바로 확인할 수 있어 검증이 쉽다. 일을 하는 함수는 결과가 화면에 나타난다. 둘을 섞지 않는 것(계산 함수 안에서 화면을 건드리지 않기)이 좋은 설계의 첫 규칙이다.

**`return`은 즉시 종료.** 1-3의 가드 절이 바로 이것이다. `return` 뒤에 적은 코드는 실행되지 않는다. `calculateBalance`의 `return balance`가 `for` 안에 들어가면 첫 바퀴에서 끝나 버린다.

### 4. 함수로 쪼개는 이유

**한 줄 정의.** 같은 코드를 두 번 쓰지 않고(DRY: Don't Repeat Yourself), 한 함수가 한 가지 일만 하게 나누면 읽기·고치기·시키기가 쉬워진다.

**실제 예시.** 1-4에서 만든 두 함수.

```js
function totalIncome()  { let total = 0; for (const e of entries) { if (e.type === "income")  total += e.amount; } return total; }
function totalExpense() { let total = 0; for (const e of entries) { if (e.type === "expense") total += e.amount; } return total; }
```

다른 건 `"income"`/`"expense"` 한 단어뿐이다. 그 단어를 매개변수로 빼면 하나가 된다.

```js
function sumByType(type) {
  let total = 0;
  for (const entry of entries) {
    if (entry.type === type) {
      total += entry.amount;
    }
  }
  return total;
}
sumByType("income");    // 수입 합계
sumByType("expense");   // 지출 합계
```

**"달라지는 부분을 매개변수로."** 이게 함수 설계의 핵심 한 문장이다. 나중에 카테고리가 생기면 `sumByCategory(category)`, 월별이면 `sumByMonth(month)`로 같은 틀을 쓴다.

### 5. 스코프(scope): 변수가 보이는 범위

**한 줄 정의.** 스코프(scope)는 변수를 사용할 수 있는 범위다. MDN 용어집: "변수 또는 표현식이 '해당 스코프' 내에 있지 않다면, 사용할 수 없습니다. 스코프는 또한 계층적인 구조를 가지기 때문에, 하위 스코프는 상위 스코프에 접근할 수 있지만 반대는 불가하다."

**비유.** 회사 조직도. 부서(함수) 안의 서류(변수)는 그 부서만 본다. 회사 전체 게시판(전역)은 모든 부서가 본다. 재무부가 인사부 서류를 직접 꺼낼 수는 없다.

**세 가지 스코프 (MDN).** 전역(함수 밖, 파일 최상위), 함수(함수 안), 블록(`let`/`const`가 선언된 `{ }` 안).

```js
let entries = [];                 // 전역: 모든 함수가 읽고 쓴다

function calculateBalance() {
  let balance = 0;                // 함수 스코프: 이 함수 안에서만
  for (const entry of entries) {  // 블록 스코프: 이 for 안에서만. entries는 전역이라 보인다
    // ...
  }
  return balance;
}

console.log(balance);   // ReferenceError: balance is not defined
```

MDN 용어집 예제 그대로다. "함수 내에서만 정의된 변수는 함수 외부나 다른 함수 내에서 접근할 수 없습니다."

**규칙 세 가지.** (1) 안에서 밖은 보인다(`calculateBalance`가 `entries`를 쓴다). (2) 밖에서 안은 안 보인다(`balance`). (3) 안에서 밖과 같은 이름을 만들면 안쪽이 밖을 **가린다**(shadowing). `render()` 안의 `const title`은 전역 `titleInput`과 다른 변수다. 헷갈리니 가급적 다른 이름을 쓴다.

**왜 중요한가.** 전역 변수는 모든 함수가 바꿀 수 있어서, 커질수록 "누가 바꿨지?"를 추적하기 어렵다. `app.js`의 전역 상태는 사실상 `entries` 하나다. 나머지는 함수 안에 가둔다. 그리고 `ReferenceError: x is not defined`의 절반은 스코프 문제다. "이 줄에서 그 변수가 **보이나**?"를 묻는다.

### 6. 함수 표현식, 화살표 함수, 콜백

**한 줄 정의.** 함수는 값이다. 변수에 넣을 수 있고(함수 표현식), 짧게 쓸 수 있고(화살표 함수), 다른 함수의 인수로 넘길 수 있다(콜백).

**실제 예시.** 세 가지 쓰기 방식.

```js
// (1) 함수 선언
function double(x) { return x * 2; }

// (2) 함수 표현식: 이름 없는 함수를 변수에 담는다 (MDN: "익명 함수")
const double = function (x) { return x * 2; };

// (3) 화살표 함수: function 키워드를 빼고 =>
const double = (x) => { return x * 2; };
const double = (x) => x * 2;      // 본문이 식 하나면 중괄호와 return 생략
const double = x => x * 2;        // 매개변수가 하나면 괄호도 생략 가능
```

MDN 화살표 함수 문서가 이 변형을 단계별로 보여준다. 규칙: "괄호는 함수에 하나의 간단한 매개변수가 있는 경우에만 생략", 중괄호를 생략하면 "반환이 암시"된다. 중괄호를 **쓰면** `return`을 직접 적어야 한다(이게 흔한 실수).

**콜백(callback).** `app.js`에는 이름 없는 함수가 다른 함수의 인수로 들어가는 곳이 여럿이다.

```js
form.addEventListener("submit", function (event) { /* ... */ });   // "submit이 일어나면 이걸 실행해"
entries.filter(function (entry) { return entry.id !== id; });      // "각 entry에 이 검사를 적용해"
setTimeout(function () { pop.remove(); }, 1000);                   // "1초 뒤에 이걸 실행해"
```

"나중에 불러 달라고 맡기는 함수"가 콜백이다. 화살표로 쓰면 짧아진다: `entries.filter((entry) => entry.id !== id)`. 1-6의 `filter`, `map`, `find`는 전부 콜백을 받는다. 그래서 이 단원이 1-6보다 앞에 있다.

**선언과 표현식의 차이 하나.** 함수 **선언**은 파일 아래쪽에 있어도 위에서 부를 수 있다(MDN 문법 문서: "함수 선언으로는 호이스팅되지만 함수 표현식으로는 호이스팅 되지 않습니다"). `app.js`에서 `addEntry`(4번 구역)가 `render`(5번 구역)를 부를 수 있는 이유다. 표현식은 선언 줄 뒤에서만 부를 수 있다.

### 실습 1. 인수를 빠뜨리면 (10분)

콘솔에서.

```js
formatMoney(9000)
formatMoney("9000")
formatMoney()
addEntry("expense", "food", "매개변수 실험")
```

세 번째는 `TypeError: Cannot read properties of undefined (reading 'toLocaleString')`(크롬 문구). 네 번째는 에러 없이 금액이 `undefined`인 내역이 생기고 잔액이 `NaN원`이 된다(1-2 퀴즈 5). 실험 내역은 × 로 지운다. 함수는 "뭘 넣는지"까지 책임져야 한다는 걸 체감한다.

### 실습 2. 두 함수를 하나로 (20분)

1-4 실습 2의 `totalIncome`, `totalExpense`를 지우고 위의 `sumByType(type)`으로 바꾼다. `render()`의 요약 줄도 고친다.

```js
summaryText.textContent =
  "수입 " + formatMoney(sumByType("income")) + " · 지출 " + formatMoney(sumByType("expense")) +
  " · " + entries.length + "건";
```

저장, 새로고침, 화면이 그대로 동작하면 성공. 동작은 같은데 코드는 줄었다. 이런 작업을 **리팩터링(refactoring)** 이라 부른다. "동작을 바꾸지 않고 구조를 개선"하는 것.

### 실습 3. 스코프 에러 직접 보기 (10분)

콘솔에서.

```js
balance
function test() { const inner = "안"; return inner; }
test()
inner
```

1번째와 4번째가 `ReferenceError: ... is not defined`. `balance`는 `calculateBalance` 안에만, `inner`는 `test` 안에만 있다. 이제 이 에러를 보면 "어느 함수 안에 갇힌 변수를 밖에서 찾고 있구나"라고 읽을 수 있다.

### 실습 4. 매매 판단기를 함수로 조립 (30분)

`study/judge2.js`. 1-3의 `judge.js`를 함수 세 개로 다시 쓴다.

```js
// 1) 계산 함수: 입력 → 결과. 화면도 저장도 없다
function profitRate(buyPrice, currentPrice) {
  return (currentPrice - buyPrice) / buyPrice * 100;
}

// 2) 판단 함수: 숫자를 받아 문자열을 돌려준다
function judge(rate, holdingDays) {
  if (rate <= -3) return "손절";
  if (rate >= 5) return "익절";
  if (holdingDays >= 3 && rate < 1) return "시간 손절";
  return "보유";
}

// 3) 출력 함수: 결과를 보여준다 (부수효과)
function report(stock, buyPrice, currentPrice, holdingDays) {
  const rate = profitRate(buyPrice, currentPrice);
  console.log(`${stock}: ${rate.toFixed(2)}% → ${judge(rate, holdingDays)}`);
}

report("삼성전자", 52000, 50200, 4);
report("SK하이닉스", 180000, 191000, 1);
report("카카오", 40000, 40300, 5);
```

`node judge2.js`로 실행(Windows PowerShell, Mac 동일). 세 함수의 역할이 다르다는 점을 보자. `profitRate`와 `judge`는 콘솔에서 아무 값이나 넣어 검증할 수 있다. `report`는 그 둘을 조립한다. 다음으로 `judge`의 가드 절(`if (...) return ...;`)이 1-3의 `else if` 사다리와 같은 일을 더 짧게 한다는 걸 비교해 본다.

### 실습 5. 화살표 함수로 바꿔 보기 (15분)

`app.js`의 `deleteEntry`를 화살표 함수 버전으로 바꾼다.

```js
function deleteEntry(id) {
  entries = entries.filter((entry) => entry.id !== id);
  save();
  render();
}
```

저장, 새로고침, 삭제와 팝업이 그대로 동작하면 성공. 동작은 같고 글자만 줄었다. 클로드가 써 주는 코드는 대부분 화살표를 쓰니 읽을 줄은 알아야 한다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 함수를 불렀는데 아무 일도 안 일어남 | 괄호를 빼먹음 (`render` vs `render()`) | 호출엔 항상 `()` |
| 결과가 `undefined` | `return`을 안 썼거나 `return;`만 씀 | 계산 함수는 `return 값;` |
| 화살표 함수 결과가 `undefined` | `(x) => { x * 2 }` 중괄호 안에 `return` 없음 | `(x) => x * 2` 또는 `{ return x * 2; }` |
| 인수 순서가 바뀌어 엉뚱한 값 | `addEntry(9000, "food", "점심", "expense")` | 매개변수 순서를 정의에서 확인. 1-6에서 객체 하나로 넘기는 방법을 배운다 |
| `ReferenceError: x is not defined` | 함수 안 변수를 밖에서, 또는 다른 함수에서 사용 | 그 값이 필요하면 `return`으로 내보낸다 |
| `TypeError: x is not a function` | 함수 표현식을 선언 줄보다 위에서 호출, 또는 이름 오타 | 정의를 위로. 이름 대소문자 확인 (1-7) |
## 확인 퀴즈

**1. 다음에서 매개변수와 인수를 각각 가리켜라.**

```js
function profitRate(buyPrice, currentPrice) { return (currentPrice - buyPrice) / buyPrice * 100; }
profitRate(52000, 50200);
```

<details><summary>정답과 해설</summary>

매개변수: `buyPrice`, `currentPrice`(정의의 괄호 안 이름). 인수: `52000`, `50200`(호출 때 넣은 값). 순서대로 짝지어진다.
</details>

**2. `render()`와 `calculateBalance()`는 "종류"가 다르다. 무엇이 다른가?**

<details><summary>정답과 해설</summary>

`calculateBalance`는 값을 계산해서 `return`하는 함수(화면·저장소를 건드리지 않음). `render`는 `return` 없이 화면을 바꾸는 "일을 하는" 함수(부수효과).
</details>

**3. `totalIncome`과 `totalExpense`를 `sumByType(type)`으로 합칠 수 있었던 이유를 한 문장으로.**

<details><summary>정답과 해설</summary>

두 함수에서 **달라지는 부분이 `"income"`/`"expense"` 한 값뿐**이었고, 달라지는 부분을 매개변수로 빼면 나머지 틀을 공유할 수 있기 때문이다.
</details>

**4. 다음 코드의 마지막 줄은 어떻게 되는가?**

```js
function f() { const secret = 42; return secret; }
f();
console.log(secret);
```

<details><summary>정답과 해설</summary>

`ReferenceError: secret is not defined`. `secret`은 `f`의 함수 스코프 안에만 존재한다. `f()`가 42를 **돌려주긴** 했지만 받아 두지 않았다. `const s = f(); console.log(s);`처럼 반환값을 변수에 담아야 한다.
</details>

**5. `const g = (x) => { x + 1 };`에서 `g(1)`의 결과는?**

<details><summary>정답과 해설</summary>

`undefined`. 중괄호를 썼으므로 `return`을 직접 적어야 하는데 없다. `(x) => x + 1` 또는 `(x) => { return x + 1; }`로 고친다. 화살표 함수에서 가장 흔한 실수다.
</details>
