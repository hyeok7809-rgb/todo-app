# 12-3. 배포: GitHub Pages/Vercel(정적), Render/Railway(서버), 도메인 연결

| 과정 | 12. 바이브 코딩 실전과 배포 |
|---|---|
| 예상 시간 | 4시간 |
| 선수 단원 | 12-2 |
| 경험치 | 80 |

## 이 단원을 마치면

- "정적 사이트"(파일만)와 "서버 앱"(코드가 돈다)의 차이를 알고, 각각 어디에 올리는지(GitHub Pages·Vercel / Render·Railway·VPS) 고를 수 있다.
- 이 앱(정적)을 Pages(5-3)에 이어 **Vercel**에도 올려 비교하고, 작은 파이썬 API 서버(11-4의 길 C)를 호스팅 서비스에 올린다.
- 환경변수(비밀)를 호스팅 서비스의 설정 화면에 넣는 법(4-2의 "서버에서는 `.env` 대신")을 안다.
- 내 도메인을 사서 연결하고 HTTPS가 자동으로 붙는 것을 확인한다.

## 왜 배우나 (나에게 어떤 쓸모)

5-3에서 Pages로 앱을 휴대폰에서 열었다. 하지만 데이터는 기기마다 따로였다. 11-4의 길 C(API 서버)를 열면 합쳐지는데, 그러려면 서버를 **인터넷에** 둬야 한다. 또 13과정에서 남에게 보여 주거나 팔려면 "주소 하나로 열리는 것"이 기본이다. 이 단원은 "내 컴퓨터에서 되는 것"을 "세상에서 되는 것"으로 바꾸는 단계다. 12-2의 보안을 먼저 배운 이유다.

## 핵심 개념

(서비스 이름·요금·메뉴는 바뀐다. 각 공식 문서로 확인. 이 글을 쓴 환경(2026-10-21)에서는 이 서비스들의 문서에 접속할 수 없어 주소만 적는다.)

### 1. 정적 vs 서버

| | 정적 사이트 | 서버 앱 |
|---|---|---|
| 무엇 | HTML/CSS/JS 파일을 그대로 전달 | 요청마다 코드가 실행돼 응답을 만듦 |
| 예 | 이 앱, 포트폴리오 페이지 | 11-4 길 C API, 로그인 있는 서비스 |
| 데이터 | 브라우저(localStorage)나 외부 API | 서버 DB·파일 |
| 호스팅 | GitHub Pages, Vercel, Netlify 등 | Render, Railway, Fly 등 PaaS, 또는 VPS(11-3) |
| 비용 | 대부분 무료 | 무료 티어 있으나 상시 가동은 유료 |
| 보안 | 비밀이 없어야 함(코드가 공개) | 비밀은 환경변수, 인증 필요 |

**비유**: 정적은 전단지(인쇄해서 나눠 줌), 서버는 가게(손님마다 응대). 전단지는 싸고 안전하지만 손님 말을 못 듣는다.

### 2. 정적 배포 두 가지

- **GitHub Pages**(5-3): 저장소 → Settings → Pages → 브랜치 선택. `https://<id>.github.io/<repo>/`.
- **Vercel**: GitHub 저장소를 연결하면 push마다 자동 배포, 미리보기 URL, 커스텀 도메인·HTTPS 자동. 정적 파일은 설정 거의 없이 된다("Framework: Other", 출력 디렉터리 루트).
둘 다 **push = 배포**다. 그래서 5-2의 "main은 항상 동작"이 중요했다. 미리보기(브랜치별 URL)가 있는 Vercel은 PR(5-3)을 열면 그 브랜치의 앱을 바로 볼 수 있다.

### 3. 서버 앱 배포 (길 C)

11-4의 API 서버를 가장 작게: 파이썬 + 가벼운 웹 프레임워크(공식 문서에서 하나 고른다. 이 커리큘럼은 특정 프레임워크를 전제하지 않는다 — Claude Code에게 "가장 단순한 파이썬 HTTP API 2개 엔드포인트(GET /status, POST /backup) 만들어 줘, 토큰 인증 포함"을 시키고 **코드를 읽는다**).

호스팅(Render/Railway 류)의 공통 흐름:
1. GitHub 저장소 연결 → 빌드 명령(`pip install -r requirements.txt`) → 시작 명령(`python server.py` 또는 프레임워크 실행 명령).
2. **환경변수** 화면에 `API_TOKEN`, `ANTHROPIC_API_KEY` 등 입력(저장소에 `.env` 없음, 4-2·4-4 따라하기 3의 원칙).
3. 서비스가 **HTTPS 주소**를 준다. 앱은 그 주소로 `fetch`(2-6).
4. 무료 티어는 유휴 시 잠들었다 첫 요청에 깨어나 느릴 수 있다(공식 문서의 요금제 설명 확인). 상시 가동은 유료 또는 11-3의 VPS.
5. 로그·메트릭 화면에서 요청·에러를 본다(11-3 로그 세 층과 연결).

보안(12-2): 토큰 없는 요청 거부, 요청 크기 제한, CORS는 내 앱 도메인만, 비밀은 환경변수, HTTPS는 서비스가 해 준다.

### 4. 도메인과 HTTPS

- 도메인 등록 업체에서 구매(연 1~2만 원대) → 호스팅 서비스의 "Custom domain"에 입력 → 안내대로 DNS 레코드(A/CNAME) 추가 → 보통 몇 분~몇 시간 후 연결.
- HTTPS 인증서는 Pages·Vercel·Render 류가 **자동 발급**(Let's Encrypt). VPS는 직접(certbot).
- `app.내도메인`(정적), `api.내도메인`(서버)처럼 서브도메인으로 나눈다.

### 5. 배포 체크리스트

1. `main`이 동작하는가(테스트 초록, 12-1).
2. 비밀이 코드·저장소에 없는가(12-2).
3. 환경변수가 호스팅 화면에 들어갔는가.
4. 상대경로인가(5-3 Pages 함정).
5. 배포 후 **실제 주소에서** E2E(12-1 Playwright를 주소만 바꿔).
6. 롤백 방법: Pages/Vercel은 이전 배포로 되돌리기 버튼, 또는 `git revert` 후 push(5-1).

### 6. 두 앱의 관계 정리

```
휴대폰/PC 브라우저 ── 정적 앱 (Pages/Vercel, 공개) ──fetch──▶ API 서버 (Render/VPS, 토큰 인증) ──▶ 큐·로그·백업 (11-3)
                                                            ▲
                                             AI 직원들(팀장 cron) ┘
```
앱은 공개돼도 되고(코드만 있음), 데이터는 서버 뒤에 있다. 토큰은 앱에 넣지 않고(공개되니까) 사용자가 **한 번 입력**해 localStorage에 둔다(13-2에서 로그인으로 바뀐다).

## 따라하기

### 1. Vercel 배포 (40분)

Vercel에 GitHub로 가입 → 이 저장소 Import → 정적 설정 → 배포 URL에서 앱이 열리는지, 휴대폰에서도. Pages 주소와 둘 다 README에.

### 2. 미리보기 URL (20분)

브랜치를 만들어 작은 변경 후 PR → Vercel이 단 미리보기 링크로 확인 → 병합 → 본 주소에 반영되는지.

### 3. 최소 API 서버 (90분)

Claude Code에 "GET /status(status.json 반환), POST /backup(JSON 저장), 둘 다 `Authorization: Bearer` 토큰 검사, 요청 크기 1MB 제한, CORS는 환경변수의 도메인만"을 여섯 칸(8-6)으로 요청. 코드를 읽고(12-2 표) 로컬에서 curl로 테스트(4-1) → 호스팅 서비스에 배포, 환경변수 입력 → 배포 주소로 curl.

### 4. 앱 연결 (50분)

앱 사장실에 "서버 주소·토큰 입력" 설정을 추가(localStorage)하고, 백업 내보내기 옆에 "서버로 보내기"(POST /backup), AI 직원실의 상태를 GET /status로 읽게(11-4 길 B를 C로 교체). 오프라인·401 처리.

### 5. 도메인 (30분, 선택)

도메인을 사서 `app.`과 `api.`를 연결. HTTPS 자물쇠 확인.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| 비밀을 코드에 두고 배포 | 공개 노출 | 환경변수 화면, 4-2 |
| 절대경로 | Pages/Vercel에서 CSS 깨짐 | 상대경로 |
| 무료 티어 잠듦 | 첫 요청 느림 | 요금제 확인, VPS |
| CORS 전체 허용 | 아무 사이트나 내 API 호출 | 내 도메인만 |
| 배포 후 테스트 안 함 | 로컬만 동작 | 실제 주소 E2E |
| 롤백 모름 | 깨진 채 방치 | 이전 배포 복원·revert |

## 확인 퀴즈

**1. 이 앱이 정적 사이트인 이유와 그 장점.**

<details><summary>정답과 해설</summary>
HTML/CSS/JS 파일만 있고 서버 코드가 없다. 무료·안전·단순하게 배포된다. 데이터는 브라우저나 외부 API에.
</details>

**2. 서버 앱의 비밀은 어디에 두나?**

<details><summary>정답과 해설</summary>
호스팅 서비스의 환경변수 설정. 저장소에는 `.env.example`만.
</details>

**3. "push = 배포"가 5-2와 연결되는 이유.**

<details><summary>정답과 해설</summary>
main에 올라가면 바로 서비스되므로 main은 항상 동작해야 한다. 실험은 브랜치, PR 미리보기로 확인 후 병합.
</details>

**4. 공개 정적 앱이 비공개 API를 부를 때 토큰을 어디에 두나?**

<details><summary>정답과 해설</summary>
앱 코드에 넣지 않는다(공개됨). 사용자가 입력해 localStorage에 두거나, 13-2의 로그인으로.
</details>

**5. 배포 직후 반드시 하는 검증.**

<details><summary>정답과 해설</summary>
실제 배포 주소에서 E2E(기록·새로고침·API 연결). 로컬 동작은 배포 동작을 보장하지 않는다.
</details>
