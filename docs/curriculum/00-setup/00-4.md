## 이 단원을 마치면

- Claude Code가 무엇이고 claude.ai 채팅과 어떻게 다른지, 어떤 요금제에서 쓸 수 있는지 안다.
- 내 OS에 Claude Code를 설치하고 로그인해서, 이 저장소 폴더에서 첫 대화를 할 수 있다.
- 권한 모드(Manual/acceptEdits/plan/auto)가 무엇인지 알고, 권한 요청 화면을 읽고 승인·거부할 수 있다.
- `rm -rf` 같은 위험한 명령, 체크포인트(되돌리기), `/clear`로 대화 비우기를 안다.

## 왜 배우나 (나에게 어떤 쓸모)

이 과정 전체의 핵심 도구다. 8·9단원에서 깊이 배우지만, 1단원부터 "모르는 코드를 Claude에게 물어보며" 가야 하므로 지금 설치한다. claude.ai 채팅이 "설명해 주는 상담사"라면 Claude Code는 **내 컴퓨터 안에서 직접 파일을 읽고 고치고 명령을 실행하는 신입 직원**이다. 공식 문서 표현으로는 "코드베이스를 읽고, 파일을 편집하고, 명령을 실행하는 에이전트형 코딩 도구". 그래서 좋은 만큼 위험하다. 직원에게 금고 열쇠를 주기 전에 **무엇을 허락하고 무엇을 확인할지** 정하는 것이 이 단원의 절반이다.

## 핵심 개념

### 1. Claude Code란

**한 줄 정의**: 터미널(또는 VS Code, 데스크톱 앱, 웹)에서 돌아가는 AI 코딩 에이전트. 내 프로젝트 폴더를 읽고, 파일을 고치고, 명령을 실행한다.

**비유**: 채팅 AI는 전화 상담. Claude Code는 사무실에 출근해 서류함(폴더)을 직접 열어 보고 수정까지 하는 직원. 단, 직원은 **매번 보고하고 승인을 받는다**(권한 모드).

**실제 예시**: 공식 문서 "How Claude Code works"는 작업을 세 단계 순환으로 설명한다. **맥락 수집(gather context) → 행동(take action) → 결과 검증(verify results)**. "실패하는 테스트를 고쳐 줘"라고 하면 테스트를 돌리고, 에러를 읽고, 파일을 찾아 고치고, 다시 돌린다. 각 단계에서 쓰는 것이 **도구(tool)**: 파일 읽기·편집, 검색, 셸 명령, 웹 검색. 0-2에서 배운 `ls`, `cat`, `mkdir`가 그 실체다.

실행 환경은 여러 개지만 엔진은 같다. 이 과정은 **터미널 CLI**를 기본으로 한다. 터미널이 싫으면 **데스크톱 앱**의 Code 탭으로도 같은 일을 할 수 있다(문서: "CLI를 따로 설치할 필요 없음").

**왜 중요한가**: "어디까지 자동으로 하고 어디서 나한테 묻는가"를 이해해야 결과를 믿을 수 있다. 공식 문서도 "제안된 코드와 명령의 안전을 검토하는 책임은 사용자에게 있다"고 적는다.

### 2. 계정과 요금

**한 줄 정의**: Claude Code는 유료 구독(Pro/Max/Team/Enterprise) 또는 API 콘솔 계정으로 쓴다. 무료 플랜은 포함되지 않는다.

**실제 예시** (2026-10-21 공식 페이지 기준):
- claude.com/pricing: Pro는 월 $20(연간 결제 시 월 $17), Max는 월 $100부터. "Claude Code는 모든 유료 플랜에 포함"이며 "플랜의 나머지와 같은 사용 한도를 공유"한다. 무료 플랜 비교표에는 Claude Code가 "No".
- 지원 센터 문서: Pro·Max 모두 **5시간 세션 한도와 주간 한도**가 있고, "이 한도는 Claude(채팅)와 Claude Code가 공유"한다. 한도에 가까워지면 경고가 뜬다. 한도를 넘기면 API 크레딧(별도 과금) 사용을 제안할 수 있는데, 플랜 안에서만 쓰려면 거절하고 초기화를 기다린다.
- 사용량 확인은 세션 안에서 `/usage`(별칭 `/cost`, `/stats`). 계정·모델·연결 상태는 `/status`.
- **주의**: `ANTHROPIC_API_KEY` 환경변수가 설정되어 있으면 구독 대신 그 키로 **API 요금**이 나간다(0-2 환경변수의 실제 사례). 4단원에서 API 키를 만들기 전까지는 이 변수를 만들지 않는다.

모델 이름도 알아 두자. 개발자 플랫폼 모델 페이지(확인일 2026-10-21)의 현재 라인업은 Fable 5.1(`claude-fable-5-1`), Opus 5.5(`claude-opus-5-5`), Sonnet 5.5(`claude-sonnet-5-5`), Haiku 5.5(`claude-haiku-5-5`). 비용 문서는 "Sonnet이 대부분의 코딩 작업을 잘 처리하고 Opus보다 싸다"며 `/model`로 바꾸라고 한다(6-4).

**왜 중요한가**: 백수 기간의 고정비다. 한도 구조를 알아야 "왜 멈췄지?"에 당황하지 않고, 예상 밖 API 과금을 막는다.

### 3. 설치

**한 줄 정의**: 공식 설치 스크립트 한 줄. Node.js 불필요(0-3).

**실제 예시** (Claude Code 설치 문서 그대로):

| OS | 명령 |
|---|---|
| Mac / Linux / WSL | `curl -fsSL https://claude.ai/install.sh \| bash` |
| Windows PowerShell | `irm https://claude.ai/install.ps1 \| iex` |
| Windows CMD | `curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd` |
| Mac Homebrew | `brew install --cask claude-code` |
| Windows WinGet | `winget install Anthropic.ClaudeCode` |

(표 안의 `\|`는 실제로는 `|` 한 글자다.) 문서의 주의사항: 설치 명령은 **진행 표시 없이** 조용히 내려받으니 창을 닫지 말고 기다린다. 끝나면 **새 터미널**에서 `claude --version`. `2.1.211 (Claude Code)`처럼 버전이 나오면 성공. `claude doctor`는 설치·설정 상태를 점검해 준다. 기본 설치는 백그라운드에서 자동 업데이트되고, 수동은 `claude update`. Windows는 Git for Windows를 함께 설치하면 Bash 도구를 쓴다(0-3에서 했다).

**왜 중요한가**: 설치 실패의 대부분은 PATH(0-2)와 셸 혼동(PowerShell/CMD)이다. 흔한 실수 표에 문서의 처방을 모았다.

### 4. 로그인과 세션

**한 줄 정의**: 프로젝트 폴더에서 `claude`를 치면 세션이 시작되고, 첫 실행 때 브라우저로 로그인한다.

**실제 예시** (인증 문서 기준):
1. `cd 프로젝트폴더` → `claude`.
2. 브라우저가 열리면 claude.ai 계정으로 로그인. 브라우저가 안 열리면 `c`를 눌러 로그인 URL을 복사해 직접 연다. 브라우저에 코드가 보이면 터미널의 `Paste code here if prompted`에 붙여 넣는다.
3. `Login successful`이 뜨고 `Enter`.
4. 자격 증명은 Mac은 키체인, Windows는 `%USERPROFILE%\.claude\.credentials.json`에 저장되어 다음부터는 묻지 않는다. 계정을 바꾸려면 세션 안에서 `/login`, 로그아웃은 `/logout`.

처음 여는 폴더에서는 **신뢰(trust) 확인 대화상자**가 뜬다. 내 폴더면 수락. 보안 문서는 홈 폴더에서 바로 시작하면 신뢰가 저장되지 않아 매번 묻는다며 **프로젝트 폴더에서 시작하라**고 한다(0-1).

세션 조작(터미널 가이드·대화형 모드 문서):

| 하고 싶은 것 | 방법 |
|---|---|
| 메시지 보내기 | 입력 후 `Enter` |
| 줄 바꿈 | `\` 뒤 `Enter`, 또는 `Shift+Enter` |
| Claude 멈추기 | `Esc` |
| 명령 목록 | `/help`, 또는 `/`만 쳐서 메뉴 보기 |
| 파일 지목 | `@app.js`처럼 `@` 뒤 경로 (자동 완성) |
| 셸 명령 직접 실행 | `!ls`처럼 `!`로 시작 |
| 이전 입력 | 위 화살표 |
| 종료 | `exit` 또는 빈 프롬프트에서 `Ctrl+D` 두 번 |

프롬프트 위에 버전·모델·작업 폴더가 표시된다.

**왜 중요한가**: 세션은 **폴더에 묶인다**. 대화 기록은 `~/.claude/projects/`에 저장되고 `claude -c`로 이어 간다. 엉뚱한 폴더에서 열면 Claude가 엉뚱한 파일을 본다.

### 5. 권한 모드(permission mode)

**한 줄 정의**: Claude가 묻지 않고 할 수 있는 행동의 범위. `Shift+Tab`으로 순환한다.

**비유**: 직원의 전결 권한. "읽기만", "서류 수정까지", "계획서만", "알아서 하되 감사팀이 검토".

**실제 예시** (권한 모드 문서):

| 모드 | 묻지 않고 하는 것 | 상태 표시 |
|---|---|---|
| `default` (화면 이름 **Manual**) | 읽기만. 파일 편집·셸 명령은 매번 확인 | `⏸ manual mode on` |
| `acceptEdits` | 읽기 + 파일 편집 + `mkdir`, `touch`, `mv`, `cp` 등 | `⏵⏵ accept edits on` |
| `plan` | 읽고 조사해서 **계획만** 제시. 승인 전엔 수정 금지 | `⏸ plan mode on` |
| `auto` | 별도 분류 모델이 위험한 행동만 차단, 나머지는 자동 | `⏵⏵ auto mode on` |
| `bypassPermissions` | 전부. 문서: "격리된 컨테이너·VM에서만" | `⏵⏵ bypass permissions on` |

문서에 따르면 최신 버전(v2.1.283 이상)의 터미널 세션은 **auto 모드로 시작**한다. 초보 단계에서는 `claude --permission-mode default`로 Manual에서 시작하길 권한다. Claude가 무엇을 하려는지 **전부 눈으로 보며** 배우기 위해서다. Manual에서도 `ls`, `cat`, `git status` 같은 읽기 전용 명령은 묻지 않는다.

권한 요청 화면(문서 예시)은 무엇을 하려는지와 선택지를 보여 준다. **Yes** / **Yes, and don't ask again for: npm test \*** / **Yes, and switch to auto mode** / **No**. "don't ask again"은 `.claude/settings.local.json`에 규칙으로 저장된다. 승인 전에 **명령 문자열을 끝까지 읽는 습관**이 이 단원의 핵심이다.

**왜 중요한가**: 보안 문서: "Manual 모드는 읽기 전용으로 시작하고, 편집·명령 실행 전에 묻는다." 이 한 줄이 내 컴퓨터를 지킨다.

### 6. 위험한 명령 주의

**한 줄 정의**: 되돌릴 수 없는 명령(삭제, 외부 전송, 결제)은 승인 전에 반드시 읽는다.

**실제 예시**:
- **삭제**: 0-2의 `rm`은 영구 삭제다. Claude Code는 안전장치로 루트, 홈 폴더, 작업 폴더와 그 상위 등을 **critical path**로 정해 `rm`/`rmdir`를 어떤 허용 규칙으로도 자동 승인하지 않고, `.git` 같은 **protected path** 쓰기도 자동 승인하지 않는다. 그래도 프로젝트 안의 파일 삭제는 승인하면 바로 실행된다.
- **네트워크**: `curl`, `wget`처럼 인터넷에서 가져오는 명령은 Manual에서 다른 명령처럼 묻는다. 모르는 주소면 No.
- **`--dangerously-skip-permissions`**: 모든 확인을 끈다. 문서: "컨테이너, VM처럼 호스트를 망칠 수 없는 격리 환경에서만". 인터넷에서 이 플래그를 권하는 글을 봐도 내 컴퓨터에서는 쓰지 않는다.
- **프롬프트 인젝션(prompt injection)**: 파일이나 웹 페이지에 숨은 지시문이 Claude를 조종하려는 공격. 문서의 권고: 제안된 명령을 검토하고, 신뢰할 수 없는 내용을 그대로 Claude에게 붓지 말라.
- **되돌리기**: 프롬프트마다 **체크포인트**가 생긴다. `Esc` 두 번 또는 `/rewind`로 코드·대화를 이전 시점으로 복원한다. 단, **Bash 명령으로 바뀐 파일은 추적되지 않는다**(`rm`, `mv`로 지운 건 복원 불가). 영구 안전망은 Git(5단원)이다.

**왜 중요한가**: lesson-01의 "망가져도 `git checkout`으로 돌릴 수 있다"는 Git이 있을 때 얘기다. 되돌릴 수 있는 것과 없는 것을 구분하면 과감하게 실험할 수 있다.

### 7. 컨텍스트와 대화 관리

**한 줄 정의**: 컨텍스트 윈도우는 Claude의 작업 기억. 대화·읽은 파일·명령 출력이 쌓이며, 가득 차면 성능이 떨어진다.

**실제 예시** (베스트 프랙티스·비용 문서): 관련 없는 작업으로 넘어갈 땐 `/clear`로 비운다. 같은 작업을 이어 가며 공간만 확보하려면 `/compact`. 무엇이 공간을 차지하는지는 `/context`. 같은 지적을 두 번 이상 했다면 `/clear` 후 더 구체적인 요청으로 다시 시작하는 게 낫다. 요청은 구체적으로: "버그 고쳐"보다 "잘못된 비밀번호 입력 후 빈 화면이 뜨는 로그인 버그 고쳐".

**왜 중요한가**: 긴 세션 하나가 하루치 한도를 먹을 수 있다. `/clear` 습관이 곧 절약이다.

## 따라하기

이 저장소 `todo-app`이 바탕화면에 있다고 가정한다. 유료 구독이 있어야 한다.

### 1. 설치와 확인

Mac은 터미널에, Windows는 **PowerShell**에(프롬프트 앞 `PS` 확인) 핵심 개념 3의 명령을 붙여 넣고 기다린다. 끝나면 **새 터미널**에서:

```bash
claude --version
claude doctor
```

버전이 나오면 `setup-log.md`에 기록한다. `command not found`면 흔한 실수 표.

### 2. 프로젝트 폴더에서 로그인

```bash
cd ~/Desktop/todo-app
claude
```
```powershell
cd $Env:USERPROFILE\Desktop\todo-app
claude
```

브라우저 로그인 → `Login successful` → `Enter`. 신뢰 대화상자가 뜨면 수락. 프롬프트 위의 폴더 경로가 `todo-app`으로 끝나는지 본다. `Shift+Tab`을 눌러 상태 표시가 `⏸ manual mode on`이 되게 한다(처음 몇 주는 Manual).

### 3. 읽기만 하는 질문 세 개

```text
이 프로젝트는 무엇을 하는 앱이야? 파일 세 개의 역할을 한 줄씩 설명해 줘
```
```text
@app.js 에서 calculateBalance 함수가 하는 일을 초보자에게 설명해 줘
```
```text
@docs/lesson-01b.md 의 레벨 계산식이 app.js 어디에 있는지 찾아 줘
```

Claude가 파일을 읽는 동안 화면에 어떤 도구를 쓰는지 본다. 읽기만 하므로 권한 요청이 없거나 거의 없다. 답이 lesson-01 내용과 맞는지 **직접 대조**한다.

### 4. 계획 모드로 숙제 설계

`Shift+Tab`을 눌러 `⏸ plan mode on`으로 바꾼다(또는 메시지 앞에 `/plan`).

```text
lesson-01 숙제 3번: 잔액 아래에 "총 N건"을 표시하고 싶어. 어떤 파일의 어디를 어떻게 바꿀지 계획만 세워 줘. 아직 수정하지 마
```

계획이 나오면 선택지가 뜬다. 문서 기준: **Yes, and use auto mode** / **Yes, manually approve edits** / **No, keep planning**. 계획이 lesson-01의 힌트(`index.html`에 `<p id="count">`, `app.js`의 `getElementById`, `render()`에서 `textContent`)와 비슷한지 읽고, **Yes, manually approve edits**를 고른다.

### 5. 편집을 하나씩 승인하고 검증

이제 Claude가 파일을 고치겠다고 **하나씩 묻는다**. 각 요청에서 바뀌는 줄(diff)을 읽고 `Yes`. 끝나면 브라우저에서 `index.html`을 새로고침해 "총 N건"이 나오는지 본다. 내역을 하나 추가해 숫자가 느는지 확인한다. 마음에 안 들면 `Esc` 두 번 → **Restore code and conversation**으로 되돌린다.

### 6. Git으로 남기기

```text
방금 바꾼 내용을 설명하는 메시지로 커밋해 줘
```

`git commit` 실행 권한을 물으면 명령을 읽고 `Yes`. 0-3에서 이름·이메일을 설정했으므로 커밋이 된다. 권한 화면의 명령 문자열을 끝까지 읽었는가? 이것이 습관이 되어야 한다.

### 7. 사용량 확인과 종료

`/usage`로 사용량을 본다. `/clear`로 대화를 비우고 `exit`로 나온다. `setup-log.md`에 "첫 대화 완료"를 적는다.

## 확인 퀴즈

**1. Manual 모드에서 Claude가 묻지 않고 실행하는 것과 묻는 것은?**

<details><summary>정답과 해설</summary>

묻지 않음: 파일 읽기, 검색, `ls`·`cat`·`git status` 같은 읽기 전용 명령. 묻는 것: 파일 편집·생성, 그 외 셸 명령, 웹 요청. 권한 문서의 "Read-only는 승인 불필요, Bash와 파일 수정은 승인 필요"가 근거다.
</details>

**2. 권한 요청에 `rm -rf node_modules`가 떴다. 무엇을 확인하고 어떻게 답하나?**

<details><summary>정답과 해설</summary>

경로가 프로젝트 안의 `node_modules`인지, 내 요청에 필요한 삭제인지 읽는다. `rm`은 영구 삭제이고 Bash 변경은 체크포인트로 복원되지 않는다. 확신이 없으면 **No**를 고르고 이유를 묻는다.
</details>

**3. `Esc` 두 번(또는 `/rewind`)으로 되돌릴 수 있는 것과 없는 것은?**

<details><summary>정답과 해설</summary>

되돌림: Claude의 파일 편집 도구로 바꾼 파일과 대화. 안 됨: Bash 명령(`rm`, `mv`, `cp`)으로 바뀐 파일, 외부 시스템 변경. 체크포인트 문서가 "Git의 대체가 아니다"라고 명시한다.
</details>

**4. 구독을 쓰는데 `/status`에서 API 키가 활성이라고 나온다. 원인과 조치는?**

<details><summary>정답과 해설</summary>

`ANTHROPIC_API_KEY` 환경변수가 설정되어 있고 승인했기 때문. 이러면 API 요금이 나간다. `unset ANTHROPIC_API_KEY`(0-2 환경변수) 후 `/status`로 구독이 활성인지 확인한다.
</details>

**5. 관련 없는 두 작업(가계부 기능 추가 → 헬스 기록 설계)을 한 세션에서 이어 하면 왜 나쁜가?**

<details><summary>정답과 해설</summary>

컨텍스트에 무관한 내용이 쌓여 성능이 떨어지고 사용 한도를 낭비한다. 베스트 프랙티스 문서의 "kitchen sink session" 실수다. 작업 사이에 `/clear`.
</details>
