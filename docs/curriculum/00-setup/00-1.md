# 0-1. 컴퓨터는 어떻게 일하는가: 파일, 폴더, 경로, 확장자, 프로그램과 프로세스

| 과정 | 0. 준비: 개발 환경 만들기 |
|---|---|
| 예상 시간 | 2시간 |
| 선수 단원 | 없음 |
| 경험치 | 40 |

## 이 단원을 마치면

- `C:\Users\철수\Desktop\todo-app\index.html` 같은 경로를 보고 "어디에 있는 무슨 파일"인지 읽을 수 있다.
- 절대 경로와 상대 경로의 차이, `..`와 `/`의 뜻을 안다.
- `.html` `.js` `.css` `.md` `.py` `.csv` 같은 확장자를 보고 "어떤 프로그램이 여는 어떤 종류의 파일"인지 안다.
- "프로그램"과 "프로세스"가 어떻게 다른지 비유로 설명할 수 있다.
- 이 저장소(나의 1인 회사 앱)의 파일 구조를 그림으로 그릴 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

코딩을 배우면 결국 하는 일은 딱 두 가지다. **파일을 만들고 고치는 것**, 그리고 **그 파일을 프로그램으로 실행하는 것**. 그런데 많은 초보자가 여기서 막힌다. "파일을 어디에 저장했는지 모르겠다", "분명 만들었는데 브라우저가 못 찾는다". 이 문제의 90%는 코드가 아니라 **경로**를 몰라서 생긴다.

주식으로 비유하면 이렇다. 계좌번호를 모르면 아무리 좋은 종목을 골라도 돈을 보낼 수 없다. 파일 경로는 **파일의 계좌번호**다. 앞으로 터미널(0-2), Claude Code(0-4), Git(5단원), 자동매매 스크립트(4단원) 전부가 "이 경로에 있는 이 파일"이라는 말로 시작한다.

그리고 12월부터 매매 복기, 헬스 기록, 가계부를 전부 파일로 쌓을 것이다. 처음부터 이름과 폴더 규칙을 세우면, 나중에 AI 직원(11단원)에게 "이 폴더 읽고 이번 달 매매 요약해 줘"라고 시킬 수 있다. 정리 안 된 폴더는 AI도 못 읽는다.

## 핵심 개념

### 1. 파일(file)

**한 줄 정의**: 이름이 붙은 데이터 덩어리. 컴퓨터가 저장하고 꺼내 쓰는 최소 단위.

**비유**: 서류 한 장. 매매일지 한 장, 영수증 한 장. 내용(글자·숫자·그림)이 있고, 겉에 이름표(파일 이름)가 붙어 있다.

**실제 예시**: 이 저장소에는 파일이 이렇게 있다.

```
index.html   ← 화면에 뭐가 있는지 (건물 뼈대)
style.css    ← 어떻게 보이는지 (인테리어)
app.js       ← 어떻게 움직이는지 (전기 배선)
README.md    ← 이 프로젝트 소개 글
```

lesson-01의 "파일 세 개의 역할" 표가 바로 이것이다. 세 파일 모두 **그냥 글자로 된 문서**라서 메모장으로 열어도 내용이 보인다. 코드 파일은 "규칙에 맞게 쓴 텍스트 파일"일 뿐이다.

**왜 중요한가**: 코딩은 결국 텍스트 파일을 쓰는 일이다. 워드(.docx)나 한글(.hwp) 문서는 서식 정보가 섞여 있어 코드 파일로 쓸 수 없다. 0-3에서 설치할 VS Code는 이 텍스트 파일을 편하게 쓰는 전용 편집기다.

### 2. 폴더(folder) = 디렉터리(directory)

**한 줄 정의**: 파일과 다른 폴더를 담는 상자. 터미널에서는 "디렉터리"라고 부르며 같은 뜻이다.

**비유**: 서류함의 칸. "2026년 → 12월 → 매매일지" 처럼 칸 안에 칸을 만들 수 있다. MDN(웹 기술 공식 문서)은 아이콘으로 볼 땐 "폴더", 명령어로 다룰 땐 "디렉터리"라 부른다고 설명한다. 같은 것이다.

**실제 예시**: 이 저장소의 구조를 그려 보면 이렇다. (`/`가 붙은 것이 폴더)

```
todo-app/
├── index.html
├── style.css
├── app.js
├── README.md
└── docs/
    ├── ROADMAP.md
    ├── lesson-01.md
    ├── lesson-01b.md
    └── curriculum/
        ├── OUTLINE.md
        ├── modules.json
        └── 00-setup/
            └── 00-1.md   ← 지금 읽는 파일
```

MDN "파일 다루기" 문서는 웹사이트 프로젝트를 `index.html` 하나, `images`·`styles`·`scripts` 폴더로 정리하라고 권한다. 우리 앱은 작아서 전부 최상위에 두었지만, 커지면 같은 식으로 쪼갠다.

**왜 중요한가**: 폴더 하나가 곧 "프로젝트 하나"다. Claude Code도 "프로젝트 폴더로 이동한 뒤 실행"하며(0-4), 그 폴더 안의 파일만 자유롭게 읽고 고친다. 폴더가 프로젝트의 울타리다.

### 3. 경로(path)

**한 줄 정의**: 파일이나 폴더가 어디 있는지를 나타내는 주소 문자열.

**비유**: 택배 주소. "서울시 강남구 테헤란로 1길 2 3층"처럼 큰 단위에서 작은 단위로 내려간다. 경로도 "드라이브 → 사용자 → 폴더 → 파일" 순서로 적는다.

**실제 예시**: 같은 `index.html`이라도 운영체제(OS)마다 주소를 적는 법이 다르다.

| | Windows | Mac |
|---|---|---|
| 홈 폴더 | `C:\Users\철수` | `/Users/철수` |
| 바탕화면의 프로젝트 | `C:\Users\철수\Desktop\todo-app` | `/Users/철수/Desktop/todo-app` |
| 그 안의 index.html | `C:\Users\철수\Desktop\todo-app\index.html` | `/Users/철수/Desktop/todo-app/index.html` |
| 칸을 나누는 기호 | `\` (역슬래시, 한글 자판에선 `₩`로 보이기도 함) | `/` (슬래시) |

Node.js 공식 문서(`path` 모듈): 경로 구분자 `path.sep`은 Windows에서 `\`, POSIX(Mac·Linux)에서 `/`이며, Windows는 `/`도 받아 준다. 그래서 MDN은 "Windows에서 개발하더라도 HTML 코드 안에서는 `/`를 쓰라"고 한다.

경로에는 두 종류가 있다.

- **절대 경로(absolute path)**: 맨 꼭대기부터 전부 적은 주소. Windows는 `C:\`처럼 드라이브 문자로, Mac은 `/`로 시작한다. Node.js 문서의 예: `path.isAbsolute('/foo/bar')`는 `true`, `path.isAbsolute('bar\\baz')`는 `false`.
- **상대 경로(relative path)**: "지금 있는 곳"을 기준으로 적은 주소. MDN의 규칙:
  - 같은 폴더의 파일: 파일 이름만. 예 `my-image.jpg`
  - 하위 폴더의 파일: 폴더 이름과 `/`를 앞에. 예 `subdirectory/my-image.jpg`
  - 상위 폴더의 파일: 점 두 개. 예 `../my-image.png`
  - 섞어 쓰기: `../subdirectory/another-subdirectory/my-image.png`

특수 기호 세 가지는 외우자.

| 기호 | 뜻 | 예 |
|---|---|---|
| `.` | 지금 있는 폴더 | `./app.js` = 여기 있는 app.js |
| `..` | 한 칸 위 폴더 | `../ROADMAP.md` = 위 폴더의 ROADMAP.md |
| `~` | 내 홈 폴더 (Mac/Linux 표기. Windows에선 `%USERPROFILE%`) | `~/.claude` = `C:\Users\철수\.claude` |

**왜 중요한가**: 이미지가 안 뜨는 문제, "파일을 찾을 수 없습니다" 에러, Claude Code가 엉뚱한 폴더를 여는 문제. 전부 경로 문제다. 경로를 읽을 줄 알면 에러 메시지의 절반을 스스로 해석할 수 있다.

### 4. 확장자(extension)

**한 줄 정의**: 파일 이름 맨 끝 `.` 뒤의 글자. 파일의 종류를 알려 주는 꼬리표.

**비유**: 주식 종목 뒤의 시장 구분(코스피/코스닥)처럼, 이름만 봐도 "어느 동네 물건인지" 알게 해 주는 표시.

**실제 예시**: 앞으로 자주 만날 확장자.

| 확장자 | 종류 | 여는 프로그램 | 이 과정에서 |
|---|---|---|---|
| `.html` | 웹 페이지 구조 | 브라우저, 편집기 | 2단원 |
| `.css` | 웹 페이지 꾸밈 | 브라우저, 편집기 | 2단원 |
| `.js` | JavaScript 코드 | 브라우저, Node.js | 1·2단원 |
| `.py` | Python 코드 | Python | 3단원 |
| `.md` | 마크다운 문서(이 파일) | 편집기 | 곳곳에서 |
| `.json` | 데이터 묶음(`modules.json`) | 편집기, 코드 | 1-6 |
| `.csv` | 표 데이터(주가 내려받기) | 엑셀, pandas | 3-6 |
| `.exe` / `.app` | 실행 프로그램(Windows / Mac) | 운영체제 | |

Node.js `path.extname` 문서의 예가 규칙을 정확히 보여 준다. `'index.html'` → `'.html'`, `'index.coffee.md'` → `'.md'`(마지막 점 기준), `'index'` → `''`(없음), `'.index'` → `''`(맨 앞 점은 확장자가 아님).

**주의**: MDN 한국어 문서는 Windows의 **알려진 확장자 자동 숨김** 옵션 때문에 파일 이름을 보는 데 문제가 생길 수 있다고 경고한다. `index.html`이 `index`로 보이면 이것 때문이다. 따라하기에서 끈다.

**왜 중요한가**: 확장자를 보면 "이 파일은 누가 실행하나"를 안다. `.js`는 브라우저나 Node.js가, `.py`는 Python이 실행한다. 0-3에서 그 "실행할 프로그램"들을 설치한다. 확장자 하나 틀려서(`.txt`로 저장) 코드가 안 도는 실수는 정말 흔하다.

### 5. 파일 이름 규칙

**한 줄 정의**: 소문자, 공백 없이, 단어 사이는 하이픈(`-`).

**비유**: 주문서에 "삼성 전자"처럼 띄어 쓰면 전산이 두 종목으로 인식할 수 있다. 파일도 마찬가지다.

**실제 예시**: MDN 한국어 문서의 근거 두 가지.
1. 많은 컴퓨터(특히 웹 서버)는 대소문자를 구분한다. `MyImage.jpg`를 `myimage.jpg`로 부르면 못 찾는다.
2. 공백은 시스템마다 다르게 처리되어, 어떤 서버는 `%20`으로 바꿔 링크가 깨진다. 밑줄(`_`)보다 하이픈(`-`)이 낫다.

이 저장소의 `lesson-01.md`, `modules.json`, `00-setup`도 전부 소문자·하이픈이다. 날짜는 `2026-12-01`처럼 `연-월-일`로 쓰면 이름순 정렬이 곧 날짜순이 된다(app.js의 `date` 필드도 `"2026-10-21"` 형태다).

**왜 중요한가**: 지금 습관을 들이면 "파일명에 공백이 있어서 스크립트가 터지는" 문제를 겪지 않는다. Claude Code에게 파일 이름을 말로 전달할 때도 오해가 없다.

### 6. 프로그램(program)과 프로세스(process)

**한 줄 정의**: 프로그램은 디스크에 저장된 실행 파일, 프로세스는 그 프로그램이 메모리에 올라가 **지금 돌고 있는 상태**.

**비유**: 프로그램은 레시피(종이), 프로세스는 지금 불 위에서 요리 중인 냄비. 같은 레시피로 냄비 두 개를 올릴 수 있듯, 브라우저 창을 두 개 띄우면 프로세스도 둘이다. HTS 설치 파일(프로그램)과 켜 놓은 HTS 창(프로세스)의 차이다.

**실제 예시**:
- `index.html`을 더블클릭하면 → 브라우저 **프로그램**이 실행되어 **프로세스**가 되고, 그 프로세스가 `index.html`을 읽어 화면을 그린다. 파일은 가만히 있고, 프로세스가 일한다.
- 0-4에서 터미널에 `claude`라고 치면 → Claude Code 프로그램이 프로세스로 떠서, 내가 `exit`를 칠 때까지 살아 있다(Claude Code 문서: `exit`를 치거나 빈 프롬프트에서 `Ctrl+D`를 두 번).
- 프로세스는 각자 "지금 어느 폴더에서 일하는 중인지"를 안다. 이것이 **작업 디렉터리(working directory)**다. Node.js 문서의 `process.cwd()`가 "현재 작업 디렉터리를 돌려주는" 함수이고, 0-2의 `pwd` 명령이 같은 역할이다.

**왜 중요한가**: "파일을 고쳤는데 반영이 안 돼요"의 흔한 원인이 **이미 떠 있는 프로세스가 옛날 내용을 들고 있어서**다. 새로고침, 터미널 새 창, 프로그램 재시작이 해결책인 이유다. 0-3에서 "설치 후 터미널을 새로 열어라"가 반복되는 것도 같은 이유다.

### 7. 홈 폴더(home directory)

**한 줄 정의**: 내 계정의 기본 폴더. MDN: "모든 운영체제는 기본 설정이라면 터미널을 홈 디렉터리에서 연다." Windows는 `C:\Users\이름`, Mac은 `/Users/이름`. Claude Code 설정 폴더 `~/.claude`는 Windows에서 `%USERPROFILE%\.claude`로 풀린다. 점(`.`)으로 시작하는 항목은 설정용 숨김 항목인 경우가 많다.

**왜 중요한가**: 터미널은 홈에서 시작하므로 프로젝트 폴더로 "이동"해야 일을 할 수 있다. Claude Code 보안 문서도 **홈 폴더가 아니라 프로젝트 폴더에서 시작하라**고 권한다(홈 폴더는 신뢰 설정이 저장되지 않아 매번 물어본다).

## 따라하기

이번 단원은 설치가 필요 없다. 탐색기(Windows)나 Finder(Mac)만 있으면 된다. 명령어는 0-2에서 배우니 여기선 마우스로 한다.

### 1. 프로젝트 폴더의 위치를 확인한다

이 저장소(`todo-app` 폴더)를 찾아 열고 아래를 확인한다.

- `index.html`, `style.css`, `app.js`, `README.md` 네 파일이 보이는가
- `docs` 폴더가 보이는가. 그 안에 `curriculum` 폴더, 그 안에 `00-setup` 폴더가 있는가

이제 종이에(또는 메모장에) 이 파일의 **절대 경로**를 적어 본다. 예를 들어 바탕화면에 있다면:

- Windows: `C:\Users\내이름\Desktop\todo-app\docs\curriculum\00-setup\00-1.md`
- Mac: `/Users/내이름/Desktop/todo-app/docs/curriculum/00-setup/00-1.md`

"내이름" 자리에 실제 계정 이름을 넣는다. 탐색기 주소창(Windows)이나 Finder의 정보 보기(Mac)에서 실제 경로를 볼 수 있다.

### 2. 확장자가 보이게 한다 (Windows)

탐색기에서 `index.html`이 `index`로만 보이면 "알려진 확장자 자동 숨김"이 켜져 있는 것이다. MDN은 "폴더 옵션에서 알려진 확장자 자동 숨김을 선택 해제"하라고 하며, Windows 버전마다 위치가 달라 인터넷 검색을 권한다. 끄고 나면 `index.html`, `app.js`처럼 확장자가 전부 보여야 한다. Mac은 Finder 설정에서 확장자 표시를 켠다(메뉴 이름은 Apple 도움말에서 확인).

### 3. 같은 파일을 두 프로그램으로 열어 본다

1. `index.html`을 더블클릭한다. 브라우저가 열리고 "나의 1인 회사" 지도가 보인다. 브라우저 **프로세스**가 파일을 읽어 화면으로 그린 것이다.
2. 같은 `index.html`을 오른쪽 클릭 → 연결 프로그램(Windows) / 다음으로 열기(Mac)로 메모장 또는 텍스트 편집기에서 연다. 글자로 된 코드가 보인다. **같은 파일인데 여는 프로그램에 따라 다르게 보인다.**
3. 아무것도 고치지 말고 닫는다(실수로 고쳤다면 저장하지 않고 닫는다).

### 4. 코드 안의 경로를 읽어 본다

`index.html`을 텍스트로 연 상태에서 다음 두 줄을 찾는다.

```html
<link rel="stylesheet" href="style.css">
```

```html
<script src="app.js"></script>
```

`style.css`와 `app.js`는 **상대 경로**다. 폴더 이름 없이 파일 이름만 있으니 MDN 규칙 "같은 디렉터리의 파일"이다. `index.html`과 같은 폴더에 두 파일이 있어야 동작한다.

반면 `style.css`의 첫 부분에는 `src: url("https://cdn.jsdelivr.net/...DungGeunMo.woff")`처럼 `https://`로 시작하는 **인터넷 주소**가 있다. 내 컴퓨터가 아니라 인터넷에서 글꼴 파일을 가져온다. 주석에 "인터넷이 안 되면 기본 폰트로 대체된다"고 적혀 있는 이유다.

실험: `style.css`의 이름을 `style2.css`로 바꾸고 브라우저에서 새로고침해 보라. 꾸밈이 사라진 밋밋한 화면이 나온다. `style.css`라는 주소에 파일이 없기 때문이다. 확인했으면 **반드시 `style.css`로 되돌린다.**

### 5. 나의 기록 폴더를 설계한다

12월부터 쌓을 기록의 폴더 구조를 **이름 규칙에 맞게** 만든다. 바탕화면에 아래처럼 만들어 보자(폴더는 탐색기/Finder에서 "새 폴더").

```
my-company/
├── trading/          ← 매매 복기
│   └── 2026/
│       └── 12/
├── health/           ← 헬스 기록
├── ledger/           ← 가계부 내보내기
└── study/            ← 코딩 공부 메모
```

규칙 점검: 전부 소문자인가, 공백이 없는가, 한글 폴더명을 피했는가(동작은 하지만 터미널에서 입력이 번거롭다). `trading/2026/12/` 안에 메모장으로 `2026-12-01.md`라는 빈 파일을 만든다. 저장할 때 `.txt`가 붙지 않았는지 확인한다(메모장은 "파일 형식: 모든 파일"로 저장해야 `.md`가 유지된다). 이 폴더가 11단원에서 AI 직원들이 읽을 "회사 서류함"이 된다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `index.html`을 열었는데 꾸밈이 없다 | `style.css`가 같은 폴더에 없거나 이름이 다르다 | 같은 폴더에 정확히 `style.css`가 있는지 확인. 대소문자까지 똑같이 |
| 파일이 `index`로만 보여서 `index.html.txt`가 되어 버렸다 | Windows 확장자 숨김 옵션 | 따라하기 2번대로 숨김을 끄고, 이름 끝의 `.txt`를 지운다 |
| 경로의 `\`가 `₩`로 보인다 | 한국어 글꼴 표시 문제 | 같은 문자다. 그대로 써도 된다 |
| 파일을 고쳤는데 브라우저에 반영이 안 된다 | 떠 있는 프로세스가 옛 내용을 들고 있다 | 새로고침. 안 되면 브라우저를 닫고 다시 연다 |
| "파일을 찾을 수 없습니다" | 상대 경로의 기준 폴더가 다르다 | `..` 횟수와 하위 폴더 이름을 한 칸씩 짚어 본다 |

## 확인 퀴즈

**1. Mac에서 홈 폴더가 `/Users/minsu`일 때, 바탕화면의 `todo-app` 폴더 안 `app.js`의 절대 경로는?**

<details><summary>정답과 해설</summary>

`/Users/minsu/Desktop/todo-app/app.js`. Mac은 `/`로 시작하고 `/`로 칸을 나눈다. Windows였다면 `C:\Users\minsu\Desktop\todo-app\app.js`.
</details>

**2. `docs/curriculum/00-setup/00-1.md` 파일 안에서 `docs/ROADMAP.md`를 상대 경로로 가리키면?**

<details><summary>정답과 해설</summary>

`../../ROADMAP.md`

지금 위치는 `00-setup` 폴더. `..` 한 번이면 `curriculum`, 두 번이면 `docs`. 거기에 `ROADMAP.md`가 있다. MDN 규칙 "상위 디렉터리는 점 두 개"를 두 번 적용한 것이다.
</details>

**3. `index.coffee.md`의 확장자는? `.index`의 확장자는?**

<details><summary>정답과 해설</summary>

`.md`, 그리고 없음(빈 문자열).

Node.js `path.extname` 문서의 예 그대로다. 확장자는 **마지막** 점 뒤의 글자이고, 맨 앞의 점은 확장자로 치지 않는다(`.index`는 숨김 파일 표기).
</details>

**4. "브라우저를 두 개 띄워 둔 상태"를 프로그램/프로세스로 설명하면?**

<details><summary>정답과 해설</summary>

프로그램은 하나(디스크의 브라우저 실행 파일), 프로세스는 둘(메모리에서 돌고 있는 창 두 개). 레시피 하나로 냄비 두 개를 올린 상태라, 하나를 닫아도 다른 하나는 멀쩡하다.
</details>

**5. 다음 중 파일 이름 규칙에 가장 잘 맞는 것은? (a) `매매 복기 12월.md` (b) `Trading_Review_Dec.md` (c) `trading-review-2026-12.md`**

<details><summary>정답과 해설</summary>

(c). MDN 기준: 소문자, 공백 없음, 단어 구분은 하이픈. (a)는 공백과 한글, (b)는 대문자와 밑줄.
</details>
