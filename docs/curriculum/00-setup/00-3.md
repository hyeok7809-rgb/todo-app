## 왜 배우나 (나에게 어떤 쓸모)

0-1에서 "코드는 텍스트 파일, 실행은 프로그램이 한다"를 배웠다. 이제 그 프로그램들을 들인다. 사무실 개업에 비유하면 **VS Code**는 책상과 모니터(코드를 쓰는 곳), **Node.js**와 **Python**은 전기(코드를 실제로 돌리는 실행기), **Git**은 금고 겸 장부(변경 이력을 남기고 되돌리는 도구)다. 1단원의 JavaScript 실습은 브라우저만으로도 되지만, 3단원 Python 자동화와 4단원 API 호출은 실행기가 있어야 하고, 5단원 Git은 말할 것도 없다.

Claude Code(0-4)와의 관계: 공식 문서에 따르면 기본 설치 방식은 Node.js가 **필요 없다**. 다만 Windows에서는 Git for Windows가 있어야 Bash 도구를 쓴다. 그리고 Claude가 "테스트를 돌려 봤다"고 할 때 실제로 돌리는 것이 Node.js와 Python이다. 실행기가 없으면 Claude도 코드를 검증할 수 없다.

## 핵심 개념

### 1. 버전(version)과 LTS

**한 줄 정의**: 버전은 소프트웨어의 "몇 번째 개정판"인지 나타내는 번호. LTS(Long Term Support, 장기 지원)는 오래 고쳐 주기로 약속한 안정 버전.

**비유**: 스마트폰 OS 업데이트 번호. 최신 베타는 기능이 많지만 가끔 터지고, 안정판은 보수적이지만 믿을 수 있다. 매매로 치면 "검증된 전략"과 "백테스트만 한 전략"의 차이다.

**실제 예시**: Node.js 다운로드 페이지(2026-10-21 확인)는 **v24.22.0을 "Latest LTS"**, v26.12.0을 "Latest Release"(Current)로 표시한다. 공식 릴리스 문서는 LTS가 "치명적 버그를 총 30개월 동안 고쳐 주는" 상태이고 "운영 환경에서는 LTS만 써야 한다"고 못 박는다. 짝수 버전(v22, v24)이 LTS가 된다.

버전 번호 `24.22.0`은 세 덩어리다. 보통 첫 숫자는 호환이 깨질 수 있는 큰 변화, 둘째는 기능 추가, 셋째는 버그 수정이다. Pro Git 책은 "2.0 이후 버전이면 다 잘 동작한다"고 한다.

**왜 중요한가**: 문서에 "Node 22 이상 필요"처럼 버전 조건이 붙는다(Claude Code를 npm으로 설치할 때 실제로 그렇다). 내 버전을 확인할 줄 알아야 조건을 맞춘다. 그리고 **초보자는 LTS를 고른다**.

### 2. 설치 확인 = `--version`

**한 줄 정의**: 설치 직후 터미널에서 버전을 출력해 보는 것이 "설치 성공"의 유일한 증거.

**비유**: 계좌 개설 후 잔고 조회 한 번. 화면이 뜨면 개설된 것이다.

**실제 예시**: 공식 문서에 적힌 확인 명령.

| 도구 | 확인 명령 | 출처 |
|---|---|---|
| Node.js | `node -v`, `npm -v` | Node.js 다운로드 페이지 |
| Python (Windows) | `py --list` (설치된 버전 목록) | Python "Using Python on Windows" |
| Python (Mac) | `python3 --version` | Python 명령줄 문서(`-V`/`--version`) |
| Git | `git --version` | Pro Git 책 |

출력이 나오면 성공, `command not found`/`is not recognized`면 0-2의 PATH 문제다.

**왜 중요한가**: "설치했는데 안 돼요"의 절반은 설치가 안 된 것, 나머지 절반은 PATH에 없는 것이다. 버전 확인 한 줄이 둘을 구분해 준다.

### 3. VS Code: 코드 편집기(editor)

**한 줄 정의**: 코드 전용 텍스트 편집기. 파일 탐색, 색 구분, 터미널 내장, 확장(extension) 설치가 된다.

**비유**: 메모장이 "종이와 연필"이라면 VS Code는 호가창·차트·주문창이 한 화면에 있는 HTS다.

**실제 예시** (VS Code 공식 설치 문서 기준):
- **Windows**: "User setup"이 권장. 관리자 권한이 필요 없고 `%LOCALAPPDATA%\Programs\Microsoft VS Code`에 설치된다. 설치 프로그램이 `%PATH%`에 추가하므로 **터미널을 다시 연 뒤** 폴더에서 `code .`을 치면 그 폴더가 열린다.
- **Mac**: `.dmg`를 열어 `Visual Studio Code.app`을 **Applications**로 끌어다 놓는다. 터미널에서 `code`를 쓰려면 명령 팔레트(`Cmd+Shift+P`)에서 **Shell Command: Install 'code' and optionally 'copilot' commands in PATH**를 실행한다(Copilot CLI는 "No"). 터미널을 다시 연 뒤 `code .`.
- **내장 터미널**: 메뉴 **Terminal > New Terminal**. 공식 문서: "mkdir, git 같은 명령을 독립 터미널처럼 실행할 수 있다."
- **확장 보기**: `Ctrl+Shift+X`(Windows) / `Cmd+Shift+X`(Mac). 0-4의 Claude Code 확장도 여기서 설치한다.

**왜 중요한가**: Claude Code가 고친 파일을 **눈으로 확인하고 직접 손보는 곳**이 VS Code다. AI가 코드를 써 줘도 읽고 검증하는 건 내 몫이다(12단원).

### 4. Node.js: JavaScript 실행기 + npm

**한 줄 정의**: 브라우저 밖에서 JavaScript를 실행하는 프로그램. 패키지 관리자 **npm**이 함께 설치된다.

**비유**: 지금까지 `app.js`는 브라우저라는 "매장"에서만 돌았다. Node.js는 그 코드를 "본사 사무실"(내 컴퓨터, 서버)에서도 돌게 한다. npm은 남이 만든 부품을 가져오는 "부품 도매상"이다. MDN은 패키지 저장소를 "명령줄 도구를 위한 앱스토어"에 비유한다.

**실제 예시**: 다운로드 페이지(nodejs.org/en/download)는 **설치 프로그램(Installer)**과 **패키지 관리자(Package Manager)** 두 방식을 보여 준다. 초보자는 설치 프로그램으로 **LTS(v24)**를 받는다. 확인 명령은 `node -v`, `npm -v`.

**왜 중요한가**: 2-6의 API 호출, 10단원의 Claude API JavaScript 예제, 11단원의 에이전트가 Node.js 위에서 돈다. Claude Code를 npm으로 설치하는 경로(`npm install -g @anthropic-ai/claude-code`)는 Node.js 22 이상이 필요하다(기본 설치 방식은 불필요).

### 5. Python: 자동화의 언어

**한 줄 정의**: 읽기 쉬운 문법으로 데이터 처리·자동화에 가장 많이 쓰이는 언어와 그 실행기.

**비유**: 엑셀 매크로의 상위 호환. 주가 CSV 요약, 텔레그램 알림이 Python 몇십 줄이다(3·4단원).

**실제 예시** (Python 공식 문서 기준):
- **Windows**: python.org/downloads 또는 Microsoft Store에서 받는다. 공식 문서는 두 세대의 설치 방식을 설명한다. 3.13 문서의 **전통 설치 프로그램**은 첫 화면에 "Install Now"와 "Customize installation"이 있고, **"Add Python to PATH"** 옵션을 켜면 터미널에서 `python`과 `pip`를 바로 쓸 수 있다(안 켰다면 설치 프로그램을 다시 실행해 Modify에서 켠다). 최신 문서는 **Python install manager**라는 새 방식을 설명하는데, 설치 후 `python`, `py`, `pymanager` 명령이 생기고 `py list`로 설치된 버전을 본다. **화면에 보이는 대로 따르되, PATH 관련 옵션이 나오면 켠다.**
- **Mac**: python.org/downloads에서 `.pkg`를 받아 더블클릭 → Continue → Agree → Install. 끝나면 Applications의 Python 폴더에서 **Install Certificates.command**를 더블클릭한다. 공식 문서의 경고: macOS에는 Apple이 쓰는 `/usr/bin/python3`가 이미 있는데 **절대 건드리지 말라**. python.org 버전은 `/usr/local/bin/python3`에 들어가 공존한다. 터미널에서는 항상 `python3`로 부른다.
- 가상환경(venv)과 pip는 3-1에서 다룬다.

**왜 중요한가**: 이 과정의 목표 1번 "내 매매·생활 자동화"의 주력 언어다. 한국투자증권 API(4-3), pandas(3-6)가 전부 Python이다.

### 6. Git: 이력 관리

**한 줄 정의**: 파일의 모든 변경 이력을 저장하고, 언제든 과거로 되돌리고, 다른 사람과 합치는 도구.

**비유**: 매매 체결 내역서. 어떤 거래를 언제 했는지 전부 남아 복기가 된다. lesson-01의 "망가져도 `git checkout app.js`로 돌릴 수 있다"가 Git 덕분이다.

**실제 예시** (Pro Git 한국어판 기준):
- **Windows**: git-scm.com/download/win 에서 **Git for Windows**를 받는다. Claude Code 터미널 가이드: 각 화면에서 Next로 기본값 유지, **"Adjusting your PATH environment" 화면은 권장 옵션 유지**. 설치하면 **Git Bash**가 생겨 0-2의 Mac 명령을 Windows에서도 쓸 수 있다.
- **Mac**: 터미널에서 `git --version`을 치면, 없을 경우 Xcode Command Line Tools 설치 안내 창이 뜬다. 설치하면 끝.
- **최초 설정**: 설치 후 딱 한 번, 커밋에 찍힐 이름과 이메일을 등록한다. Pro Git의 명령 그대로:

```bash
git config --global user.name "John Doe"
git config --global user.email johndoe@example.com
```

`--global`은 이 컴퓨터의 모든 저장소에 적용한다는 뜻이고, 설정은 홈 폴더의 `~/.gitconfig`에 저장된다.

**왜 중요한가**: Claude Code는 Git을 "대화로" 쓴다. 퀵스타트의 예시 요청이 `commit my changes with a descriptive message`다. 이름·이메일이 없으면 커밋이 안 된다.

**공식 사이트에서만 받고**(증권사 앱을 공식 스토어에서 받듯이), **설치 후 터미널을 새로 열고**(VS Code 문서: "설치 후 콘솔을 재시작하라"), **즉시 버전을 확인해 기록한다.**

## 따라하기

순서대로 한다. 각 단계 끝에 **반드시 새 터미널을 열어** 확인 명령을 친다. 명령은 Mac → Windows(PowerShell) 순서. 같은 명령이면 한 번만 적었다.

### 1. 설치 기록 파일 만들기

0-2에서 만든 `my-company/study` 폴더에 기록 파일을 만들고, 확인 명령의 출력을 이 파일에 복사해 간다.

```bash
cd ~/Desktop/my-company/study
touch setup-log.md
```
```powershell
cd $Env:USERPROFILE\Desktop\my-company\study
New-Item -Path .\setup-log.md -ItemType File
```

### 2. VS Code

1. code.visualstudio.com 에서 받아 설치한다. Windows는 User setup, Mac은 Applications로 끌어 놓기.
2. Mac은 `Cmd+Shift+P` → **Shell Command: Install 'code' ... in PATH** 실행.
3. **새 터미널**을 열고 프로젝트 폴더로 간 뒤 VS Code로 연다.

```bash
cd ~/Desktop/todo-app
code .
```
```powershell
cd $Env:USERPROFILE\Desktop\todo-app
code .
```

VS Code가 뜨고 왼쪽에 `index.html`, `app.js`가 보이면 성공. 메뉴 **Terminal > New Terminal**로 내장 터미널을 열고 `pwd`/`Get-Location`으로 `todo-app`에 있는지 본다. 기록 파일에 "VS Code 설치, code . 확인"이라고 적는다.

### 3. Node.js

1. nodejs.org/en/download 에서 **LTS**(v24) 설치 프로그램을 받아 실행한다. 기본값으로 진행.
2. **새 터미널**에서:

```bash
node -v
npm -v
```

`v24.`로 시작하는 줄과 npm 버전 줄이 나온다. 두 줄을 기록 파일에 붙여 넣는다.

3. 맛보기: 이 저장소의 `app.js`는 브라우저용이라 Node.js로 바로 돌리진 않는다. 대신 한 줄 계산을 시켜 본다(0-1 lesson의 레벨 계산식).

```bash
node -e "console.log(Math.floor(230 / 100) + 1, 230 % 100)"
```

`3 30`이 나오면 성공. 230 경험치 → Lv.3, 남은 30. (`-e`는 "문자열을 코드로 실행". Node.js `process` 문서 예시에도 나온다.)

### 4. Python

1. **Windows**: python.org/downloads 에서 받아 실행. 화면에 "Add Python to PATH"가 있으면 **켠다**. Install Now. 새 관리자 방식 화면이면 안내대로 진행하고 PATH 추가를 수락한다.
   **Mac**: python.org/downloads 에서 `.pkg` 받아 설치 → 끝나면 **Install Certificates.command** 더블클릭.
2. **새 터미널**에서:

```bash
python3 --version
```
```powershell
py --list
python --version
```

새 관리자 방식이면 `py list`. 버전 줄을 기록 파일에 붙여 넣는다.

3. 맛보기 한 줄. 잔액 계산을 Python으로:

```bash
python3 -c "print(1500000 - 9000 - 4500)"
```
```powershell
python -c "print(1500000 - 9000 - 4500)"
```

`1486500`이 나오면 끝. (`-c`는 Python 명령줄 문서의 "코드를 실행" 옵션.)

### 5. Git

1. **Windows**: git-scm.com/download/win 에서 Git for Windows를 받아 설치. 기본값으로 Next, PATH 화면은 권장 옵션 유지.
   **Mac**: 터미널에서 `git --version`. 설치 안내 창이 뜨면 설치.
2. **새 터미널**에서:

```bash
git --version
git config --global user.name "내 이름"
git config --global user.email 내메일@example.com
git config --global user.name
```

마지막 줄이 방금 넣은 이름을 다시 출력하면 저장된 것이다. Windows 사용자는 시작 메뉴에서 **Git Bash**를 열어 `ls`, `pwd`가 동작하는지 본다.

### 6. 최종 점검

새 터미널 하나에서 네 줄을 연달아 친다.

```bash
code --version
node -v
python3 --version
git --version
```
```powershell
code --version
node -v
python --version
git --version
```

(`code --version`은 VS Code 문서에서 직접 확인하지 못했다. 안 되면 `code .`으로 대신한다.) 네 줄이 전부 버전을 출력하면 개업 준비 끝. 0-2 숙제 3번의 PATH 목록을 다시 뽑아 **새로 생긴 줄**을 찾아본다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 설치 직후 `node -v`가 `not recognized` | 열려 있던 터미널은 옛 PATH | 모든 터미널(VS Code 내장 포함)을 닫고 새로 연다 |
| Windows에서 `python`이 엉뚱하게 반응한다 | PATH 미설정 또는 앱 실행 별칭 | 설치 프로그램 → Modify → PATH 옵션. 시작 메뉴의 "Manage App Execution Aliases"(Python 문서)도 확인. 또는 `py` 사용 |
| Mac `python --version`이 안 된다 | python.org 설치본은 `python3` 이름 | `python3`로 친다 |
| `code .`이 안 된다 | Mac: PATH에 `code` 미등록 / Windows: 터미널 미재시작 | Mac은 명령 팔레트의 Shell Command 실행, 둘 다 새 터미널 |

**2. `node -v`를 쳤더니 `'node' is not recognized`가 나온다. 설치는 분명히 끝났다. 가장 먼저 할 일은?**

<details><summary>정답과 해설</summary>

터미널을 전부 닫고 새로 연다. 설치 프로그램이 PATH를 바꿔도 이미 열린 창은 옛 PATH를 들고 있다(0-2). 그래도 안 되면 0-2의 PATH 점검 명령으로 Node 폴더가 있는지 본다.
</details>

**3. Mac에서 python.org 설치 후 `/usr/bin/python3`를 지우면 더 깔끔할까?**

<details><summary>정답과 해설</summary>

절대 안 된다. Python 공식 문서: 그것은 Apple이 개발 도구용으로 쓰는 것이라 "절대 수정하거나 삭제하지 말라". python.org 버전은 `/usr/local/bin/python3`에 따로 들어가 공존한다.
</details>

**4. `git config --global user.name "홍길동"`에서 `--global`의 뜻과 저장 위치는?**

<details><summary>정답과 해설</summary>

이 컴퓨터의 모든 저장소에 적용. 홈 폴더의 `~/.gitconfig`에 저장된다. `--global`을 빼면 현재 저장소에만 적용된다.
</details>

**5. Claude Code를 쓰려면 Node.js가 반드시 필요한가?**

<details><summary>정답과 해설</summary>

아니다. 설치 문서에 따르면 기본 설치 방식(native)은 Node.js가 필요 없고, npm으로 설치할 때만 Node.js 22 이상이 필요하다. Windows에서는 Git for Windows가 권장된다.
</details>
