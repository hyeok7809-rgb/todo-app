# 0-2. 터미널 첫걸음: 기본 명령어, 경로 이동, 환경변수 개념, Windows(PowerShell)와 Mac 차이

| 과정 | 0. 준비: 개발 환경 만들기 |
|---|---|
| 예상 시간 | 3시간 |
| 선수 단원 | 0-1 |
| 경험치 | 60 |

## 이 단원을 마치면

- 터미널을 열고, 지금 어떤 셸(PowerShell/CMD/zsh)에 있는지 구분할 수 있다.
- `pwd` `ls` `cd` `mkdir` `cat`으로 폴더를 돌아다니고 파일을 만들 수 있다.
- 환경변수가 무엇이고, `PATH`가 왜 "명령을 찾을 수 없습니다" 에러의 범인인지 설명할 수 있다.
- Windows(PowerShell)와 Mac(zsh)에서 같은 일을 하는 명령을 짝지어 쓸 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

Claude Code는 터미널에서 산다. 설치도, 실행도, 로그인도 터미널에서 한다(0-4). 터미널이 낯설면 "Claude가 뭘 했는지" 읽을 수 없어서 위험한 명령을 승인해 버리거나 반대로 아무것도 못 하게 된다. Claude Code 공식 문서에 "터미널을 한 번도 안 써 본 사람을 위한 안내"가 따로 있을 정도다. 이 단원은 그것을 한국어로 더 천천히 풀어 쓴 것이다.

비유하자면 터미널은 **전화 주문**이다. HTS에서 클릭하는 대신 "삼성전자 10주 시장가 매수"처럼 정확한 문장으로 말한다. 문장은 복사·반복·자동화가 된다. 4단원의 매매 스크립트 자동 실행, 9단원의 훅이 전부 "문장으로 시키기"의 연장이다.

## 핵심 개념

### 1. 터미널(terminal)과 셸(shell)

**한 줄 정의**: 터미널은 글자를 입력하고 결과를 보는 창, 셸은 그 글자를 해석해 실행하는 프로그램.

**비유**: 터미널은 전화기, 셸은 전화를 받는 상담원. 상담원(셸)이 다르면 알아듣는 말이 다르다. Windows에는 PowerShell과 CMD가 있고, Mac은 기본이 zsh다.

**실제 예시**: 여는 법(Claude Code 터미널 가이드 기준).
- **Mac**: `Cmd + Space`로 Spotlight를 열고 `Terminal` 입력 후 `Enter`.
- **Windows**: `Win + X`를 누르고 **Windows PowerShell**(또는 **Terminal**)을 고른다.

**Windows에서 꼭 확인할 것**: PowerShell인지 CMD인지. 문서의 구분법은 프롬프트 모양이다.

```
PS C:\Users\YourName>     ← PowerShell (앞에 PS)
C:\Users\YourName>        ← CMD (PS 없음)
```

이 과정은 **PowerShell** 기준이다. Claude Code 설치 명령을 CMD에 넣으면 `'irm' is not recognized`가 나는데, 문서는 이것을 "당신은 CMD에 있다"는 신호라고 설명한다.

**왜 중요한가**: 인터넷의 명령어 예시 대부분은 Mac/Linux 기준이다. "내가 어느 셸에 있는지"가 모든 에러 해결의 1단계다.

### 2. 프롬프트(prompt)와 현재 위치

**한 줄 정의**: 프롬프트는 "입력을 기다리고 있다"는 표시 줄. 보통 현재 폴더가 함께 표시된다.

**비유**: 상담원이 "재무부 창구입니다, 말씀하세요"라고 하는 순간. 어디인지와 준비됐음을 함께 알려 준다.

**실제 예시**: MDN은 "모든 OS는 터미널을 홈 디렉터리에서 연다"고 한다. 현재 위치 확인은 Mac `pwd`, PowerShell `Get-Location`(별칭 `pwd`, `gl`). PowerShell 공식 문서는 정식 이름과 짧은 **별칭(alias)**을 함께 제공한다. 아래 표의 괄호가 공식 별칭이다.

**왜 중요한가**: 모든 명령은 "지금 있는 폴더" 기준이다. 길을 잃으면 `pwd`부터.

### 3. 이동하기 `cd`와 둘러보기 `ls`

**한 줄 정의**: `cd`는 폴더를 바꾸는 명령(Change Directory), `ls`는 폴더 안 목록을 보는 명령(list).

**비유**: 서류함 앞으로 걸어가기(`cd`)와 서랍을 열어 안을 들여다보기(`ls`).

**실제 예시** (MDN 예시 그대로):

```bash
cd Desktop               # 홈에서 바탕화면으로
cd ..                    # 한 칸 위로
cd Desktop/project/src   # 한 번에 깊이 (Windows는 \ 도 가능)
ls                       # 목록
ls -l                    # 자세히 (맨 왼쪽 d가 폴더)
```

| 하는 일 | Mac (zsh) | Windows (PowerShell) |
|---|---|---|
| 폴더 이동 | `cd 폴더` | `Set-Location 폴더` (별칭 `cd`, `chdir`, `sl`) |
| 목록 보기 | `ls`, `ls -l` | `Get-ChildItem` (별칭 `dir`, `ls`, `gci`) |

MDN이 강조하는 습관 둘. **Tab**: `cd D`까지 치고 Tab을 누르면 `Desktop`이 자동 완성된다. **위 화살표**: 방금 친 명령을 다시 부른다.

**왜 중요한가**: Claude Code의 기본 사용법이 "프로젝트 폴더로 `cd`한 뒤 `claude`"다.

### 4. 만들기·보기·복사·이동·삭제

**한 줄 정의**: 파일과 폴더를 다루는 다섯 동사.

**실제 예시** (MDN 예시와 PowerShell 공식 별칭):

| 하는 일 | Mac (zsh) | Windows (PowerShell) |
|---|---|---|
| 폴더 만들기 | `mkdir trading` | `New-Item -Path .\trading -ItemType Directory` |
| 빈 파일 만들기 | `touch note.md` | `New-Item -Path .\note.md -ItemType File` |
| 내용 보기 | `cat note.md` | `Get-Content note.md` (별칭 `cat`, `type`, `gc`) |
| 이름 바꾸기/이동 | `mv note.md memo.md` | `Move-Item` (별칭 `mv`, `move`) |
| 복사 | `cp memo.md memo.bak` | `Copy-Item` (별칭 `cp`, `copy`) |
| 삭제 | `rm memo.bak` / 빈 폴더는 `rmdir` | `Remove-Item` (별칭 `rm`, `del`, `rd`, `ri`) |

**경고**: MDN은 `rm`이 "영구 삭제이며 휴지통으로 되돌릴 수 없다"고 못 박고, 폴더째 지우는 `rm -r`은 "위험하다"고 한다. Claude Code가 `rm -rf ...`를 실행하겠다고 물어보면 이 단원을 떠올리자(0-4).

**왜 중요한가**: Claude Code도 같은 명령을 쓴다. 권한 모드 문서에서 `acceptEdits` 모드가 자동 승인하는 명령이 정확히 `mkdir`, `touch`, `rm`, `rmdir`, `mv`, `cp`, `sed`다.

### 5. 옵션(option)과 플래그(flag)

**한 줄 정의**: 명령 뒤에 붙여 동작을 바꾸는 추가 지시. 보통 `-글자` 또는 `--단어`. **비유**: 주문에 붙이는 "IOC" 조건. 본 주문은 같고 조건만 바뀐다. **예시**: MDN의 `ls -l`(자세히), 합쳐 쓰는 `ls -lah`, Claude Code 문서의 `claude --version`. 각 명령의 옵션은 `man ls`로 본다(`q`로 종료).

### 6. 환경변수(environment variable)

**한 줄 정의**: 운영체제가 들고 있다가 모든 프로그램에게 나눠 주는 "이름=값" 메모.

**비유**: 사무실 벽의 공지판. 단, 직원(프로세스)은 **들어올 때 공지판을 복사해서 들고 간다**. 그래서 이미 들어온 직원은 옛 공지를 들고 있다(0-1의 "터미널을 새로 열어라"의 진짜 이유).

**실제 예시**: Node.js 문서의 `process.env` 출력 예에는 `"USER": "maciej"`, `"PATH": "~/.bin/:/usr/bin:/bin:..."`, `"HOME": "/Users/maciej"`가 있다. 읽고 쓰는 법은 OS마다 다르다.

| 하는 일 | Mac (zsh) | Windows (PowerShell) |
|---|---|---|
| 값 보기 | `echo $HOME` | `$Env:USERPROFILE` |
| 이 창에서만 설정 | `export API_TIMEOUT_MS="1200000"` | `$Env:Foo = 'An example'` |

Claude Code 문서: `export`로 만든 변수는 "그 터미널 세션 동안만" 유지되고, 영구히 하려면 `~/.zshrc` 같은 셸 설정 파일에 `export` 줄을 추가한다. Windows 영구 설정은 세 가지(PowerShell 문서): 프로필 파일, `[Environment]::SetEnvironmentVariable('Foo', 'Bar', 'User')`, **시스템 제어판 → 시스템 → 고급 시스템 설정 → 고급 탭 → 환경 변수...** 화면. Node.js 문서: Windows는 환경변수 이름의 대소문자를 구분하지 않고, Mac/Linux는 구분한다.

**왜 중요한가**: 4단원에서 API 키를 코드에 적지 않고 환경변수로 넣는다(유출 방지). Claude Code도 `ANTHROPIC_API_KEY`가 있으면 구독 대신 그 키로 과금한다고 경고한다.

### 7. PATH: "명령을 찾을 수 없습니다"의 범인

**한 줄 정의**: `PATH`는 명령을 쳤을 때 운영체제가 실행 파일을 **찾아보는 폴더 목록**을 담은 환경변수.

**비유**: 상담원의 "담당 부서 연락처 목록". `claude`라고 말하면 목록의 폴더를 순서대로 뒤져 실행 파일을 찾는다. 없으면 "그런 담당자 없습니다"(command not found).

**실제 예시**: Node.js 문서에 따르면 PATH 안의 폴더들은 Mac에선 `:`(`/usr/bin:/bin:/usr/local/bin`), Windows에선 `;`(`C:\Windows\system32;C:\Windows`)로 구분된다. Claude Code 설치 문제 해결 문서는 PATH를 이렇게 점검한다.

```bash
# Mac: PATH를 한 줄에 하나씩 보고 ~/.local/bin이 있는지 확인
echo $PATH | tr ':' '\n' | grep -Fx "$HOME/.local/bin"
```

```powershell
# Windows PowerShell: 같은 확인
$env:PATH -split ';' | Select-String '\.local\\bin'
```

없으면 추가한다. 같은 문서의 명령 그대로:

```bash
# Mac (zsh). 설정 파일에 한 줄 추가하고 지금 창에도 적용
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

```powershell
# Windows PowerShell. 사용자 PATH에 추가. 실행 후 새 창
$currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')
```

**왜 중요한가**: 0-3·0-4의 가장 흔한 에러 `command not found`의 원인은 거의 항상 PATH다.

### 8. Windows와 Mac 차이 한눈에

| 항목 | Windows (PowerShell) | Mac (zsh) |
|---|---|---|
| 프롬프트 | `PS C:\Users\이름>` | `이름@컴퓨터 ~ %` (설정마다 다름) |
| 홈 폴더 | `C:\Users\이름` = `$Env:USERPROFILE` | `/Users/이름` = `$HOME` = `~` |
| 경로 구분 | `\` (`/`도 허용) | `/` |
| PATH 구분 | `;` | `:` |
| 환경변수 읽기 | `$Env:이름` | `$이름` |
| 셸 설정 파일 | PowerShell 프로필(`$PROFILE`) | `~/.zshrc` |

**Windows 사용자의 선택지 둘**. (1) **Git Bash**: 0-3에서 설치할 Git for Windows에 딸려 오는 bash 셸. Claude Code 문서: "Git for Windows가 있으면 Bash 도구를, 없으면 PowerShell 도구를 쓴다." (2) **WSL**: Windows 안의 리눅스(Microsoft 문서: 관리자 PowerShell에서 `wsl --install`). 이 과정은 PowerShell + Git Bash로 간다.

## 따라하기

`todo-app` 폴더가 바탕화면에 있다고 가정한다(다른 곳이면 경로를 바꾼다). 각 단계는 Mac → Windows(PowerShell) 순서다. 한 줄 치고 `Enter`, 결과를 읽고, 다음 줄.

### 1. 터미널을 열고 위치를 확인한다

```bash
pwd
```
```powershell
Get-Location
```

Mac은 `/Users/이름`, Windows는 `C:\Users\이름`. 홈 폴더다.

### 2. 프로젝트 폴더로 이동한다

```bash
cd Desktop/todo-app
pwd
```
```powershell
cd Desktop\todo-app
Get-Location
```

`cd D`까지 치고 Tab으로 자동 완성해 본다. 경로 끝이 `todo-app`인지 확인한다.

### 3. 안을 둘러본다

```bash
ls
ls -l
```
```powershell
Get-ChildItem
```

`index.html`, `style.css`, `app.js`, `README.md`, `docs`가 보여야 한다. `ls -l`에서 `docs` 줄 맨 왼쪽이 `d`인지 본다(폴더).

### 4. 파일 내용을 터미널에서 읽는다

```bash
cat docs/ROADMAP.md
```
```powershell
Get-Content docs\ROADMAP.md
```

Claude Code 보안 문서는 `ls`, `cat`, `git status` 같은 **읽기 전용 명령은 묻지 않고 실행**한다고 설명한다. 읽기는 안전하기 때문이다.

### 5. 회사 서류함을 명령어로 만든다

0-1 숙제에서 마우스로 만든 `my-company` 구조를 이번엔 명령으로 만든다. 홈 폴더의 바탕화면에서 시작한다.

```bash
cd ~/Desktop
mkdir my-company
cd my-company
mkdir trading health ledger study
ls
cd trading
touch 2026-12-01.md
ls -l
```
```powershell
cd $Env:USERPROFILE\Desktop
New-Item -Path .\my-company -ItemType Directory
cd my-company
New-Item -Path .\trading, .\health, .\ledger, .\study -ItemType Directory
Get-ChildItem
cd trading
New-Item -Path .\2026-12-01.md -ItemType File
Get-ChildItem
```

(PowerShell 문서: `-Path`는 여러 경로를 쉼표로 받는다.) 0-1 숙제로 폴더가 이미 있다면 `my-company-cli`로 한다. 탐색기/Finder로 확인한다. **마우스로 만든 것과 명령으로 만든 것은 같은 폴더**다.

### 6. 환경변수를 읽고, 만들고, 사라지는 것을 본다

```bash
echo $HOME
echo $PATH | tr ':' '\n'
export MY_COMPANY="나의 1인 회사"
echo $MY_COMPANY
```
```powershell
$Env:USERPROFILE
$Env:PATH -split ';'
$Env:MY_COMPANY = '나의 1인 회사'
$Env:MY_COMPANY
```

`PATH`에 폴더가 여러 줄로 나온다. 0-3에서 도구를 설치하면 여기에 추가된다. 이제 **터미널 창을 하나 더 열고** `echo $MY_COMPANY`(Mac) / `$Env:MY_COMPANY`(Windows)를 쳐 본다. 아무것도 안 나온다. "이 창에서만 설정"을 몸으로 확인한 것이다.

### 7. 위험한 명령을 안전하게 체험한다

연습 파일 하나를 지워 본다. 지우기 전에 반드시 `ls`로 **무엇을 지우는지** 본다.

```bash
cd ~/Desktop/my-company/trading
ls
rm 2026-12-01.md
ls
```
```powershell
cd $Env:USERPROFILE\Desktop\my-company\trading
Get-ChildItem
Remove-Item .\2026-12-01.md
Get-ChildItem
```

휴지통에 없다. 영구 삭제다. 이 감각이 0-4의 권한 요청을 읽을 때 필요하다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `'irm' is not recognized` | PowerShell이 아니라 CMD에 있다 | 창을 닫고 `Win + X` → Windows PowerShell |
| `command not found` / `is not recognized` | PATH에 설치 폴더가 없다 | 핵심 개념 7의 PATH 점검·추가 명령. 끝나면 새 창 |
| 설치했는데 여전히 안 된다 | 열려 있던 창은 옛 PATH | 모든 터미널을 닫고 새로 연다. 편집기 안 터미널이면 편집기 재시작 |
| `rm`으로 지운 파일이 없다 | 영구 삭제 | 되돌릴 수 없다. 5단원 Git이 안전망이다 |

## 확인 퀴즈

**1. 프롬프트가 `C:\Users\minsu>`로 보인다. 어느 셸이며, `irm ... | iex` 설치 명령을 쳐도 되는가?**

<details><summary>정답과 해설</summary>

CMD다. 앞에 `PS`가 없다. `irm`은 PowerShell 명령이라 CMD에서는 `'irm' is not recognized`가 난다. PowerShell을 새로 연다.
</details>

**2. 홈 폴더에서 `cd Desktop/todo-app/docs`로 들어간 뒤 `app.js`를 `cat`으로 보려면?**

<details><summary>정답과 해설</summary>

`cat ../app.js` (Windows: `Get-Content ..\app.js`). 현재 위치는 `docs`, `app.js`는 한 칸 위 `todo-app`에 있다. 또는 `cd ..` 뒤 `cat app.js`.
</details>

**3. `export MY_KEY="abc"`를 친 뒤 새 터미널 창을 열었다. 새 창에서 `echo $MY_KEY`의 결과는?**

<details><summary>정답과 해설</summary>

빈 줄(아무것도 없음). Claude Code 문서: 셸 변수는 "그 터미널 세션 동안만" 유지된다. 지금 창에서 만든 변수는 새 창이 받지 못한다. 영구히 하려면 `~/.zshrc`에 `export` 줄을 넣는다.
</details>

**4. `claude`를 치면 `command not found`가 나오는데 `~/.local/bin/claude` 파일은 존재한다. 무엇이 문제인가?**

<details><summary>정답과 해설</summary>

PATH에 `~/.local/bin`이 없다. 핵심 개념 7의 점검 명령이 아무것도 출력하지 않을 것이다. `echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc` 후 `source ~/.zshrc`, 그리고 새 창.
</details>

**5. PowerShell에서 Mac의 `ls`, `cat`, `rm`과 같은 일을 하는 정식 명령 이름은?**

<details><summary>정답과 해설</summary>

`Get-ChildItem`, `Get-Content`, `Remove-Item`. 별칭 `ls`, `cat`, `rm`도 통한다.
</details>
