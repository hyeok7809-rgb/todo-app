# 10-4. Agent SDK: 에이전트 루프, 파일·명령 실행 에이전트 만들기

| 과정 | 10. Claude API와 Agent SDK |
|---|---|
| 예상 시간 | 5시간 |
| 선수 단원 | 10-3 |
| 경험치 | 100 |

## 이 단원을 마치면

- Agent SDK가 "Claude Code의 도구·에이전트 루프·컨텍스트 관리를 **내 프로그램 안에서** 쓰는 라이브러리"라는 것과, Client SDK(10-1~10-3)·CLI·Managed Agents와의 차이를 표로 말할 수 있다.
- `claude-agent-sdk`로 "파일을 읽고 버그를 고치는 에이전트"를 20줄로 만들고, 메시지 스트림을 읽을 수 있다.
- `allowed_tools`, `permission_mode`, `system_prompt`로 에이전트의 **권한과 역할**을 제한한다(8-4·9-1의 원칙).
- 10-3의 "직접 짠 루프"와 비교해 언제 Client SDK를, 언제 Agent SDK를 쓸지 판단한다.

## 왜 배우나 (나에게 어떤 쓸모)

10-3에서 도구 왕복을 손으로 짰다. 도구가 10개가 되고, 파일 읽기·명령 실행·재시도·컨텍스트 관리까지 하려면 그 루프가 수백 줄이 된다. Agent SDK는 **Claude Code 그 자체를 라이브러리로** 준다: Read/Edit/Bash 같은 도구, 권한, 세션, 훅, 서브에이전트, MCP, 그리고 저장소의 `.claude/`(스킬·CLAUDE.md)까지 그대로 읽는다. 11과정 AI 직원의 **몸체**가 이것이다. "내 저장소를 읽고 리포트를 커밋하는 직원"이 이 단원에서 처음 움직인다.

## 핵심 개념

(공식 agent-sdk overview·quickstart, 확인일 2026-10-23.)

### 1. 네 가지 도구 비교 (공식 표)

| 원하는 것 | 쓰는 것 | 얻는 것 |
|---|---|---|
| Claude Code의 에이전트를 내 Python/TS 앱에 넣기 | **Agent SDK** | Claude Code 바이너리를 실행하는 라이브러리. 내장 도구·권한·세션·훅 |
| 터미널에서 대화형·일회성 작업 | Claude Code CLI | 8·9과정 |
| 내 코드에서 Claude API를 직접 부르기 | Client SDK | 10-1~10-3. 루프는 내가(또는 Tool Runner) |
| Anthropic이 에이전트를 호스팅 | Managed Agents | 관리형 샌드박스에서 도는 에이전트 |

**비유**: Client SDK는 "전화기"(말 주고받기), Agent SDK는 "직원 한 명"(사무실에서 서류함 열고 일함), Managed Agents는 "파견 직원"(남의 사무실에서 일함).

### 2. 설치와 키

```bash
# Python (가상환경 안에서)
pip install claude-agent-sdk
# TypeScript
npm install @anthropic-ai/claude-agent-sdk
```

SDK는 Claude Code 바이너리를 **번들**하므로 보통 별도 설치가 없다. 인증은 **API 키**(환경변수 `ANTHROPIC_API_KEY`). 공식 주의: SDK는 `.env`를 자동으로 읽지 않으니 `load_dotenv()`를 **먼저** 부른다. 또 하나(공식): 제3자 개발자가 자기 제품에 claude.ai 구독 로그인을 쓰게 하는 것은 허용되지 않는다 — **API 키로**. 즉 Agent SDK 비용은 종량(10-1의 지갑 분리).

### 3. 첫 에이전트 (공식 퀵스타트 Python 그대로)

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, AssistantMessage, ResultMessage

async def main():
    async for message in query(
        prompt="Review utils.py for bugs that would cause crashes. Fix any issues you find.",
        options=ClaudeAgentOptions(
            allowed_tools=["Read", "Edit", "Glob"],   # 이 도구들은 자동 승인
            permission_mode="acceptEdits",           # 파일 편집 자동 승인
        ),
    ):
        if isinstance(message, AssistantMessage):
            for block in message.content:
                if hasattr(block, "text"):
                    print(block.text)                # Claude의 생각·설명
                elif hasattr(block, "name"):
                    print(f"Tool: {block.name}")     # 부른 도구
        elif isinstance(message, ResultMessage):
            print(f"Done: {message.subtype}")        # 최종 결과

asyncio.run(main())
```

세 부분(공식): **`query`**(에이전트 루프를 만드는 진입점, 비동기 반복자) / **`prompt`**(할 일) / **`options`**(도구·권한·시스템 프롬프트·MCP 등). `async for`는 Claude가 생각하고, 도구를 부르고, 결과를 보고, 다음을 정하는 동안 **메시지를 하나씩** 준다. 루프는 작업이 끝나거나 에러가 나면 멈춘다.

`async`/`await`는 커리큘럼에서 처음 나오는 문법이다. 지금은 "기다리는 동안 다른 일을 할 수 있는 함수"라고만 이해하고, 공식 예제 틀을 그대로 쓴다. 3-5의 예외 처리처럼 `try/except`로 감싼다.

### 4. 권한 = 도구 목록 (공식 표)

| 도구 | 에이전트가 할 수 있는 것 |
|---|---|
| `Read`, `Glob`, `Grep` | 읽기 전용 분석 |
| `Read`, `Edit`, `Glob` | 분석과 코드 수정 |
| `Read`, `Edit`, `Bash`, `Glob`, `Grep` | 완전 자동화 |

`permission_mode`는 8-4의 모드와 같다(`acceptEdits`, `default`, `plan`, `dontAsk`, `bypassPermissions`). 11과정 원칙: **직원마다 최소 도구**. 리포트 직원은 `Read`+`Write`만, 테스트 직원만 `Bash`. `system_prompt`로 역할을 주고(7-2 SKILL.md 본문), `WebSearch`를 추가하면 검색도 한다.

### 5. 저장소 설정을 그대로 읽는다

공식 capabilities 표: 스킬·명령·메모리는 "프로젝트의 `.claude/`와 `~/.claude/`에서 **자동으로** 로드"된다. 즉 9-2에서 만든 `/trade-review`, 8-3의 CLAUDE.md, 9-3의 훅, 9-4의 MCP가 Agent SDK 에이전트에도 적용된다. **지금까지의 설정이 그대로 직원의 사규가 된다.** 세션(이어 가기·분기), 서브에이전트, 플러그인도 지원.

### 6. Client SDK vs Agent SDK 선택

| 상황 | 선택 |
|---|---|
| 텍스트 생성·분류·JSON 추출, 도구 1~3개 | Client SDK (싸고 단순, 10-2·10-3) |
| 파일을 읽고 고치고 명령을 돌리는 작업 | Agent SDK |
| 저장소 규칙(CLAUDE.md·스킬·훅)을 그대로 적용 | Agent SDK |
| 비용을 토큰 단위로 꽉 쥐어야 함 | Client SDK (에이전트는 도구 호출마다 토큰) |

11과정에서는 둘을 섞는다: 분류·요약 직원은 Client SDK, 저장소를 만지는 직원은 Agent SDK.

## 따라하기

### 1. 퀵스타트 그대로 (40분)

`my-agent/` 폴더에서 공식 퀵스타트의 `utils.py`(버그 2개)와 `agent.py`를 만들어 실행. `Tool: Read`, `Tool: Edit`, `Done: success`가 찍히고 `utils.py`가 고쳐지는지. 키는 `.env` + `load_dotenv()`.

### 2. 읽기 전용 직원 (40분)

이 저장소에서 `allowed_tools=["Read","Glob","Grep"]`, `system_prompt`에 9-1의 beginner-reviewer 본문을 넣고 "assets.js를 검사해 보고서만 출력"을 시킨다. 파일이 **바뀌지 않았는지** `git status`로 확인.

### 3. 리포트 직원 (60분)

`allowed_tools=["Read","Write","Glob"]`, `permission_mode="acceptEdits"`, prompt: "docs/review/ 의 이번 주 JSON을 읽고 위반 통계를 docs/weekly/YYYY-MM-DD.md 로 써라. 형식: 표 + 3줄 요약." 결과 파일을 읽고 `git diff`로 범위 확인. 9-5의 예약 작업 프롬프트와 비교해 보라 — 같은 지시가 **내 코드에서** 돈다.

### 4. Bash 직원과 안전장치 (50분)

`allowed_tools`에 `Bash`를 추가하고 "node -e로 모든 js 문법 검사 후 결과 보고"를 시킨다. 그다음 `.claude/settings.json`의 deny 규칙(9-6: `.env` 읽기, `rm -rf`)이 SDK에서도 적용되는지 "`.env` 보여 줘"로 확인. (SDK 권한 평가 순서는 공식 permissions 문서.)

### 5. 비용 비교 (30분)

따라하기 3을 Client SDK(10-2 구조화 출력, 파일은 내 코드가 읽어 넣음)로도 만들어 `usage`를 비교. 어느 쪽이 싸고, 어느 쪽이 코드가 짧은지 표로.

## 흔한 실수와 해결

| 실수 | 증상 | 해결 |
|---|---|---|
| `.env`를 안 읽음 | Not logged in / Invalid API key | `load_dotenv()` 먼저, 또는 셸에 export |
| 도구 과다 허용 | 의도치 않은 수정·실행 | 직원별 최소 도구 |
| `bypassPermissions` | 검사 없음 | 격리 환경 외 금지(8-4) |
| 메시지 스트림 전부 출력 | 노이즈 | 공식 예제처럼 필터 |
| 작업 범위 모호 | 저장소 전체 탐색, 비용 | 파일·출력 경로·형식 명시(8-6) |
| 구독으로 쓰려 함 | 허용 안 됨 | API 키 |

## 확인 퀴즈

**1. Client SDK와 Agent SDK의 결정적 차이.**

<details><summary>정답과 해설</summary>
Client SDK는 모델을 직접 부르고 도구 루프를 내가 짠다. Agent SDK는 Claude Code의 도구·루프·권한·설정을 라이브러리로 제공해 에이전트가 파일·명령을 직접 실행한다.
</details>

**2. `allowed_tools=["Read","Glob","Grep"]`인 에이전트가 할 수 없는 것.**

<details><summary>정답과 해설</summary>
파일 수정·생성, 명령 실행. 읽기 전용 분석만 가능. 리뷰·보고 직원에 맞다.
</details>

**3. SDK 에이전트가 이 저장소의 `/trade-review` 스킬과 CLAUDE.md를 아는 이유.**

<details><summary>정답과 해설</summary>
Agent SDK는 프로젝트 `.claude/`와 `~/.claude/`의 스킬·명령·메모리를 Claude Code처럼 자동 로드한다.
</details>

**4. Agent SDK로 만든 제품에 claude.ai 구독 로그인을 쓰게 해도 되나?**

<details><summary>정답과 해설</summary>
공식 문서상 사전 승인 없이는 허용되지 않는다. API 키 인증을 쓴다(종량 과금).
</details>

**5. 분류 직원과 저장소 정리 직원에 각각 어느 SDK?**

<details><summary>정답과 해설</summary>
분류(텍스트→JSON)는 Client SDK(싸고 단순), 저장소를 읽고 파일을 쓰는 정리 직원은 Agent SDK.
</details>
