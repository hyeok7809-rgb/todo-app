## 이 단원을 마치면

- CSS 규칙을 "선택자 + 선언 블록"으로 읽고, 요소·클래스·ID·상태(`:hover`) 선택자를 골라 쓸 수 있다.
- 두 규칙이 충돌할 때 어느 쪽이 이기는지(소스 순서, 우선 순위)를 설명하고, "CSS를 넣었는데 안 먹어요"를 스스로 잡을 수 있다.
- 박스 모델(내용·안쪽 여백·테두리·바깥 여백)과 `box-sizing: border-box`가 크기 계산을 어떻게 바꾸는지 안다.
- `display: flex`로 한 줄 배치, `display: grid`로 격자 배치를 만들고 `gap`, `flex: 1`, `1fr`, `repeat()`를 쓸 수 있다.
- `@media`로 폰 화면과 PC 화면에 다른 규칙을 주는 반응형 CSS를 쓸 수 있다.
- `transition`과 `@keyframes`/`animation`이 우리 앱의 경험치 바·캐릭터·팝업을 어떻게 움직이는지 설명하고, 값을 바꿔 다른 모션을 만들 수 있다.
- `:root`의 CSS 변수(`--sky` 등)로 테마 색을 한 곳에서 바꿀 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

CSS는 "어떻게 보이는지"를 정하는 언어다. 1단계 레슨의 비유로는 **인테리어**. 사용자(지금은 나 자신)가 앱을 열었을 때 첫인상과 사용 편의를 전부 CSS가 좌우한다. 폰에서 열었는데 입력칸이 화면 밖으로 삐져나간다면, 기능이 아무리 좋아도 안 쓰게 된다. 13과정에서 앱을 팔거나 외주를 받을 때 "모바일에서도 멀쩡하게 보이는가"는 거의 첫 번째 검수 항목이다.

주식으로 비유하면 CSS는 **차트 설정**이다. 같은 데이터(HTML)라도 캔들 색, 이동평균선 굵기, 보조지표 배치(레이아웃)에 따라 읽기 쉬운 차트와 어려운 차트가 갈린다. 좋은 트레이더가 자기 차트 세팅을 손에 익히듯, 내 앱의 CSS를 내가 다룰 수 있어야 한다.

그리고 CSS는 클로드가 가장 자주 써 주는 코드이자, 가장 자주 "조금 다르게" 써 주는 코드다. 요청한 대로 안 나왔을 때 "`.entry-form`의 `gap`을 12px로", "`@media (max-width: 480px)`에서는 세로 배치로"라고 **CSS 용어로 다시 말할 수 있으면** 두 번째 시도에 끝난다. 못 하면 열 번을 돌아도 제자리다.

## 핵심 개념

### 1. CSS 규칙의 구조와 선택자

**한 줄 정의.** CSS(Cascading Style Sheets) 규칙은 "어떤 요소에(선택자)" + "무엇을 어떻게(선언)"로 이루어진다. MDN 'CSS 선택자': "CSS 선택자는 CSS 규칙의 첫 번째 부분입니다. 선택자는 규칙 내부의 CSS 속성 값을 적용하기 위해 어떤 HTML 요소를 선택해야 하는지 브라우저에 알려주는 요소 및 기타 용어의 패턴입니다."

**비유.** HTS의 조건검색. "거래량 100만 이상인 종목(선택자)에 빨간 배경(선언)". 조건이 틀리면 아무 종목도 안 잡히듯, 선택자가 틀리면 아무 요소도 안 바뀐다. 그리고 브라우저는 에러를 내지 않고 **조용히 무시**한다. MDN 'CSS 작동 방식': "브라우저가 이해하지 못하는 선택자를 만나면, 전체 규칙을 무시하고 다음 규칙으로 넘어갑니다." 속성 이름 오타도 마찬가지다("이를 무시하고 다음 선언으로 넘어갑니다").

**실제 예시.** `style.css`에서 하나씩.

```css
/* 요소(유형) 선택자: 모든 <body> */
body { margin: 0; }

/* 클래스 선택자: class="room"인 모든 요소. 마침표로 시작 */
.room { cursor: pointer; }

/* ID 선택자: id="entry-title"인 단 하나. 샵으로 시작 */
#entry-title { flex: 1; }

/* 자손 선택자: .sign 안쪽 어딘가의 h1 */
.pill b { color: var(--yellow); }

/* 두 클래스를 모두 가진 요소: class="room locked" */
.room.locked { cursor: not-allowed; }

/* 선택자 목록: 쉼표로 묶어 같은 규칙을 여러 대상에 */
.entry-form input,
.entry-form select,
.entry-form button { font-family: inherit; }

/* 의사 클래스: 마우스가 올라간 상태의 .room */
.room:hover { outline: 3px solid var(--yellow); }

/* 의사 요소: .room.locked 안에 가짜 요소를 하나 만들어 자물쇠를 그린다 */
.room.locked::after { content: "🔒"; }
```

MDN이 분류한 기본 세 가지가 **유형(`h1`)**, **클래스(`.box`)**, **ID(`#unique`)**다. 여기에 두 가지만 더 알면 우리 `style.css`가 전부 읽힌다.

- 의사 클래스(pseudo-class): "특정 상태에 있는 요소를 선택하는 선택자입니다. (...) 콜론으로 시작하는 키워드입니다. 예를 들어, `:hover`는 의사 클래스입니다." `:hover`는 "사용자가 포인팅 장치를 사용해 상호작용 중인 요소", `:active`는 누르고 있는 동안이다. 추가 버튼이 눌릴 때 들어가는 효과가 `.entry-form button:active`다.
- 의사 요소(pseudo-element): "완전히 새로운 HTML 요소를 마크업에 추가한 것처럼 작동합니다. 의사 요소는 이중 콜론 `::`으로 시작합니다." 잠긴 방의 🔒는 HTML에 없고 `::after`가 그린 것이다.

**왜 중요한가.** 선택자는 "CSS가 안 먹어요"의 1순위 용의자다. 클래스에 마침표를 빼먹거나(`room`), ID를 클래스처럼 쓰거나(`.entry-title` vs `#entry-title`), 오타가 나면 아무 일도 안 일어난다. 요소 탭(2-2)에서 요소를 클릭해 오른쪽 스타일 창에 내 규칙이 보이는지부터 확인하는 습관을 들이자.

### 2. 충돌 해결: 소스 순서와 우선 순위

**한 줄 정의.** 같은 요소에 두 규칙이 걸리면 (1) 우선 순위(specificity)가 높은 쪽, (2) 같으면 나중에 쓴 쪽이 이긴다. MDN '계단식 및 상속': "동일한 우선 순위를 갖는 두 규칙이 적용될 때, CSS 에서 마지막에 나오는 규칙이 사용 될 것입니다." 그리고 "class 선택자는 요소 선택자보다 가중치가 높으므로, class 에 정의된 속성이 요소에 직접 적용된 속성보다 우선합니다."

**비유.** 사내 규정. 전사 규정(요소 선택자)보다 부서 규정(클래스)이, 부서 규정보다 개인 특약(ID)이 우선한다. 같은 급이면 **나중에 공지된 것**이 유효하다.

**실제 예시.** 우리 앱의 방 버튼.

```css
.room { cursor: pointer; }            /* 클래스 1개 */
.room.locked { cursor: not-allowed; } /* 클래스 2개 → 더 구체적 → 이긴다 */
```

`locked`가 붙은 방은 `.room`보다 `.room.locked`가 더 구체적이라 "금지" 커서가 나온다. 순서를 바꿔도 결과는 같다. 반면 아래 둘은 우선 순위가 같아서 순서로 결정된다.

```css
.balance-amount { font-size: 30px; }
.balance-amount { font-size: 24px; }   /* 나중 것이 이긴다 → 24px */
```

MDN은 덮어쓰기가 "전체 규칙이 아니라 동일한 속성일 뿐"이라고 짚는다. 위 예에서 `font-size`만 바뀌고 다른 속성은 그대로다.

**왜 중요한가.** 클로드가 추가한 규칙이 안 먹을 때 열에 아홉은 "더 구체적인 규칙이 위에 있다"다. 요소 탭의 스타일 창에서 취소선이 그어진 선언이 바로 **져서 무시된 선언**이다. 그걸 보면 어느 규칙이 이겼는지 바로 안다.

### 3. 박스 모델: 모든 요소는 상자다

**한 줄 정의.** 모든 요소는 안에서부터 내용(content), 안쪽 여백(padding), 테두리(border), 바깥 여백(margin) 네 겹의 상자다. MDN '박스 모델': "테두리 박스는 콘텐츠와 패딩까지 둘러쌉니다." "여백은 박스의 실제 크기에 포함되지 않습니다."

**비유.** 택배 상자. 물건(내용), 완충재(패딩), 골판지(테두리), 그리고 옆 상자와의 간격(마진).

**실제 예시.** 잔액 카드.

```css
.balance {
  background: #fff;
  border: 4px solid var(--ink);   /* 테두리 4px */
  padding: 12px 16px;              /* 안쪽 여백: 위아래 12px, 좌우 16px */
  margin-bottom: 16px;             /* 아래쪽 바깥 여백 16px */
}
```

크기 계산에는 두 방식이 있다. MDN의 숫자 예를 그대로 쓰면, `width: 350px; padding: 25px; border: 5px`일 때 **표준 박스 모델**에서는 "패딩과 테두리는 박스의 너비와 높이에 추가되어" 실제 폭이 350 + 25 + 25 + 5 + 5 = **410px**이 된다. 반면 **대체 박스 모델**은 지정한 350px 안에 패딩과 테두리까지 들어간다.

우리 `style.css` 맨 위에 이 한 줄이 있는 이유다.

```css
* { box-sizing: border-box; }
```

MDN `box-sizing`: "`border-box`는 테두리와 안쪽 여백의 크기도 요소의 크기로 고려합니다. 너비를 100 픽셀로 설정하고 테두리와 안쪽 여백을 추가하면, 콘텐츠 영역이 줄어들어 총 너비 100 픽셀을 유지합니다. 대부분의 경우 이 편이 크기를 조절하기 쉽습니다." `*`는 모든 요소를 뜻하는 선택자다.

한 가지 함정. 위아래로 맞닿은 두 마진은 합쳐진다. MDN: "여백이 서로 맞닿은 두 개의 요소가 있으면 해당 여백은 합쳐져 하나의 여백이 됩니다." 큰 쪽 하나만 남는다. "분명 16px + 16px인데 16px밖에 안 벌어져요"가 이것이다.

**블록과 인라인.** `<div>`, `<p>`, `<section>` 같은 블록 상자는 "새 줄로 행갈이를" 하고 폭·높이를 가진다. `<span>`, `<a>` 같은 인라인 상자는 "새 줄로 행갈이를 하지 않습니다"이고 폭·높이가 안 먹는다. 그래서 `.room-label`(span)에 테두리는 들어가지만 `width`를 줘도 변화가 없다. 바꾸고 싶으면 `display` 값을 바꾼다.

**왜 중요한가.** "왜 상자가 삐져나오지?", "왜 간격이 안 벌어지지?"의 답이 전부 여기 있다. 특히 `box-sizing: border-box`를 모르면 클로드가 준 `width: 100%` 코드가 왜 화면을 넘치는지 영원히 모른다.

### 4. 레이아웃: `display: flex`와 `display: grid`

**한 줄 정의.** `display`는 요소가 블록인지 인라인인지, 그리고 **자식들을 어떤 방식으로 배치할지** 정한다. MDN `display`(영어판): "sets whether an element is treated as a block or inline box and the layout used for its children". `flex`는 한 방향으로 줄 세우기, `grid`는 행과 열의 격자.

**비유.** flex는 **한 줄 호가창**(가로로 쭉, 남는 공간을 나눠 가짐), grid는 **엑셀 시트**(열과 행을 먼저 긋고 칸에 넣음).

**실제 예시 1 — flex.** 입력 폼 한 줄.

```css
.entry-form {
  display: flex;   /* 자식(select, input, input, button)을 가로로 */
  gap: 8px;        /* 자식 사이 간격 */
}
#entry-title { flex: 1; }     /* 남는 공간을 전부 가져간다 */
#entry-amount { width: 100px; }
```

MDN 'Flexbox': `display: flex`를 지정한 부모가 **flex 컨테이너**, 그 안의 자식이 **flex 아이템**이다. 아이템이 놓이는 방향이 주축(main axis), 그 직각이 교차축(cross axis). 기본 방향은 행(`flex-direction: row`)이고 `column`으로 바꾸면 세로가 된다. `.room`이 `flex-direction: column`으로 라벨·아이콘·설명을 세로로 쌓는 것이 그 예다.

자주 쓰는 속성 네 개.

| 속성 | 하는 일 (MDN 한국어판) | 우리 앱 |
|---|---|---|
| `flex: 1` | "각 flex item이 기본 축을 따라 남은 공간을 어느 정도나 점유할지를 결정하는 단위가 없는 비율 값" | `#entry-title`, `.xp-bar`, `.entry-title` |
| `justify-content` | "flex item 무리가 기본 축 상 어디에 놓이는지를 제어합니다" (주축 정렬) | 쓸 곳: 버튼들을 가운데로 |
| `align-items` | "flex item이 교차축 어디에 놓일 지를 제어합니다" (교차축 정렬) | `.level-row { align-items: center }` 로 배지·바·글자의 세로 중앙 맞춤 |
| `gap` | "행과 열 사이의 간격(gutters)을 설정합니다" | `.entry-form`, `.level-row`, `.entry-list li` |
| `flex-wrap: wrap` | 넘치면 "다음 행으로 넘어갑니다" | 반응형에서 유용 |

**실제 예시 2 — grid.** 회사 건물의 방 배치.

```css
.building {
  display: grid;
  grid-template-columns: 1fr 1fr;   /* 같은 너비의 열 2개 */
  gap: 12px;
}
```

MDN '그리드': "`fr` 단위는 그리드 컨테이너에서 (...) 사용 가능한 공간의 한 분율을 나타냅니다." `1fr 1fr`은 남는 공간을 1:1로 나눈 두 열. `repeat(3, 1fr)`로 쓰면 세 열이고 "`repeat()` 함수에 전달되는 첫 번째 값은 목록을 반복할 횟수를 지정"한다. 방이 6개이니 2열이면 3행이 자동으로 생긴다(명시하지 않은 행은 "암시적 그리드"로 자동 생성). 특정 방을 두 칸 차지하게 하려면 `grid-column: 1 / 3`처럼 "시작 줄과 끝 줄을 슬래시 `/`로 구분하여" 지정한다.

**둘 중 무엇을 쓰나.** 한 줄(또는 한 열)로 흐르는 것은 flex, 행과 열이 둘 다 중요한 것은 grid. 폼 한 줄·헤더·목록 한 줄은 flex, 방 배치·대시보드·달력은 grid.

**왜 중요한가.** 화면 배치의 90%는 이 둘로 끝난다. 로드맵 4단계의 월별 그래프 대시보드, 5단계의 루틴 체크 달력이 전부 grid이고, 그 안의 각 칸이 flex다.

### 5. 반응형: 화면 크기에 따라 규칙 바꾸기

**한 줄 정의.** 반응형 디자인(responsive design)은 "웹 페이지가 모든 화면 크기와 해상도에서 잘 렌더링되도록 하면서도 사용성을 보장하는 웹 디자인 접근 방식"(MDN '반응형 디자인')이고, 도구는 미디어 쿼리 `@media`다. MDN `@media`: "스타일 시트의 일부를 하나 이상의 미디어 쿼리 결과에 따라 적용할 때 사용할 수 있습니다."

**비유.** HTS를 PC 모니터에서 보는 화면과 MTS를 폰에서 보는 화면. 같은 데이터인데 폰에서는 한 열로 쌓고 글자를 키운다.

**실제 예시.** 2-2에서 라벨을 넣은 뒤 폼이 폰에서 좁아진 문제를 푸는 규칙.

```css
/* 기본(모바일 우선): 세로로 쌓는다 */
.entry-form { display: flex; flex-direction: column; gap: 8px; }

/* 화면 폭이 560px 이상이면 가로 한 줄로 */
@media screen and (min-width: 560px) {
  .entry-form { flex-direction: row; }
}
```

MDN은 좁은 화면용 단순 배치를 먼저 쓰고 넓은 화면에서 덧붙이는 방식을 "모바일 우선 디자인"이라 부른다. 세 가지가 함께 간다.

1. `<head>`의 `<meta name="viewport" content="width=device-width,initial-scale=1">`. MDN은 "항상 포함"하라고 한다. 우리 `index.html`에 이미 있다.
2. 이미지가 넘치지 않게 `img, picture, video { max-width: 100%; }`.
3. flex와 grid는 "기본적으로 반응형"이다. `flex: 1`과 `1fr`이 남는 공간에 맞춰 늘고 준다. `.screen { max-width: 560px; margin: 0 auto; }`가 PC에서는 가운데 정렬된 폰 폭, 폰에서는 꽉 찬 화면이 되는 이유다.

**왜 중요한가.** 내가 만든 가계부를 가장 많이 열 기기는 폰이다. 12-3에서 배포하면 바로 폰으로 접속하게 되고, 그때 입력칸이 잘리면 안 쓴다. 요소 탭 옆의 기기 모드(크롬에서는 개발자 도구의 "Toggle device toolbar" 아이콘) 로 폰 폭을 흉내 내며 확인한다(버튼 이름은 브라우저 버전에 따라 다를 수 있다).

### 6. 움직임: `transition`과 `animation`

**한 줄 정의.** `transition`은 속성 값이 **바뀔 때** 그 변화를 시간에 걸쳐 부드럽게 만들고, `animation`은 `@keyframes`에 적어 둔 **중간 상태들을 따라** 스스로 움직인다. MDN 'CSS 트랜지션 사용하기': "속성 변경이 즉시 영향을 미치게 하는 대신, 그 속성의 변화가 일정 기간에 걸쳐 일어나도록 할 수 있습니다." MDN 'CSS 애니메이션 사용하기': "애니메이션은 애니메이션을 나타내는 CSS 스타일과 애니메이션의 중간 상태를 나타내는 키프레임들로 이루어집니다."

**비유.** transition은 **체결 시 깜빡임**(값이 바뀌는 순간만 효과), animation은 **흐르는 시세 전광판**(계속 스스로 움직임).

**실제 예시 1 — transition.** 경험치 바.

```css
.xp-fill {
  width: 0%;
  transition: width 0.6s ease-out;  /* 어떤 속성 / 얼마 동안 / 어떤 속도 곡선 */
}
```

`app.js`가 `xpFill.style.width = "30%"`로 바꾸는 순간, 브라우저가 0.6초에 걸쳐 0%→30%의 중간값을 그려 준다. `transition`은 `transition-property`, `transition-duration`, `transition-timing-function`, `transition-delay`를 한 줄에 쓰는 단축 속성이다. `.room:hover`의 `transform`에 `transition: transform 0.15s`를 붙이면 방이 튀지 않고 스르륵 떠오른다(따라하기 3).

**실제 예시 2 — animation.** 복도를 걷는 사장님.

```css
@keyframes stroll {
  from { left: 20px; }
  to   { left: calc(100% - 52px); }
}
.walker {
  position: absolute;
  animation: stroll 6s linear infinite alternate;
  /*          이름  시간  속도   반복      왕복 */
}
```

`@keyframes`는 "애니메이션 중간중간의 특정 지점들을 거칠 수 있는 키프레임들을 설정"하는 규칙이다. `from`은 "시작 offset인 `0%`", `to`는 100%. 사이에 `50% { ... }`를 넣으면 중간 동작을 추가할 수 있다. `animation`은 `animation-name`, `animation-duration`, `animation-timing-function`, `animation-iteration-count`(`infinite`), `animation-direction`(`alternate`) 등의 단축 속성이다. `+10 EXP` 팝업의 `pop-up`도 같은 구조로, 1초 동안 위로 떠오르며 투명해진다(`forwards`는 끝난 상태를 유지).

**왜 CSS로 움직이나.** MDN은 세 가지 이점을 든다. "JavaScript를 모르더라도 간단하게 애니메이션을 만들 수 있습니다." JS 애니메이션은 "잘 만들어졌더라도 성능이 좋지 못할때가 있습니다. CSS 애니메이션은 (...) 최대한 부드럽게 렌더링됩니다." 그래서 1.5단계 레슨에서 "자바스크립트가 매 프레임 그리는 게 아니라, CSS에 '이렇게 움직여'라고 적어두면 브라우저가 알아서 움직인다"고 했던 것이다.

### 7. 보너스: CSS 변수와 `position`, `box-shadow`

**CSS 변수(사용자 지정 속성).** MDN: "CSS 저작자가 정의하는 개체로, 문서 전반적으로 재사용할 임의의 값을 담습니다. (...) `--main-color: black;` (...) `var()` 함수를 사용해 접근할 수 있습니다." 우리 `:root`의 `--sky`, `--ink`, `--accent`가 이것이고, `var(--ink)`로 꺼내 쓴다. "수 백 곳의 서로 다른 위치에서 같은 색상을 사용한다면, 그 색을 바꿔야 할 상황이 왔을 때 대규모 전역 검색 바꾸기를 피할 수 없습니다"를 막아 준다. 1.5단계 숙제의 "숫자 하나를 이름 붙여서 맨 위에 모아두는 이유"가 CSS에도 똑같이 있다. 이름은 대소문자를 구분한다.

**`position`.** "문서 상에 요소를 배치하는 방법을 지정합니다." `static`이 기본("일반적인 문서 흐름"), `relative`는 제자리 기준으로 살짝 이동, `absolute`는 "일반적인 문서 흐름에서 제거하고 (...) 가장 가까운 위치 지정 조상 요소에 대해 상대적으로 배치", `fixed`는 화면(뷰포트) 기준 고정. 캐릭터(`.walker { position: absolute }`)가 복도(`.hall { position: relative }`) 안에서 `left`로 움직이고, 🔒가 방의 오른쪽 위에 붙고, `+10 EXP` 팝업이 스크롤과 무관하게 화면 중앙에 뜨는(`fixed`) 이유다.

**`box-shadow`.** "adds shadow effects around an element's frame. You can set multiple effects separated by commas."(영어판) 보통은 그림자 하나지만, 쉼표로 여러 개를 찍을 수 있다. 다만 우리 앱의 캐릭터·가구는 `box-shadow`가 아니라 `sprites.js`의 `drawSprite()`가 `<canvas>`에 그린다(1.6단계). `style.css`에서 겹친 효과의 예는 `.rug`의 금색 테두리 + `box-shadow: inset 0 0 0 3px #1f6b3a`(안쪽 진초록 선)이다. 각진 그림자 `4px 4px 0 var(--ink)`가 픽셀 게임 느낌의 핵심이다.

## 흔한 실수와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 규칙을 추가했는데 아무 변화 없음 | 선택자 오타, 클래스에 `.` 누락, ID에 `#` 누락, 속성 이름 오타(`colour`) | 요소 탭 스타일 창에 내 규칙이 뜨는지 확인. 안 뜨면 선택자, 뜨는데 취소선이면 우선 순위 |
| 규칙은 뜨는데 취소선 | 더 구체적인 규칙 또는 같은 우선 순위의 뒤쪽 규칙에 짐 | 선택자를 더 구체적으로 하거나 순서를 뒤로. `!important`는 최후 수단 |
| `width: 100%`인데 화면을 넘침 | 표준 박스 모델에서 패딩·테두리가 더해짐 | `* { box-sizing: border-box }` 확인 |
| 두 블록 사이 간격이 생각보다 좁음 | 마진 상쇄(큰 쪽 하나만 남음) | 한쪽 마진만 쓰거나 flex/grid의 `gap` 사용 |
| `span`에 `width`를 줬는데 안 먹음 | 인라인 상자는 폭·높이를 무시 | `display: inline-block` 또는 `block`으로 |
| `flex: 1`을 줬는데 안 늘어남 | 부모에 `display: flex`가 없음 | 부모를 flex 컨테이너로 |
| `@media` 규칙이 안 먹음 | `min-width`/`max-width` 혼동, 위쪽 규칙보다 우선 순위가 낮음, viewport 메타 누락 | 모바일 우선이면 `min-width`. 미디어 쿼리는 파일 **아래쪽**에. `<meta name="viewport">` 확인 |
| `transition`을 넣었는데 즉시 바뀜 | 애니메이션 불가능한 속성(`display` 등), 또는 변화가 없는 속성을 지정 | `opacity`, `transform`, `width` 같은 수치형 속성으로 |
| 애니메이션이 한 번만 돌고 멈춤 | `animation-iteration-count` 기본값 1 | `infinite` 추가. 끝 상태 유지는 `forwards` |
| 변수가 안 먹음 | `--My-color`처럼 대소문자 불일치, `var()` 누락 | 변수 이름은 대소문자 구분. 반드시 `var(--이름)` |

## 확인 퀴즈

**1. 아래 두 규칙이 같은 요소에 걸릴 때 글자 색은 무엇이고 왜인가?**

```css
#entry-title { color: red; }
.entry-form input { color: blue; }
```

<details><summary>정답과 해설</summary>
빨강. ID 선택자가 클래스+요소 조합보다 우선 순위가 높다. MDN이 말하는 "선택자의 선택이 얼마나 구체적인지"에서 ID는 가장 구체적이다. 소스 순서는 우선 순위가 같을 때만 따진다.
</details>

**2. `width: 200px; padding: 10px; border: 2px solid`인 상자의 실제 폭은 표준 모델과 `border-box`에서 각각 몇 px인가?**

<details><summary>정답과 해설</summary>
표준(`content-box`): 200 + 10 + 10 + 2 + 2 = 224px. MDN: "패딩과 테두리는 박스의 너비와 높이에 추가되어". `border-box`: 200px("테두리와 안쪽 여백의 크기도 요소의 크기로 고려"). 마진은 어느 쪽이든 폭에 포함되지 않는다.
</details>

**3. 방 6개를 PC에서는 3열, 폰에서는 2열로 보이게 하려면 어떤 속성과 규칙을 쓰나?**

<details><summary>정답과 해설</summary>
기본(모바일 우선)으로 `.building { display: grid; grid-template-columns: 1fr 1fr; }`를 두고, `@media screen and (min-width: 560px) { .building { grid-template-columns: repeat(3, 1fr); } }`처럼 넓은 화면에서 덮어쓴다. `1fr`은 "사용 가능한 공간의 한 분율", `repeat(3, 1fr)`은 같은 열 세 개.
</details>

**4. 경험치 바에 `transition: width 0.6s`가 있다. `app.js`가 `style.width`를 바꾸지 않고 `style.display`를 `none`에서 `block`으로 바꾼다면 부드럽게 나타날까?**

<details><summary>정답과 해설</summary>
아니다. 첫째, `transition`은 지정한 속성(`width`)의 변화에만 적용된다. 둘째, `display`처럼 중간값이 없는 속성은 애니메이션이 되지 않는다. 서서히 나타나게 하려면 `opacity`를 0→1로 바꾸고 `transition: opacity 0.6s`를 쓴다.
</details>

**5. `transition`과 `animation`의 차이를 한 문장으로, 그리고 우리 앱에서 각각이 쓰인 곳을 하나씩 말하라.**

<details><summary>정답과 해설</summary>
`transition`은 어떤 속성 값이 바뀌는 순간 그 변화를 시간에 걸쳐 그려 주는 것(두 상태 사이, 변화의 계기는 JS나 `:hover`), `animation`은 `@keyframes`에 적은 중간 상태들을 따라 스스로 반복해 움직이는 것이다. 앱에서는 `.xp-fill`의 `transition: width 0.6s`(JS가 폭을 바꿀 때)와 `.walker`의 `animation: stroll 6s linear infinite alternate`(계속 왕복), `.xp-pop`의 `animation: pop-up 1s`가 있다.
</details>

## 숙제

1. **매매 복기 페이지 꾸미기** — 2-2에서 만든 `trade-log.html`에 `<link rel="stylesheet" href="trade.css">`를 추가하고 `trade.css`를 새로 만든다. 조건: (a) `:root`에 색 변수 3개 이상, (b) 폼은 모바일 우선 세로 배치 + `@media (min-width: 560px)`에서 grid 2열, (c) 기록 버튼에 `:hover`와 `transition`. 가계부와 같은 픽셀 느낌을 내려면 `style.css`의 `.window-body`, `.entry-form button` 규칙을 참고(복사해도 좋다. 다만 한 줄씩 무슨 뜻인지 주석을 단다).
2. **취소선 찾기** — 요소 탭에서 `.entry-form button`을 선택하고 스타일 창에서 취소선이 그어진 선언을 전부 찾아, 각각 어느 규칙에 졌는지(우선 순위인지 소스 순서인지) 적는다.
3. **폰 점검** — 개발자 도구의 기기 모드로 폭 360px에서 가계부와 매매 복기 페이지를 열어, 가로 스크롤이 생기거나 잘리는 요소가 있는지 찾아 고친다. 고친 규칙을 `@media` 안에 두었는지 밖에 두었는지 이유와 함께 적는다.
- 보너스(선택): **레벨업 연출** — `renderLevel()`이 레벨을 올릴 때 `.level-badge`가 한 번 커졌다 돌아오게 하고 싶다. CSS에 `@keyframes level-up`과 `.level-badge.bump { animation: level-up 0.4s; }` 규칙을 먼저 작성해 두고, JS로 클래스를 붙이는 부분은 2-4에서 완성한다. 지금은 요소 탭에서 `bump` 클래스를 수동으로 붙여 동작을 확인한다.
