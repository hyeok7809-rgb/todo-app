# 2-4. DOM과 이벤트: 요소 찾기·바꾸기·만들기, 이벤트 리스너, '데이터가 바뀌면 화면을 다시 그린다' 패턴

| 과정 | 2. 웹 기초 (HTML / CSS / JavaScript) |
|---|---|
| 예상 시간 | 4시간 |
| 선수 단원 | 2-3 |
| 경험치 | 80 |

## 이 단원을 마치면

- DOM(Document Object Model)이 "브라우저가 메모리에 만든 HTML 나무"라는 것을 알고, `document`로 그 나무를 다루는 네 가지 동작(찾기·읽기/바꾸기·만들기/붙이기·지우기)을 쓸 수 있다.
- `getElementById`, `querySelector`, `querySelectorAll`의 차이(하나 vs 목록, `null` vs 빈 목록)를 알고 상황에 맞게 고른다.
- `textContent`, `classList`, `style`, `dataset`으로 요소를 바꾸고, `innerHTML`을 왜 조심해야 하는지 설명할 수 있다.
- `addEventListener`로 클릭·제출·입력 이벤트를 받고, 이벤트 객체(`event.target`, `event.preventDefault()`)를 쓸 수 있다.
- `app.js`의 `render()`가 왜 "목록을 비우고 처음부터 다시 그리는지", 이 패턴의 장단점을 설명할 수 있다.
- 2-2에서 만든 매매 복기 폼에 JS를 붙여 "입력 → 배열 → 화면" 흐름을 혼자 완성할 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

1과정에서 배운 변수·배열·함수는 **머릿속 계산**이었다. 결과가 콘솔에만 찍혔다. 이 단원부터 그 계산이 **화면**에 나온다. DOM은 JS와 화면을 잇는 유일한 다리이고, 이벤트는 사용자의 손가락을 JS로 전달하는 유일한 통로다. 가계부의 "추가 버튼을 누르면 목록에 쌓인다"가 바로 이벤트(누름) → 데이터(배열) → DOM(목록) 흐름이다.

주식 비유로는 **호가창과 주문 버튼**. 호가창의 숫자가 바뀌는 것은 서버 데이터가 바뀌어 화면을 다시 그린 것이고(DOM 조작), 매수 버튼을 누르면 주문이 나가는 것은 클릭 이벤트에 함수가 묶여 있기 때문이다(이벤트 리스너). 이 둘을 알면 HTS가 마법이 아니라 "데이터가 바뀌면 다시 그리는 코드"라는 것이 보인다.

그리고 이 단원의 핵심 패턴 "데이터가 바뀌면 화면 전체를 다시 그린다"는 1단계 레슨에서 "작은 앱에서는 이게 제일 실수가 적다"고 소개했던 그것이다. 나중에 React 같은 도구를 쓰더라도 사고방식은 똑같다. 클로드가 써 주는 프런트엔드 코드의 뼈대가 전부 이 패턴이라서, 읽을 줄 알아야 고칠 수 있다.

## 핵심 개념

### 1. DOM: 브라우저가 들고 있는 HTML 나무

**한 줄 정의.** DOM은 브라우저가 HTML을 읽어 메모리에 만든 나무(tree) 구조이고, JS는 이 나무를 통해 화면을 읽고 바꾼다. MDN 'DOM scripting'(영어판): "The document currently loaded in each one of your browser tabs is represented by a DOM. This is a 'tree structure' representation created by the browser that enables the HTML structure to be easily accessed by programming languages". 나무의 각 항목은 노드(node)다. "Each entry in the tree is called a node. (...) some nodes represent elements (...) and others represent text".

**비유.** 회사 조직도. 사장(`html`) 아래 본부(`body`), 그 아래 부서(`section`), 팀(`form`), 팀원(`input`). JS는 조직도를 보고 "재무부의 금액 담당자"를 찾아 지시를 내린다. 2-2에서 요소 탭으로 본 트리가 정확히 이 조직도다.

**실제 예시.** 2-1에서 봤듯 HTML 파일은 글자일 뿐이고, 브라우저가 파싱해서 DOM을 만든 뒤에야 JS가 손댈 수 있다. JS에서 이 나무의 뿌리가 `document`다. MDN은 브라우저의 세 주요 객체를 든다. `window`(탭 자체), `navigator`(브라우저 정보), `document`(페이지). 우리가 거의 매번 쓰는 것은 `document`다.

```js
document.title;                  // "나의 1인 회사" (탭 제목 읽기)
document.body;                   // <body> 요소
```

**왜 중요한가.** "HTML 파일을 고쳤는데 JS가 못 찾는다"와 "JS로 만든 요소가 파일에는 없다"가 둘 다 여기서 설명된다. 파일 ≠ DOM. JS는 **DOM**을 다룬다.

### 2. 찾기: `getElementById`, `querySelector`, `querySelectorAll`

**한 줄 정의.** 요소를 다루려면 먼저 **참조**(reference)를 변수에 담아야 한다. 세 가지 방법이 있다.

| 메서드 | 받는 것 | 돌려주는 것 | MDN 한국어판 설명 |
|---|---|---|---|
| `document.getElementById("id")` | id 문자열 | 요소 하나, 없으면 `null` | "주어진 문자열과 일치하는 `id` 속성을 가진 요소를 찾고 (...) ID는 문서 내에서 유일해야 하기 때문에 특정 요소를 빠르게 찾을 때 유용합니다." |
| `document.querySelector("CSS선택자")` | 2-3의 선택자 | **첫 번째** 요소 하나, 없으면 `null` | "제공한 선택자 또는 선택자 뭉치와 일치하는 문서 내 첫 번째 Element를 반환합니다. 일치하는 요소가 없으면 `null`을 반환합니다." |
| `document.querySelectorAll("CSS선택자")` | 선택자 | 요소 **목록**(NodeList), 없으면 빈 목록 | "지정된 셀렉터 그룹에 일치하는 다큐먼트의 엘리먼트 리스트를 나타내는 정적(살아 있지 않은) NodeList를 반환합니다." |

**비유.** 사번으로 찾기(`getElementById`), 조건으로 첫 사람 찾기(`querySelector`), 조건에 맞는 전원 명단(`querySelectorAll`).

**실제 예시.** `app.js` 2번과 6번 구역.

```js
const form = document.getElementById("entry-form");        // id로 하나
const list = document.getElementById("entry-list");

for (const roomBtn of document.querySelectorAll(".room")) {  // 클래스로 전부
  roomBtn.addEventListener("click", function () { ... });
}
for (const backBtn of document.querySelectorAll("[data-back]")) { ... }  // 속성 선택자
```

`querySelectorAll`이 돌려주는 NodeList는 배열과 비슷해서 `for...of`로 돌 수 있지만 "정적(살아 있지 않은)" 목록이다. 나중에 `.room`이 추가돼도 이미 받아 둔 목록에는 안 들어온다. MDN은 `querySelector()`를 "the recommended modern approach"라고 하며, CSS 선택자를 그대로 쓸 수 있어 편하다고 설명한다. 다만 id가 있으면 `getElementById`가 더 빠르고 의도가 분명하다.

**왜 중요한가.** 1-7의 `Cannot read properties of null`은 거의 전부 "찾기가 `null`을 돌려줬는데 그걸 모르고 썼다"이다. id 오타, 스크립트가 HTML보다 먼저 실행됨(2-1), 선택자 오타. 찾은 뒤 `console.log(form)`으로 `null`이 아닌지 확인하는 습관이 디버깅 시간을 반으로 줄인다.

### 3. 읽고 바꾸기: `textContent`, `classList`, `style`, `dataset`, `value`

**한 줄 정의.** 참조를 얻었으면 **속성(property)**으로 읽고 쓴다. 글자는 `textContent`, 꼬리표는 `classList`, 인라인 스타일은 `style`, `data-*`는 `dataset`, 입력칸 값은 `value`.

**비유.** 직원(요소)의 명찰 글자 바꾸기, 완장 달기/떼기, 유니폼 색 바꾸기, 메모 읽기.

**실제 예시.**

```js
// 글자: Node.textContent — "노드와 그 자손의 텍스트 콘텐츠를 표현합니다"
balanceText.textContent = formatMoney(calculateBalance());
levelText.textContent = level;

// 꼬리표: Element.classList — "엘리먼트의 클래스 속성의 컬렉션"
mapScreen.classList.add("hidden");           // 붙이기
screen.classList.remove("hidden");           // 떼기
roomBtn.classList.contains("locked");        // 있나? → true/false
// classList.toggle("x")는 있으면 떼고 없으면 붙인다

// 인라인 스타일: style.속성 (CSS의 width → style.width)
xpFill.style.width = (xpInLevel / XP_PER_LEVEL) * 100 + "%";

// data-*: dataset (data-room → dataset.room)
if (roomBtn.dataset.room === "ledger") { ... }

// 입력칸 값: value (항상 문자열!)
const title = titleInput.value.trim();
const amount = Number(amountInput.value);    // 문자열 "9000" → 숫자 9000
titleInput.value = "";                       // 비우기
```

주의할 점 둘. (1) `value`는 **항상 문자열**이다. `type="number"`여도 `"9000"`이 온다. 그래서 `Number()`로 바꾼 뒤 계산한다(1-2의 자료형). (2) `style`로 바꾸면 CSS 파일보다 우선하는 인라인 스타일이 된다. 1.5단계 레슨의 원칙대로 **가능하면 클래스를 붙였다 떼고, 모양은 CSS에 맡기자**. 경험치 바처럼 값이 연속적으로 변하는 것만 `style`로 한다.

**`innerHTML`은 왜 피하나.** `list.innerHTML = ""`처럼 **비울 때**는 간편하다. 하지만 사용자 입력을 `innerHTML`에 넣으면 그 문자열이 HTML로 해석된다. MDN: "`innerHTML`이 웹 페이지에 텍스트를 삽입하는데 사용되는 것은 종종 볼 수 있습니다. 이것은 사이트의 공격 경로가 되어 잠재적인 보안 위험이 발생할 수 있습니다." 가계부 내용 칸에 `<img src=x onerror="...">` 같은 글을 넣으면 코드가 실행될 수 있다. 그래서 `app.js`는 사용자가 친 글자를 전부 `textContent`로 넣는다. `textContent`는 글자를 글자로만 취급한다. 12-2 보안 단원의 첫 번째 규칙이 이것이다.

**왜 중요한가.** 화면을 바꾸는 방법이 이 다섯 개면 거의 끝이다. 그리고 "글자는 `textContent`, 모양은 클래스, 값은 `value`를 `Number()`로"라는 세 습관이 버그의 절반을 미리 막는다.

### 4. 만들고 붙이고 지우기: `createElement`, `appendChild`, `remove`

**한 줄 정의.** 새 요소는 `document.createElement("태그")`로 만들고, `부모.appendChild(자식)`으로 나무에 붙이며, `요소.remove()`로 뗀다. MDN: `createElement()`는 "지정한 `tagName`의 HTML 요소를 만들어 반환합니다." `appendChild()`는 "한 노드를 특정 부모 노드의 자식 노드 리스트 중 마지막 자식으로 붙입니다." `remove()`(영어판)는 "removes the element from its parent node."

**비유.** 새 직원 채용(만들기) → 부서 배치(붙이기) → 퇴사(지우기). 만들기만 하고 배치를 안 하면 조직도(화면)에 안 나타난다.

**실제 예시.** `render()`의 한 줄 만들기.

```js
const item = document.createElement("li");        // 만들기 (아직 화면에 없음)

const title = document.createElement("span");
title.className = "entry-title";                  // class 통째로 지정
title.textContent = entry.title;                  // 글자 넣기

item.appendChild(title);                          // li 안에 span
list.appendChild(item);                           // ul 안에 li → 이제 보인다
```

`showXpPop()`은 세 단계를 한 번에 보여 준다. 만들고(`createElement("div")`), 붙이고(`document.body.appendChild(pop)`), 1초 뒤 지운다(`pop.remove()`). `setTimeout`은 "만료된 후 함수나 지정한 코드 조각을 한 번 실행하는 타이머를 설정합니다."(MDN) 첫 인수가 함수, 둘째가 밀리초(1000 = 1초).

`appendChild`의 성질 하나: "만약 주어진 노드가 이미 문서에 존재하는 노드를 참조하고 있다면 `appendChild()` 메소드는 노드를 현재 위치에서 새로운 위치로 이동시킵니다." 즉 복사가 아니라 **이동**이다. 같은 요소를 두 군데 붙일 수 없다.

**왜 중요한가.** 목록·카드·표처럼 "데이터 개수만큼 반복되는 화면"은 전부 이 세 줄의 반복이다. 로드맵의 루틴 체크, 보유 종목, 학습 기록이 모두 `for (const x of 배열) { 만들고 붙인다 }`이다.

### 5. 이벤트: 사용자의 행동을 함수로 받기

**한 줄 정의.** 이벤트(event)는 "여러분이 프로그래밍하고 있는 시스템에서 일어나는 사건(action) 혹은 발생(occurrence)"(MDN '이벤트 입문')이고, `addEventListener()`는 "지정한 유형의 이벤트를 대상이 수신할 때마다 호출할 함수를 설정합니다."(MDN)

**비유.** 알람 조건. "삼성전자가 7만 원 닿으면(이벤트) 알림 울려(핸들러)". 조건을 등록해 두면 내가 지켜보지 않아도 그 순간 실행된다. MDN의 구분: "리스너는 발생되는 이벤트에 대해 듣고, 핸들러는 발생되는 이벤트에 응답해서 실행되는 코드입니다."

**실제 예시.** `app.js` 7번 구역.

```js
form.addEventListener("submit", function (event) {   // ① 대상.addEventListener(이벤트이름, 함수)
  event.preventDefault();                            // ② 폼의 기본 동작(페이지 이동)을 막는다
  const title = titleInput.value.trim();
  const amount = Number(amountInput.value);
  if (title === "" || amount <= 0) { return; }       // ③ 검사
  addEntry(typeInput.value, categoryInput.value, title, amount);   // ④ 데이터 바꾸기 → 안에서 save(), render()          // ④ 데이터 바꾸기 → 안에서 save(), render()
  titleInput.value = "";
  amountInput.value = "";
  titleInput.focus();
});
```

- **이벤트 이름**: `"click"`(버튼), `"submit"`(폼 제출: 버튼 클릭 또는 엔터), `"input"`(입력칸 글자가 바뀔 때마다), `"change"`(값 확정), `"keydown"`. MDN `click`: "포인팅 장치의 포인터가 어느 요소 안에 위치하는 동안, 마우스 주 버튼처럼 장치의 버튼을 눌렀다 떼면 그 요소에서 `click` 이벤트가 발생합니다."
- **이벤트 객체**: 핸들러의 첫 매개변수(`event`, 흔히 `e`). `event.target`은 "항상 이벤트가 발생된 요소에 대한 참조"다. 방 버튼처럼 같은 핸들러를 여러 요소에 달 때 "어느 것이 눌렸나"를 `e.target`으로 안다.
- **`preventDefault()`**: 2-2에서 봤듯 폼의 기본 동작은 서버로 전송하며 페이지를 새로고침하는 것이다. 우리는 JS가 처리하니 막는다. 이 한 줄을 빼면 "추가 누르면 화면이 깜빡이고 목록이 사라져요"가 된다(실제로는 localStorage 덕에 다시 로드되지만 입력 흐름이 끊긴다).
- **왜 `onclick=` 속성이 아니라 `addEventListener`인가.** MDN은 HTML 안에 `onclick="..."`을 쓰는 인라인 방식을 "구식이며 권장되지 않"는다고 한다. "하나의 버튼은 괜찮지만, 100개의 버튼이라면 어떡할 건가요?" 또 `addEventListener`는 같은 이벤트에 여러 핸들러를 달 수 있다("같은 리스너에 대해 다수의 핸들러를 등록하는 것을 가능하게").

**동적으로 만든 요소의 이벤트.** `render()` 안에서 삭제 버튼을 만들 때마다 `deleteBtn.addEventListener("click", ...)`을 단다. 요소를 새로 만들면 리스너도 새로 달아야 한다. 더 큰 앱에서는 부모 `<ul>` 하나에 리스너를 달고 `e.target`으로 어느 자식인지 가리는 **이벤트 위임**(MDN '이벤트 입문'의 "이벤트 위임")을 쓴다. 이벤트가 자식에서 부모로 올라가는 버블링(bubbling) 덕분이다. 지금은 "리스너는 요소를 만들 때 단다"만 기억하자.

**왜 중요한가.** 앱의 모든 상호작용은 이벤트 하나로 시작한다. 그리고 "어떤 이벤트에, 어떤 요소에, 어떤 함수를" 세 가지를 말할 수 있으면 클로드에게 기능을 정확히 주문할 수 있다. "엔터로도 추가되게"는 `submit`, "글자 칠 때마다 글자 수 표시"는 `input`, "드롭다운 바꾸면 즉시 반영"은 `change`.

### 6. 패턴: 데이터가 바뀌면 화면 전체를 다시 그린다

**한 줄 정의.** 데이터(배열)를 **진실의 원본**(single source of truth)으로 두고, 데이터가 바뀔 때마다 화면을 데이터로부터 통째로 다시 만든다. `app.js`의 모든 변경은 `entries 변경 → save() → render()`로 끝난다.

**비유.** 장부와 전광판. 전광판 숫자를 손으로 고치지 않는다. **장부**(배열)를 고치고 전광판은 장부를 보고 다시 그린다. 그러면 전광판과 장부가 어긋날 일이 없다.

**실제 예시.**

```js
function render() {
  renderLevel();
  balanceText.textContent = formatMoney(calculateBalance());
  list.innerHTML = "";                 // 1. 싹 비운다
  if (entries.length === 0) { ... return; }
  const recentFirst = entries.slice().reverse();
  for (const entry of recentFirst) {   // 2. 배열을 보고 처음부터 다시 만든다
    const item = document.createElement("li");
    ...
    list.appendChild(item);
  }
}
```

반대 방식("DOM을 직접 고치기")은 `addEntry`에서 `<li>` 하나만 붙이고, `deleteEntry`에서 그 `<li>`만 떼는 것이다. 코드는 빨라 보이지만 잔액, 레벨, 빈 목록 문구, 정렬 순서까지 **각각** 따로 고쳐야 하고, 하나라도 빼먹으면 화면과 데이터가 어긋난다.

| | 전체 다시 그리기 | DOM 직접 수정 |
|---|---|---|
| 코드 양 | 적다. 바꾸는 함수는 데이터만 건드림 | 많다. 변경마다 화면 조작 코드 |
| 어긋남 위험 | 거의 없음 | 높음 |
| 성능 | 수백 건까지는 체감 없음. 수만 건이면 느려짐 | 빠름 |
| 입력 중인 값 | 폼은 목록 밖이라 안전. 목록 안에 입력칸이 있으면 초기화 주의 | 유지됨 |

**왜 중요한가.** 1단계 레슨의 말을 다시 빌리면 "작은 앱에서는 이게 제일 실수가 적다." 그리고 React·Vue 같은 도구는 이 패턴을 "데이터가 바뀌면 **바뀐 부분만** 다시 그려 주는 것"으로 자동화한 것이라, 지금 손으로 익혀 두면 나중에 그 도구들이 왜 존재하는지 바로 이해된다.

### 따라하기 3. 매매 복기 폼에 JS 붙이기 (90분)

2-2의 `trade-log.html` 아래쪽 `</body>` 직전에 `<script src="trade.js"></script>`를 추가하고, `trade.js`를 새로 만든다. `app.js`의 구조(데이터 → 요소 → 기능 → 그리기 → 이벤트 → 시작)를 그대로 따른다. 저장은 2-5에서 붙이니 지금은 새로고침하면 사라져도 된다.

```js
// ---------- 1. 데이터 ----------
let trades = [];

// ---------- 2. 화면 요소 ----------
const tradeForm = document.getElementById("trade-form");
const nameInput = document.getElementById("trade-name");
const sideInput = document.getElementById("trade-side");
const priceInput = document.getElementById("trade-price");
const qtyInput = document.getElementById("trade-qty");
const memoInput = document.getElementById("trade-memo");
const tradeList = document.getElementById("trade-list");

// ---------- 3. 기능 ----------
function addTrade(name, side, price, qty, memo) {
  trades.push({
    id: Date.now(),
    name: name,
    side: side,            // "buy" 또는 "sell"
    price: price,
    qty: qty,
    memo: memo,
    date: todayString(),   // 현지 시간 기준. app.js의 twoDigits·dateToString·todayString 세 함수를 trade.js 맨 위에 복사해 둔다 (toISOString()은 UTC라 아침 9시 전엔 어제 날짜가 된다)
  });
  render();
}

function deleteTrade(id) {
  trades = trades.filter(function (t) { return t.id !== id; });
  render();
}

// ---------- 4. 그리기: trades 배열을 보고 목록 전체를 다시 만든다 ----------
function render() {
  tradeList.innerHTML = "";

  if (trades.length === 0) {
    const empty = document.createElement("li");
    empty.textContent = "아직 기록이 없다. 오늘 매매를 적어 보자.";
    tradeList.appendChild(empty);
    return;
  }

  for (const t of trades.slice().reverse()) {
    const item = document.createElement("li");

    const head = document.createElement("strong");
    head.textContent = (t.side === "buy" ? "매수 " : "매도 ") + t.name;
    head.className = t.side === "buy" ? "side-buy" : "side-sell";

    const detail = document.createElement("span");
    detail.textContent = " " + t.price.toLocaleString("ko-KR") + "원 × " + t.qty + "주 · " + t.date;

    const memo = document.createElement("p");
    memo.textContent = t.memo;                 // 사용자가 친 글자는 반드시 textContent로

    const del = document.createElement("button");
    del.type = "button";                       // submit이 아니라는 표시 (폼 밖이지만 습관)
    del.textContent = "삭제";
    del.addEventListener("click", function () { deleteTrade(t.id); });

    item.appendChild(head);
    item.appendChild(detail);
    item.appendChild(memo);
    item.appendChild(del);
    tradeList.appendChild(item);
  }
}

// ---------- 5. 이벤트 ----------
tradeForm.addEventListener("submit", function (event) {
  event.preventDefault();

  const name = nameInput.value.trim();
  const price = Number(priceInput.value);
  const qty = Number(qtyInput.value);
  if (name === "" || price <= 0 || qty <= 0) { return; }

  addTrade(name, sideInput.value, price, qty, memoInput.value.trim());

  tradeForm.reset();        // 폼 전체 비우기
  nameInput.focus();
});

// ---------- 6. 시작 ----------
render();
```

확인 순서. (1) 페이지를 열면 "아직 기록이 없다" 문구가 보인다(`render()`가 시작 시 한 번 돈다). (2) 기록을 두 건 넣으면 최근 것이 위에 온다. (3) 삭제 버튼이 동작한다. (4) 요소 탭에서 `<ul id="trade-list">`를 펼쳐 JS가 만든 `<li>` 구조를 본다. (5) 콘솔에 `trades`를 쳐서 배열과 화면이 일치하는지 본다. 어긋나면 `render()`를 안 부른 곳이 있는 것이다.

| 증상 | 원인 | 해결 |
|---|---|---|
| `Cannot read properties of null (reading 'addEventListener')` | 찾기가 `null`. id 오타, `<script>`가 HTML보다 위, 다른 페이지의 id | `console.log(요소)`로 `null` 확인. id 복사·붙여넣기. 스크립트는 `</body>` 직전 |

| 버튼을 눌러도 아무 일 없음 | 리스너를 안 달았거나 이벤트 이름 오타(`"clik"`), 또는 요소를 새로 만들었는데 리스너를 안 닮 | 이벤트 이름 확인. 동적 요소는 만들 때 달거나 부모에 위임 |

| `querySelectorAll` 결과에 `.map`이 없다는 에러 | NodeList는 배열이 아님 | `for...of`로 돌거나 `Array.from(목록)`으로 배열화 |

## 확인 퀴즈

**1. DOM과 HTML 파일의 관계를 한 문장으로 설명하고, 요소 탭에는 보이지만 파일에는 없는 요소의 예를 우리 앱에서 하나 들어라.**

<details><summary>정답과 해설</summary>
HTML 파일은 글자로 된 설계도이고, DOM은 브라우저가 그것을 읽어 메모리에 만든 나무 구조로 JS는 DOM을 다룬다(MDN: "a 'tree structure' representation created by the browser"). `render()`가 `createElement("li")`로 만들어 `appendChild`한 내역 `<li>`들, `showXpPop()`이 만드는 `.xp-pop` div가 파일에는 없고 DOM에만 있다.
</details>

**2. `document.getElementById("x")`와 `document.querySelectorAll("#x")`는 대상이 없을 때 각각 무엇을 돌려주며, 그 차이가 왜 중요한가?**

<details><summary>정답과 해설</summary>
전자는 `null`, 후자는 빈 NodeList(`[]`와 비슷)다. `null`에 `.textContent`를 쓰면 에러가 나지만 빈 목록은 `for...of`를 0번 돌 뿐 에러가 없다. 그래서 "하나를 찾아 바로 쓸 때"는 `null` 검사가 필요하고, "여러 개를 반복 처리"할 때는 빈 목록이 자연스럽게 아무 일도 안 한다. MDN: `querySelector`는 "일치하는 요소가 없으면 `null`을 반환", `querySelectorAll`은 "일치하는 것이 없는 경우에는 비어 있는 NodeList".
</details>

**3. 가계부 내용 칸에 `<script>alert(1)</script>`를 입력해도 아무 일이 없는 이유는? 어떤 코드로 바꾸면 위험해지는가?**

<details><summary>정답과 해설</summary>
`render()`가 `title.textContent = entry.title`로 넣기 때문이다. `textContent`는 문자열을 글자로만 취급해 태그로 해석하지 않는다. `title.innerHTML = entry.title`로 바꾸면 문자열이 HTML로 해석되어 공격 경로가 된다(MDN: "사이트의 공격 경로가 되어 잠재적인 보안 위험이 발생할 수 있습니다"). 사용자 입력은 항상 `textContent`.
</details>

**4. `form.addEventListener("submit", ...)` 대신 추가 버튼에 `"click"` 리스너를 달면 무엇이 달라지나?**

<details><summary>정답과 해설</summary>
입력칸에서 엔터를 쳤을 때의 처리가 빠진다. `submit` 이벤트는 버튼 클릭과 엔터 양쪽에서 발생하지만 `click`은 버튼만 잡는다. 또 `click` 핸들러에서는 폼의 기본 제출을 막기 위해 여전히 `preventDefault()`가 필요하거나 버튼을 `type="button"`으로 바꿔야 한다. 폼 처리는 `submit`에 다는 것이 정석이다.
</details>

**5. `deleteEntry(id)`가 해당 `<li>`를 직접 `remove()`하지 않고 `entries.filter` → `save()` → `render()`를 하는 이유를 "진실의 원본" 개념으로 설명하라.**

<details><summary>정답과 해설</summary>
화면이 아니라 데이터(`entries`)가 진실의 원본이기 때문이다. 배열에서 빼고 전체를 다시 그리면 목록·잔액·레벨·경험치 바·빈 목록 문구가 전부 같은 데이터로부터 한 번에 갱신되어 어긋날 수 없다. `<li>`만 떼면 잔액과 레벨을 따로 고쳐야 하고 하나라도 빼먹으면 화면과 저장된 데이터가 달라진다. 1단계 레슨: "데이터가 바뀌면 화면 전체를 다시 그린다는 단순한 방식인데, 작은 앱에서는 이게 제일 실수가 적다."
</details>

## 숙제

1. **레벨업 연출 완성** — 2-3 숙제 4에서 만든 `.level-badge.bump` 애니메이션을 JS로 연결한다. `renderLevel()`에서 레벨이 **이전보다 커졌을 때만** `levelText.parentElement.classList.add("bump")`를 하고, `setTimeout`으로 0.4초 뒤 `remove("bump")`한다. 힌트: 이전 레벨을 기억할 변수가 하나 필요하다(1-5 스코프).
2. **총 건수와 이번 달 건수** — 1단계 숙제 3의 "총 N건"을 `render()` 안에서 그리도록 만들고, 그 옆에 "이번 달 N건"을 추가한다. `entry.date.slice(0, 7)`과 오늘 날짜의 앞 7자리를 비교한다(1-6 `filter`).
3. **이벤트 위임으로 바꾸기** — `render()` 안의 `deleteBtn.addEventListener`를 없애고, `list`에 리스너 하나를 달아 `event.target`이 `.delete-btn`인지 확인한 뒤 삭제하도록 바꾼다. 어느 항목인지 알려면 `deleteBtn.dataset.id = entry.id`처럼 `data-*`에 id를 심어 두면 된다(2-2 속성). 동작이 같은지 확인하고, 두 방식의 장단점을 세 줄로 적는다.
- 보너스(선택): **매매 복기에 입력 중 미리보기** — `trade-log.html`의 체결가·수량 칸에 `input` 이벤트를 달아, 둘 다 숫자가 들어오면 "예상 금액: 710,000원"을 폼 아래에 실시간으로 보여 준다. `toLocaleString("ko-KR")`을 쓴다.
