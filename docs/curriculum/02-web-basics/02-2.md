## 이 단원을 마치면

- 요소(element)·태그(tag)·속성(attribute)·내용(content)을 구별하고, 여는 태그와 닫는 태그의 짝을 틀리지 않게 쓸 수 있다.
- `<!DOCTYPE html>`부터 `</html>`까지 문서의 뼈대를 외워서 빈 파일에 새로 쓸 수 있다.
- `<form>`, `<label>`, `<input>`, `<select>`, `<button>`으로 입력 폼을 만들고, `placeholder`·`required`·`min`·`type` 속성이 각각 무엇을 하는지 안다.
- `<header>`, `<main>`, `<section>`, `<footer>` 같은 시맨틱 태그와 `<div>`·`<span>`의 차이를 설명하고 골라 쓸 수 있다.
- 개발자 도구의 요소(Elements/Inspector) 탭에서 페이지 구조를 트리로 보고, 그 자리에서 글자나 속성을 바꿔 실험할 수 있다.
- 매매 복기 입력 폼 한 페이지를 HTML만으로 직접 만들 수 있다.

## 왜 배우나 (나에게 어떤 쓸모)

HTML은 "화면에 뭐가 있는지"를 적는 언어다. 가계부의 입력칸·버튼·목록이 전부 `index.html`에 적혀 있고, 로드맵의 다음 단계(카테고리, 자산관리부, 루틴 체크)도 결국 **입력칸과 목록을 HTML로 추가하는 일**에서 시작한다. 클로드가 코드를 대신 써 주더라도, 어떤 태그가 어떤 역할인지 모르면 결과물이 맞는지 볼 수가 없다.

주식으로 비유하면 HTML은 **주문표 양식**이다. 종목, 수량, 가격, 매수/매도 선택란이 어디에 있는지 정하는 것이 HTML이고, 칸을 예쁘게 꾸미는 것은 CSS(2-3), 칸에 적힌 값을 읽어서 계산하는 것은 JS(2-4)다. 양식을 제대로 못 만들면 그 뒤가 전부 꼬인다.

그리고 HTML은 **가장 빨리 성취감이 나는 언어**다. 문법 에러로 멈추지 않고, 틀려도 브라우저가 어떻게든 그려 준다. 오늘 매매 복기 폼을 한 페이지 만들어 보면 "앱을 만든다"는 감각이 생긴다.

## 핵심 개념

### 1. HTML과 요소의 구조

**한 줄 정의.** HTML(HyperText Markup Language)은 프로그래밍 언어가 아니라 **마크업 언어**다. MDN 'HTML 시작하기': "프로그래밍 언어는 아니고, 우리가 보는 웹페이지가 어떻게 구조화되어 있는지 브라우저로 하여금 알 수 있도록 하는 마크업 언어입니다."

**비유.** 형광펜과 포스트잇. 원고(내용)에 "여기는 제목", "여기는 목록"이라고 표시를 붙이는 것이 마크업이다. 계산을 하지 않으니 1과정의 변수·조건문 같은 것이 없다.

**실제 예시.** `index.html`의 한 줄.

```html
<p>방을 눌러서 들어가세요</p>
```

| 조각 | 이름 | 설명 |
|---|---|---|
| `<p>` | 여는 태그(opening tag) | 요소 이름을 꺾쇠로 감쌈. 여기서 효과 시작 |
| `방을 눌러서 들어가세요` | 내용(content) | 요소가 감싸는 실제 내용 |
| `</p>` | 닫는 태그(closing tag) | 요소 이름 앞에 `/`. MDN: 닫는 태그를 빠뜨리는 것은 "흔한 초보자 실수" |
| 전체 | 요소(element) | 여는 태그 + 내용 + 닫는 태그 |

요소는 **중첩**(nesting)된다. `<header>` 안에 `<h1>`이 있고 `<h1>` 안에 글자가 있다. 규칙은 하나, **안쪽에서 연 것은 안쪽에서 닫는다**. `<p><strong>굵게</p></strong>`처럼 엇갈리면 안 된다. MDN은 브라우저가 "잘못된 마크업을 자체적으로 보정해 보여 줄 수 있어" 오히려 초보자가 실수를 눈치채기 어렵다고 경고한다.

닫는 태그가 없는 요소도 있다. `<input>`, `<img>`, `<meta>`, `<br>`처럼 "주로 문서에 무언가를 첨부하기 위해 단일 태그를 사용하는 요소"를 빈 요소(void element)라고 부른다. `<input></input>`이라고 쓰지 않는다.

**왜 중요한가.** 화면이 이상하게 밀리거나 글자가 전부 굵어지는 버그의 대부분이 닫는 태그 하나 빠진 것이다. 개발자 도구(핵심 개념 6)로 보면 브라우저가 어디서 임의로 닫아 버렸는지 바로 보인다.

### 2. 문서의 뼈대: `index.html`을 위에서부터 읽기

**한 줄 정의.** 모든 HTML 문서는 `<!DOCTYPE html>` 선언, `<html>` 안의 `<head>`(안 보이는 설정)와 `<body>`(보이는 내용)로 이루어진다.

**비유.** 회사 서류철. 표지(doctype), 서류철 자체(html), 앞장의 색인·메타 정보(head), 실제 서류(body).

**실제 예시.** 우리 `index.html`의 위쪽 10줄.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>나의 1인 회사</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  ...
  <script src="app.js"></script>
</body>
</html>
```

| 줄 | 역할 (MDN 'HTML 시작하기' 설명) |
|---|---|
| `<!DOCTYPE html>` | "유효한 문서 형식을 나타내는 짧은 문장이고, 이 것만 알고 있으면 됩니다." 옛날 규칙 흔적이라 외우기만 하면 된다 |
| `<html lang="ko">` | 페이지 전체를 감싸는 "기본 요소". `lang="ko"`는 한국어 문서라는 표시 |
| `<head>` | "홈페이지 이용자에게는 보이지 않지만" 브라우저와 검색엔진이 읽는 정보 |
| `<meta charset="UTF-8">` | 문자 인코딩. "이 설정을 사용하면" 한글을 포함한 "대부분의 문자"가 깨지지 않는다. 한글이 `ë°©` 같은 외계어로 보이면 이 줄을 의심 |
| `<meta name="viewport" ...>` | 폰에서 볼 때 화면 폭에 맞추라는 설정. MDN 반응형 디자인 문서는 이 태그를 "항상 포함"하라고 한다(2-3에서 다시) |
| `<title>` | "브라우저 탭에 표시되는 제목" |
| `<link rel="stylesheet" href="style.css">` | CSS 파일 연결. 2-1에서 본 "추가 HTTP 요청"이 여기서 발생 |
| `<body>` | "텍스트, 이미지, 비디오, 게임" 등 화면에 보이는 모든 것 |
| `<script src="app.js">` | JS 파일 연결. `</body>` 직전에 두는 이유는 2-1 핵심 개념 5 |

**왜 중요한가.** 빈 파일에서 새 페이지를 만들 때 이 뼈대를 손으로 쓸 수 있어야 한다. 따라하기 3에서 매매 복기 페이지를 새로 만들 때 그대로 쓴다. 또 `<meta charset>`을 빼먹은 한글 깨짐은 클로드에게 물어보기 전에 스스로 잡을 수 있는 1분짜리 버그다.

### 3. 속성: 태그에 붙이는 추가 정보

**한 줄 정의.** 속성(attribute)은 여는 태그 안에 `이름="값"` 형태로 붙여 요소에 정보를 더하는 것이다. MDN: "속성은 요소에 실제론 나타내고 싶지 않지만 추가적인 내용을 담고 싶을 때 사용합니다."

**비유.** 주문표의 작은 체크박스와 메모란. 화면에 그대로 보이지는 않지만 "이 칸은 숫자만", "이 방은 재무부" 같은 지시가 적혀 있다.

**실제 예시.** `index.html`의 방 버튼 하나.

```html
<button class="room open" data-room="ledger">
```

- `class="room open"` — 꼬리표. 공백으로 구분해 여러 개를 붙일 수 있다. CSS가 모양을 정할 때(2-3), JS가 `classList`로 붙였다 뗄 때(2-4) 쓴다. 1.5단계 레슨에서 "자바스크립트는 꼬리표를 붙였다 뗐다만 하고, 꼬리표가 어떻게 보이는지는 CSS가 정한다"고 했던 그 꼬리표다.
- `id="entry-form"` — 문서 안에서 **하나뿐인** 이름. `app.js`의 `document.getElementById("entry-form")`이 이걸로 찾는다. 같은 id가 두 개면 첫 번째만 잡힌다.
- `data-room="ledger"` — 내가 마음대로 이름 붙인 사용자 데이터 특성. MDN 'HTMLElement: dataset': `dataset`은 "요소의 사용자 데이터 특성(`data-*`)에 대한 읽기/쓰기 접근을 제공합니다." 그래서 `app.js`에서 `roomBtn.dataset.room === "ledger"`로 읽는다(`data-` 접두사를 떼고 읽는다).

속성 쓰는 규칙 세 가지(MDN): 요소 이름과 속성 사이, 속성과 속성 사이에 **공백**, 이름 뒤에 **등호**, 값은 **따옴표**로 감싼다. `required`처럼 값 없이 이름만 쓰는 불 속성(boolean attribute)도 있다. "때때로 값이 없는 속성을 볼 수 있을텐데 이것은 허용되는 것입니다."

**왜 중요한가.** JS가 HTML을 찾는 손잡이가 `id`와 `class`, JS에 작은 정보를 넘기는 통로가 `data-*`다. 2-4에서 "요소 찾기"의 절반이 이 속성 이야기다.

### 4. 폼과 입력: 사용자의 값을 받는 요소들

**한 줄 정의.** 폼(form)은 사용자가 값을 입력해 제출하는 영역이다. MDN `<form>`: "정보를 제출하기 위한 대화형 컨트롤을 포함하는 문서 구획을 나타냅니다."

**비유.** 주문표 한 장. `<form>`이 종이, `<label>`이 각 칸의 이름표, `<input>`·`<select>`가 칸, `<button type="submit">`이 "주문" 도장.

**실제 예시.** 가계부 폼 전체.

```html
<form id="entry-form" class="entry-form">
  <select id="entry-type">
    <option value="expense">지출</option>
    <option value="income">수입</option>
  </select>
  <input type="text" id="entry-title" placeholder="내용 (예: 점심, 월급)" required>
  <input type="number" id="entry-amount" placeholder="금액" min="1" required>
  <button type="submit">추가</button>
</form>
```

| 요소·속성 | 하는 일 | 근거 (MDN) |
|---|---|---|
| `<form>` | 입력 컨트롤을 묶고, 제출(submit) 이벤트를 낸다. 원래는 `action`(보낼 URL)과 `method`(get/post)로 서버에 전송하지만, 우리는 JS가 가로채서 처리한다(2-4) | '당신의 첫 HTML 폼': "`action` 속성은 폼이 제출될 때 수집된 데이터를 전송할 위치(URL)를 정의합니다." |
| `<select>` + `<option>` | 드롭다운 메뉴. 각 `<option>`의 `value`가 JS가 받는 실제 값("expense"), 태그 사이 글자("지출")가 사람이 보는 값 | `<select>`(영어판): "represents a control that provides a menu of options." "Each `<option>` element should have a `value` attribute containing the data value to submit" |
| `<input type="text">` | 한 줄 글자 입력. `<input>`은 빈 요소라 닫는 태그가 없다 | '당신의 첫 HTML 폼': "`<input>` 태그는 빈 요소이므로 닫는 태그가 필요하지 않습니다." |
| `<input type="number">` | 숫자 입력. 숫자가 아닌 글자를 거른다 | `<input type="number">`(영어판): "include built-in validation to reject non-numerical entries." |
| `min="1"` | 이보다 작은 값이면 제출 검사 실패 | 같은 문서: "The minimum value to accept for this input. If the `value` of the element is less than this, the element fails constraint validation." |
| `placeholder` | 비어 있을 때 회색으로 보이는 힌트 글. 값이 아니다 | `<input>` 속성 목록에 있음 |
| `required` | 비우면 제출이 막힌다(불 속성) | `<input>` 속성 목록에 있음 |
| `<button type="submit">` | 누르면 폼이 제출된다. 엔터로도 제출됨 | '당신의 첫 HTML 폼': "`submit` 버튼 (기본값)을 클릭하면 폼의 데이터가 (...) 전송됩니다." |

**우리 폼에 빠진 것: `<label>`.** MDN `<label>`: "사용자 인터페이스 항목의 설명을 나타냅니다." 연결법은 "`<input>`에 `id` 속성을 넣어야합니다. 그런 다음 `<label>`에 `id`와 같은 값의 `for` 속성을 넣어야합니다." 라벨을 클릭하면 해당 입력칸에 커서가 가고, 화면 읽기 프로그램도 칸의 이름을 읽어 준다. 따라하기 2에서 추가한다.

**왜 중요한가.** 앞으로 만들 모든 기록 기능(매매 복기, 루틴 체크, 자산 입력)이 "폼을 만들고 → JS로 값을 읽고 → 배열에 넣는" 같은 패턴이다. `type="number"`와 `min`, `required`만 제대로 써도 `app.js`에서 `if (title === "" || amount <= 0)`로 거르던 검사의 상당 부분을 브라우저가 대신해 준다.

### 5. 시맨틱 태그: 의미가 있는 상자와 없는 상자

**한 줄 정의.** 시맨틱(semantics)은 "코드 조각의 '의미'"다. MDN 용어집: "이 HTML 엘리먼트가 가진 목적이나 역할은 무엇일까요?" 를 묻는 것. `<h1>`은 "이 페이지에서 최상위 제목"이라는 의미를 가진 시맨틱 요소이고, `<span style="font-size:32px">`는 똑같이 보여도 "의미적 가치가 없으므로" 그 이점을 얻지 못한다.

**비유.** 서류 봉투에 "계약서", "영수증"이라고 적어 두는 것과, 전부 빈 봉투에 넣고 색깔로만 구분하는 것. 나는 색으로 알아보지만 남(검색엔진, 화면 읽기 프로그램, 클로드)은 글씨가 있어야 안다.

**실제 예시.** MDN 'Structuring documents'(영어판)가 제시하는 대표 구획 요소를 우리 앱에 대입했다.

| 태그 | 뜻 | 우리 앱에서 |
|---|---|---|
| `<header>` | 머리글(제목, 로고) | 간판 `<header class="sign">`, 창 제목 `<header class="window-title">` |
| `<nav>` | 이동 메뉴 | 지도의 방 버튼들을 묶을 때 쓸 수 있다 |
| `<main>` | 이 페이지의 고유 내용. "Use `<main>` only once per page, and put it directly inside `<body>`" | 아직 없음. 숙제 |
| `<section>` | "HTML 문서의 독립적인 구획", "보통 제목을 포함" | `<section id="map-screen">`, `<section id="ledger-screen">` |
| `<article>` | 혼자서도 성립하는 글 한 편 | 매매 복기 한 건, 월별 리포트 한 편 |
| `<aside>` | 곁가지 정보 | 참고 메모, 관련 링크 |
| `<footer>` | 바닥글 | 저작권, 버전 표시 |
| `<ul>`/`<li>` | "정렬되지 않은 목록" | `<ul id="entry-list">`와 JS가 만드는 `<li>` |

의미가 없는 상자도 필요하다. `<div>`(블록)와 `<span>`(인라인)이다. MDN: "`<div>` is a block level non-semantic element, which you should only use if you can't think of a better semantic block element to use". 우리 앱의 `<div class="balance">`, `<span class="room-label">`이 그 예다. 다만 경고도 따른다. "Divs are so convenient to use that it's easy to use them too much. (...) they just clutter your HTML code."

**왜 중요한가.** MDN 용어집이 꼽는 이점: 검색엔진이 중요한 키워드로 본다, 화면 읽기 프로그램 사용자가 "안내판"으로 쓴다, "의미없고 클래스 이름이 붙여져있거나 그렇지 않은 끊임없는 `div`들을 탐색하는 것보다, 의미있는 코드 블록을 찾는 것이 훨씬 쉽습니다." 마지막 이점은 클로드에게도 그대로 적용된다. `<main>`, `<section>`으로 나뉜 HTML은 "재무부 화면의 폼만 고쳐 줘"라는 요청을 훨씬 정확하게 이해시킨다.

### 6. 개발자 도구로 구조 보기

**한 줄 정의.** 개발자 도구의 요소 탭(크롬: Elements, 파이어폭스: Inspector)은 "what the HTML on your page looks like at runtime, as well as what CSS is applied to each element"를 보여 주고, "instantly modify the HTML and CSS and see the results of your changes reflected live"하게 해 준다(MDN 'What are browser developer tools?').

**비유.** HTS의 "종목 상세" 창. 차트 위를 클릭하면 그 캔들의 시가·고가·저가가 뜨듯, 화면의 요소를 클릭하면 그 요소의 태그·속성·CSS가 뜬다.

**실제 예시.** 여는 법은 2-1과 같다. Windows `Ctrl`+`Shift`+`I` 또는 `F12`, Mac `⌘`+`⌥`+`I`. 더 빠른 길은 MDN이 안내하는 우클릭 메뉴다: "right-click an item on a webpage (Ctrl-click on the Mac), and choose Inspect Element". 그러면 "this method straight-away highlights the code of the element you right-clicked" — 그 요소의 코드가 바로 선택된다. 트리에서 `▶`를 눌러 펼치고 접으며 중첩 구조를 눈으로 확인한다.

**왜 중요한가.** 소스 파일(`index.html`)과 **지금 브라우저가 들고 있는 DOM**은 다르다. `app.js`가 `<li>`를 만들어 붙이면 파일에는 없는 `<li>`가 요소 탭에는 보인다. 2-4의 DOM 조작을 눈으로 검증하는 유일한 창이자, 다른 사람 사이트의 구조를 훔쳐보며 배우는 교과서다.

### 따라하기 2. 가계부 폼에 라벨 달기 (20분)

`index.html`의 폼을 아래처럼 고친다. 화면에 보이는 라벨이 아니라 **입력칸의 이름표**를 다는 작업이다.

```html

  <label for="entry-type">구분</label>
  <select id="entry-type">
    <option value="expense">지출</option>
    <option value="income">수입</option>

  <input type="number" id="entry-amount" placeholder="금액" min="1" required>

</form>
```

저장하고 새로고침한 뒤 확인할 것 세 가지.

- "금액" 글자를 클릭하면 금액 칸에 커서가 간다. `for`와 `id`가 연결된 증거다.

- 금액에 0을 넣으면 `min="1"` 때문에 역시 막힌다.

폼이 세로로 길어져 보기 싫을 수 있다. 모양은 2-3의 일이다. 지금은 구조만 맞으면 된다.

## 확인 퀴즈

**1. `<input type="number" id="entry-amount" min="1" required>`에서 요소·태그·속성·빈 요소를 각각 짚어 보라.**

<details><summary>정답과 해설</summary>
요소는 이 `<input ...>` 전체이고, `<input ...>`은 여는 태그다. `type`, `id`, `min`, `required`가 속성이며 `required`는 값이 없는 불 속성이다. `<input>`은 빈 요소(void element)라 닫는 태그와 내용이 없다. MDN: "`<input>` 태그는 빈 요소이므로 닫는 태그가 필요하지 않습니다."
</details>

**2. 새 HTML 파일을 열었더니 한글이 전부 깨져 보인다. `<head>` 안에서 가장 먼저 확인할 한 줄은?**

<details><summary>정답과 해설</summary>
`<meta charset="UTF-8">`. MDN: "이 요소는 HTML 문서의 문자 인코딩 설정을 UTF-8로 지정하는 것이며 (...) 대부분의 문자가 포함됩니다." 이 줄이 없거나 파일이 다른 인코딩으로 저장되면 한글이 깨진다.
</details>

**3. `<label>`을 `<input>`과 연결하는 두 가지 방법은?**

<details><summary>정답과 해설</summary>
(1) `<input>`에 `id`를 주고 `<label for="그 id">`로 연결한다. (2) `<label>` 안에 `<input>`을 중첩한다. MDN: "`<label>` 안에 `<input>`을 중첩시킬 수 있습니다. 이 경우 연관이 암시적이므로 `for` 및 `id` 속성이 필요없습니다." 우리 앱은 (1)을 쓴다. 라벨을 클릭하면 입력칸에 초점이 가는지로 연결을 확인할 수 있다.
</details>

**4. 가계부 화면의 잔액 카드 `<div class="balance">`를 `<section>`으로 바꾸는 것이 좋을까? 근거를 들어 답하라.**

<details><summary>정답과 해설</summary>
꼭 그렇지는 않다. `<section>`은 "독립적인 구획"이고 "보통 제목을 포함"하는 데 쓰는 요소다. 잔액 카드는 제목 없는 작은 표시 상자이고 스타일 묶음 용도에 가까우므로 `<div>`가 적절할 수 있다. MDN도 `<div>`는 "더 나은 시맨틱 요소가 없을 때" 쓰라고 한다. 반면 재무부 화면 전체(`#ledger-screen`)는 제목이 있는 독립 구획이므로 `<section>`이 맞다. 핵심은 "의미가 있으면 시맨틱, 단순 묶음이면 div".
</details>

**5. `index.html` 파일에는 `<li>`가 하나도 없는데 요소 탭에는 `<li>`가 여러 개 보인다. 왜인가?**

<details><summary>정답과 해설</summary>
요소 탭은 파일이 아니라 "지금 브라우저가 들고 있는 DOM"을 보여 준다(MDN: "what the HTML on your page looks like at runtime"). `app.js`의 `render()`가 `document.createElement("li")`로 만들어 `appendChild`로 붙였기 때문에 DOM에는 있고 파일에는 없다. 2-4에서 이 과정을 직접 다룬다.
</details>

## 숙제

1. **`<main>` 넣기** — `index.html`에서 두 `<section>`을 `<main>` 하나로 감싸라. MDN 규칙(페이지당 하나, `<body>` 바로 안)을 지켰는지 요소 탭으로 확인한다. 화면은 달라지지 않아야 정상이다.
2. **매매 복기 폼 확장** — 따라하기 3의 `trade-log.html`에 "매매일"(`<input type="date">`)과 "전략"(`<select>`: 돌파, 눌림, 역추세, 기타) 칸을 추가하라. `<label>`과 `id` 연결을 빠뜨리지 말 것. `type="date"`의 동작은 브라우저마다 다르니 직접 열어서 어떻게 보이는지 적어 둔다.
3. **남의 사이트 뜯어보기** — 자주 보는 증권·뉴스 사이트 하나를 열고 요소 탭으로 `<header>`, `<nav>`, `<main>`, `<footer>`가 쓰였는지 찾아보라. 없다면 `<div>`를 어떻게 쓰고 있는지, 그 `class` 이름이 어떤 규칙으로 지어졌는지 세 개만 메모한다.
4. **닫는 태그 실수 체험** — `index.html`의 `</header>` 하나를 일부러 지우고 새로고침해 본다. 화면이 어떻게 바뀌는지, 요소 탭에서 브라우저가 `<header>`를 어디서 닫았는지 적은 뒤 되돌린다(`git checkout index.html`).
