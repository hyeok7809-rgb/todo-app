# 2단계: 인사부(데일리 루틴)와 교육부(커리큘럼 진도)

방 두 개가 더 열렸다. 이제 세 부서(재무부·인사부·교육부)에서 오는 경험치가 합쳐지고, 상단 바는 "오늘 남은 일"을 보여 준다.

## 이번에 만든 것

- **인사부**: 매일 할 일 4개(주식 매매 복기, 헬스, 코딩 공부, 가계부 기록)를 체크한다. 가계부 기록은 재무부에 오늘 내역이 있으면 자동으로 체크된다. 4개를 다 한 날이 며칠 이어지는지 **연속 달성일**을 세고, 최근 14일 표를 보여 준다.
- **교육부**: 14과정 66단원 커리큘럼을 과정별로 접었다 펼 수 있다. 단원을 끝내면 체크하고 그 단원의 경험치(예상 시간 × 20)를 받는다. 12월 1일 개강 기준으로 단원마다 **예정일**이 자동 계산되고, 밀린 단원 수도 보인다.
- **상단 바**: "남은 일 2개: 인사부·교육부" 처럼 오늘 안 끝난 부서를 알려 주고, 전부 끝나면 "오늘 할 일 전부 완료"가 된다. 사장실 알약도 전부 끝났을 때만 ✅가 된다.

## 파일이 다섯 개가 됐다

| 파일 | 역할 |
|---|---|
| `sprites.js` | 그림 (글자 격자 → canvas) |
| `curriculum.js` | 데이터 (66단원 목록, `docs/curriculum/modules.json`에서 자동 생성) |
| `routine.js` | 인사부 |
| `study.js` | 교육부 |
| `app.js` | 공용 함수 + 지도 + 재무부 + **시작** |

`index.html` 맨 아래에서 이 순서대로 읽는다. **순서가 중요하다.** `app.js`가 맨 마지막인 이유는, 시작할 때(8번 구역) 다른 파일의 함수(`routineLoad()`, `renderStudy()` 등)를 부르기 때문이다. 반대로 `routine.js`가 `app.js`의 `makeElement()`를 쓰는 건 괜찮다. 함수는 **정의될 때**가 아니라 **불릴 때** 존재하면 되는데, 부르는 시점은 모든 파일을 읽은 뒤이기 때문이다.

> 부서마다 파일 하나. 다음에 자산관리부를 열 때도 `assets.js`를 하나 만들고 `index.html`에 한 줄 추가하면 된다.

## 꼭 이해하고 넘어갈 개념 4가지

### 1. 날짜를 키로 쓰는 객체

```js
// routine.js
let routineChecks = {};   // { "2026-10-21": ["trade", "gym"], "2026-10-22": ["gym"] }
const ids = routineChecks[date] || [];
```

재무부는 내역을 **배열**에 쌓았다. 루틴은 "어느 날 무엇을 했나"를 물어야 하니 **날짜 → 그날 체크한 id 배열** 모양의 객체가 편하다. `routineChecks[date]`가 없으면 `undefined`인데, `|| []`를 붙이면 "없으면 빈 배열로 치자"가 된다. 이 한 줄이 없으면 `.includes()`에서 에러가 난다.

### 2. 거꾸로 세는 반복문 (연속 달성일)

```js
function routineStreak() {
  let streak = 0;
  const day = new Date();
  if (!allRoutinesDone(dateToString(day))) {
    day.setDate(day.getDate() - 1); // 오늘은 아직 진행 중이면 어제부터
  }
  while (allRoutinesDone(dateToString(day))) {
    streak = streak + 1;
    day.setDate(day.getDate() - 1); // 하루 전으로
  }
  return streak;
}
```

`for`가 "몇 번"을 정해 놓고 도는 반복이라면, `while`은 "조건이 참인 동안" 돈다. 며칠이 이어질지 미리 모르니 `while`이 맞다. `setDate(getDate() - 1)`은 자바스크립트가 월 바뀜(1일 → 지난달 말일)을 알아서 처리해 준다.

### 3. 자동으로 계산되는 값은 저장하지 않는다

"가계부 기록" 루틴은 체크 버튼이 없다. `isRoutineDone()`이 재무부의 `entries`에서 오늘 날짜 내역이 있는지 **그때그때 계산**한다. 같은 사실을 두 군데(내역 + 체크)에 저장하면 둘이 어긋나는 순간이 온다. **원본 하나, 나머지는 계산**이 원칙이다. 경험치도 마찬가지로 저장하지 않고 `totalXp()`가 매번 더한다.

### 4. 부서마다 다른 "오늘 했나"를 한 함수로

```js
// app.js
function roomDoneToday(roomId) {
  if (roomId === "ledger") return todayEntries().length > 0;
  if (roomId === "routine") return routineDoneToday();
  if (roomId === "study") return studyDoneToday();
  if (roomId === "ceo") return openRooms().every(function (room) { return roomDoneToday(room.id); });
  return false;
}
```

지도의 팀장 알약마다 `data-room="routine"` 같은 꼬리표가 붙어 있고, `renderStatus()`는 꼬리표를 읽어 `roomStatus(roomId)`를 묻는다. 방이 늘어도 `renderStatus()`는 안 바꾼다. 이 함수에 한 줄만 추가하면 된다. 사장실은 자기 자신을 다시 부르는(재귀) 모양인데, "열린 부서 전부가 완료인가"를 그대로 코드로 옮긴 것이다.

## 숙제 (3개)

1. **루틴 바꾸기** — `routine.js`의 `ROUTINES`에서 "헬스"를 내가 실제로 하는 운동 이름으로 바꾸고, 다섯 번째 루틴을 하나 추가해 보라. (id는 영문, 겹치지 않게.) 추가하면 "4개 다 하면 하루 달성" 문구도 자동으로 5개가 되는지 확인.
2. **개강일 바꾸기** — `study.js`의 `STUDY_START`를 다음 주 월요일로 바꾸고, 교육부에서 예정일이 전부 밀리는지, 일요일이 건너뛰어지는지 확인하라. 끝나면 다시 `2026-12-01`로.
3. **경험치 규칙 바꾸기** — 루틴 체크 1개를 10이 아니라 20 EXP로 바꾸려면 어디를 고쳐야 할까? 한 군데만 고치면 되는 이유를 `totalXp()`를 읽고 한 줄로 적어 보라.

## 2.5단계 추가분: 카테고리·이번 달 요약·사장실 백업

### 카테고리와 이번 달 요약 (`app.js` renderMonth)
- 내역 객체에 `category: "food"` 같은 칸이 하나 늘었다. 옛날 기록에는 이 칸이 없으므로 `entry.category || "etc"`로 "없으면 기타"라고 읽는다. **데이터 모양이 바뀌면 옛 데이터도 읽을 수 있게** 하는 습관이다.
- 이번 달 것만 고르기: 날짜 문자열 `"2026-10-21"`의 앞 7글자 `"2026-10"`을 비교한다. `filter` 한 줄이다.
- 카테고리별 합계는 `byCategory[key] = (byCategory[key] || 0) + entry.amount` 한 줄로 모은다. 루틴에서 본 `|| []`와 같은 꼴이다.
- 막대 너비는 "가장 큰 항목 = 100%"로 비율을 잡는다. `sort`로 큰 순서를 만든다.

### 사장실 백업 (`ceo.js`)
- 브라우저는 파일을 함부로 못 만진다. 그래서 내려받기는 "글자 → Blob → 임시 주소 → 보이지 않는 링크 클릭" 네 단계, 가져오기는 `<input type="file">` + `FileReader`로 한다. 코드의 주석을 따라 읽으면 된다.
- 가져오기 전에 `confirm()`으로 한 번 묻고, 전부 지우기는 두 번 묻는다. **되돌릴 수 없는 일은 묻는다.**

### 숙제 (2개 추가)
