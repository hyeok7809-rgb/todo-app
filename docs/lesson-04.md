# 4단계: 기획부 — 주간 목표, 회고, 리포트

다른 부서는 "오늘"을 적는다. 기획부는 "이번 주"를 본다. 월요일에 목표를 세우고, 일요일에 돌아보고, 다른 부서가 쌓은 기록을 한 장으로 모아 보여준다. 로드맵에 적었던 "월별 그래프"는 외부 라이브러리 없이 `div` 8개의 높이로 먼저 그려 봤다. 라이브러리를 가져다 쓸지는 커리큘럼 2-6(fetch)과 4-1(API)을 끝낸 뒤에 정한다.

## 이번에 만든 것

- 이번 주 목표 최대 3개. 체크하면 10 EXP, × 로 지울 수 있다. 3개가 차면 입력 폼이 숨는다(`MAX_GOALS`).
- 주간 회고(잘한 것 / 아쉬운 것 / 다음 주에 할 것). 저장하면 30 EXP, **같은 주에 다시 저장하면 내용만 바뀌고 경험치는 없다.** 지난주 회고가 카드로 보인다.
- 이번 주 리포트: 루틴 체크 n/가능, 완료한 단원 수, 가계부 건수와 지출, 순자산 변화, 이번 주 경험치. 다른 부서의 데이터를 **읽기만** 해서 계산한다.
- 최근 8주 경험치 막대그래프. 가장 높은 주를 100%로 두고 나머지는 비율로 높이를 정한다.
- 팀장 상태: 이번 주 목표가 하나라도 있으면 "완료", 일요일에는 회고까지 저장해야 "완료". 자산관리부처럼 `weekly: true`라 상단 바의 "오늘 남은 일"에는 안 들어간다.
- 백업(사장실)에 `weekly-plans` 키가 추가됐다.
- 덤: 교육부의 "문서" 링크가 GitHub 주소(`DOC_BASE`)로 바뀌었다. GitHub에서 열면 마크다운이 보기 좋게 바뀌고 퀴즈 정답 접기도 동작한다. 내 컴퓨터 파일로 열고 싶으면 `study.js`의 `DOC_BASE`를 `""`로 바꾸면 된다.

## 꼭 이해하고 넘어갈 개념 3가지

### 1. "이번 주"를 계산하기: 월요일 찾기

```js
function weekStartOf(dateString) {
  const date = new Date(dateString + "T00:00:00"); // 현지 시간 자정으로 읽는다
  const back = (date.getDay() + 6) % 7;            // 월요일까지 되돌아갈 일수
  date.setDate(date.getDate() - back);
  return dateToString(date);
}
```

`getDay()`는 일요일이 0, 월요일이 1, … 토요일이 6이다. 우리는 "월요일부터 일요일까지"를 한 주로 보니까 월요일이 0이 되게 숫자를 돌려야 한다. `(getDay() + 6) % 7`을 계산해 보면 월1→0, 화2→1, …, 일0→6이 나온다. 그 일수만큼 날짜를 빼면 월요일이다. `"T00:00:00"`을 붙이는 이유는 `new Date("2026-12-03")`처럼 날짜만 주면 브라우저가 UTC 자정으로 읽어서 한국에서는 전날 밤이 되기 때문이다(1단계에서 `toISOString()`을 금지한 것과 같은 함정). 날짜 범위 검사는 `inWeek()`처럼 문자열 비교로 끝난다. `"2026-12-01" <= "2026-12-03"`은 글자 순서 비교지만 연-월-일 순서로 적어 둔 덕에 날짜 순서와 같다.

### 2. 다른 부서의 데이터를 "읽기만" 해서 합치기

`weekXp()`와 `renderWeekReport()`는 `entries`(재무부), `routineChecks`(인사부), `studyDone`(교육부), `assetData.history`(자산관리부)를 돌면서 그 주의 것만 골라 더한다. 어느 것도 **고치지 않는다.** 그리고 결과를 저장하지도 않는다. 2단계에서 배운 "계산값은 저장하지 않는다"의 큰 버전이다. 저장된 건 사실(언제 무엇을 했나)뿐이고, 리포트는 매번 새로 계산한다. 그래야 과거 기록을 고쳤을 때 리포트도 저절로 맞는다.

같은 이유로 계획을 읽는 함수와 고치는 함수를 둘로 나눴다.

```js
function planOf(weekStart)  { return planData[weekStart] || { goals: [], review: null }; } // 읽기: 없으면 빈 모양을 "빌려준다"
function planFor(weekStart) { if (!planData[weekStart]) planData[weekStart] = { goals: [], review: null }; return planData[weekStart]; } // 고치기: 없으면 만든다
```

그래프를 그리려고 8주를 읽을 때마다 빈 주가 저장 데이터에 생기면 안 되니까, 읽기는 `planOf`, 목표 추가·체크·회고 저장은 `planFor`를 쓴다. `||`는 "왼쪽이 비어 있으면 오른쪽을 쓴다"는 뜻이다.

### 3. 다시 그릴 때 입력 중인 글을 지우지 않기

`render()`는 데이터가 바뀌면 화면 전체를 다시 그린다. 목표 목록처럼 데이터에서 만든 화면은 그래도 된다. 그런데 회고 입력칸(`textarea`)은 다르다. 거기 쓰고 있는 글은 아직 데이터가 아니라 **화면에만** 있다. 회고를 쓰다가 목표 하나를 체크하면 `render()`가 돌고, 그때 입력칸을 저장된 값으로 다시 채우면 쓰던 글이 날아간다. 그래서 `renderReport()`는 입력칸을 건드리지 않고 상태 글자(`#review-status`)만 바꾼다. 입력칸은 시작할 때(`reportLoad`)와 저장 직후에만 `fillReviewForm()`으로 채운다. "화면 = 데이터"가 항상 성립하지는 않는다. 사용자가 손대는 중인 칸은 예외다.

작은 것 하나 더. 목표 목록을 `for...of`로 돌면서 버튼마다 "몇 번째인지"를 알려줘야 한다. 그래서 `const myIndex = index;`로 그 줄의 번호를 고정해 두고 클릭 함수가 `myIndex`를 쓴다. `index`를 그대로 쓰면 반복이 끝난 뒤의 마지막 값을 보게 된다.

## 숙제 (3개)

1. **목표 개수와 경험치 바꾸기** — `report.js`의 `MAX_GOALS`를 5로 바꾸고, `index.html`의 안내 문구(help-text)도 맞춰 고쳐라. 그다음 `XP_PER_GOAL`을 20으로 바꾸고 목표 하나를 체크해 상단 바의 경험치가 얼마나 오르는지 확인한다. 끝나면 둘 다 원래대로 돌려 놓는다(숫자를 한 곳에만 적어 둔 이유를 몸으로 느끼는 숙제).
2. **리포트에 줄 추가** — "헬스 횟수"를 리포트에 한 줄 더 넣어라. 힌트: `renderWeekReport()`의 루틴 반복문 안에서 `routine.id === "gym"`일 때만 따로 세고, `reportLine("헬스", gymCount + "번")`으로 붙인다.
3. **그래프를 12주로** — `renderWeekChart()`의 `back = 7`을 `11`로 바꿔 12주를 그려라. 390px 폭에서 아래 날짜 글자가 겹치면 `style.css`의 `.week-bar` 글자 크기를 줄이거나, 날짜를 `week.start.slice(8)`(일만)로 바꿔 보라. 보너스: 0 EXP인 주는 막대 위 숫자를 숨겨라(힌트: `if (week.xp > 0)`).
