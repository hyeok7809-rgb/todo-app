# 3단계: 자산관리부 — 계좌별 잔고와 순자산

재무부가 "들어오고 나간 돈(흐름)"이라면 자산관리부는 "지금 얼마 있나(잔액)"다. 둘은 다른 질문이라 데이터 모양도 다르다.

## 이번에 만든 것

- 계좌 등록(은행·증권·현금·부채), 계좌마다 새 잔고를 적고 "기록"을 누르면 **오늘 날짜의 스냅샷**으로 저장.
- 순자산 = 자산 합계 − 부채 합계. 각 계좌의 **가장 최근** 잔고로 계산.
- 날짜별 순자산 변화(최근 8개)와 전 기록 대비 증감.
- 잔고 기록 1회 = 10 EXP (같은 날 다시 고치면 경험치 없음). 7일 넘게 안 적으면 팀장 상태가 "근무 중"으로 돌아간다. 자산관리부는 매일이 아니라 **주 1회 점검** 부서라서 상단 바의 "오늘 남은 일"에는 안 들어간다(`ROOMS`의 `weekly: true`).
- 백업(사장실)에 `asset-accounts` 키가 추가됐다.

## 꼭 이해하고 넘어갈 개념 3가지

### 1. 왜 잔고를 계좌 안에 안 두고 날짜별로 두나

```js
// 이렇게 하면 "지난달 잔고"가 사라진다
{ id: 1, name: "통장", balance: 1500000 }

// 이렇게 하면 날짜마다 남는다 (assets.js의 history)
history: { "2026-10-21": { "1": 1500000 }, "2026-11-21": { "1": 1800000 } }
```

"변화를 보고 싶다"는 요구가 있으면 **과거 값을 덮어쓰지 않는** 구조가 필요하다. 그래서 `updateBalance()`는 오늘 날짜 칸에만 쓴다. 계좌를 지워도 과거 스냅샷은 그대로 둔다(지난달 순자산이 바뀌면 안 되니까).

### 2. "가장 최근 값" 찾기: 날짜 문자열 정렬

```js
const dates = Object.keys(assetData.history).sort().reverse(); // 최신 날짜부터
```

`"2026-10-21"` 같은 문자열은 그냥 정렬해도 날짜 순서가 맞는다(연-월-일 순서로 적었기 때문). `latestBalance()`는 최신 날짜부터 내려가며 그 계좌의 값이 처음 나오는 곳에서 멈춘다(`return`). `netWorthAt(date)`는 같은 일을 "그 날짜 이전"으로 제한해서 한다. 반복문 안의 `break`는 "찾았으니 이 계좌는 그만"이다.

### 3. 부서마다 할 일의 주기가 다르다

재무부·인사부·교육부는 매일, 자산관리부는 주 1회. 그래서 `roomDoneToday("assets")`는 "오늘 했나"가 아니라 "최근 7일 안에 했나"(`assetsUpdatedRecently`)를 돌려주고, `openRooms()`는 `weekly` 부서를 오늘 요약에서 뺀다. **같은 함수 이름을 쓰되 부서마다 기준이 다를 수 있다**는 걸 데이터(`weekly: true`)로 표현했다. 새 부서의 주기가 또 다르면 같은 방식으로 늘린다.

## 숙제 (3개)

1. **계좌 종류 추가** — "연금"을 자산 종류로 추가해 보라. `assets.js`의 `ACCOUNT_TYPES`와 `index.html`의 `<option>` 두 군데다. 2.5단계 숙제 4와 같은 구조 문제다. 이번에는 `ACCOUNT_TYPES`를 반복문으로 돌려 `<option>`을 JS가 만들게 바꿔 보라(힌트: `for (const key in ACCOUNT_TYPES)`와 `makeElement("option")`, `option.value`, `option.textContent`).
2. **점검 주기 바꾸기** — `assetsUpdatedRecently()`의 7일을 14일로 바꾸면 어디가 달라지는지 확인하고, 이 숫자를 `const CHECK_DAYS = 7;` 로 맨 위에 빼 보라.
3. **백업 확인** — 사장실에서 백업을 내려받아 `asset-accounts` 부분을 메모장으로 열어 보라. `history`가 위 1번 개념의 모양인지 확인한다.
